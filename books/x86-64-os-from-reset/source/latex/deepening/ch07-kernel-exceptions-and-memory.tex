\section{64 位入口先把固件状态收敛为内核 ABI}

入口汇编不承担通用内核逻辑，只完成无法用普通 C++ 表达的边界动作：确认
BootInfo 指针、选择内核栈、保持 16 字节栈对齐、清 DF、关闭尚未配置的中断，
再调用 \code{kernelMain}。所有未定义寄存器都视为垃圾，不能偶然依赖 QEMU
初值。

System V AMD64 ABI 在调用点要求栈对齐，并区分调用者与被调用者保存寄存器。
入口没有正常调用者，因此 C++ 返回属于不可恢复错误；汇编适配层转入 panic
或安全停机，而不是执行 \code{ret} 读取不存在的返回地址。

\section{内核链接边界驱动 BSS 与构造初始化}

链接脚本导出代码、只读数据、数据、BSS、构造数组和内核末端符号。入口在使用
全局对象前清零 \([bssBegin,bssEnd)\)，必要时遍历构造数组。所有区间先验证
单调、对齐并落入已映射内核范围。

BSS 不占 ELF 文件字节，但占运行内存；漏清零会让默认状态随 RAM 残留变化。
把清零交给 C++ 静态对象构造会形成循环，因为调用构造前语言运行环境尚未建立。

\section{IDT 门描述符定义异常入口的硬件动作}

IDTR 保存 IDT 基址和界限。64 位门描述符包含 64 位处理函数地址、段选择子、
IST 索引、门类型、DPL 和 present 位。处理器根据向量索引门，检查权限，
必要时切换栈，再压入返回现场。

\section{TSS 在 64 位模式主要提供特权栈}

长模式不使用 TSS 做硬件任务切换，但保留 RSP0--RSP2 和七个 IST 指针。
从 Ring 3 进入 Ring 0 时处理器使用 RSP0；设置 IST 的门无条件切到对应栈。
双重故障、NMI 和机器检查适合使用独立 IST，避免普通内核栈溢出导致再次故障。

TSS 描述符占两个 GDT 槽，必须编码完整 64 位基址。加载 TR 前，TSS 内存、
GDT 描述符和专用栈都要映射并保持生命周期覆盖整个内核运行。

\section{统一异常帧让 C++ 分发器看到稳定布局}

处理器有时压错误码，有时不压；特权切换时还会多压 SS 与 RSP。每个汇编桩
补齐缺失字段并保存通用寄存器，把向量号与规范化错误码放到固定位置。C++ 只
接受指向统一 \code{InterruptFrame} 的指针。

结构字段偏移由汇编常量和 C++ \code{static_assert} 双向检查。新增寄存器或
改变压栈顺序必须同时更新弹栈路径；\code{iretq} 前残留一个八字节字段都会把
后续值错当 RIP 或 CS。

\section{页故障错误码提供访问分类}

页故障错误码的 P 位区分不存在与权限违反，W/R 区分写与读，U/S 区分用户与
内核，RSVD 表示页表保留位错误，I/D 表示取指。CR2 保存故障线性地址。

用户访问不存在页可能触发按需分配，用户写只读共享页可能触发写时复制，用户
访问内核页应终止进程；内核访问非法地址通常是内核缺陷。处理器给出的位只描述
机制原因，内核还要结合虚拟区间元数据决定策略。

\section{内存图规范化先于物理页分配}

BootInfo 可能提供重叠、未对齐和不同类型区间。内核先验证每个
\([begin,end)\) 不溢出，按地址排序并切分重叠，保留类型优先于可用类型，
再按 4 KiB 边界向内收缩可用 RAM。零页、内核、BootInfo、页表、栈和设备
窗口全部扣除。

规范化输出是互不重叠、按地址递增的区间集合。物理分配器只消费这个集合，
不重复猜测固件语义。随机区间测试覆盖相邻、包含、部分重叠和最高地址溢出。

\section{位图分配器提供最小可审计实现}

每个物理页对应一位，0 与 1 的含义在模块契约固定。分配时寻找空闲位、原子
标记占用并返回页号；释放时验证对齐、范围和当前占用。连续页需求可以扫描一段
连续位，但时间复杂度随内存增长。

位图自身也占物理页，必须在开放可用页之前保留。若管理 4 GiB RAM，共
\(2^{20}\) 个 4 KiB 页，一位一页需要 128 KiB 位图。这个计算决定元数据
放置与早期映射范围。

\section{伙伴系统用阶数管理连续物理块}

伙伴分配器把 \(2^k\) 页作为一阶块。大块分裂成两个同阶伙伴，释放时若伙伴
空闲则递归合并。它能快速提供页表、DMA 或大页所需连续内存，但元数据和正确性
比位图复杂。

项目先用位图验证所有权，再在性能和连续分配需求出现后引入伙伴系统。替换时
公共接口仍使用 \code{PhysicalPageNumber} 与 \code{PageCount}，上层不应
依赖位图内部表示。

\section{页表遍历必须验证每一级}

映射函数从虚拟地址提取四级索引。中间表不存在时按策略分配并清零；存在时验证
它不是意外的大页且物理地址对齐。叶表项写入前检查目标虚拟页未映射，取消映射
则返回旧物理页和权限供所有权层处理。

页表页本身来自物理分配器并通过内核直接映射或临时窗口访问。递归映射、物理
内存直映区和临时映射各有不同复杂度，项目必须选定一种并写入地址空间契约。

\section{权限在页表层级上累积}

任一上级项 RW=0 都会限制下级写，任一上级 US=0 都会限制用户访问；NX 也按
处理器规则生效。只正确设置叶项不够。映射器从请求权限推导所有层允许的最小
集合，并在收紧权限后刷新 TLB。

内核执行 W\^X，用户页默认不可执行，用户地址空间不映射可写内核对象。页表
构造测试读取最终 64 位表项，检查地址掩码与权限位，而不是只查询上层缓存。

\section{TLB 是页表结果的处理器缓存}

处理器不会每次访问都重新走四级表。修改页表后，本核心可能继续使用旧 TLB
项；\code{invlpg} 使单页失效，写 CR3 或相应指令刷新更大范围。PCID 可以
减少地址空间切换的刷新，但需要额外代际管理。

多核系统每个核心有自己的 TLB。取消映射后必须向曾运行该地址空间的核心发送
shootdown，并等待确认，才能释放和复用物理页。否则另一个核心可能通过旧翻译
写入已经分配给新对象的页面。

\section{内核堆需要检测破坏而不隐藏失败}

早期堆可以按大小类别维护空闲块，大对象直接占整页。块头记录大小、状态和
校验，释放时检查重复释放与边界。调试构建用固定模式填充分配与释放内存，使
未初始化读取和 use-after-free 更容易暴露。

分配器不能在持有自身锁时调用可能再次分配的日志格式化。panic 和低内存路径
使用预分配缓冲与串口最小输出，避免诊断代码递归触发原故障。

\section{panic 是终止协议而不是普通日志函数}

panic 首先禁止本地中断并阻止其他核心继续修改共享状态，随后输出原因、CPU、
RIP、寄存器、控制寄存器和有限栈回溯。输出函数不得动态分配或获取未知锁。
最后进入明确停机、调试陷阱或重启策略。

QEMU 测试可让 panic 写入专用退出端口或稳定串口标记，宿主据此区分预期故障
与超时。生产硬件则可能保存崩溃区或触发看门狗，机制边界保持相同。
