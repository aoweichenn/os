\chapter{工具链怎样制造可执行事实}

\section{三个不同层次}

NASM 把 Intel 语法汇编成 ELF32 可重定位目标文件；LLD 按链接脚本为各节
分配最终虚拟地址；\code{llvm-objcopy} 去掉 ELF 元数据并用
\code{0xFF} 填充地址空洞，生成 QEMU 读取的裸 ROM。每一步解决不同问题：
指令编码、地址决议、介质字节布局。

\section{链接脚本是硬件布局的一部分}

普通应用程序由操作系统装载器解释 ELF；ROM 没有装载器。链接脚本必须直接
表达 ROM 起点、入口、复位向量和末端，并用 \code{ASSERT} 阻止入口代码覆盖
最后 16 字节。地址选择一旦错误，源码语义再正确也无法执行。

\section{ELF32 只是中间容器}

当前入口只包含 16 位指令，但 NASM 的 \code{elf32} 输出能让 LLD 处理节和
符号；它不表示 CPU 已进入 32 位模式。执行模式由 CPU 状态和指令前缀决定，
目标文件容器格式与运行模式必须分开理解。

\section{宿主与目标}

工具可能运行在 AArch64、x86-64 或其他宿主架构，产物仍由 NASM 和 LLD
明确指向 x86。QEMU TCG 翻译目标指令，因此构建机和模拟 CPU 不必同构。

\section{编译工具链的历史分工}

早期程序员直接输入机器码，任何地址变化都要求手工重算跳转和数据位置。汇编器
把助记符翻译成机器码，并用符号代替易错的绝对地址。随着程序跨越多个源文件，
链接器承担合并节、解析外部符号和重定位的工作。后来出现的编译器再把高级语言
翻译到汇编或目标代码，但它仍依赖汇编器与链接器完成最终布局。

普通 C++ 构建常把这些阶段隐藏在一个驱动命令后面。裸机固件必须重新看见它们，
因为没有操作系统装载器在运行时修正地址，也没有动态链接器补齐符号。每一层
工具输出都对应一组不同的可审计事实。

\section{节、符号与重定位}

汇编器遇到同一节内可确定的局部距离时，可以立即编码；遇到尚未知道最终地址的
引用时，则在目标文件中留下重定位记录。链接器把输入节放入输出节，为符号分配
地址，再按照重定位类型修改指令或数据字段。符号是名字到位置的映射，重定位是
“哪个字段需要按什么规则依赖哪个符号”的计算说明。

ELF 文件还保存节表、符号表、程序头和机器类型等元数据，适合审计和调试。
裸 ROM 则只是一串硬件可见字节。保留 \code{firmware.elf} 供
\code{readelf}、\code{nm} 与 \code{objdump} 分析，再从它产生
\code{firmware.bin}，可以同时获得可解释性与准确介质布局。

\section{16 位指令与 ELF 类别相互独立}

\code{BITS 16} 指示 NASM 按 16 位默认操作数和地址大小编码当前指令；
\code{-f elf32} 选择承载这些字节的目标文件结构。CPU 不读取 ELF 类别，
它只看到 ROM 中的机器码，并依据当前模式译码。链接器使用 ELF32 是因为当前
固件对象的地址和重定位需求适合这一容器，而不是因为 CPU 已经进入保护模式。

同理，后续 64 位内核会采用 ELF64，但磁盘上的 ELF64 标记也不会自动切换
处理器模式。引导代码必须先建立长模式，验证并装载 ELF 段，最后跳到入口地址。

\section{链接地址、装载地址与文件偏移}

链接地址描述代码运行时使用的地址，装载地址描述字节被放到物理存储的位置，
文件偏移描述字节位于镜像中的下标。普通程序由装载器把三者关联起来；本项目
的 ROM 由平台固定映射，因此链接脚本和镜像生成步骤必须直接保持这组关系：
\[
  \mathrm{fileOffset} =
  \mathrm{physicalAddress} - \mathrm{romPhysicalBase}.
\]

复位向量位于文件偏移 \code{0x1FFF0}，不是因为源文件在第几行，而是因为
它的运行地址与 ROM 起点相差该数值。链接断言把这类布局要求变成构建失败，
避免依靠人工查看映射图。

\section{可复现构建与产物审计}

同一提交、同一受控工具链和同一参数应产生相同字节。时间戳、未初始化填充、
宿主路径和未固定工具行为都会削弱这一性质。可复现性使代码评审能够对应到
唯一镜像，也使失败测试可以由其他机器重放。

构建完成后，项目分别检查结构与字节：\code{readelf} 查看 ELF 类别和节，
\code{nm} 查看关键符号地址，\code{objdump} 反汇编指令，
\code{llvm-objcopy} 生成镜像，Python 审计器再直接读取固定偏移。源码意图、
链接解释和最终介质因而形成三份相互独立的证据。
