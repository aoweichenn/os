\chapter*{前言}

写一个操作系统很容易被误解为“先写一个内核主函数”。真正的机器没有主函数，
也不会替开发者建立栈、清空未初始化区或选择执行模式。CPU 复位以后只承诺
一组架构状态；固件必须从固定地址取到合法指令，建立最早的观测通道，找到
后续程序，把处理器带入长模式，最后才可能进入 C++20 内核。

进入内核也不是终点。页表、异常、中断、Process、Thread、系统调用、VFS、
文件系统、用户运行时和 Shell 都在回答不同问题；把它们堆在一个目录或一个
巨型章节里，会让“功能已经运行”掩盖控制权、所有权和失败语义尚未说清。
本书以 v2.0 冻结实现为事实底座，重新按知识依赖组织整台系统。

\section*{这本书不要求预先成为硬件或历史专家}

本书从 bit、byte、电压、电流、地址、CPU、寄存器、ROM、RAM 和磁盘开始。
第一次使用重要概念时，不只给英文全称和一句翻译，还要说明它对应什么物理器件
或软件结构、当初为解决什么问题而出现、由谁在什么时候初始化、数据怎样经过
它、条件不满足时会看到什么失败。

例如“RAM 是随机存取存储器”不足以理解启动；读者还需要知道 DRAM 为什么
断电丢失、为什么需要刷新和训练、固件为什么必须先从非易失 Flash 执行、
Kernel 又为什么要从磁盘复制到 RAM。“进程拥有地址空间”也不足以理解 fork；
还要区分 VMA 意图、PTE 驻留、物理页引用、Thread 执行现场和 FileDescription
共享状态分别由谁拥有。

硬件史不按年份表背诵。本书始终采用：

\[
\text{当时的问题}
\rightarrow \text{工程限制}
\rightarrow \text{当时方案}
\rightarrow \text{今天仍保留的兼容痕迹}
\]

由此解释 8086 分段、A20、独立 I/O 空间、保护模式、长模式、PIC、PIT、
PS/2、ATA，以及现代 PCIe/UEFI 平台为什么与早期 PC 既相连又不同。

\section*{QEMU 与实体硬件分别证明什么}

配套工程坚持严格边界：QEMU 只模拟 x86-64 CPU、内存、串口、IDE 等硬件，
不使用 SeaBIOS、OVMF、GRUB、Limine、Multiboot 或 \code{-kernel}
替代启动链。汇编采用 NASM Intel 语法，高层目标代码采用 freestanding
C++20；构建和测试脚本可以使用宿主 Python，但进入镜像的目标运行时由项目
自行实现。

为了不把 QEMU 地址/端口关系误当成 PCB 铜线，第三章使用 LattePanda Mu
N100/N305 计算模块和 DFR1142 Lite Carrier V2 作为实体案例。书中嵌入
十页真实 KiCad 参考原理图、一页纯 TikZ 模块方向图和三张矢量学习图，逐项
解释三路输入、电源树、260-pin 接口、HDMI、USB、PCIe、M.2、GbE、
I2C、UART、SPI、RTC、风扇和四层 PCB。

实体案例用于建立真实电气载体和实机适配知识，不声称当前系统已能在该板裸机
启动。UEFI 入口、ACPI、PCIe 枚举、NVMe、GOP、xHCI、DMA/IOMMU 等缺口
会被明确列为未来适配条件。

\section*{为什么从十章重构为十六章}

旧结构的第九章同时承载进程、同步、文件系统、VFS、虚拟内存、COW、用户
Thread、时间、signal、TTY、写回、journal、ABI 与 Shell，约占正文
四成。顺序虽然保留了版本历史，却迫使读者在一个章节中自行维护过多对象和
寿命。相反，数据与汇编章篇幅过薄，寄存器别名、RFLAGS、寻址、模式相关
语义和原子指令没有形成完整知识面。

新结构采用六部分十六章：

\begin{enumerate}[leftmargin=2.2em]
  \item 机器基础、x86 历史与真实硬件；
  \item 数据、指令、工具链与自研固件；
  \item Loader、内核保护、内存、中断与 Ring 3；
  \item Process/Thread、对象/VFS、PID1/VM；
  \item 持久化、并发服务、Shell 与 ABI；
  \item 工程治理、v2.0 集成和可复现发布。
\end{enumerate}

这不是把长章机械切成短章。新的边界分别围绕一种核心问题：控制权、地址
翻译、执行身份、对象身份、程序映像、持久顺序、等待竞争或发布身份。每章
仍保留背景、机制、失败、源码走读和证据，不产生只有几页提纲的孤立章节。

\section*{本书怎样组织“完整知识”}

这里的“完整”不表示穷举 Intel 手册或复制 Linux 所有子系统，而表示当前
承诺范围中的每个核心概念都回答七个问题：

\begin{enumerate}[leftmargin=2.2em]
  \item 它是什么，为解决什么历史问题出现？
  \item 它属于 CPU、平台、Kernel、用户 ABI 还是磁盘格式？
  \item 谁创建它，谁拥有它，谁只能临时引用它？
  \item 正常路径怎样从候选状态进入公开状态？
  \item 中途失败时哪些事实必须保持不变？
  \item 哪类测试能反驳错误实现？
  \item 当前实现没有承诺什么，未来扩展要重建哪些边界？
\end{enumerate}

正文中的位字段、状态图和数据结构服务于这七个问题，而不是为了显得底层。
读者如果只能背出 CR3 或 inode 的定义，却不能沿一次缺页、一次 write 或一次
exec 解释所有权转移，就还没有形成系统知识。

\section*{v2.0 提供什么事实底座}

当前系统从自研 ROM 复位入口启动，经 Stage 1、长模式、ELF64 loader 和
freestanding C++20 Kernel，建立异常、内存、中断、设备和 Ring 3。其上
已经形成 Process/Thread、双系统调用入口、VMA/PTE、COW、类型化对象、
动态 FileTable、VFS、rootfs 格式 3、PID1、用户 Thread、futex、deadline、
signal、TTY、作业控制、IRQ14 writeback、ordered metadata journal、
devfs、procfs、外部 Shell 与 32 个磁盘工具。

v2.0 不再增加机制，而是冻结项目版本、ABI 与盘面边界，补齐目标 ELF 审计，
并把三档 QEMU、完整失败矩阵、LaTeX PDF、手机副本、主仓、独立网站和
Sites 生产部署绑定为同一份可追溯证据。第十六章专门解释这条发布身份链，
避免前言再次按版本复述整本书。

\section*{怎样读每一章}

建议采用四遍法：

\begin{enumerate}[leftmargin=2.2em]
  \item 第一遍只找输入状态、输出状态和本章边界；
  \item 第二遍手算地址、位字段、大小、对齐、队列或引用变化；
  \item 第三遍沿源码与汇编检查真实控制流；
  \item 第四遍主动寻找能推翻错误实现的测试与故障注入。
\end{enumerate}

书后的十六章实验为每章提供“解释、推导、观察、证伪”四类任务。答案不要求
与作者使用相同措辞，但必须能指出硬件事实、软件所有者、提交点和失败现象。

\section*{当前边界必须诚实保留}

本系统仍是单 BSP、Kernel 不可抢占，不支持 SMP、网络、完整权限模型、动态
链接、共享库、USB、图形、DMA、AHCI/NVMe、swap、OOM killer 或完整 POSIX。
devfs/procfs 也不承诺 Linux 文本兼容。书中会解释这些机制的前置知识与未来
影响，但不会把路线图写成已经实现的能力。

\begin{contractbox}
本书的目标不是让读者相信系统“很完整”，而是让读者能够准确说出已经实现
什么、为什么这样实现、每一步怎样失败、如何证明，以及下一步扩展会破坏哪些
既有假设。
\end{contractbox}
