\chapter*{前言}

写一个操作系统很容易被误解为“先写一个内核主函数”。真正的机器没有主函数，
也不会替开发者建立栈、清空未初始化区或选择执行模式。CPU 复位以后只承诺一组
架构状态；固件必须从固定地址取到合法指令，初始化最早的观测通道，找到后续
程序，把处理器带入长模式，最后才可能进入 C++20 内核。

本书和配套工程坚持一个严格边界：QEMU 只模拟 x86-64 CPU、内存、串口、IDE
等硬件，不使用 SeaBIOS、OVMF、GRUB、Limine、Multiboot 或
\code{-kernel} 替代启动链。汇编统一采用 NASM Intel 语法，高层代码采用
freestanding C++20。构建和测试脚本运行在宿主机，可以使用 Python；进入
镜像的目标代码则必须由我们掌握。

全书既讲原理，也讲证据。每个阶段都明确记录输入状态、输出不变量、失败语义
和可重复验收。正文先补足所需背景，再进入寄存器、地址、字节布局和控制流，
使实验现象能够沿硬件与软件因果链得到解释。

正文组织为五部分、十个完整主题章。相关的小主题被放回同一条因果链，而不是
拆成只有提纲的短章。每章从历史背景和机器状态出发，继续深入位字段、数据结构、
时序或控制流，再落到失败路径、调试证据和阶段验收。尚未进入当前版本代码的
机制会明确标注为设计路线；已经实现的机制则同时给出源码、二进制和整机行为
三类证据。

当前配套实现已经完成 v0.8：Stage 1 在 64 位模式中自行读取 Kernel 容器，
验证 CRC32 与 ELF64，执行两遍加载和 BSS 清零，通过版本化 BootInfo 调用
freestanding C++20 内核。内核随后自建 GDT、TSS 和 IDT，规范化 32 个架构
异常；再读取并验证物理内存图，管理页帧，建立四级 4 KiB 页表、guard page
与高半区早期堆。INT3、UD2、not-present 页故障和 Ring 0 写只读页共同验证
异常返回、panic、NX 与 CR0.WP。内核又接管本地 APIC/PIC 兼容路由，为
向量 32--47 建立硬件 IRQ 入口，以 PIT 形成单调 tick，处理中断驱动的
PS/2 按键，并用独立 ATA PIO 驱动重读启动盘。QEMU 自动注入的按键必须经过
真实 i8042、IRQ1、IDT 与解码状态机才能成为语义事件。内核进一步严格装入
自研用户 ELF，以 GDT、TSS.RSP0、用户页权限和 \code{IRETQ} 进入 Ring 3，
通过 \code{INT 0x80} 提供有界系统调用，并把用户非法指令与页故障隔离为
用户终止而非内核 panic。
