\chapter*{前言}

普通程序可以从 \code{main()} 开始，因为操作系统已经替它准备好了内存、
栈和运行环境。操作系统自己没有这样的起点。CPU 刚刚复位时，内存里没有
可以依赖的内核，也没有 \code{printf}、文件系统和进程。它只能从硬件规定
的地址读取第一条机器指令。

这个项目就从那条指令开始。我们先制作一块能够被 CPU 读取的 ROM，让它通过
串口输出第一行文字；然后从磁盘加载 Stage 1，打开 A20，进入保护模式和
64 位长模式，最后跳到 C++20 内核。进入内核以后，再逐步加入异常、内存
管理、中断、用户程序、进程和文件系统。

书中的代码都来自同一个可运行项目。每一章只增加当前阶段需要的能力，并通过
QEMU 输出、宿主测试或磁盘检查观察结果。遇到新的硬件概念时，我们先看它
解决什么问题，再回到代码中看它怎样工作。

正文共二十章，另有四章硬件深化附录。目录中的章号就是本书唯一使用的章号；
每个机制只在第一次需要它的位置进入主线，后续章节直接沿用已经建立的概念。

\section*{先从机器能够做什么开始}

完全没有计算机基础也可以从第一章读起。前三章从 bit、byte、计数和编码
开始，接着介绍电压、电流、电阻、晶体管、逻辑门、触发器、CPU、存储器和
总线，最后走到复位后的第一次取指。这些内容不是启动代码前的一份术语表。
后面手算地址、读取原理图、设置时钟或分析页表时，会反复用到它们。

第一次认识 ROM 时，我们只需要解决一个具体问题：RAM 断电后内容会消失，
机器上电时却仍然需要一段代码供 CPU 执行。因此，启动代码要放在断电后仍能
保存内容的存储器中。等这个事实清楚以后，再讨论复位地址怎样映射到 ROM
中的某个字节。

其他概念也按这个顺序出现。A20 从一次地址计算引出；UART 从第一次输出实验
引出；页表从虚拟地址无法直接访问物理内存的问题引出；fork 从父子进程既要
共享已有内容、又要隔离后续写入的冲突引出。

\section*{跟着一次运行往下走}

阅读一个阶段时，我们先只做一件事。启动 ROM 阶段先确认 CPU 是否执行到了
自己的字节；串口阶段先让终端出现一行文本；磁盘阶段先读回一个已知扇区；
进入长模式时先核对控制寄存器、页表和跳转目标。现象出现以后，再打开对应的
汇编和 C++ 文件追踪控制流。

地址、位字段和容量公式最好亲手算一遍。例如，看到
\code{FFFF:0010} 时先算出线性地址，再讨论 8086 的 20 根地址线怎样造成
回绕。看到四级页表时，拿一个虚拟地址依次取出 PML4、PDPT、PD 和 PT
索引。纸上的计算能够把缩写还原成 CPU 真正执行的步骤。

测试也服务于学习。单元测试适合把状态控制在很小的范围内，QEMU 则能让这些
状态穿过真实的 x86 指令和设备端口。某个测试通过以后，继续问它实际覆盖了
哪条路径，以及换一个输入是否会走到另一条分支。

\section*{QEMU 扮演一台硬件机器}

本项目让 QEMU 模拟 x86-64 CPU、内存、串口和 IDE 等硬件。复位 ROM、
Stage 1、模式转换、内核、驱动、用户空间和文件系统由项目自行实现。汇编
使用 NASM Intel 语法，高层目标代码使用 freestanding C++20。

实体硬件还有 QEMU 模型没有呈现的电气细节。书中选用 LattePanda Mu
N100/N305 计算模块和 DFR1142 Lite Carrier V2 作为案例，阅读它的供电、
260-pin 接口、HDMI、USB、PCIe、M.2、网络、风扇和 PCB。这个案例帮助我们
把端口访问和地址译码放回真实芯片、引脚与铜线中。

\section*{这套系统目前走到哪里}

当前项目可以从自研 ROM 启动，经磁盘加载进入 64 位 C++20 内核，并运行
用户程序、进程、虚拟内存、VFS、文件系统、Shell、信号和作业控制。系统仍
使用单个 BSP，不支持 SMP、网络、USB、图形、动态链接、swap、AHCI 或
NVMe。实体载板案例也不表示它已经能够绕过 UEFI 在该板上直接启动。

这些限制只在这里集中说明一次。正文会把注意力放在已经运行的代码上：CPU
执行了什么，内存中的状态怎样变化，失败时看到了什么，以及我们怎样找到
原因。
