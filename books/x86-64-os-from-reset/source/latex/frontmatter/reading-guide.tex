\begin{keyidea}
这不是一本按源码目录从头抄到尾的手册。全书按“机器事实先于软件抽象、失败
边界先于功能扩张、所有权先于接口数量”的依赖顺序组织。读者既可以顺序建立
完整体系，也可以沿一条端到端路径反复穿越硬件、汇编、C++、用户态与测试。
\end{keyidea}

\section*{三、六条可独立选择的阅读路线}

\topic{第一次系统学习。}
按第 1--16 章顺序阅读。第一次不要追求记住每个端口值，而要持续回答：
当前状态由谁建立、下一步依赖什么、失败会留下什么可观察事实。

\topic{只想先把机器启动起来。}
阅读第 1--7 章，再读第 8 章的入口、GDT/TSS/IDT 与页表前半部分。此路线能
理解 ROM、Stage 1、ATA、ELF64、长模式和 C++ Kernel 入口，但还不能解释
完整用户系统。

\topic{重点学习 CPU、汇编和内存。}
阅读第 2、4、7、8、9、10 章。把每一段汇编同时写成“输入寄存器、输出
寄存器、内存副作用、RFLAGS、副作用发生前的失败条件”五列表。

\topic{重点学习 Unix 内核对象。}
阅读第 8--15 章，尤其区分 Process/Thread、fd/FileDescription、
Path/Vnode/inode、VMA/PTE、pending/action/frame。名称相似不表示寿命相同。

\topic{重点学习文件系统与持久性。}
先读第 3 章 ATA 端口与第 11 章 VFS，再读第 13 章。始终区分用户可见、
页缓存已接收、设备已接收、FLUSH 已完成和新实例可恢复五种状态。

\topic{重点学习软件工程和验证。}
先读第 6 章，再读每章的 failure box 与 evidence，最后完整阅读第 16 章和
书末实验。不要用 QEMU 启动成功替代 ELF、盘面、随机模型或公网身份证据。

\section*{五、每个概念都用七个问题验收}

\begin{enumerate}[leftmargin=2.2em]
  \item 它解决了什么历史或工程问题？
  \item 它属于 CPU 架构、平台硬件、内核对象、用户 ABI 还是持久盘面？
  \item 哪个阶段、哪段代码或哪条硬件规则创建它？
  \item 它拥有哪一份状态，明确不拥有什么？
  \item 正常路径如何提交，失败以前哪些状态必须保持不变？
  \item 单元、随机、产物和 QEMU 证据分别能证明什么、不能证明什么？
  \item 若替换为另一个方案，必须新增哪些约束和反例？
\end{enumerate}

\section*{六、当前事实、历史基线和未来方向必须分栏}

正文会同时出现 v0.x 的第一次实现、v1.x 的机制深化和 v2.0 冻结状态。版本
较早不代表内容错误，而是它只能说明当时建立的最小契约。每次遇到容量、路径、
结构大小或测试数量，应先确认它属于哪一个阶段。

\begin{contractbox}
当前产品事实以 v2.0 为准：项目版本 2.0.0，用户 ABI 2.0.0，rootfs 格式 3，
三档内存为 64 MiB、256 MiB、64 GiB。系统仍是单 BSP、Kernel 不可抢占，
没有网络、权限模型、动态链接、SMP、NVMe 或 USB；后续路线不能被写成已经
完成的能力。
\end{contractbox}
