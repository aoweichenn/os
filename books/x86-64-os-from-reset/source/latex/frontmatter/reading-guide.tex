\begin{keyidea}
全书不把“会使用电脑”当作“理解计算机”。前四章从量、单位、电路和逻辑开始，
让读者亲手推导一台可取指机器；后十六章再沿真实 v2.0 系统建立固件、内核、
用户空间与工程证据。任何路线都不能把尚未建立的名词当作前置知识。
\end{keyidea}

目录只保留每章 5--6 个承担完整知识链的主节。主节内部不再用连续编号把一个
机制切成几十段；必要的局部转折以段首主题进入连续正文，读者可以沿因果、
状态、所有权和证据一路读完，也可以从目录直接找到一条完整主线。

\section*{三、真正零基础的顺序}

第一次接触计算机的人按第 1--20 章顺序阅读，并遵守四条规则：

\begin{enumerate}[leftmargin=2.2em]
  \item 公式先代入单位，再代入数值；结果先检查数量级。
  \item 图中每根箭头都说清“传的是能量、时钟、地址、数据还是所有权”。
  \item 第一次见缩写时写出全称、所属层次和一句自己的解释。
  \item 不背端口和位值；先说明它在状态机中选择了什么转换。
\end{enumerate}

第 1--4 章每章都可脱离项目代码完成纸笔学习。第 5 章以后才要求逐步接触
源码、反汇编、QEMU 和测试。

\section*{四、已有基础时的六条专题路线}

\topic{先把机器启动起来。}
读第 4--11 章，再读第 12 章的入口、GDT/TSS/IDT 与页表前半部分。电路基础
不牢时回读第 2--3 章，不要把 reset、clock、ready 当作普通变量。

\topic{重点学习电路、芯片和载板。}
读第 1--4、7 章。先在教学图中辨认电源/地、上拉、去耦、时钟、复位和引脚
方向，再进入实体模块的 260-pin、差分对和十页参考原理图。

\topic{重点学习 CPU、汇编和内存。}
读第 3--4、6、8、11--14 章。把每条指令写成输入状态、有效地址、输出状态、
RFLAGS 和异常条件；把每个虚拟地址继续拆到页表和物理事务。

\topic{重点学习 Unix 内核对象。}
读第 12--19 章，尤其区分 Process/Thread、fd/FileDescription、
Path/Vnode/inode、VMA/PTE、pending/action/frame 的创建者和寿命。

\topic{重点学习文件系统与持久性。}
先读第 4、7 章的设备事务、第 15 章 VFS，再读第 17 章。始终区分用户缓冲、
页缓存、设备缓存、FLUSH 完成和新实例恢复五种状态。

\topic{重点学习软件工程和验证。}
先读第 1 章的测量/证据、第 5、10 章，再读各章 failure box，最后完整阅读
第 20 章和书末实验。

\section*{六、图表的阅读规则}

全书表格统一使用闭合实线网格：外框界定表的范围，每条竖线界定字段，每条
横线界定一条记录；跨页长表会重复表头。阅读时先锁定行与列的交点，再解释
单元格内容，不能把相邻记录或相邻字段拼成同一个事实。

\section*{七、每个概念都用八个问题验收}

\begin{enumerate}[leftmargin=2.2em]
  \item 它属于物理元件、可测量量、编码、硬件状态还是软件抽象？
  \item 它解决了什么历史或工程问题？
  \item 它的单位、范围、位宽、有效极性或地址空间是什么？
  \item 哪个阶段、器件、代码或规则创建它？
  \item 它拥有哪一份状态，明确不拥有什么？
  \item 正常路径如何提交，失败以前哪些状态必须保持不变？
  \item 公式、原理图、产物、测试和整机证据分别能证明什么？
  \item 若替换方案，必须新增哪些条件和反例？
\end{enumerate}

\begin{contractbox}
当前产品事实仍以 v2.0 为准：项目版本 2.0.0，用户 ABI 2.0.0，rootfs 格式 3，
三档内存为 64 MiB、256 MiB、64 GiB。新增零基础章节只扩展解释深度，不改变
Kernel、盘面、ABI 或 QEMU 硬件边界。
\end{contractbox}
