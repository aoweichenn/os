\begin{partbridge}
先从尺子、秒表和电压表能够测到的量开始。我们会把连续的电压解释成离散的
0 和 1，再用逻辑门保存状态、执行加法，最后拼出能够读取指令的 CPU。读完
这一部分，你应该能沿着电源、时钟、地址和数据说明第一条指令怎样到达 CPU。

\part{认识我们要启动的 x86 机器}
\begin{partbridge}
CPU 能够取指以后，仍然没有操作系统。我们先看看固件、Loader、Kernel、
驱动和应用程序各自接过哪一段工作，再回到 8086 理解今天的 x86 为什么仍从
实模式启动。最后把 QEMU 中的端口和地址放回实体芯片、引脚与 PCB。
\end{partbridge}

\part{写出 CPU 能执行的字节}
\begin{partbridge}
我们先手算几条 Intel 语法指令怎样改变寄存器和标志位，再让 NASM、Clang

\part{从磁盘进入内核和用户态}
\begin{partbridge}
ROM 空间有限，内核要从磁盘装入内存。我们先读回扇区、解析 ELF64，再依次
打开 A20、保护模式、分页和长模式。进入内核后，异常、中断和页表让错误能够
被定位，也让第一个用户程序在 Ring 3 中运行。
\end{partbridge}

\part{让进程共享 CPU、文件和内存}
\begin{partbridge}
多个程序开始运行以后，CPU 要在 Thread 之间切换，文件描述符要找到仍然存活
的内核对象，虚拟地址也要在缺页时取得内容。我们沿一次调度、一次路径查找、
一次 exec 和一次 fork，把这些关系接起来。
\end{partbridge}

\part{让数据留下来，让程序彼此协作}
\begin{partbridge}
一次 \code{write} 返回以后，数据还要经过页缓存、设备请求和磁盘缓存。
我们会在不同位置模拟断电，观察哪些内容能够恢复。随后再加入 pipe、futex、
signal、TTY 和 Shell，让程序能够等待、通信并接受终端控制。
\end{partbridge}
