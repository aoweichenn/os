\part{先把物理世界变成一台计算机}
\begin{partbridge}
先从尺子、秒表和电压表能够测到的量开始。我们会把连续的电压解释成离散的
0 和 1，再用逻辑门保存状态、执行加法，最后拼出能够读取指令的 CPU。读完
这一部分，你应该能沿着电源、时钟、地址和数据说明第一条指令怎样到达 CPU。
\end{partbridge}

\part{读懂 x86，并从复位现场进入内核}
\begin{partbridge}
CPU 能够取指以后，仍然没有操作系统。我们先区分固件、Loader、Kernel 和
应用程序，再学习最小 x86 寄存器、寻址和跳转。读懂这些状态以后，才回到
8086 的兼容历史和现代处理器的复位现场。随后把源码制成 ROM，通过 UART
观察执行结果，并由 Stage 1 把 64 位 C++ 内核装入内存。
\end{partbridge}

\part{让内核接管异常、内存和中断}
\begin{partbridge}
进入 C++ 以后，内核先接住异常，再接管物理页、页表、虚拟地址、动态栈和堆。
物理页与页表放在同一条地址翻译链中，KVA、动态栈与堆放在同一条分配链中。
最后再让时钟、键盘和用户态程序通过中断进入这些基础设施。
\end{partbridge}

\part{让进程共享 CPU、对象和地址空间}
\begin{partbridge}
多个程序开始运行以后，CPU 要在 Thread 之间切换，系统调用要找到当前线程，
文件描述符要找到仍然存活的对象，路径要穿过 VFS。随后 PID 1 从磁盘装入
程序，缺页和 fork 再决定物理页怎样共享。
\end{partbridge}

\part{让数据穿过缓存并在断电后留下来}
\begin{partbridge}
ATA 只提供扇区，文件系统要在其上建立 inode、目录和块索引。一次
\code{write} 返回以后，数据还要经过页缓存、块缓存、IRQ14 和设备 FLUSH。
最后在不同写入位置模拟断电，由 journal replay 恢复元数据。
\end{partbridge}

\part{让程序等待、通信并进入用户环境}
\begin{partbridge}
条件未满足时，Thread 从运行队列进入 WaitQueue；数据、超时、关闭或信号到来
时再恢复运行。pipe、futex、signal 和 TTY 在同一等待框架上组合，Shell
最终用进程组和控制终端组织前后台作业。本部分最后从复位向量重新走到
Shell，并说明怎样继续修改和验证这个系统。
\end{partbridge}
