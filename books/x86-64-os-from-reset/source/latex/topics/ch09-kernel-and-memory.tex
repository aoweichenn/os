\section{内核入口、异常与内存管理}

\subsection{内核入口契约}

64 位入口要明确栈对齐、方向标志、中断状态、参数寄存器、页表和可写内存范围。
汇编适配层建立 C++ ABI 后才调用 \code{kernelMain}。freestanding 环境没有
宿主标准库、异常展开和默认运行时，链接审计必须拒绝未知未解析符号。

\subsection{v0.5 先处理异常，再增加复杂性}

GDT 定义代码段和数据段，TSS 提供特权切换所需栈，IDT 把向量映射到门描述符。
每个异常桩统一保存寄存器并规范化错误码，再交给 C++ 分发器。页故障日志至少
包含 CR2、错误码和 RIP，否则后续内存管理无法定位。

当前内核已经建立五槽 GDT、104 字节 TSS 和 256 槽 IDT。双重故障、NMI、
机器检查分别拥有 16 KiB IST 栈；32 个架构异常都有 NASM Intel 语法桩。
启动时用 INT3 验证可恢复往返，并用独立 UD2/页故障镜像验证 panic。

\subsection{物理页与虚拟地址空间}

物理页分配器管理“哪些页可用”；页表管理“虚拟地址怎样映射、具有什么权限”；
内核堆管理“小对象怎样复用页面”。三者不能混成一个分配器。

\subsection{大类型与精确宽度}

物理地址、虚拟地址和全局计数优先用 64 位，为后续扩展保留空间；页表项必须
严格用 \code{std::uint64_t}，设备寄存器则按 8/16/32 位协议宽度访问。
“能用大的就用大的”不意味着把端口寄存器错误地扩大，而是避免内部模型被
无意义的小上限锁死。

\subsection{异常是同步控制流}

除零、非法指令、一般保护和页故障由当前指令同步引起；硬件中断由外部设备
异步请求。二者都通过 IDT 进入处理函数，但错误码、可重启性和处理策略不同。
异常入口必须保存统一现场，使 C++ 分发器不依赖每个向量偶然不同的栈形状。

处理器对部分异常自动压入错误码，其他异常没有。汇编桩为后者补一个占位值，
再保存通用寄存器和段状态。返回前按相反顺序恢复，并由 \code{iretq} 原子恢复
RIP、CS 与 RFLAGS。入口和退出是 ABI，任何偏移错误都会把栈数据当作控制状态。

\subsection{页故障把内存策略带入执行流}

CR2 保存导致故障的线性地址，错误码区分不存在页面、权限违反、读写、用户态
和取指。内核缺页可能表示自身错误，用户缺页则可能由按需分配、写时复制或非法
访问引起。页故障处理程序必须先按地址范围与进程状态分类，再决定映射、终止
任务或 panic。

处理故障本身也需要栈、代码和日志映射。若处理程序再次访问无效页，会形成嵌套
故障。因此最初实现采用固定映射的异常栈，并让 panic 路径避免动态分配。

\subsection{物理页分配记录所有权}

固件提供的内存图区分可用 RAM、固件保留、设备窗口和内核占用。物理页分配器
先把所有页标为不可用，再只释放经过验证的可用区，同时扣除内核、页表、栈与
BootInfo。位图每位表示一个页，简单且适合早期；伙伴系统可在后续提供大块
连续分配。

释放操作必须验证页对齐、合法范围和当前所有权。重复释放会使两个调用者获得
同一物理页，是比内存泄漏更危险的破坏。调试构建可以保留分配状态和来源标记，
让所有权错误尽早暴露。

\subsection{虚拟内存建立隔离与共享}

页表管理器把虚拟范围映射到物理页，并显式选择 writable、user、global 和
NX 权限。内核代码映射为只读可执行，常量只读不可执行，数据与栈可写不可执行，
设备映射采用适合的缓存属性。W\^X 原则避免同一页同时可写与可执行。

修改当前页表后，处理器的 TLB 可能仍缓存旧翻译。单页变化使用
\code{invlpg}，大范围或地址空间切换通过 CR3 与相应策略刷新。多核阶段还要
向其他处理器发送 TLB shootdown，在所有相关 CPU 确认前不能复用旧物理页。

\subsection{内核堆位于页管理之上}

物理页分配器以页为单位，通用对象往往只有几十字节。堆分配器从虚拟内存获得
页面，再按大小类别切分小对象。初期可采用简单空闲链表或 slab，优先保证边界
检查、对齐和可诊断性；复杂性能策略在测量后引入。

分配失败是正常状态，不能默认通过异常处理。核心路径返回显式状态或空结果，
调用者决定回收、拒绝请求或 panic。中断上下文不得调用可能睡眠或递归获取锁的
分配路径。
