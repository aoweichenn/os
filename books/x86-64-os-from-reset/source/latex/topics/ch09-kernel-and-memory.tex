\section{内核入口、异常与内存管理}

\subsection{内核入口契约}

64 位入口要明确栈对齐、方向标志、中断状态、参数寄存器、页表和可写内存范围。
汇编适配层建立 C++ ABI 后才调用 \code{RunKernel}。freestanding 环境没有
宿主标准库、异常展开和默认运行时，链接审计必须拒绝未知未解析符号。

\subsection{v0.5 先处理异常，再增加复杂性}

GDT 定义代码段和数据段，TSS 提供特权切换所需栈，IDT 把向量映射到门描述符。
每个异常桩统一保存寄存器并规范化错误码，再交给 C++ 分发器。页故障日志至少
包含 CR2、错误码和 RIP，否则后续内存管理无法定位。

v0.5 内核先建立五槽 GDT、104 字节 TSS 和 256 槽 IDT。双重故障、NMI、
机器检查分别拥有 16 KiB IST 栈；32 个架构异常都有 NASM Intel 语法桩。
启动时用 INT3 验证可恢复往返，并用独立 UD2/页故障镜像验证 panic。
v0.6 又在每个 IST 栈下方建立 4 KiB guard，并用新页表接管长期地址空间。
v0.8 为用户数据/代码段扩为七槽 GDT，把 TSS 移到 \code{0x28}，令 RSP0
指向带 guard 的独立特权转换栈；用户异常由 176 字节扩展帧终止用户执行，
不再与 Ring 0 panic 混为一种策略。

\subsection{物理页与虚拟地址空间}

物理页分配器管理“哪些页可用”；KVA 分配器管理“哪些内核虚拟区间已经有
软件所有者”；页表管理“虚拟地址怎样映射、具有什么权限”；内核堆管理
“小对象怎样复用页面”。四者不能混成一个分配器。

\subsection{大类型与精确宽度}

物理地址、虚拟地址和全局计数优先用 64 位，为后续扩展保留空间；页表项必须
严格用 \code{std::uint64_t}，设备寄存器则按 8/16/32 位协议宽度访问。
“能用大的就用大的”不意味着把端口寄存器错误地扩大，而是避免内部模型被
无意义的小上限锁死。

\subsection{异常是同步控制流}

除零、非法指令、一般保护和页故障由当前指令同步引起；硬件中断由外部设备
异步请求。二者都通过 IDT 进入处理函数，但错误码、可重启性和处理策略不同。
异常入口必须保存统一现场，使 C++ 分发器不依赖每个向量偶然不同的栈形状。

处理器对部分异常自动压入错误码，其他异常没有。汇编桩为后者补一个占位值，
再保存通用寄存器和段状态。返回前按相反顺序恢复，并由 \code{iretq} 原子恢复
RIP、CS 与 RFLAGS。入口和退出是 ABI，任何偏移错误都会把栈数据当作控制状态。

\subsection{页故障把内存策略带入执行流}

CR2 保存导致故障的线性地址，错误码区分不存在页面、权限违反、读写、用户态
和取指。内核缺页可能表示自身错误，用户缺页则可能由按需分配、写时复制或非法
访问引起。页故障处理程序必须先按地址范围与进程状态分类，再决定映射、终止
任务或 panic。

处理故障本身也需要栈、代码和日志映射。若处理程序再次访问无效页，会形成嵌套
故障。因此最初实现采用固定映射的异常栈，并让 panic 路径避免动态分配。

\subsection{物理页分配记录所有权}

Stage 1 从 \code{fw\_cfg} 的 \code{etc/e820} 得到可用 RAM、保留窗口等
物理事实，转换为 BootInfo v2 的 24 字节条目。物理页分配器先把所有页标为
unavailable，再只释放完整落入可用区的页，同时扣除低端平台、内核和初始栈。
当前每帧 2 bit，区分 unavailable、free、allocated、reserved；完成全部启动
保留后，同一分配器再建立每阶 free/allocated 双位图 buddy。旧单页接口统一
解释为 order 0，新接口交付 \(2^k\) 页连续块。allocated 位图记录原始 order，
因此错阶、大块内部页和重复释放会在修改状态前失败。

释放操作必须验证页对齐、阶对齐、合法范围和当前所有权。重复释放会使两个
调用者获得同一物理页，是比内存泄漏更危险的破坏。当前完整校验交叉核对块位图、
逐页状态、父子不重叠、可合并伙伴与统计；64 MiB/64 GiB QEMU 都真实写回并
回收八页连续块。

\subsection{虚拟内存建立隔离与共享}

页表管理器把虚拟范围映射到物理页，并显式选择 writable、user 和 NX 权限。
内核代码映射为只读可执行，常量只读不可执行，数据与栈可写不可执行；零页、
初始栈和三个 IST 底页保持 not-present。内核设置 EFER.NXE 与 CR0.WP，
W\^X 因而不只是 ELF 意图，而是处理器执行权限。

修改当前页表后，处理器的 TLB 可能仍缓存旧翻译。单页变化使用
\code{invlpg}，大范围或地址空间切换通过 CR3 与相应策略刷新。多核阶段还要
向其他处理器发送 TLB shootdown，在所有相关 CPU 确认前不能复用旧物理页。

\subsection{KVA 记录页表无法表达的软件许诺}

页表中的 not-present 只表示处理器当前不能翻译该页，不表示这个地址无人持有。
动态内核栈两端的 guard page 就是“已有所有者、故意不映射”；尚未完成物理页
准备的事务也会暂时处于同一状态。若只扫描页表找空洞，两个调用者可能在首个
PTE 提交前选中同一地址。

当前 KVA 窗口从 \code{0xFFFFC90000000000} 开始，大小 32 TiB，首个 4 KiB
页永久保留。256 项有序描述符只记录 allocation 与 reservation，空闲区间由
相邻描述符的缝隙隐式推导。申请使用 best-fit 和绝对虚拟页号对齐，释放要求
精确匹配原起点与页数；\code{Validate} 重新证明有序、无重叠、尾部清零和
统计守恒。它只分配地址，不申请物理页，也不修改页表。

整机自检申请一个 6 页、8 页对齐的区间，以 buddy order-2 块映射中间 4 页，
保留首尾 guard，真实写回后按“撤销映射、归还物理块、释放 KVA”逆序回收。
64 MiB 与 64 GiB 使用同一条协议，热路径不逐次打印日志。

\subsection{动态内核栈把三层资源协议接入调度生命周期}

当前每个进程不再占用链接期静态 Ring 0 栈。创建进程先向
\code{KernelStackManager} 申请 6 页 KVA：低端和高端各一页保持
not-present，中间 4 页分别映射四个 order-0 物理帧，得到 16 KiB
supervisor、RW、NX 栈。虚拟连续允许四个物理帧彼此不连续，双 guard 又把
向下溢出和错误正偏移都与相邻对象隔开。

首次 176 字节用户特权帧在动态栈顶下方按 16 字节对齐构造；切换 CR3 时同步
更新 TSS.RSP0。用户退出或异常只能先标记 Terminated 并销毁独占用户地址
空间，不能在仍使用当前 Ring 0 栈时自我撤映射。汇编返回永久启动栈后，安全点
回收器读取真实 RSP，确认它不属于待回收栈，再依次撤销叶映射、清零并归还
物理帧、精确释放 KVA。管理器以 256 个槽记录累计创建、销毁和活动/映射峰值；
单元、集成、100000 步固定种子模型和三条 QEMU 用户路径共同证明最终活动栈
归零。

\subsection{内核堆位于页管理之上}

物理页分配器以页为单位，通用对象往往只有几十字节。当前堆从
\code{0xFFFF800000000000} 开始，把 16 个后备页组织成连续 64 KiB 高半区，
采用边界标记和地址有序空闲链。分配使用 best-fit，支持二的幂对齐与失败
原子性；释放验证精确块头并向前、向后合并。\code{Validate} 交叉核对物理
块覆盖、空闲集合和活动/累计统计。v0.6 的单调实现解释了为什么启动期能够先
用最小机制，v1.1 的可回收实现则为动态 Thread、栈和对象缓存建立生命周期
基础。

分配失败是正常状态，不能默认通过异常处理。核心路径返回显式状态或空结果，
调用者决定回收、拒绝请求或 panic。中断上下文不得调用可能睡眠或递归获取锁的
分配路径。当前 heap 仍固定为 64 KiB 且由串行启动路径调用。固定尺寸
type cache 已用单后备块、活动位图与槽内 LIFO 链建立独立容量和生命周期；
KVA 区间层和动态内核栈已经完成；空中间页表回收、把 heap/type cache
改为按页增长和多 slab 后备，以及加入并发锁，仍属于后续边界。
