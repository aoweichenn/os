一层都需要显式数据结构、版本、范围和失败返回。

\section{七条系统旅程覆盖 v2.0 的主要控制流}

\subsection{旅程一：复位到普通磁盘程序}

\[
\text{Reset}
\rightarrow \text{ROM}
\rightarrow \text{Stage 1}
\rightarrow \text{Kernel}
\rightarrow \text{rootfs}
\rightarrow \text{/sbin/init}
\rightarrow \text{/bin/sh}
\]

前四步改变 CPU 模式和控制权，后四步改变软件对象和地址空间。ROM/Stage 1
失败由固件串口 marker 表达；Kernel 入口以后由 panic 或显式错误表达；
用户 ELF 失败只隔离目标 Process。把所有失败都写成“没有 READY”会丢失真正
的层次。

\subsection{旅程二：用户指针穿过系统调用边界}

用户把地址数值放入 ABI 寄存器，不表示 Kernel 已获得一块可信内存。入口先
切换可信栈并保存 UserContext，系统调用实现再验证半开区间、加法溢出、每级
PTE 的 Present/User/Write/NX 条件，最后通过固定内核缓冲复制。锁内不得发生
可能触页或阻塞的任意用户访问。

\subsection{旅程三：缺页把地址意图变成驻留事实}

VMA 描述允许发生什么，PTE 描述当前驻留在哪里。第一次匿名访问取得零页；
文件 VMA 从稳定 FileBacking 读取对应偏移；private COW 写入根据共享引用
选择恢复写权限或复制一页。成功后更新 PTE/TLB 并重试原指令，失败则保持
VMA、引用计数和旧映射可回收。

\subsection{旅程四：一次阻塞只有一个完成赢家}

pipe 空、futex 值仍匹配、deadline 未到、子进程尚未产生事件、TTY 没有完整
行，本质上都要求 Thread 离开 Ready 集合。condition、timeout、signal、
close 和 cancel 在同一调度临界区竞争 WakeReason；输家只能更新自己的
pending 或统计，不能再次发布 Thread。

\subsection{旅程五：一个用户字节成为持久文件}

\[
\text{user buffer}
\rightarrow \text{fd}
\rightarrow \text{FileDescription}
\rightarrow \text{Vnode}
\rightarrow \text{page/block state}
\rightarrow \text{journal + ATA}
\rightarrow \text{FLUSH}
\]

write 返回、metadata commit、home checkpoint 和新启动可读是四个不同
线性化边界。ordered journal 只承诺相关数据先稳定、元数据事务旧或新，不把
普通数据内容变成全量 data journal。

\subsection{旅程六：按键成为前台作业事件}

QMP 只向模拟键盘产生硬件输入。i8042 状态、IRQ1、扫描码 make/break、TTY
行规和控制字符仍由来宾处理。普通字符进入前台读取；Ctrl-C/Ctrl-Z 转成前台
PGID 的 signal。Shell 通过 wait event 更新作业表，\code{fg} 再交还终端并
发送 Continue。

\subsection{旅程七：源码成为公开可复核事实}

干净主仓提交产生目标产物、CTest 和 LaTeX PDF；手机副本与网站下载件按
SHA-256 比较；独立 web commit 记录代码目录和主仓身份；Sites 只保存该精确
提交生成的归档；最后从公网访问文档、源码、PDF、sitemap 和 Worker 路由。
任一身份断开都只能称为局部完成。

\section{三档机器不是容量从小到大的重复}

64 MiB bootstrap 强迫系统面对紧张内存和最小启动路径；256 MiB functional
组合 PID1、Shell、32 个工具、VM、I/O、signal、TTY 与持久化；64 GiB
capacity 则触及 4 GiB 以上物理页，验证 64 位 PFN、direct-map、页表和动态
容量。相同生产镜像在三档运行，区别只来自机器事实和 runtime profile。

只在 64 GiB 运行会让宽松容量掩盖失败回滚，只在 64 MiB 运行又无法发现
32 位截断。规格常量写着 64 GiB 也不是证据；测试必须实际取得、写入、读回
并释放高地址物理页。

\section{“对齐 Linux”应理解为方法而不是宣称等价}

本项目借鉴成熟系统的对象分层、生命周期、失败语义和可观察性，例如把
Process/Thread、fd/FileDescription、VMA/PTE、VFS/backend 分开，却不声称
拥有 Linux 的规模和兼容面。当前明确不包含：

\begin{itemize}
  \item SMP、内核抢占、跨核 TLB shootdown 与 NUMA；
  \item 用户/组权限、capability、完整 POSIX 与安全模块；
  \item 网络栈、USB、图形、音频和通用设备热插拔；
  \item AHCI/NVMe、DMA、IOMMU、swap、OOM killer 与 overcommit；
  \item 动态链接、共享库、ASLR 和完整进程凭据；
  \item Linux 文本兼容的 procfs/devfs 或通用 dentry cache。
\end{itemize}

限制不是缺陷隐藏区，而是 v2.0 状态空间的一部分。加入任一方向都必须重新
建立硬件依据、对象所有权、锁顺序、失败原子性、资源账本和独立证据。

\section{十六章最终汇合成四条不变量}

\begin{enumerate}[leftmargin=2.2em]
  \item \textbf{控制权可追踪：}任一时刻都能说明当前 RIP、RSP、CPL、CR3、
        中断状态和返回路径由谁建立。
  \item \textbf{资源有唯一账本：}frame、KVA、KernelStack、Thread、fd、
        Pipe、VMA、cache page、inode 与 journal credit 都有明确所有者。
  \item \textbf{失败不发布半状态：}候选对象在完整验证前不可见；提交以后
        的恢复则遵循持久或并发线性化点。
  \item \textbf{结论可被反驳：}纯模型、组合测试、目标产物、真实 QEMU、
        PDF 哈希与公网路由分别拒绝不同类别的错误。
\end{enumerate}

\begin{contractbox}
v2.0 的价值不是把所有操作系统概念都实现一遍，而是让已实现范围中的每个
状态都有来源、所有者、迁移、失败语义和证据。读者若不能从一个公开现象反向
追到对应硬件状态和源码边界，就还没有真正完成集成理解。
\end{contractbox}
