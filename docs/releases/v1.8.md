# v1.8：匿名 VMA、按需分页、受控栈增长与用户堆

## 阶段结论

v1.8 已完整建立用户虚拟内存的第一条按需路径。地址空间不再把“已经存在的
PTE”误当作全部内存语义：VMA 保存区间来源、软件权限和增长政策，页表只保存
当前驻留页与硬件权限。匿名 `mmap`、program break 和完整 8 MiB 栈预留都
可以先存在而不占用对应物理页；首次合法访问由用户 `#PF` 分配、清零并映射
一页。

正常启动链仍完全由项目实现：

```text
self-written ROM
  -> self-written Stage 1
  -> freestanding C++20 Kernel
  -> rootfs v2 /sbin/init
  -> process tree and disk ELF
  -> per-process ordered VMA map
  -> x86-64 user #PF demand resolution
  -> Ring 3 program break and self-written UserHeap
  -> unmap / exec / exit resource reclamation
```

QEMU 只提供硬件模型，没有提供 BIOS、UEFI、bootloader、Kernel、页故障策略、
libc 或用户分配器。

## VMA 数据模型

`VirtualMemoryMap` 保存按地址递增的页对齐半开区间。每个区域包含：

- `begin_address` 与 `end_address`；
- readable、writable、executable；
- `ExecutableImage`、`Anonymous`、`ProgramBreak` 或 `UserStack` kind。

插入时拒绝重叠；相邻且 kind/权限相同的区域自动合并。移除支持整段删除、
裁掉首尾和中段拆分。中段拆分会先从池中取得新描述符，资源不足时不修改旧
区域，避免只留下半次 unmap。

描述符来自一个容量 8192 的 Kernel 全局池，每个地址空间以唯一 owner
identifier 隔离；单 Process 的硬限制为 4096 个区域。池记录：

```text
capacity
active / free
peak active
successful acquire / release
```

当前有序索引链表让所有修改路径和池所有权可以逐项审计。它不是最终性能结构，
但公开契约没有暴露链表，后续可以在压力证据要求时替换为平衡树。

## 用户地址空间布局

共享 ABI 冻结以下 v1.8 规格：

| 区域 | 规格 |
| --- | --- |
| 页大小 | 4096 字节 |
| 匿名窗口 | `0x60000000` 至 `0x80000000`，共 512 MiB |
| program-break 上界 | `0x60000000` |
| 用户栈顶 | `0x00007FFFFFFF0000` |
| 栈最大预留 | 8 MiB |
| 永久栈 guard | 栈底再下一页 |
| 用户 heap 公开上限 | 8 MiB |

ELF `PT_LOAD` 仍在 exec 时 eager 装入，但现在也登记为 VMA；最高 ELF 段的
页对齐末端成为 break base。完整栈 VMA 在装载时建立，参数实际覆盖的顶部页
由 `PrepareUserStack` 提交，其余页保持 not-present。

## 系统调用 ABI

v1.8 在既有编号后追加 39..42：

| 编号 | 名称 | 参数摘要 | 成功值 |
| ---: | --- | --- | --- |
| 39 | `MapAnonymousMemory` | 地址、长度、权限、flags | 映射起点 |
| 40 | `UnmapMemory` | 页对齐地址、长度 | `0` |
| 41 | `SetProgramBreak` | `0` 查询或新地址 | 当前 break |
| 42 | `GetVirtualMemoryStatistics` | 目标地址、结构尺寸 | `0` |

新增结果 `-39..-42` 分别表示 out of memory、address in use、invalid memory
range 和 memory metadata exhausted。错误不会用一个模糊的“失败”吞掉地址
冲突、元数据容量和 frame 容量的区别。

`MapAnonymousMemory` 支持：

- 地址 `0` 加无 flags：在匿名窗口中执行 first-fit；
- 页对齐非零地址加 `FIXED`：在指定空洞建立映射；
- `NONE`、`R`、`R|W`、`R|X` 软件权限。

fixed 映射不覆盖现有区域。任何重叠返回 `AddressInUse`；未知 flags、零长度、
溢出、窗口越界、非页对齐 fixed 地址、缺少 read 的 write/execute 和 W+X
均拒绝。

`VirtualMemoryStatistics` 固定为 112 字节、十四个 `uint64_t` 字段，公开
区域/虚拟页/驻留页、各 kind 页数、栈驻留、fault、unmap、页表回收、峰值和
当前 break。结构尺寸由 ABI `static_assert` 冻结。

## x86-64 页故障分发

通用异常入口仍先保存统一现场和 CR2。只有 vector 14 且属于当前用户 Process
时才进入 `HandleUserPageFault`。处理顺序刻意区分硬件错误：

1. U/S 位必须表明 fault 来自用户态；
2. RSVD 位表示页表保留位损坏，不能被 demand paging 掩盖；
3. P 位为 1 表示 protection violation，不能当成“缺页”；
4. 用 CR2 向下对齐查找 VMA；
5. 用 W/R 与 I/D 位检查 write 与 instruction fetch；
6. 按 kind 执行匿名、break 或栈策略；
7. 取得 frame、建立页表、按 VMA 权限写 PTE；
8. 经 direct-map 清零完整 4 KiB；
9. 更新统计并从异常返回，让原指令重试。

权限错误、guard、空洞、非法栈跳跃和 present fault 会终止当前用户 Process，
不会让 Ring 0 panic。frame 或页表耗尽也形成明确用户执行结果。

Kernel 代表用户读取系统调用参数时，`CopyFromUser` 与 `CopyToUser` 可以为
匿名和 program-break VMA 解析尚未驻留的页；它们不自动增长栈，因为栈增长
必须依赖异常现场中的真实用户 RSP。

## 受控用户栈

v1.7 的栈一次映射固定 64 页；v1.8 改为完整预留 8 MiB、按需连续提交。
一个栈页故障必须：

- 命中 `UserStack` VMA；
- 恰好位于 committed bottom 的下一页；
- 不越过 VMA 底部；
- fault 地址与用户 RSP 位于允许的 64 KiB 邻近窗口；
- 满足 RW/NX 权限。

因此正常函数调用、局部数组和参数推进会增长栈；跳过大量空页、访问永久
guard、在栈上取指或写到其他 kind 都会被拒绝。memory probe 通过递归局部
块实际跨越多页；guard probe 则精确写永久 guard 并必须收到 vector 14。

## `munmap`、缩小 `brk` 与页表回收

`UnmapMemory` 只撤销 `Anonymous` kind，不能用它删除 ELF、stack 或
program-break 区域。`SetProgramBreak` 只修改从 ELF 页尾开始的连续
`ProgramBreak` VMA。

撤销先修改经过完整预检的 VMA，再逐页查询当前驻留：

- 没有 PTE 的预留页不产生物理释放；
- 有 PTE 的页释放 frame 并使该虚拟地址失效；
- 空 PT、PD 和进程私有 PDPT 由既有页表所有权协议向上回收；
- resident、released pages 和 reclaimed table frames 同步更新。

exec 成功后销毁旧地址空间，进程退出也销毁完整页表与 VMA。正常工作负载
结束时描述符 active 必须为零，acquire 与 release 增量相等。

## 自研 Ring 3 用户堆

`UserHeap` 是头源分离的 freestanding C++20 类，不调用 libc、STL 或宿主
allocator。用户为它注入 program-break 操作、页大小、增长量和最大容量。

每个物理块使用 64 字节、16 字节对齐的显式 header，保存 payload capacity、
requested size、前一物理块 offset、空闲双链 offset、状态和 signature。
算法为：

```text
Allocate(size)
  -> 16-byte align
  -> first-fit free list
  -> insufficient: grow brk by page-aligned quantum
  -> split when remainder can hold header + minimum payload
  -> mark allocated and update peak/statistics

Release(pointer)
  -> exact payload-start lookup
  -> reject foreign/interior/double-free
  -> mark free
  -> coalesce previous physical neighbor
  -> coalesce next physical neighbor
  -> keep one coherent free-list entry
```

`Validate` 同时遍历物理块链与空闲链，核对 signature、对齐、previous link、
请求字节、活动数、空闲数、尾块和链表计数。耗尽、整数溢出、break 失败和
无效配置不会损坏已有 allocation。

Ring 3 memory probe 在同一个真实 Process 中执行固定种子 5000 步分配/
释放，反复写入并校验每个活动块；宿主随机测试将状态搜索放大到 100000 步。

## PID1 端到端验收

普通 v1.7 工作负载保持不变。PID1 先并发创建六个直接子进程并回收一个收养
孤儿，随后顺序执行三个 v1.8 程序：

1. `/bin/memory_probe` 正常退出；
2. `/bin/memory_guard_probe` 必须以用户 `#PF` 退出；
3. `/bin/memory_protection_probe` 先读取零填充只读匿名页，再写入并必须以
   用户 `#PF` 退出。

memory probe 还证明：

- 预留 32 MiB 匿名空间后 resident 不增加；
- 首页与相隔 4095 页的远页首次读取均为零；
- 写入后内容在映射生命周期内保持；
- 重叠 fixed 映射被拒绝；
- 中间一页 unmap 产生 split，重新 fixed map 后可再次撤销；
- 全部 unmap 后 resident 回到基线且页表 frame 确实回收；
- 2 MiB break 增长不预分配，触页后缩回可回收；
- 栈按需连续增长；
- 用户 heap 随机工作负载结束后活动 allocation 为零。

正常启动总计注册 11 个 Process，成功 wait 10 次；峰值并发仍由 64 MiB
兼容档的 8 Process 容量覆盖。

## 日志与可观测性

页故障不是每次都写串口。Kernel 只在 demand fault 或 stack growth 累计值
达到二次幂时输出：

```text
[OS][KERNEL][VM] DEMAND_FAULT_COUNT=0x...
[OS][KERNEL][VM] STACK_GROWTH_COUNT=0x...
```

用户程序在完整不变量通过后才输出一次语义标记。最终聚合日志增加：

```text
[OS][KERNEL] VMA_DESCRIPTOR_CAPACITY=0x0000000000002000
[OS][KERNEL] VMA_ACTIVE_DESCRIPTORS=0x0000000000000000
[OS][KERNEL] VMA_PEAK_DESCRIPTORS=0x...
[OS][KERNEL] VMA_ACQUIRES=0x...
[OS][KERNEL] VMA_RELEASES=0x...
```

runner 对一次性标记使用精确次数，对采样计数使用“至少出现且数值大于零”，
不会错误要求二次幂采样日志只出现一次。来宾 PIT 毫秒和宿主
`[QEMU][T+...ms]` 继续提供双时钟证据。

## 测试证据

当前构建图注册 133 项测试。v1.8 直接新增或扩展的证据包括：

| 层次 | 证据 |
| --- | --- |
| 单元 | VMA 排序/合并/拆分/耗尽事务；UserHeap split/reuse/coalesce/invalid free |
| 集成 | 128 轮 VMA 预留、首次触页、中段撤销、页表分支与 frame/descriptor 基线 |
| 随机 | VMA 100000 步参考模型；UserHeap 100000 步活动载荷参考模型 |
| ABI | 用户边界覆盖 8 MiB 栈与系统调用 39..42 |
| ELF | 三个新增用户 probe 均通过独立 ELF64 布局与符号审计 |
| QEMU 64 MiB | 完整 PID1、按需分页、fault policy 和资源回收 |
| QEMU 256 MiB | 完整 functional smoke |
| QEMU 64 GiB | 高于 4 GiB frame、自研 VM 工作负载与完整规格 |
| 失败路径 | guard、只读写、旧用户/内核异常、损坏镜像和 CPU 能力回归 |

本次冻结验收结果：

- unit：33/33；
- integration：51/51；
- randomized：25/25；
- QEMU bootstrap 64 MiB：通过；
- QEMU functional 256 MiB：通过；
- QEMU primary 64 GiB：通过。

完整 system/failure/persistence 集合仍由发布闭环统一执行并记录，不能用上述
三个成功启动替代故障矩阵。

## 阶段边界

v1.8 没有宣称已经具备：

- file-backed VMA、按需 ELF 或 page cache；
- `MAP_PRIVATE`、`MAP_SHARED`、`mprotect`、`mremap` 或共享匿名页；
- fork、COW、匿名页引用计数、swap 或 overcommit；
- ASLR、动态链接器、共享库或完整 libc；
- 多线程 heap、arena、尾部 free 后自动缩小 break。

ELF 代码和数据页仍在 exec 时 eager 装载。下一阶段 v1.9 将在已经稳定的
VMA/page-fault 模型上加入文件页故障和有界 clean page cache；fork/COW
保持在 v1.10。
