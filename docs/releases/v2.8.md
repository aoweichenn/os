# v2.8 统一文件页缓存与写回回收

状态：六个核心增量已实现，工程候选，尚未发布

日期：2026-08-21

## 目标

让 buffered read/write、文件映射、写回和内存回收最终共享以 Vnode 文件身份和
64 位 page index 定位的权威页面；移除固定 4096 项线性文件页数组带来的容量与
查找边界。rootfs v4 和 ATA/NVMe 设备语义保持不变；ABI 以追加方式从 2.3.0 升到
2.4.0，旧 1..84 编号和 -1..-59 错误区间不变。

## 增量顺序

1. 动态稀疏页索引、文件缓存地址空间和状态契约（已实现）；
2. buffered read、ELF/file fault 与只读 `MAP_SHARED` 迁移（已实现）；
3. buffered write、可写 `MAP_SHARED`、truncate 与失效一致性（已实现）；
4. 后台 writeback worker、软硬 Dirty 水位与写入回压（已实现）；
5. `fsync`、`fdatasync`、`msync` 和按打开实例推进的写回错误序列（已实现）；
6. clean 淘汰、dirty 写回、匿名 swap、直接回收与 OOM 的统一压力路径（已实现）。

## 第一增量

- `FileCacheIdentity` 成为新旧文件缓存共享的稳定身份；
- `SparsePageIndex` 使用 64 路、最多 11 层的动态 radix tree 覆盖完整 `uint64_t`
  page index；
- 节点聚合 Present/Dirty/Writeback/Error bitmap，支持标记范围中的首项查找；
- 插入先申请完整缺失路径，失败逆序回滚；删除裁剪空分支并收缩 root；
- `FileCacheAddressSpace` 动态拥有页元数据，冻结映射引用及
  Clean/Dirty/Writeback/Error 转换；
- 8192 页生命周期超过旧 4096 项上限，十万步随机模型逐操作对照参考容器；
- Kernel 自检同时覆盖 `UINT64_MAX` 和 2 KiB 子堆中途耗尽，启动成功只增加一个
  内存日志 marker。

## 第二增量

- `FilePageCache` 删除外部 `FilePageCacheEntry[4096]` 存储，改为动态文件身份链表；
  每个记录内嵌 `FileCacheAddressSpace`，页面查找走 radix；
- 缓存页 frame 仍由 `PhysicalFrameAllocator` 所有，metadata 改用 buddy block 上的
  专用 KernelHeap；三档容量为 256/4096/8192 页；
- VFS 新增一次性 regular-file read cache hook 和显式 `ReadUncachedAt` 填页边界；
- rootfs/legacy superblock 允许缓存普通文件，memfs/procfs/devfs 默认直读；
- VFS buffered read、ELF header reader、按需 file fault 和 read-only/writable
  `MAP_SHARED` 现在共享同一 FileIdentity/page-index 页面；
- 直接 buffered write 仍先撤销映射和失效 cache，writable shared 写回继续使用同一
  dynamic cache，未产生第二份权威数据；
- 新增 8192 页动态 FilePageCache 生命周期、metadata 小堆失败回滚、VFS hook/bypass
  和 QEMU buffered hit 证据；最终 payload 校验后裁剪 clean cache，再关闭 NVMe；

## 第三增量

- VFS capability 改为 read/write/size/truncate 四 hook；cache fill 与 writeback 分别使用
  `ReadUncachedAt`/`WriteUncachedAt`，不会递归进入公共缓存路径；
- `write`/`WriteAt` 在唯一 frame 上先 Dirty 后复制，跨页逐页提交；逻辑 EOF 立即覆盖
  `stat`，同文件 fd 和既有 `MAP_SHARED` 无需 refault 即可观察新字节；
- VfsWriteback 描述符按文件身份保留 open reference；原 fd 关闭或 unlink 后 Dirty 页
  仍可写回，Dirty/Error 清空后释放该引用；
- writeback 按缓存 EOF 裁短最后一页，失败保持 Error；`sync` 先写保护 shared PTE，
  再写回、释放 clean writeback 引用，最后提交 rootfs journal 与设备 Flush；
- truncate 只撤销 EOF 后驻留映射；缩小丢弃范围外 Clean/Dirty/Error 并清零尾页，
  扩大不分配页面且恢复逻辑零区间；private COW 页保持隔离；
- FilePageCache 单元新增 busy/discard/tail-zero，十万步随机模型加入 grow/shrink；VFS
  单元冻结四 hook 与 uncached bypass，QEMU memory probe 覆盖双 shared alias、private
  隔离及 truncate shrink/grow。

## 第四增量

- FileCacheAddressSpace 新增 Loading 瞬态；miss 先注册身份/frame，再在 cache lock 外
  调用 VFS reader，成功转 Clean，失败逆序撤销 metadata 和 frame；
- 同页重入只返回 EntryBusy，单元测试在 reader 回调内递归 Acquire，验证没有第二次
  source read，并要求 `CurrentSpinLockDepth()==0`；
- 4 GiB cache 的 Dirty 后台/硬水位约为容量 10%/20%，回落目标约 5%；Error 重试不
  重复占用 quota，Dirty+Writeback+Error 共同构成 outstanding 脏页账本；
- 单 BSP 使用 user-return safe-point worker，不在 IRQ 中执行 VFS I/O，也不伪造
  Kernel Thread；每批最多 64 页，pending 请求合并并持续到目标水位；
- worker 每批前写保护全部 writable shared PTE。硬水位在普通 write 前执行同步平衡；
  后台失败把页留在 Error 并暂停，显式 sync 才恢复重试；
- 4 GiB memory probe 连续写入 1024 个 4 KiB 页；QEMU 实测 worker 7 批、写回
  448 页、失败 0，随后 shared/private/truncate 与最终持久化语义继续通过。

## 第五增量

- 新增动态 `FileWritebackErrorTracker`。记录仅在至少一个独立 FileDescription 打开时
  存活；写回失败推进文件序列，新打开实例采样当前值，因此不继承历史错误；
- duplicate 与 fork 继续共享同一 KernelObject/FileDescription，因而共享错误游标；
  独立 open 各自检查并推进，单个实例不会重复报告同一序列；
- `FilePageCache::WritebackFile` 以文件身份和闭 page-index 范围选择 Dirty/Error 页；
  显式异步请求可在低于普通软水位时继续驱动 64 页 safe-point worker；
- ABI 2.4.0 追加调用 85..87。`fsync`/`fdatasync` 只写回目标文件页，再执行 VFS 与
  设备 Flush；当前 rootfs 的 fdatasync 会多提交非必要 metadata，但不削弱数据完整性；
- `msync` 采用 Linux 的 ASYNC/INVALIDATE/SYNC 位值和组合校验。SYNC 等待指定
  `MAP_SHARED` 范围，ASYNC 只排队，`MAP_PRIVATE` 修改永不写回；统一权威 frame 下
  INVALIDATE 没有不一致副本需要额外撤销；
- 4 GiB memory probe 覆盖 async、sync+invalidate、private、非法 flags、fsync 与
  fdatasync。正常 QEMU 要求四类调用计数非零且打开实例记录最终归零。

## 第六增量

- 新增纯逻辑 `ExecuteMemoryReclaim`，严格按 clean file、dirty writeback/reclaim、
  anonymous swap 调用三个操作；无进展、clean 失败、写回失败、swap 失败分别返回；
- 用户驻留分配从 bool 改为类型化内部结果。一次回收后同步物理分配器真实 resident，
  只重试一次；写回或 swap 设备失败不进入 OOM；
- ProcessRuntime 注册全局回收操作：写回前保护全部 writable shared PTE，匿名页按进程
  游标轮转扫描，每个地址空间仍保留 65536 页扫描上限；
- PID1 不参与跨进程 swap/OOM；单线程进程保存现场指向的用户栈页不换出，多活动用户
  栈进程本轮跳过，避免恢复时使用已经 non-present 的返回栈；
- direct reclaim 仍无法满足分配时才运行既有确定性 OOM 选择器。非当前 victim 完整
  释放后重试，当前 page-fault victim 保持 SIGKILL 异常出口；系统调用路径不选择当前
  进程，避免没有异常 frame 时留下延迟 kill；
- 新增 ATA 与 NVMe 两条 4 GiB reclaim-pressure QEMU。它们使用完整 rootfs/用户环境和
  真实交换盘，在 PID1 建立后把逻辑驻留预算降为 9216 页；memory probe 实际触碰并
  回读 512 个匿名页。

## 当前边界

- rootfs 的八项 metadata/data `BlockCache` 尚未拆分；
- Loading 冲突在当前单 BSP 同步 I/O 下返回 Busy；尚无 SMP waiter、readahead、RCU、
  lockless lookup 或 large folio；
- safe-point worker 不是可独立调度的 Kernel Thread；当前批次间依赖用户返回边界，
  空闲期定时 writeback 和时间老化留给后续调度基础设施；
- writeback backing 表仍受 1024 项 FileBacking 容量约束；
- 缓存 hook 当前只覆盖逻辑 EOF；allocated size 与 mtime/ctime 仍在实际后端 writeback
  时推进。fdatasync 尚未获得比 fsync 更小的 rootfs journal/metadata 提交集合；
- 多用户线程地址空间的跨进程 swap 本轮保守跳过；尚无 page reference aging、
  active/inactive LRU、kswapd、memcg 或 NUMA reclaim；
- 本版本不启动教材、网站、Sites 或公开发布闭环。
