# v2.8 统一文件页缓存与写回回收

状态：第三增量统一写入与 truncate 已实现，工程候选，尚未发布

日期：2026-08-21

## 目标

让 buffered read/write、文件映射、写回和内存回收最终共享以 Vnode 文件身份和
64 位 page index 定位的权威页面；移除固定 4096 项线性文件页数组带来的容量与
查找边界。rootfs v4、ABI 2.3.0 和 ATA/NVMe 设备语义保持不变。

## 增量顺序

1. 动态稀疏页索引、文件缓存地址空间和状态契约（已实现）；
2. buffered read、ELF/file fault 与只读 `MAP_SHARED` 迁移（已实现）；
3. buffered write、可写 `MAP_SHARED`、truncate 与失效一致性（已实现）；
4. 后台 writeback worker、软硬 Dirty 水位与写入回压；
5. `fsync`、`fdatasync`、`msync` 和按打开实例推进的写回错误序列；
6. clean 淘汰、dirty 写回、匿名 swap、直接回收与 OOM 的统一压力路径。

## 第一增量

- `FileCacheIdentity` 成为新旧文件缓存共享的稳定身份；
- `SparsePageIndex` 使用 64 路、最多 11 层的动态 radix tree 覆盖完整 `uint64_t`
  page index；
- 节点聚合 Present/Dirty/Writeback/Error bitmap，支持标记范围中的首项查找；
- 插入先申请完整缺失路径，失败逆序回滚；删除裁剪空分支并收缩 root；
- `FileCacheAddressSpace` 动态拥有页元数据，冻结映射引用及
  Clean/Dirty/Writeback/Error 转换；
- 8192 页生命周期超过旧 4096 项上限，十万步随机模型逐操作对照参考容器；
- Kernel 自检同时覆盖 `UINT64_MAX` 和 2 KiB 子堆中途耗尽，启动成功只增加一个
  内存日志 marker。

## 第二增量

- `FilePageCache` 删除外部 `FilePageCacheEntry[4096]` 存储，改为动态文件身份链表；
  每个记录内嵌 `FileCacheAddressSpace`，页面查找走 radix；
- 缓存页 frame 仍由 `PhysicalFrameAllocator` 所有，metadata 改用 buddy block 上的
  专用 KernelHeap；三档容量为 256/4096/8192 页；
- VFS 新增一次性 regular-file read cache hook 和显式 `ReadUncachedAt` 填页边界；
- rootfs/legacy superblock 允许缓存普通文件，memfs/procfs/devfs 默认直读；
- VFS buffered read、ELF header reader、按需 file fault 和 read-only/writable
  `MAP_SHARED` 现在共享同一 FileIdentity/page-index 页面；
- 直接 buffered write 仍先撤销映射和失效 cache，writable shared 写回继续使用同一
  dynamic cache，未产生第二份权威数据；
- 新增 8192 页动态 FilePageCache 生命周期、metadata 小堆失败回滚、VFS hook/bypass
  和 QEMU buffered hit 证据；最终 payload 校验后裁剪 clean cache，再关闭 NVMe；

## 第三增量

- VFS capability 改为 read/write/size/truncate 四 hook；cache fill 与 writeback 分别使用
  `ReadUncachedAt`/`WriteUncachedAt`，不会递归进入公共缓存路径；
- `write`/`WriteAt` 在唯一 frame 上先 Dirty 后复制，跨页逐页提交；逻辑 EOF 立即覆盖
  `stat`，同文件 fd 和既有 `MAP_SHARED` 无需 refault 即可观察新字节；
- VfsWriteback 描述符按文件身份保留 open reference；原 fd 关闭或 unlink 后 Dirty 页
  仍可写回，Dirty/Error 清空后释放该引用；
- writeback 按缓存 EOF 裁短最后一页，失败保持 Error；`sync` 先写保护 shared PTE，
  再写回、释放 clean writeback 引用，最后提交 rootfs journal 与设备 Flush；
- truncate 只撤销 EOF 后驻留映射；缩小丢弃范围外 Clean/Dirty/Error 并清零尾页，
  扩大不分配页面且恢复逻辑零区间；private COW 页保持隔离；
- FilePageCache 单元新增 busy/discard/tail-zero，十万步随机模型加入 grow/shrink；VFS
  单元冻结四 hook 与 uncached bypass，QEMU memory probe 覆盖双 shared alias、private
  隔离及 truncate shrink/grow。

## 当前边界

- rootfs 的八项 metadata/data `BlockCache` 尚未拆分；
- cache miss 仍在 cache lock 内同步填页；没有 Loading waiter、readahead、RCU、
  SMP lockless lookup、large folio、后台 writeback/Dirty 软水位或按文件同步 ABI；
- writeback backing 表仍受 1024 项 FileBacking 容量约束；第四增量前，达到 Dirty hard
  limit 的首个未写字节返回有界短写/容量失败，不等待后台 worker；
- 缓存 hook 当前只覆盖逻辑 EOF；allocated size 与 mtime/ctime 仍在实际后端 writeback
  时推进。第五增量的按文件同步和错误序列会一并冻结这些 metadata 可见时点；
- 本版本不启动教材、网站、Sites 或公开发布闭环。
