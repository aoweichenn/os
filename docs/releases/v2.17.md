# v2.17 rootfs v5 journal v2、revoke 与 orphan file

状态：六个增量已完成，工程候选，尚未发布

日期：2026-08-24

## 目标与六个增量

1. 冻结 journal superblock、四槽与 descriptor/revoke/payload/commit/checkpoint 盘面；
2. 实现显式小端、CRC32C、feature、UUID、范围、重复和保留区验证；
3. 实现 512B BlockDevice 上的 4 KiB prepared → ordered → commit 提交流程；
4. 实现独立 checkpoint、按序幂等 replay 和跨事务 revoke；
5. 实现 503 槽 orphan block、原子 metadata 集成与双阶段断电矩阵；
6. 完成十万步模型、文档、全构建和 rootfs v4 整机回归。

## 完成范围

- 新增 `root_journal_v2_format.*`：81-block journal、4 个 20-block 槽、16 metadata、8 ordered
  data、32 revoke 的冻结格式；
- 新增 `root_journal_v2.*`：sequence 预留、credit、last-operation-wins、prepared flush、ordered
  flush、commit、独立 checkpoint、slot reuse、统计和恢复；
- committed transaction 在 replay 前全部验证；后续 revoke 跳过旧 payload，incomplete 丢弃，
  valid commit 引用的损坏 fail closed；
- Initialize 要求外部传入预期文件系统 UUID，完整 journal 被复制到另一文件系统也会拒绝；
- orphan file inode 冻结为 15，journal inode 为 8；orphan block 支持 503 个 64 位 inode、幂等
  add/remove 和 CRC32C；
- 测试设备把 volatile/durable sector 分离，4 KiB 操作真实拆成 8 个 512B sector；
- 随机测试保持十万步，真实盘面操作按分层采样，耗时从初版 46.51 秒降至 1.49 秒；
- rootfs v4 生产 mount、ABI、QEMU 和手机运行路径不变，v5 journal 尚未写入生产镜像。

## 验证证据

- CAW 聚焦 C++ 测试 5/5、0 失败：format unit、engine unit、revoke/orphan integration、
  commit+recovery failure-path 和十万步 randomized；总计 2.41 秒；
- commit 断电矩阵 128 点，recovery 断电矩阵 96 点；二次恢复必须 Clean；
- journal superblock 固定 profile checksum 为 `0xB797102E`，由独立 Python 小端序列化计算并由
  C++ unit 固定，防止字段偏移无声漂移；
- fresh CAW 工具链为 Python 3.13.9、Clang/LLD 21.1.8、NASM 2.16.03、QEMU 10.1.5、
  CMake 3.31.11 与 Ninja 1.13.1；Debug 全构建 3593 个目标，零编译警告；
- `python3 tools/os.py verify` 为 259/259、0 失败：79 unit、88 integration、59 randomized、
  33 system，含 26 条 failure-path；CTest 786.88 秒，后台任务墙钟约 927 秒，CAW 峰值宿主
  内存 6.7 GiB；
- 4 GiB ATA/NVMe primary 为 65.06/62.89 秒，reclaim 为 69.15/69.58 秒，OOM 为
  68.30/68.11 秒，三启动 persistence 为 128.15/127.00 秒；NVMe normal/EIO/timeout 为
  2.44/2.38/9.92 秒；
- 全部成功 system profile 继续从 reset vector 启动生产 rootfs v4，并要求 QMP screendump
  可见、资源守恒与零禁止 marker；这些结果不宣称 v5 journal 已挂载。

## 已知边界

- journal 固定四槽，不支持并发 running transaction、后台 checkpoint 或动态扩容；
- orphan file 只完成盘面和事务原子性，尚未调用 extent truncate/block release；
- journal/orphan 特殊 inode 尚未分配 extent，v5 仍不能 mount；
- 当前没有 Python journal 工具；v2.20 完整 fsck/migration 将读取 journal 与 orphan 状态；
- 本阶段不创建 `v2.17` tag，不覆盖独立在制书稿，也不启动网站/Sites 公开发布闭环。
