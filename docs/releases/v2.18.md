# v2.18 extent、block-group allocator 与 delayed allocation

状态：六个增量已完成，工程候选，尚未发布

日期：2026-08-24

## 目标与六个增量

1. 冻结 4 KiB extent leaf/index、CRC32C 与 64 位映射；
2. 实现 canonical extent、split/merge、深度增长/收缩和重复物理所有权拒绝；
3. 实现组内连续分配、locality、partial、fallback 和可回滚 reservation；
4. 实现 delayed → unwritten → initialized writeback 与失败回滚；
5. 实现 fallocate、punch、truncate、SEEK_DATA/SEEK_HOLE 和范围查询；
6. 完成 journal ordered 故障矩阵、十万步模型、文档、全构建与整机回归。

## 完成范围

- `root_extent_tree.*`：123-entry 盘面节点；运行时 256 extent、85 node、4 路、最大深度 3；
- `root_block_group_allocator.*`：外部 bitmap storage、preferred group 连续 run、minimum/partial、
  reservation commit/abort、release、protected range 和统计；
- `root_delayed_allocation.*`：64 delayed range、单 active writeback、fallocate/punch/truncate、
  SEEK_DATA/SEEK_HOLE 与 320-record 范围查询；
- logical overlap、physical duplicate ownership、stale token、double free、ENOSPC、extent capacity
  和 keep-size EOF 均 fail closed；
- extent metadata 经 journal v2 提交，ordered data 必须先稳定；
- 生产 rootfs v4、ABI v2.6.0、QEMU 和手机运行路径不变，v5 仍未 mount。

## 验证证据

- CAW 聚焦测试 5/5、0 失败：extent unit、allocator unit/failure、delalloc integration、
  extent+journal ordered failure-path 和十万步 randomized；强制重编后总计 0.18 秒；
- extent+journal 64 个持久化故障点；十万步模型逐块核对 mapping/free/file-size/seek；
- 首轮 full verify 为 263/264；唯一失败是 NVMe storage 在 11.56 秒读取到一次 VGA trace
  非追加快照。同一 Kernel/镜像不改代码定向 70.83 秒通过，确认不是 NVMe/文件系统回归；
- runner 现对首次非追加执行间隔一个 poll 的第二次 pmemsave；确认快照恢复前缀才接受，两次
  都重写仍失败。tooling unit 1/1、修复后 NVMe storage 定向 70.81 秒通过；
- final fresh CAW 工具链为 Python 3.13.9、Clang/LLD 21.1.8、NASM 2.16.03、QEMU 10.1.5、
  CMake 3.31.11、Ninja 1.13.1；Debug 全构建 3685 个目标，零警告；
- `python3 tools/os.py verify` 为 264/264、0 失败：81 unit、90 integration、60 randomized、
  33 system，含 28 条 failure-path；CTest 876.29 秒，后台墙钟约 928 秒，CAW 峰值宿主内存
  6.5 GiB；
- 4 GiB ATA/NVMe primary 为 71.88/70.82 秒，reclaim 为 77.78/73.62 秒，OOM 为
  75.53/74.99 秒，三启动 persistence 为 144.56/141.94 秒；NVMe normal/EIO/timeout 为
  2.60/2.55/10.04 秒；
- 全部成功 system profile 继续从 reset vector 启动生产 rootfs v4，并要求 QMP screendump
  可见、资源守恒与零禁止 marker；这些结果不宣称 v5 extent 已挂载。

## 已知边界

- runtime tree 通过 canonical rebuild 验证 split/merge 结果，尚未原位更新实际 v5 node block；
- allocator 尚无并发 per-group 锁和后台预分配窗口；
- hole write 使用 delalloc，已映射 initialized extent 的覆盖写继续由既有 page-cache 语义承担；
- 范围操作尚未进入用户 ABI，v5 不可 mount；
- 本阶段不创建 `v2.18` tag，不覆盖独立在制书稿，也不启动网站/Sites 公开发布闭环。
