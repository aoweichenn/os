# v0.6：物理内存、四级页表与早期堆

发布日期：2026-07-24

## 交付结果

本阶段把 Stage 1 的固定模式切换页表替换为由内核拥有、可分配、可验证权限的
地址空间。QEMU 仍只模拟 x86-64 CPU、RAM 和 `fw_cfg` 配置设备；端口协议、
E820 转换、内存图校验、页帧状态、四级页表、CR3 切换、NX/WP、guard page
和堆均由项目代码实现。

## 内存发现

Stage 1 新增 `memory_map.asm`：

- 通过 `0x510/0x511` 端口验证 `QEMU` 签名。
- 从 selector `0x0019` 读取大端文件目录，最多流式遍历 256 项。
- 精确查找 `etc/e820`，验证非空、20 字节整除和最多 128 项。
- 把 `{u64 base, u64 length, u32 type}` 扩展为 24 字节项目 ABI。
- 在交接前按物理基址排序，不把 QEMU 当前目录顺序当成契约。
- 失败只输出 `MEMORY_MAP_INVALID`，禁止继续读取或调用 Kernel。

BootInfo 升级为版本 2、104 字节，新增内存图地址 `0x18000`、条目数和条目
宽度。交接布局同时增加 `0x16000` 元数据与 `0x17000` 文件名暂存区。

## 物理页帧

内核首先拒绝空、过大、零长度、溢出、乱序、重叠和无受管可用 RAM 的内存图。
汇总值区分“所有描述区间之和”“全部可用 RAM”和“低 64 MiB 管理范围内可用
RAM”，避免把高地址保留 MMIO 窗口误称为内存容量。

物理分配器管理 16384 个 4 KiB 帧，每帧 2 bit：

- unavailable：不可分配或不是完整可用页。
- free：可分配。
- allocated：动态所有者持有。
- reserved：平台、内核或启动栈长期占用。

低 1 MiB、链接器符号界定的 Kernel 映像和 64 KiB 初始栈被显式保留。
保留操作使用先检查后提交的两遍过程，跨越 allocated 帧时不留下部分状态。
分配采用可回绕 next-fit 搜索，释放检查对齐、范围和当前所有权。

## 内核地址空间

内核从空闲帧分配、清零 PML4、PDPT、PD 和 PT，建立 4 KiB 叶映射：

| 对象 | 权限 |
| --- | --- |
| 零页 | not-present |
| `.text` | read + execute |
| `.rodata` | read + NX |
| `.data/.bss` 与栈 | read + write + NX |
| 初始栈与三个 IST 的底页 | not-present guard |
| 高半区 64 KiB heap | read + write + NX |
| 写保护测试页 | read + NX |

内核先用 CPUID 验证 NX 能力，设置 `IA32_EFER.NXE` 和 `CR0.WP`，再加载新
CR3。切换后回读 CR3、EFER、CR0，并查询代码、只读数据、可写数据、堆、
零页和四个 guard page。只有全部符合才输出 `MEMORY_PERMISSIONS_VALID`。

## 早期堆

高半区堆位于 `0xFFFF800000000000`，容量 64 KiB，由 16 个离散物理页帧
支持。单调分配器具备：

- 显式初始化与状态返回。
- 非零、二的幂对齐验证。
- 地址、padding 和容量溢出检查。
- 失败不修改输出指针。
- 容量、消耗、剩余和分配次数统计。

目标机分别做 16 字节和 4 KiB 对齐分配，写入两个不同 64 位模式并读回。
这是“虚拟页可写且对象对齐正确”的执行测试，不只检查软件计数。

## 权限故障证据

独立写保护镜像让 Ring 0 写入 `0xFFFF800000100000` 的只读 present 页。
预期现场：

```text
[OS][KERNEL] FAULT_INJECTION=WRITE_PROTECTION
[OS][KERNEL] EXCEPTION_VECTOR=0x000000000000000E
[OS][KERNEL] EXCEPTION_ERROR_CODE=0x0000000000000003
[OS][KERNEL] PAGE_FAULT_ADDRESS=0xFFFF800000100000
[OS][KERNEL] PANIC
```

错误码 `0x3` 同时证明页存在、访问是写且来自 supervisor；若 CR0.WP 未设置，
该写入不会以预期方式失败。

## 工程修正

内核 ELF 自定义链接命令此前只依赖 object target，没有把对象文件列为显式
文件依赖；部分 C++ 增量修改可能编译对象却不重新链接 ELF。本阶段把
`$<TARGET_OBJECTS:...>` 加入 `DEPENDS`，保证 Ninja 的真实文件图能够触发
重链接。ELF 审计同时新增内核映像、text、rodata 和 writable linker boundary
符号，防止页权限代码引用缺失边界。

## 验收结果

完整验证共 43 项 CTest，新增：

- 3 组内存纯逻辑单元测试。
- 1 组 QEMU 内存图形状与启动保留集成测试。
- 1 组 8192 次页表项 + 4096 步分配器模型随机测试。
- 1 条 Stage 1 `MEMORY_MAP_INVALID` QEMU 失败路径。
- 1 条 Ring 0 写只读页 QEMU 失败路径。

正常路径必须按顺序出现：

```text
[OS][STAGE1] MEMORY_MAP_READY
[OS][KERNEL] MEMORY_MAP_VALID
[OS][KERNEL] FRAME_ALLOCATOR_READY
[OS][KERNEL] PAGING_READY
[OS][KERNEL] MEMORY_PERMISSIONS_VALID
[OS][KERNEL] HEAP_READY
[OS][KERNEL] HEAP_SELF_TEST_PASSED
[OS][KERNEL] READY
```

既有复位、串口、ATA、A20、长模式、ELF、GDT/TSS/IDT、INT3、UD2 和
not-present #PF 回归全部继续通过。

## 已知边界

- 只管理低 64 MiB 物理帧；接口已经使用 64 位，但尚未动态扩大状态存储。
- 低 64 MiB 仍大范围恒等映射，尚未实现精细的物理直映窗口。
- 页表映射失败不会回滚已经创建的中间表，取消映射不回收空表。
- 早期堆不释放对象，不用于长期通用分配。
- 页故障仍全部 panic；按需分页、写时复制与用户进程错误处理尚未实现。

8259A PIC、PIT IRQ、PS/2 键盘与内核 IDE 驱动。
