# v1.3：CpuLocal、统一用户现场与 SYSCALL/SYSRET

## 阶段结论

v1.3 已把默认用户系统调用入口从兼容 `INT 0x80` 切换为 x86-64 原生
`SYSCALL`，同时保留兼容入口进行差分验证。两条路径不再维护两份帧或两套
分发器，而是汇聚为同一个 176 字节 `UserContext`：

```text
INT 0x80 ──TSS.RSP0──┐
                     ├─> UserContext ─> syscall dispatcher
SYSCALL ──SWAPGS─────┘                    │
                                         ├─ need-resched -> Thread scheduler
                                         └─ validate -> SYSRETQ | IRETQ | reject
```

处理器能力、MSR 布局、可信入口栈、IRQ 嵌套、返回前调度和返回方法都成为
显式状态与可重复证据。正常 functional 路径仍完整运行 Shell、IPC、文件系统、
Process/Thread、扩展现场和资源回收。

## 已完成能力

### 处理器规格与失败门禁

- 读取并解码 CPUID 标准/扩展最大叶；
- 必需能力固定为 long mode、NX、FXSR、SSE、SSE2、SYSCALL/SYSRET；
- 物理地址宽度只接受 36..52 位，当前虚拟地址宽度必须为 48 位；
- 同时记录 required、available、missing mask 和地址宽度；
- 缺少任一能力时在 GDT、设备和用户态之前明确停止；
- 新增 `qemu64,-syscall` 故障路径，missing mask 必须非零。

### CpuLocal 与可信 Thread 入口栈

- 64 字节对齐的单 BSP `CpuLocal`；
- 汇编 ABI 固定 self/current/entry RSP/user RSP 四个 64 位槽；
- Thread 激活时同步更新 TSS.RSP0 和 CpuLocal entry RSP；
- 记录 IRQ 深度、抢占禁止深度及峰值；
- IRQ 只提交 `need_reschedule`，由用户返回边界消费；
- 记录兼容/原生入口、IRQ 打断、返回前调度、SYSRET/IRET、回退、拒绝与
  可信栈验证；
- 非局部恢复永久内核栈时显式收束活动入口和 SWAPGS 状态。

### 原生入口 MSR

- 写入并回读 IA32_EFER.SCE；
- STAR 固定生成 kernel `0x08`、user SS `0x1B`、user CS `0x23` 的选择子关系；
- LSTAR 指向自研 NASM Intel 入口；
- FMASK 清 TF、IF、DF、NT 与 AC；
- 用户 GS base 为零，kernel GS base 指向 CpuLocal；
- CpuLocal 初始化失败与 MSR 初始化失败使用独立日志，不再冒充 CPUID 错误。

### 统一 UserContext 与安全返回

- 删除旧 `UserPrivilegeFrame`，所有初始、IRQ、兼容和原生用户现场统一为
  `UserContext`；
- 对 frame 所有权、低半规范 RIP/RSP、RX/RW-NX 映射、CS/SS、RFLAGS
  执行联合校验；
- 只有合法原生现场且 RFLAGS 属于快速集合时选择 `SYSRETQ`；
- `INT 0x80`、硬件 IRQ、初始现场和带 DF/RF 的合法原生现场选择 `IRETQ`；
- 非法返回不执行危险架构指令，而是记录有界安全诊断并终止对应用户进程；
- NMI 使用 IST2 上的最小 fail-stop 路径，不访问普通栈、锁、日志或 CpuLocal。

### 调试信息与启动载荷分离

链接产物 `kernel.elf` 保留完整 DWARF，供 GDB 和符号审计使用。启动镜像改写入
`kernel.payload.elf`：它只通过 `llvm-objcopy --strip-debug` 删除非加载调试
段，不改变三个 `PT_LOAD` 的入口和运行内容。所有正常、异常和用户隔离内核
变体都执行同一转换。

这解决了 Debug ELF 随源码增长后越过固定内核载荷区、与 LBA 2048 文件系统
区域重叠的问题，同时没有牺牲宿主调试能力。Stage 1 和镜像工具继续完整审计
实际写盘 payload。

随机种子为 `0x5A17C011BADC0FFE`。每次失败报告种子、迭代位置和性质。

### QEMU 正常路径

`os_qemu_functional_smoke` 使用 256 MiB、`-cpu qemu64` 和完整自研启动链。
验收器要求：

- `PROCESSOR_FEATURES_READY`、CpuLocal 与六个 MSR 证据各恰好一次；
- `DUAL_SYSCALL_ENTRY_EQUIVALENT`、`SYSRET_RETURNED`、
  `SYSCALL_IRET_FALLBACK_RETURNED` 各恰好一次；
- 兼容和原生入口均非零；
- IRQ 打断系统调用、返回前调度、SYSRET、IRET 和原生 IRET 回退均非零；
- 最大 IRQ/抢占深度非零，结束深度与 need-resched 都为零；
- `REJECTED_USER_RETURNS` 精确为零；
- 可信栈验证次数至少覆盖入口总数；
- 全部旧 Shell、IPC、文件系统、扩展现场、异常隔离和资源回收标记继续通过。

一次代表性运行在约 1.84 秒到达 `READY`，记录：

```text
LEGACY_SYSCALL_ENTRIES=0x2
NATIVE_SYSCALL_ENTRIES=0x230
SYSCALL_IRQ_INTERRUPTS=0x56
SYSCALL_RETURN_RESCHEDULES=0x36
SYSRET_RETURNS=0x1C1
IRET_RETURNS=0xE
SYSCALL_IRET_FALLBACKS=0x1
REJECTED_USER_RETURNS=0x0
TRUSTED_SYSCALL_STACK_VALIDATIONS=0x232
```

这些与 PIT 时序相关的累计值只要求满足下界，不作为跨宿主精确常数。

### QEMU 失败路径

`os_qemu_native_system_call_unsupported` 使用同一 ROM、Stage 1 和 Kernel
payload，仅把 CPU 模型改为 `qemu64,-syscall`。它必须到达：

```text
PROCESSOR_FEATURES_UNSUPPORTED=0x...
PROCESSOR_MISSING_FEATURES=0x0000000000000020
```

并禁止出现 `PROCESSOR_FEATURES_READY`、扩展现场 ready、GDT、用户态、panic
和 `READY`。这证明失败来自显式能力门禁，而不是执行未支持指令后的偶然 #UD。

## 关键故障与修复

### 阻塞/退出绕过普通系统调用尾部

原生入口执行过 `SWAPGS`。当最后一个 Ready Thread 在系统调用内阻塞或退出时，
调度器可能直接恢复永久内核调用链，普通尾部没有机会交换回来。最初表现为后续
系统调用 GS 基址错误。修复后，非局部返回在清理 CpuLocal 前捕获入口类型，
永久栈恢复桩按需执行 `SWAPGS`。

### IRQ 保存的 RF 与来源 vector

硬件 IRQ 保存的合法 RFLAGS 可能包含 RF，且 vector 是 32..47，不应被当作
伪造系统调用现场。统一模型增加明确的 HardwareInterrupt 来源，并把 RF 纳入
“合法但不得 SYSRET”的集合，因此该现场由 IRET 安全恢复。

### Debug ELF 超过固定载荷区

源码与 DWARF 增长使写盘 ELF 接近文件系统起始 LBA。修复不是缩减调试信息或
扩大每次镜像布局，而是长期分离 debug ELF 与 stripped payload，并让所有
变体复用同一 CMake 生成规则。

## 已知边界与下一阶段

- 当前只有单 BSP CpuLocal，不含 AP 启动和 SMP；
- 用户 GS/TLS 尚未开放；
- 四级 48 位虚拟地址模型保持冻结；
- NMI 当前 fail-stop；
- `INT 0x80` 作为兼容入口继续存在；
- 当前每进程描述符仍是 v1.0 的固定槽模型。

下一阶段 v1.4 将建立 `KernelObject`、动态 `FileTable` 与共享
`FileDescription`，但不改变本阶段已经冻结的架构入口、UserContext 和返回
验证边界。
