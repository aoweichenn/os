# v1.9：文件页故障、按需 ELF 与有界 clean page cache

## 阶段结论

v1.9 已完整打通“VFS 文件字节 → 稳定后备 → 文件 VMA → 用户 `#PF` →
物理 frame/PTE → cache 引用 → write/truncate 失效 → unmap/exit 回收”。

正常磁盘 ELF 不再在 `spawn/exec` 时预先分配全部 `PT_LOAD` 页。校验阶段建立
VMA 和稳定文件后备，入口页在返回 Ring 3 前解析，其余页由真实用户访问触发。
QEMU 仍只提供 CPU、RAM、ATA、PIC/PIT、PS/2 等硬件模型；ROM、Stage 1、
ELF 校验、页故障策略、缓存、文件系统和用户探针均为项目代码。

## 文件后备与身份

新增 `FileBackingManager`，固定容量保存 VFS 打开实例和专用内存镜像。VFS
后备增加打开实例引用，因此：

```text
open -> mmap -> close(fd) -> mapping remains valid -> munmap -> final close
```

文件身份包含 superblock id/generation 与 inode id/generation。后备句柄包含
槽位 generation 与 owner；槽复用、inode 复用和 fd 复用都不会让旧 VMA
命中新对象。

VFS 新增 `RetainOpenFile`、`StatOpenFile` 和 `ReadAt`，FileDescription
snapshot 暴露稳定身份与当前文件长度。随机访问不修改共享文件偏移，页故障
不会改变用户随后 `read` 的 offset。

## VMA 与 ABI

VMA 新增 `FilePrivate` 和 `FileShared`，`ExecutableImage` 也保存文件后备。
文件 split 会同步重定位 offset/data length；只有身份、generation、权限和
文件区间连续的邻接段才合并。

系统调用 43 为 `MapFileMemory`。48 字节 `FileMemoryMapRequest` 包含：

| 字段 | 含义 |
| --- | --- |
| `requested_address` | 自动选择或页对齐固定地址 |
| `length_bytes` | 映射字节数 |
| `protection_flags` | read/write/execute |
| `map_flags` | private/shared 与 fixed |
| `file_descriptor` | 建立后备时使用的进程 fd |
| `file_offset_bytes` | 页对齐文件偏移 |

公开支持可写 `MAP_PRIVATE` 与只读 `MAP_SHARED`。writable shared 明确拒绝，
不伪装成 private。通用 `UnmapMemory` 可以撤销匿名和文件映射，但仍拒绝用户
删除 ELF、栈与 program-break。

`VirtualMemoryStatistics` 从 112 字节扩展为 160 字节，追加 file VMA/page、
file fault、cache hit/invalidation 等 64 位字段。

## 页故障策略

页故障仍先验证 U/S、P、RSVD、W/R、I/D 和 VMA 软件权限。文件路径再计算：

```text
file_offset = vma.file_offset + (fault_page - vma.begin)
valid_bytes = clamp(vma.data_length - page_delta, 0, 4096)
```

处理矩阵：

| 页面 | frame 来源 | 未覆盖字节 | 是否共享 |
| --- | --- | --- | --- |
| 完整只读 ELF/file | clean page cache | 不适用 | 是 |
| 可写 private | 新私有 frame + ReadAt | 零 | 否 |
| 文件尾部分页 | 新私有 frame + ReadAt | 零 | 否 |
| ELF BSS 尾部 | 新私有 frame | 零 | 否 |

PTE 权限始终由 VMA 导出，W+X 继续拒绝。用户返回验证会先解析 entry instruction
page，再检查 executable/user/not-writable，避免按需 ELF 在第一次 `iret/sysret`
前被旧的“入口必须已驻留”假设拒绝。

## 有界 clean page cache

新增固定容量 `FilePageCache`：

- 唯一键为 `(FileIdentity,page_index)`；
- entry 保存 frame、mapping reference 与 LRU generation；
- cache miss 读取一次并发布唯一权威页；
- hit 增加映射引用；
- unmap/exit 释放引用；
- 无引用 clean LRU 可直接丢弃；
- 全部被引用时明确返回容量错误。

容量随 managed frames 缩放，范围 256..4096 页。没有 dirty/writeback，也没有
后台线程；clean 页的权威数据始终可以从 rootfs 重新读取。

## 文件修改一致性

write/truncate 扫描仍存在的地址空间，撤销匹配的只读文件 PTE，再失效 cache。
下一次访问重新 fault 并观察新内容。可写 private 映射保持进程私有，不因文件
后续改变而被覆盖，也不回写文件。

进程槽中的 Zombie 已经销毁地址空间但尚未被父进程收集。失效扫描显式跳过
`root_physical_address == 0` 的 Zombie，避免把正常生命周期误报为损坏。

## 启动布局扩容

Kernel payload 增长后超过历史 1 MiB 暂存窗口。v1.9 建立
`tools/os_tools/boot_layout.py` 作为 Python 启动布局权威，并同步汇编/C++：

- Stage 1 Kernel staging：`0x03600000..0x03E00000`，8 MiB；
- Kernel 可加载物理末端不得越过 `0x03600000`；
- rootfs v2 从 LBA 32768（16 MiB）开始；
- 历史 legacy-fs 测试区域仍保留 LBA 2048，二者不混用。

新工具测试同时扫描 NASM、C++ 和 Python 常量，阻止打包时再次出现各层边界
不同步。

## Ring 3 端到端证据

`/bin/memory_probe` 在匿名 VM 与 heap 验收后继续：

1. 创建并分块写入 4096 字节 `/v1_9_map.bin`；
2. 关闭 fd 后读取 3000 字节 private 映射，验证文件尾之后清零；
3. 建立两个只读 shared 映射，触发一次 cache miss 和至少一次 hit；
4. 关闭原 fd，证明后备独立存活；
5. 重新写文件，证明旧 PTE 被撤销且下次访问看到新字节；
6. 拒绝 writable shared；
7. 建立 writable private，修改映射后重新读文件仍是原值；
8. 撤销全部映射并核对统计与页表回收。

完整通过后只输出：

```text
[OS][USER][VM] FILE_MAPPING_CACHE_VERIFIED
```

任一失败输出具名 `[OS][USER][VM][FAIL] ...`，成功 QEMU 将整个失败前缀列为
禁止标记。

## 日志

高频事件只在累计计数达到二次幂且本次确实变化时输出：

```text
[OS][KERNEL][VM] FILE_FAULT_COUNT=0x...
[OS][KERNEL][VM] PAGE_CACHE_HIT_COUNT=0x...
[OS][KERNEL][VM] PAGE_CACHE_INVALIDATION_COUNT=0x...
[OS][KERNEL][IO] DESCRIPTOR_READ_BLOCK_COUNT=0x...
```

宿主仍为每行增加 `[QEMU][T+...ms]`，来宾 PIT 提供自身单调时间。QMP 键盘输入
在第一个 descriptor read block 后注入，证明 Shell 已实际进入阻塞读取。

## 测试证据

当前构建图注册 137 项顶层 CTest。新增或扩展证据：

| 层次 | 证据 |
| --- | --- |
| 单元 | FilePageCache、FileBacking、file VMA、VFS random access/identity、ELF 大窗口 |
| 集成 | 两地址空间共享 cache frame 后独立 unmap；fd-close 后后备生命周期 |
| 随机 | FilePageCache 100000 步；VMA 100000 步含文件 offset/split/merge |
| 工具 | 启动暂存范围/rootfs LBA 跨 NASM、C++、Python 同步 |
| Ring 3 | partial tail、shared hit、invalidation、private no-writeback、完整回收 |
| QEMU | 64 MiB、256 MiB、64 GiB 同一 PID1 工作负载全部通过 |
| 容量 | 64 GiB 512 个内核栈、2048 个映射页生命周期闭合 |

完整 CTest 首轮发现并修复两项真实回归：rootfs 移位后稀疏测试设备仍按旧容量，
以及 ELF 工具仍冻结 512 页。修复后受影响测试通过；发布闭环再次运行完整
`verify`。发布验证又捕获并修复了 Kernel 已切换 v1.9、但 PID1 参数/环境和
Shell banner 仍断言 v1.8 的版本契约遗漏。最终 `python3 tools/os.py verify`
在 244.84 秒内通过 137/137 项顶层 CTest，失败数为零。

## 阶段边界

v1.9 没有宣称：

- writable `MAP_SHARED`、dirty page、writeback 或 `msync`；
- fork、COW、匿名页共享引用或 swap；
- `mprotect`、`mremap`、共享匿名映射或 ASLR；
- SMP 下把磁盘 I/O 移出 cache 全局锁；
- readahead、madvise、huge page 或动态链接。

下一阶段 v1.10 在已经稳定的 VMA/PTE/FileBacking/CachePage 分层上实现 fork
与 COW。
