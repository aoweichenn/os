# v0.8：用户边界、用户 ELF 与系统调用

## 阶段目标

本阶段让项目第一次执行硬件隔离的 Ring 3 代码。用户程序不再是“约定上不能
碰内核”的普通函数，而是受 GDT 特权级、页表 U/S 权限、TSS 栈切换和 IDT
门共同约束的执行主体。

QEMU 仍只模拟 x86-64 CPU、内存和设备。用户 ELF 生成、验证、装载、
`IRETQ` 降权、`INT 0x80` 入口、指针复制、退出恢复与异常隔离均由项目代码
实现。

## 已实现能力

### 严格用户 ELF64

- 新增独立 `abi` 与 `user` 模块，用户程序采用 freestanding C++20 与
  NASM Intel 语法，不链接宿主标准库。
- LLD 生成链接基址为 `0x40000000` 的 `ET_EXEC` AMD64 ELF64。
- 内核只接受最多八个 `PT_LOAD` 和 32 个映射页，验证标识、机器、版本、
  头大小、表范围、文件范围、虚拟范围、4 KiB 对齐、段重叠、W^X 与入口。
- 三个测试程序以原始 ELF 文件嵌入 Kernel 只读段；内核解析 ELF，而不是
  直接跳转编译期已知的宿主函数地址。
- 独立 Python 审计器按另一份实现检查真实用户 ELF，降低生产解析器与测试
  共享同一个错误的风险。

### 用户地址空间

- 用户低半地址从 `0x10000` 开始，排除零页附近的低地址。
- 代码页映射 RX，数据页映射 RW/NX；中间页表项同样设置 U/S。
- 用户栈位于 `0x00007FFFFFFEB000..0x00007FFFFFFEFFFF`：底部
  `0x00007FFFFFFEA000` 为未映射 guard，随后四个 RW/NX 页，栈顶为
  `0x00007FFFFFFF0000`。
- ELF 段不能与用户栈和 guard 区相交。
- 任何分配或映射失败都会逆序回滚已经建立的用户页。

### 特权切换

- GDT 现含 Ring 0 代码/数据、Ring 3 数据/代码和 64 位 TSS。
- TSS.RSP0 改用独立 16 KiB 特权转换栈，并由第四个内核 guard page 保护。
- `OsKernelEnterUserMode` 保存原内核调用链和非易失寄存器，构造完整
  `SS:RSP:RFLAGS:CS:RIP` 后执行 `IRETQ`。
- 系统调用与用户异常结束时，`OsKernelReturnFromUserMode` 丢弃转换栈内容，
  恢复原内核 RSP、段寄存器、寄存器和 RFLAGS，再返回 C++ 调用者。

### 系统调用与异常隔离

- IDT `0x80` 是 present、DPL3 的 interrupt gate；其余内核门的权限不被
  放宽。
- ABI 使用 `RAX/RDI/RSI`，当前实现 `WriteLog` 与 `ExitProcess`。
- `WriteLog` 最多接收 160 字节；错误指针、未知编号、过长写入和设备失败
  都有稳定的 `int64_t` 错误值。
- 入口校验当前用户生命周期、CPL、向量、CS/SS、RIP、RSP 及栈叶页权限。
- Ring 3 `#UD` 与 `#PF` 只终止用户执行；相同异常来自 Ring 0 时仍 panic。

## 目标机验收

正常用户程序依次：

1. 传入未映射指针并确认内核拒绝。
2. 调用未知系统调用编号并确认内核拒绝。
3. 输出 `[OS][USER] HELLO_FROM_RING3`。
4. 以退出码 0 结束。

目标日志证明入口为 `0x40000000`、用户栈已映射、共发生六次系统调用、控制权
已回到原内核调用链，之后硬件 IRQ 和 `READY` 仍然可达。

两个隔离镜像分别执行：

- `UD2`：得到用户异常向量 6、错误码 0，无 `PANIC`，内核继续到 `READY`。
- 访问 `0x30000000`：得到向量 14、错误码 `0x4`
  （not-present、read、user）和同值 CR2，无 `PANIC`，内核继续到
  `READY`。

非法 ELF 镜像把用户文件截断为 63 字节。内核报告验证状态 2，在设备初始化和
Ring 3 进入前停止该启动路径。

## 测试证据

完整回归为 55 项 CTest，全部通过：

- 用户 ELF 单元测试覆盖 20 类有效与非法布局。
- C++ 固定种子随机测试验证 16,384 条用户地址范围性质。
- Python 固定种子随机测试破坏 ELF 头、程序头、范围、权限和入口。
- 边界集成测试核对扩展异常帧、四页栈与 guard、用户地址范围和 ABI。
- 三个真实用户 ELF 分别经过独立宿主审计。
- 正常、用户 `#UD`、用户 `#PF`、非法 ELF 四条 QEMU 路径从复位向量执行。
- v0.0..v0.7 的启动、设备、内存、异常和 22 条失败路径同时回归。

## 已知限制与下一阶段

当前只有单个同步用户执行单元；所有用户程序共享当前页表根，执行结束后尚未
回收页，也没有 PID、调度队列或等待状态。`WriteLog` 的用户文本只用于教学
观测，不能视为可信内核日志。

下一阶段 v0.9 将建立进程控制块、独立内核栈与用户地址空间生命周期、上下文
切换、PIT 驱动的抢占以及退出后的资源回收。开始调度前必须先定义可测试的进程
状态机和切换 ABI。
