# v1.5：VFS、挂载命名空间、memfs 与旧文件系统适配

## 阶段结论

v1.5 已把路径、挂载、底层文件系统和一次打开实例分离。Shell 和
`FileDescription` 不再直接操作旧 `FileSystemHandle`；所有普通文件和目录
访问都经过同一条 VFS 路径：

```text
Process FsContext(root, cwd)
  -> VFS name walk
  -> Path(Mount, Vnode)
  -> Superblock BackendOperations
  -> legacy-fs 或 memfs

fd -> FileTable -> FileDescription -> OpenFile(Path, offset)
```

启动磁盘仍使用原有 v1.0 格式作为根文件系统，`/tmp` 挂载完整 memfs。这样
既保留旧磁盘与损坏拒绝回归，又能用第二个真正后端证明 VFS 不是对旧 inode
接口的改名包装。

## 已完成能力

### VFS 对象与后端契约

- `Vnode` 以 Superblock、64 位 identifier、generation 和类型识别对象；
- `Path` 同时保存 mount identifier 与 vnode，避免跨文件系统身份混淆；
- `Superblock` 保存后端种类、根 vnode、只读标志、名称上限和操作表；
- `Mount` 保存父挂载、父文件系统中的挂载点与子 Superblock；
- `FsContext` 为每个 Process 保存独立 root/cwd；
- `OpenFile` 保存 Path、共享偏移、读写模式和打开状态；
- 后端操作统一覆盖 lookup/create/parent/read/write/truncate/readdir/
  get-name/sync/validate/resource-usage；
- VFS 和两个后端都提供可重新计算的一致性检查与有界统计。

根 Mount 的 identifier 固定为 0，默认挂载表容量为 64。当前拓扑在用户调度
开始前一次建立，运行期只读；v1.5 不伪造动态 unmount 或跨 namespace 传播。

### 路径语义

当前路径解析完整支持：

- 绝对路径和相对路径；
- 重复 `/`；
- `.` 与 `..`；
- 到达进程 root 后的钳制；
- 进入子挂载和从子挂载根返回父目录；
- 尾部 `/` 的“最终对象必须为目录”语义；
- 从对象父链重建 `getcwd`，不缓存易失真的路径字符串。

公共路径上限为 4096 字节，组件上限为 255 字节；旧格式的 40 字节名称限制
只保留在 legacy Superblock。空路径、非法控制字符、过长路径、过长组件、
非目录中间节点、挂载环和容量耗尽都有不同状态，不发生静默截断。

### 完整 memfs

memfs 不是专为某条测试硬编码的目录表。它实现：

- 动态目录和规则文件节点；
- 稳定的非零 64 位 identifier/generation；
- lookup、create、parent、read/write、truncate、readdir 和 get-name；
- 文件数据从 64 字节开始的有界几何增长；
- 对小于 64 字节的实例上限正确收敛；
- 稀疏写空洞和 truncate 扩展区域清零；
- 确定性目录枚举游标；
- 节点、目录、文件、数据容量、读写字节和增长次数统计；
- KernelHeap consumed/requested/allocation 的精确所有权统计；
- 父链、名称唯一性、容量、数据指针、资源总量和循环的完整校验；
- Destroy 后全部节点与数据分配归还。

内核实例把 memfs 挂载在 `/tmp`，节点上限 128，单文件上限 64 KiB。该数值
是当前启动工作负载配置，不是 VFS 接口上限。

### legacy-fs 适配

旧文件系统的磁盘格式没有改变。适配器提供：

- inode 到 vnode 的身份映射；
- 单组件 lookup 与基础文件/目录创建；
- 文件读写、零长度 truncate 与目录枚举；
- parent/get-name，供 `..` 和 `getcwd` 使用；
- sync、consistency check 与状态转换；
- 旧 40 字节名称上限和原有事务语义。

全零新镜像仍可格式化；未知或损坏的非零磁盘仍被拒绝，不会因 VFS 初始化
失败而自动重格式化。持久化测试继续在同一可写 QEMU 镜像上完成写入、重启和
读取。

### FileDescription 与 Process 迁移

v1.4 的对象/fd 所有权保持不变，但文件载荷已从：

```text
FileSystem* + FileSystemHandle
```

迁移为：

```text
Vfs* + OpenFile
```

因此 duplicate 仍共享同一打开偏移，独立 open 仍拥有独立偏移，最后一个
引用释放时只关闭一次 VFS OpenFile。控制台和 Pipe 不受路径层影响。

每个 `ProcessRuntimeProcess` 现在持有自己的 `FsContext`。启动期已经准备的
Process 在 VFS 挂载完成后统一初始化；以后创建的 Process 也走相同路径。
当前 Shell 的 `cd` 只修改调用 Process 的 cwd。

### 用户 ABI 与 Shell

系统调用编号 29、30 新增：

- `ChangeDirectory(path, length)`；
- `GetWorkingDirectory(destination, capacity)`。

新增错误码：

- `-26`：路径超过 4096 字节；
- `-27`：组件超过后端名称上限；
- `-28`：路径或挂载循环；
- `-29`：只读文件系统。

ABI `DirectoryEntry` 名称容量提升为 255 字节，结构大小固定为 280 字节。
最后一个字节是显式 `reserved` 字段，内核写零后再复制给用户，避免把 C++
尾部填充泄露到 Ring 3。

Shell 新增 `cd <path>`，`pwd` 读取真实 cwd，提示符显示 `[os:<cwd>]$`，
无参数 `ls` 默认枚举 `.`。functional 输入同时操作 `/tmp` memfs 和根目录
legacy-fs。

## 路径与挂载示例

假设根文件系统中存在 `/tmp`，其上挂载 memfs：

```text
legacy root mount (id 0)
/
├── demo
└── tmp  <── mount point
          │
          └── memfs root mount (id 1)
              └── session
                  └── message
```

从 `/tmp/session` 解析不同路径时：

| 输入 | 起点与结果 |
| --- | --- |
| `message` | cwd 开始，得到 memfs 文件 |
| `./message` | 跳过 `.`，得到同一文件 |
| `../session/message` | 先到 memfs 根，再回到 session |
| `/tmp/session/message` | Process root 开始，进入挂载点 |
| `/tmp/..` | 从 memfs 根退出，得到 legacy `/` |
| `../../..` | 到 Process root 后保持在 root |

`getcwd` 从 memfs 的 `session` 取名，再在挂载根处改用 legacy 挂载点名
`tmp`，最终返回 `/tmp/session`。

## 锁与资源所有权

当前锁顺序和拓扑约束为：

```text
FileTable -> KernelObjectManager -> temporary reference
  -> release global locks
  -> FileDescription operation lock
  -> VFS read-only topology
  -> backend lock
  -> KernelHeap 或 block cache/ATA
```

mount 只在调度前发布；VFS 统计锁不包围后端调用；对象 finalizer 在
FileTable、KernelObjectManager 和对象操作锁之外调用 `Vfs::Close`。

memfs 是挂载后长期存在的内核资源。Process 最终资源快照会先读取 VFS 的
精确 heap/vnode 使用量，再只从 Process 对比项中扣除这些已登记的持久资源。
这不会屏蔽普通泄漏：frame、KVA、页表、KernelObject、FileDescription、
FileTable 分块或未登记 heap 分配只要残留，最终差异仍非零。

成功启动新增有界阶段日志：

```text
[OS][KERNEL] VFS_READY
[OS][KERNEL] MEMFS_MOUNTED=/tmp
[OS][KERNEL] VFS_MAX_PATH_BYTES=0x0000000000001000
[OS][KERNEL] VFS_MAX_NAME_BYTES=0x00000000000000FF
[OS][KERNEL] VFS_VALID
[OS][KERNEL] VFS_MOUNTS=...
[OS][KERNEL] VFS_PATH_RESOLUTIONS=...
[OS][KERNEL] VFS_FAILED_PATH_RESOLUTIONS=...
[OS][KERNEL] VFS_MOUNT_TRANSITIONS=...
[OS][KERNEL] MEMFS_ACTIVE_NODES=...
[OS][KERNEL] MEMFS_DATA_CAPACITY_BYTES=...
```

统计只在 VFS 建立和用户任务结束两个阶段输出，不在每个路径组件或每次
字节 I/O 中刷屏。来宾继续打印 PIT/单调时间；QEMU 运行器为宿主侧每条日志
增加 `[QEMU][T+...]` 相对时间并使用分阶段硬超时，因此异常路径不会无限
等待。

## 测试证据

v1.5 完整集合为 110 项 CTest，在 v1.4 的 107 项基础上新增：

| 测试 | 层次 | 核心证据 |
| --- | --- | --- |
| `os_kernel_vfs_unit_tests` | 单元 | 路径、边界、尾斜杠、I/O、mount、getcwd、环与容量 |
| `os_kernel_vfs_backend_contract_integration_tests` | 集成 | memfs/legacy 同契约、旧格式重新挂载、堆归还 |
| `os_kernel_vfs_namespace_randomized_tests` | 随机 | 固定种子十万步独立目录树模型 |

随机测试执行 100000 步，每一步分别选择创建、解析、切换 cwd、返回父目录、
文件 I/O、目录枚举或缺失路径，并比较独立 `std::vector` 模型；最终还有一次
完整状态断言，共 100001 项逐步证据。

整机验证继续覆盖：

- 64 MiB 历史启动；
- 256 MiB functional Shell、IPC、对象/fd、legacy-fs 和 `/tmp` memfs；
- 64 GiB capacity 内存规格；
- 文件系统跨 QEMU 实例持久化和损坏拒绝；
- 用户非法指令隔离、用户页故障隔离和非法 ELF 启动拒绝；
- 缺失 CPU 必需能力和既有 Stage 1/Kernel 故障路径；
- 固件、Stage 1、Kernel、七个用户 ELF、命名、学习图和教材门禁。

- 项目版本提升为 `1.5.0`，Shell banner 同步为 v1.5；

- 生产目标有效代码 28706 行，其中 C++ 26273 行、NASM 2433 行；

- QEMU marker 增加 VFS/memfs 阶段和 Shell `cd` 证明。

## 阶段边界

v1.5 没有宣称已经具备：

- rootfs v2、间接块、64 MiB 单文件或通用大磁盘格式；
- unlink、rename、非零 truncate、stat 或符号链接；
- dentry/inode cache、动态 unmount、bind mount 或 mount namespace 复制；
- Unix 权限、uid/gid、时间戳、设备节点或 `/proc`；
- 从磁盘 exec、PID1、fork 时 FsContext 复制；
- SMP 下的 RCU 路径查找或并发挂载拓扑变更。

这些能力分别属于 v1.6 及以后阶段。v1.5 的完成标准是先让路径、挂载、
后端和打开实例边界稳定，并用两个后端、独立模型和真实 QEMU 工作负载证明。
