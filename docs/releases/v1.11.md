# v1.11：Unix I/O、外部 Shell 与核心工具

## 阶段结论

v1.11 已完成从“Shell 内函数分派”到“独立 ELF 进程图”的迁移：

```text
Shell execution plan
  → dynamic 64 KiB pipes
  → fork
  → dup2 / redirection
  → exec rootfs tools
  → wait and reverse-order cleanup
```

QEMU 仍只模拟 x86-64 CPU、内存、串口、PIC/PIT、PS/2 和 IDE 等硬件。pipe、
描述符、Shell、工具、进程和失败回收均由项目代码实现。

## ABI

新增系统调用：

| 编号 | 名称 | 语义 |
| ---: | --- | --- |
| 45 | `CreatePipe` | 原子返回 16 字节 reader/writer fd pair |
| 46 | `DuplicateDescriptorTo` | 精确复制到指定 fd，必要时替换旧对象 |

新增 `PIPE_LIMIT_EXCEEDED=-43`。所有 ABI 字段使用 `uint64_t`/`int64_t`；
`PipeDescriptorPair` 由 `static_assert` 固定为 16 字节。

## 动态管道

- 每条容量 64 KiB；
- 4 KiB 页按首次写入申请，最多 16 页；
- 支持跨页环形短读/短写；
- 多页申请失败回滚本次新增页；
- reader 最后引用关闭产生 broken pipe；
- writer 最后引用关闭且缓冲排空产生 EOF；
- 两端关闭后释放数据页和 PipeManager slot。

同一镜像按 RAM 选择 8/128/1024 条容量。启动自检真实耗尽配置容量、验证下一
条被拒绝，再释放全部 slot。结束遥测包含：

```text
DYNAMIC_PIPE_CAPACITY
DYNAMIC_PIPE_ACTIVE
DYNAMIC_PIPE_PEAK_ACTIVE
DYNAMIC_PIPE_CREATIONS
DYNAMIC_PIPE_RELEASES
DYNAMIC_PIPE_CAPACITY_REJECTIONS
```

正常结束必须 `ACTIVE=0` 且 `CREATIONS=RELEASES`。

## 描述符与对象生命周期

`FileTable::DuplicateTo` 支持：

- source 无效时 destination 不变；
- source==destination 成功；
- destination 已打开时原子替换；
- fd flags 独立设置；
- 旧 KernelObject handle 在表锁外释放；
- 提交前引用获取失败保持 destination 不变，提交后 finalizer 失败以
  release failure 显式上报而不伪回滚；
- replacement 和 duplicate-to 独立统计。

Pipe reader/writer 作为 FileDescription payload 存在。duplicate 和 fork
共享 FileDescription 强引用；只有最后引用 finalizer 才关闭逻辑端点并通知
PipeManager。

functional FileTable hard limit 从 256 提升为 512，使 128 条 pipe 的 256 个
端点和标准/临时 fd 能同时存在。bootstrap 保持 64，capacity 保持 4096。

## Shell

Shell 解析与执行分离。执行计划支持：

- 512 字节命令行；
- 最多 16 个 stage；
- 每 stage 最多 8 个参数；
- 单双引号、反斜杠；
- 有无空格的 `|`、`<`、`>`；
- 完整语法错误分类和零副作用失败。

执行计划由 `static_assert` 保持在单个 4 KiB 用户栈页内，避免按需栈增长下的
跨页 stack jump。

Shell 只保留 `cd` 和 `exit`。普通命令映射到 `/bin/<command>`；含 `/` 的
命令按给定路径执行。每条管线先创建全部 Pipe，再 fork 全部 stage，child
完成 dup2/重定向/关闭后 exec，parent 关闭临时 fd 并等待所有 child。

任一 pipe/fork/dup/open/exec 失败都会关闭临时 fd并回收已创建 child，不留下
Zombie 或活跃 Pipe。

## 核心工具

rootfs 新增十九个外部路径，均由自研 freestanding C++20 多调用 ELF 提供：

```text
/bin/help      /bin/echo      /bin/cat       /bin/wc
/bin/head      /bin/tee       /bin/true      /bin/false
/bin/pwd       /bin/ls        /bin/stat      /bin/mkdir
/bin/write     /bin/touch     /bin/rm        /bin/rmdir
/bin/mv        /bin/truncate  /bin/sync
```

工具不依赖 libc、libstdc++ 或宿主运行时。每个路径都从 rootfs 读取并通过项目
ELF 装载器 exec；Kernel 与 Shell 不包含工具实现。

## QEMU 端到端

64 MiB bootstrap 继续执行基础命令集。256 MiB functional 在此基础上执行：

```text
echo redirected > /tmp/redirected
cat < /tmp/redirected
touch /tmp/touched
true
false
rm /tmp/touched
echo pipeline | 12 × cat | tee /tmp/pipeline | head | wc
rm /tmp/redirected
```

管线共 16 stage、15 条 Pipe。成功标记：

```text
[OS][USER][SHELL] REDIRECTION_VERIFIED
[OS][USER][SHELL] PIPELINE_16_VERIFIED
```

功能工作负载最终：

- Process registered/exited/collected：88；
- wait success：87；
- 动态 Pipe 自检 128 条，运行期管线 15 条；
- Pipe creations/releases：143/143；
- active Pipe 与 Zombie：0；
- runtime、smoke、process resource validation：全部 1。

QEMU 键盘注入器新增 `<`、`>`、`|` 的 Shift 组合键映射，并有 Python 单元
测试，确保系统测试真实经过 PS/2 Set 1 解码而不是旁路输入。

## 实现中捕获的问题

整机闭环发现并修复：

1. 初版 Shell 执行计划栈帧超过一页，函数序言跨过未提交用户栈页；
2. `WaitProcess` 成功返回 PID，Shell 曾错误按零返回判断；
3. QEMU 键盘工具最初没有 `|`、`<`、`>` 的 Shift 键映射；
4. 外部命令使正常进程数从 45 增至 bootstrap 65、functional 88，旧固定
   运行态计数会把正确回收误报为失败；
5. Pipe 页释放失败路径曾先清除地址，现保留未归还页的可追踪所有权。
6. 功能档扩展到 88 个进程和 16 级管道后，旧 15 秒宿主预算在共享负载下会
   误杀仍持续前进的 QEMU；现按 64 MiB/256 MiB/64 GiB 分为
   15/30/75 秒，外层 CTest 仍保持独立硬上界。

这些问题说明解析器宿主测试不能替代真实用户栈、键盘、调度与资源账本。

## 阶段边界

v1.11 不宣称：

- 用户 Thread、TLS 或 futex；
- 后台任务、job control、进程组或信号；
- PATH 搜索、通配符、变量/命令展开、追加或错误重定向；
- socket、poll/select/epoll；
- writable `MAP_SHARED` 或 `msync`；
- SMP 与跨核 TLB shootdown。

下一阶段 v1.12 在当前 Process/FileTable/WaitQueue 边界上开放用户 Thread、
FS-base TLS 与 private futex。
