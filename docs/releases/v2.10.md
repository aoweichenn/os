# v2.10 异步块 I/O 与可等待页缓存

状态：前四增量与第五增量 5a/5b/5c 已完成，工程候选，尚未发布

日期：2026-08-23

## 目标

把现有控制器请求模型接入设备无关的异步提交、完成和等待路径，再让同页 cache miss、
预读、writeback 与 reclaim 使用同一可睡眠 I/O 生命周期。rootfs v4、ABI 2.4.0、ATA
回退和 4 GiB 手机参考机保持不变。

## 增量顺序

1. `BlockRequestQueue` 有序 completion FIFO 与 owner 交付（已完成）；
2. 异步 `BlockDevice` adapter，统一 ATA/NVMe submit/cancel/timeout/completion（已完成）；
3. `BlockIo` WaitQueue 与生产 rootfs/swap 迁移：3a 协调器/Worker/Kernel 等待、3b 栈式
   User Kernel 续体、RuntimeMutex 与生产迁移均已完成；
4. FilePageCache Loading waiter、同页 miss 合并与失败广播（已完成）；
5. 顺序读预读窗口、命中/浪费反馈与内存压力收缩（5a 纯策略、5b 生产执行、5c 取消反馈已完成）；
6. 并发 writeback/reclaim、取消、EIO/timeout 和 ATA/NVMe 持久化矩阵。

## 第一增量范围

- Completed 请求按解析发生顺序进入独立有界 FIFO；
- `BlockCompletion` 冻结 request id、操作、范围、owner 和终态结果；
- `TakeCompletion` 原子交付并回收，空队列明确返回 unavailable；
- 直接 Reap 可以摘除 FIFO 中间项，其余顺序保持不变；
- ATA IRQ/timeout 改用统一完成出口；
- 单元、集成和十万步随机 oracle 同时覆盖 IRQ、timeout、cancel、直接回收与完成交付；
- 不迁移 rootfs，不增加系统调用，不改变磁盘格式。

## 当前边界

- 用户 rootfs、journal 和 swap 生产调用已经由 `BlockIoDevice` 等待异步 ATA/NVMe
  completion；early boot 和受限 Kernel worker 仍可同步回退；
- FilePageCache Loading 冲突在合格 User Thread 上进入 per-load WaitQueue；early boot、
  受限 Kernel worker 和调度停止期仍明确返回 Busy；
- BlockIo bottom-half/WaitQueue、生产迁移、同页 miss 合并、异步顺序预读、generation 取消
  和反馈闭环已完成；设备硬取消与并发回收错误矩阵仍不在本次完成声明内。

## 第二增量范围

- 新增无 virtual/RTTI/分配的 `AsynchronousBlockDevice` 静态适配层；
- ATA 系统调用 submit、timer timeout、IRQ14 completion 通过公共接口；
- NVMe namespace 使用 64 位 request id 映射 16 位 CID，完成按 CQ 顺序交付；
- NVMe IRQ 不复制 Read 数据，非 IRQ TakeCompletion 回拷 DMA 页并释放 slot；
- timeout reset 保留已有完成，并把最早到期/其余未完成分别交付 TimedOut/DeviceError；
- cancel 冻结 best-effort 语义，不伪造已签发硬件请求被撤销；
- 不迁移 rootfs、journal、swap，不改变 ABI 2.4.0 或 rootfs v4。

## 第三增量基础范围

- 新增 64 槽 `BlockIoCoordinator`，用 owner、request id 和 generation ticket 表达
  Registered/Waiting/Completed/Abandoned 生命周期；
- completion-before-wait 直接取结果，wait-before-completion 精确唤醒，迟到 abandoned
  completion 只回收身份；
- 常驻 completion Kernel Thread 在非 IRQ 上消费已登记设备，IRQ/timer 只增加通知
  generation；worker 睡前复核 generation，关闭扫描与阻塞间的丢通知窗口；
- `AwaitRuntimeBlockIo` 只允许 Kernel Thread 使用；请求接受后的协议损坏采用 fail-stop，
  防止设备继续访问已经展开的 caller buffer；
- secondary ATA Flush probe 真实通过 IRQ15 完成，primary root 与 secondary swap 状态机分离；
- rootfs/swap `BlockIoDevice` 保持 async 开关关闭，生产操作统计必须为零；
- 用户地址空间销毁记录精确阶段、映射状态、文件后备 close 状态，失败不再只报告笼统
  `AddressSpaceFailure`；
- 不改变 rootfs v4、ABI 2.4.0、磁盘容量或 4 GiB 主规格。

## 第三增量生产迁移范围

- User Thread 可在自己的 Kernel stack 上挂起并恢复深层 C++ I/O 调用，续体保存 FX、
  原生系统调用、双 GS 基址和 CR3 模式；
- `RuntimeMutex` 替换 rootfs、VFS resolution、BlockCache、文件后备、swap 与打开文件
  payload 的运行期 spin lock，竞争时通过 WaitQueue 睡眠；
- User Thread 先以 `Initializing` 完成跨模块元数据提交，再原子进入 `Ready`；
- root/swap `BlockIoDevice` 打开异步等待，ATA PIO Write 按 DRQ 传输、最终 IRQ completion
  的真实协议运行；
- 生产 root/swap NVMe controller 在 READY/事件循环保持活动；独立 probe 与 EIO/timeout
  recovery 继续验证 shutdown 资源回收；
- 进程退出先完成所有可阻塞清理并进入 Scheduler `Zombie`，随后才发布 ProcessTree 退出
  事件；Shell 退出前终止并收集全部作业成员；
- primary 验收要求 BlockIo registration/wait/completion 非零且相等、root async 非零；
  reclaim 换出 profile 另要求 swap async 非零；
- ABI 2.4.0、rootfs v4、4 GiB RAM、128 GiB 存储规格不变。

## 第四增量范围

- 新增固定容量 `FilePageLoadCoordinator`、per-thread waiter 和 per-load WaitQueue；
- owner 在 cache lock 内发布 Loading 并登记 load，冲突者在同一锁内登记后才允许睡眠；
- completion-before-wait 直接取结果，wait-before-completion 精确广播，generation 拒绝
  复用后的旧 token；
- 成功广播前按登记 waiter 数预留真实 page reference，waiter 醒来直接接管，owner 先释放
  也不能被 invalidate/reclaim 抢先淘汰；
- 失败先逆序撤销 entry/frame/address-space，再向所有同期 waiter 交付同一错误；
- 登记后的生产协议损坏 fail-stop，Loading 的 truncate/invalidate/writeback/reclaim 禁止
  规则保持不变；
- 不实现 readahead，不改变 ABI 2.4.0、rootfs v4、4 GiB RAM 或 128 GiB 存储规格。

## 第五增量 5a 范围

- 新增无分配 `FileReadaheadPolicy`，实例边界对应未来一个共享 FileDescription；
- 默认最大窗口 32 页，初始窗口和 4/2 倍增长规则对齐 Linux `file_ra_state` 核心语义；
- DemandHit、DemandMiss、PrefetchedHit 明确分型，伪造触发、随机访问和 EOF 都有确定行为；
- Balanced/BelowHigh/BelowLow/BelowMinimum 把有效上限收缩为全量、1/2、1/4、0；
- useful/wasted 反馈有界减半或恢复，已经发布的 generation 范围不被反馈改写；
- 本增量不接 FileDescription、WorkQueue、FilePageCache 或设备 I/O，不新增运行期日志；
- ABI 2.4.0、rootfs v4、4 GiB RAM 和 128 GiB 存储规格不变。

## 第五增量 5b 范围

- `FileReadaheadPolicy` 内嵌共享 FileDescription；duplicate/fork 共享，独立 open 隔离；
- VFS 缓存 hook 发布真实页范围、hit、miss 与 prefetched hit，同页内小 read 不伪造随机流；
- 新增 64 槽 `FileReadaheadRequestQueue`，任务持有 retained OpenFile、范围与 generation；
- 现有常驻 Kernel worker 用独立持久 WorkHandle 每次执行一个请求，退出前排空并关闭引用；
- FilePageCache 增加 Demand/Prefetch intent 和 one-shot prefetched 身份，首次 demand 消费为
  useful，失效、truncate、reclaim/trim 丢弃为 waste；
- 预读 Kernel worker 可成为 Loading owner 并睡眠等待生产 BlockIo，但不等待同页 owner；
- 缓存满或 BelowMinimum 时停止预测，队列满只拒绝预测，不驱逐 demand 页、不回滚 read；
- QEMU 只输出最终聚合，要求 schedule/enqueue/completion 守恒、loaded/useful/hit 非零，
  active/failure/final prefetched resident 为零；
- ABI 2.4.0、rootfs v4、4 GiB RAM 和 128 GiB 存储规格保持不变；generation 取消与反馈
  闭环由 5c 完成，完整并发 writeback/reclaim 矩阵留给第六增量。

## 第五增量 5c 范围

- 新增 4096 槽 `FileReadaheadFeedbackLedger`，stream token 使用 slot+generation；
- duplicate/fork 共享 stream，独立 open 隔离；Active/Retiring/task retain 阻止 close 后复用；
- cache page 保存 stream 和 policy generation，Demand 归因 useful，所有未消费删除归因 waste；
- producer 在 read/close 领取反馈，waste 大于 useful 时下一窗口按 5a 规则减半；
- request queue 支持 stream generation 和 file identity 过滤，queued 稳定摘除、running 每页
  检查取消，terminal 统计改为 completion+queued cancellation；
- random reset 取消旧 generation，BelowMinimum/close 取消全部，truncate 先取消同文件任务；
- close 后迟到反馈进入 stale，不访问已销毁策略，也不能命中复用 token；
- 不实现设备硬取消，不改变 ABI/rootfs/4 GiB/128 GiB 规格；完整并发 writeback/reclaim
  EIO/timeout 矩阵留给第六增量。
