# v0.11：固定布局文件系统与跨启动持久化

## 阶段目标

v0.11 不以“内存中写完马上读回”为完成标准，而是建立从 Ring 3 文件 API
到 ATA 持久介质的完整边界：磁盘格式必须可独立审计，空间所有权必须可证明，
多块修改中断后必须可检测，同一磁盘上的第二个全新 QEMU 实例必须读到旧数据。

## 完成内容

- 启动盘从 1 MiB 扩展为 2 MiB。前 1 MiB 固定属于启动链，文件系统使用
  LBA `2048..3071`，其后 1024 个扇区保留。镜像工具拒绝 Kernel 负载跨过
  LBA 2048。
- 实现 1024 块固定格式：superblock、inode bitmap、32 个 128 字节 inode、
  data bitmap 和 1013 个数据块。多字节字段全部显式 little-endian 编码。
- superblock 和每个已分配 inode 使用 IEEE CRC32；只有全零超级块允许首次
  格式化，非零未知格式和 CRC 错误一律拒绝。
- inode 1 为根目录，十个直接块给出 5120 字节显式文件上限；64 字节目录项
  支持最长 40 字节名称和绝对多级路径。
- 全盘一致性检查联合验证 bitmap、inode/目录语义、数据块唯一所有权与从根
  开始的有界可达性，拒绝孤儿、环、重复引用和非法目录名称。
- 实现八项固定容量 LRU 写回块缓存，提供命中、未命中、淘汰和设备 I/O 统计；
  默认日志只输出阶段汇总。
- ATA PIO 驱动增加单扇区 `WRITE SECTORS` 与 `FLUSH CACHE`，所有 BSY/DRQ
  轮询保持有界并保留明确失败状态。
- 修改操作采用 Dirty → 数据/元数据写回 → Clean 的提交协议。Dirty 只提供
  未完成事务检测，不假装具备日志恢复能力。
- 系统调用 ABI 增加 Open、Read、Write、Close、Mkdir 和 Sync，第三参数经
  RDX 传递；每个进程拥有四个普通文件句柄并在退出/异常时自动关闭。
- PID1 写入并同步 `/shared/payload.bin`，PID2 在管道 EOF 后重新打开并
  验证；内核最后再次同步、执行全盘一致性检查并独立读回。

## 关键工程发现

最初文件系统从 LBA 1024 开始。宿主内存设备测试全部通过，但真实 Kernel ELF
从 LBA 66 延伸到约 LBA 1054，第一次 QEMU 启动把 Kernel 尾部误当成
superblock。修复没有采用“在当前尾部后留一点余量”，而是冻结 1 MiB 启动
ABI，并让镜像生成器对最终产物执行越界拒绝。

这个故障证明：宿主模型可以验证算法，却不能替代最终镜像的所有者边界验证。
因此 v0.11 的系统证据同时覆盖宿主块设备、真实 ATA 端口和最终磁盘文件。

## 测试证据

- 格式单元测试覆盖 superblock、inode、目录项的往返、布局与 CRC 损坏。
- 生命周期集成测试覆盖格式化、嵌套目录、1300 字节跨块文件、重挂载、截断、
  孤儿 inode、非法名称和超级块损坏。
- 固定种子随机测试执行 128 轮随机 rewrite，每轮都以全新的文件系统与缓存
  对象重挂载，并与参考字节数组逐项比较。
- 正常 QEMU 路径证明 Ring 3 文件 ABI、ATA 写入/flush、进程统计、最终同步、
  全盘一致性和内核独立读回。
- 持久化测试对同一 snapshot-off 临时磁盘启动两个全新 QEMU 实例；第二次
  必须先恢复旧载荷。随后翻转超级块字节，第三次必须报告损坏，不能格式化、
  进入 Ring 3 或到达 `READY`。
- 完整回归共 68 项 CTest，原有复位、固件、长模式、ELF、异常、内存、设备、
  用户态、调度与 IPC 路径全部保留。

## 可观测性

QEMU 捕获器继续给每条串口行附加 `[QEMU][T+......ms]` 宿主单调时间。
来宾只在格式化/挂载、持久化恢复、同步、全盘一致性、最终载荷验证和损坏停止
这些冷路径输出稳定标记；块缓存命中、每扇区 I/O 和轮询迭代不刷串口。

## 已知限制与下一阶段

当前没有删除、rename、硬链接、权限、时间戳、间接块、稀疏文件或日志重放；
ATA 仍是单扇区轮询 PIO，文件系统全局锁使操作串行。管道端点尚未并入普通
文件描述符。

下一阶段 v1.0 将先定义通用打开对象与引用生命周期，再把文件、管道和控制台
统一到用户 I/O 接口，最终实现 Shell、基础命令和完整系统回归。
