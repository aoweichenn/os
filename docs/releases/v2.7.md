# v2.7 通用块设备层与自研 NVMe

状态：NVMe rootfs/swap 迁移、ATA 回退与持久化完成，工程候选，未公开发布

日期：2026-08-20

## 目标

在不扩展硬件驱动数量的前提下，把 rootfs、swap 和后续统一页缓存放到设备无关
块层之上；保留 ATA PIO 启动/回退路径，自行实现一个面向 QEMU NVMe 1.4 的最小
PCI/NVMe 运行驱动。

## 第一增量

- `BlockDevice` 从文件系统缓存模块上移到设备模块；
- 静态函数表和类型化 adapter 取代 C++ virtual，不引入 RTTI 或纯虚运行时；
- 驱动声明逻辑块大小、块数、最大传输、最大 outstanding、写与 Flush 能力；
- 请求记录逻辑块数，队列拒绝非整块、越界、能力和乘法溢出；
- FIFO 签发支持设备深度，完成允许乱序；超时按 deadline/identifier 确定选择；
- ATA 适配为 512 字节、单块、单飞几何，既有硬件行为保持不变；
- 单元、集成和十万步随机模型升级为通用多深度块请求证据。

## 第二增量

- `pci_model` 编码/解码 mechanism #1 BDF 与 256 字节 configuration space DWORD；
- 解码 vendor/device、revision 与 01/08/02 NVMe class code；
- 解析 32/64 位 memory BAR、预取属性和 BAR aperture 探测掩码；
- `pci` 以 irq-save 锁保护 `0xCF8/0xCFC` 成对 32 位访问；
- `port_io` 增加自研 32 位 IN/OUT；
- 单元测试覆盖非法 BDF/偏移/class/BAR，固定种子随机测试覆盖 4096 组地址往返
  和 32/64 位二次幂 BAR 尺寸。

## 第三增量

- `pci` 扫描完整 BDF 空间并只接受一个 `01/08/02` 控制器；configuration
  address/data 事务由 irq-save lock 覆盖；
- BAR0 探测先保存 command/BAR，关闭 memory decode 与 bus master，读取 aperture，
  在 `0xF8000000..0xFC000000` 窗口内按尺寸对齐分配，编程后回读验证；
- 内核 KVA 为 MMIO 建立 supervisor、RW、NX、cache-disabled 映射，失败回滚已经
  映射的页；正常退出解除映射并归还 KVA；
- 自研 NVMe 驱动解析 CAP/VS，执行 CC.EN/CSTS.RDY 有界状态机，分配物理连续单页
  admin SQ、CQ 与 Identify 缓冲，编程 AQA/ASQ/ACQ；
- admin queue 深度为 2；Identify Controller 与 Namespace 1 使用 PRP1、CID、doorbell、
  completion phase/CID/status 完成，随后关闭控制器并恢复 DMA 页、MMIO 与原 PCI BAR；
- 第三增量当时的 `os_qemu_nvme_identify` 给 QEMU 挂独立 128 GiB raw namespace，
  真实识别 NVMe 1.4.0、128 GiB 容量和 512 字节逻辑块；第四增量已由
  `os_qemu_nvme_io` 替代该测试；
- CAP/CC/AQA、Identify command/data、CQE 与十万步 SQ/CQ wrap/phase 纯模型加入门禁。

## 第四增量

以下是第四增量当时的单页同步边界，第五增量已在其上扩展 PRP/MSI-X：

- admin queue 先用 Set Features `07h` 请求一对 I/O queue，再按规范顺序创建 CQ1
  和 SQ1；队列深度取 `min(CAP.MQES, 64)`，CQ 关闭中断并使用有界轮询；
- 新增两页 I/O SQ/CQ 和一页数据 bounce buffer，合计六页 DMA 资源；doorbell 使用
  QID 1 对应的索引 2/3，completion 同时校验 phase、CID、SQID 和 status；
- `NvmeController` 通过静态 `BlockDeviceAdapter` 暴露 namespace 1；几何由 Identify
  和 MDTS 推导，当前 512 字节逻辑块、单请求最多 8 块、单 outstanding、可写且
  支持 Flush；
- Read `02h`、Write `01h` 和 Flush `00h` 使用项目自建 SQE/CQE；Read/Write 编码
  64 位 SLBA、零基 NLB 和单页 PRP1，Flush 不携带数据指针；
- QEMU 在 `0x0FFFFFF8` 起的最后 8 个 LBA 执行 4 KiB Write、Flush、Read，读回
  校验和为 `0x4C16736F7C9CA383`；测试使用 snapshot，不修改源 namespace 镜像；
- 命令超时或异常完成立即冻结后续 I/O，控制器 reset 后才释放 DMA；同步路径用
  拒绝重入保护唯一 bounce page，不虚报多 outstanding 能力；
- 纯模型增加 Set Features、Create CQ/SQ、Read/Write/Flush、几何边界及十万组
  64 位 SLBA/NLB 随机编码证据，系统测试升级为 `os_qemu_nvme_io`。

## 第五增量

- 解析 PCI capability 链和 MSI-X capability `11h`，校验 table size、table/PBA
  BIR 与 offset；QEMU table 位于 BAR0，提供 65 个 entry；
- IDT 新增向量 `0x50`，MSI-X entry 0 指向 BSP LAPIC，统一硬件中断帧分发 NVMe
  CQ，处理后写 LAPIC EOI；admin 阶段保持 function/vector mask，CQ1/SQ1 创建完成
  后才解除屏蔽；
- 每个请求槽拥有 16 个独立数据页和一页 PRP list；一页使用 PRP1、两页直接使用
  PRP2，三页以上由 PRP2 指向 packed list，单请求提升到 64 KiB/128 个 512 B 块；
- 四个槽位可同时处于 Submitted，CQ 按 phase 批量 drain，再按 CID/SQID 找回槽位，
  不依赖提交顺序；几何最大 outstanding 从 1 提升到 4；
- 正常 QEMU 在 LBA `0x0FFFFE00` 起并发四笔 64 KiB Write，Flush 后并发四笔 Read，
  产生 6 次 MSI-X，峰值 outstanding 为 4，校验和为 `0xD524EC00224D0383`；
- QEMU blkdebug 对临时 sparse 副本注入一次 `write_aio` EIO；驱动观察错误 completion，
  冻结提交、mask MSI-X、清 CC.EN、等待 RDY=0、重建 admin/I/O queue，并回收资源；
- 专用测试内核只在首批 Write 抑制 SQ doorbell；经过 CAP.TO 后记录一次 timeout，
  执行同一 reset 状态机。正常内核不包含已武装的注入状态；
- `os_qemu_nvme_io_error_recovery` 和 `os_qemu_nvme_io_timeout_recovery` 分别要求
  reset/error 或 reset/timeout 计数为 1，资源回收完成且禁止 `NVME_IO_READY`。

## 第六增量

- `NvmeNamespaceDevice` 把同一控制器的 Namespace 1/2 暴露为两个独立
  `BlockDevice`；rootfs 使用 NSID 1，swap 使用 NSID 2，共享 I/O queue、MSI-X
  和四个 CID 槽位；
- Kernel 建立常驻 NVMe storage runtime，文件系统和 swap 生命周期结束后才 mask
  MSI-X、关闭控制器并回收 73 个 DMA 页、MMIO/KVA 与 BAR；
- QEMU 双 namespace 使用显式 controller、`nvme-ns ... nsid=1/2`；root namespace
  复用 128 GiB rootfs 镜像语义，swap namespace 使用独立 28 GiB swap 镜像；
- 运行期选择 NVMe 时输出 `STORAGE_BACKEND=NVME`；设备缺失或可安全清理的初始化
  失败自动输出 `STORAGE_BACKEND=ATA`，ROM/Stage 1 不改变 ATA 启动链；
- Process runtime 在首个用户进程前刷新持久内核资源基线，把常驻 NVMe DMA/MMIO
  视为设备所有权；进程结束仍要求零差异，NVMe shutdown 后再要求全局资源回到
  storage 初始化前；
- 64 MiB bootstrap、256 MiB functional、4 GiB primary 使用相同双 namespace
  路径并完成 rootfs、swap、自研 Shell、页缓存、journal 和资源回收；
- `qemu-nvme-file-system-persistence` 对独立可写 ATA boot/ATA swap/NVMe root/NVMe
  swap 副本连续启动：首次写入并 Flush，第二次从同一 NVMe root 恢复，第三次破坏
  NVMe root 超级块并要求拒绝挂载；源镜像始终不修改。

## 尚未完成

- 大于 64 KiB 的链式 PRP list、多 I/O queue 和调度器原生异步提交接口；
- MSI-X 多向量亲和性、interrupt coalescing 与多核并发；
- 真机 ACPI/PCIe 枚举、电源管理与非 QEMU NVMe 兼容矩阵。

本版本不启动教材、网站、Sites 或公开发布闭环。

## 当前 caw 证据

- 验证主机：WSL2 Linux 6.6.87.2 x86-64、Clang 21.1.8、QEMU 10.1.5、Debug；
- 通用块层完成后的全量验证为 192/192、0 失败，`verify` 190.96 秒，峰值 RSS
  4266252 KiB；
- PCI 模型加入后的最终全量验证为 194/194、0 失败，CTest 188.90 秒、完整
  `verify` 189.81 秒、峰值 RSS 4266600 KiB；
- 最终分层为 59 unit、70 integration、41 randomized、24 system，含 23 条
  failure-path；
- 新块请求单元/集成/十万步随机模型、PCI 单元/4096 轮随机模型、freestanding
  symbol audit、Kernel ELF、命名、ATA 三档 QEMU 与三启动持久化全部通过；
- 第三增量 focused 证据：PCI/NVMe 四个纯模型、Python tooling 与真实
  NVMe Identify 均通过；QEMU 报告 BDF `03:00.0`、16 KiB BAR、NVMe
  1.4.0、`0x10000000` 个 512 字节逻辑块，并完成资源回收；
- 第三增量全量 caw 回归为 197/197、0 失败：60 unit、70 integration、42
  randomized、25 system，含 23 条 failure-path；CTest 188.29 秒，完整 `verify`
  189.32 秒，峰值 RSS 4265184 KiB；
- 第四增量 focused caw 证据：更新后的 NVMe 单元/十万组随机模型、Python tooling
  和真实 `os_qemu_nvme_io` 全部通过；QEMU 完成深度 64 队列、4 KiB 高 LBA
  Write/Flush/Read、逐字节比较、校验和与资源回收；
- 第四增量全量 caw 回归为 197/197、0 失败：60 unit、70 integration、42
  randomized、25 system，含 23 条 failure-path；最终 CTest 184.16 秒，完整
  `verify` 185.01 秒，峰值 RSS 4265616 KiB；
- 第五增量 focused caw 证据：PCI/NVMe 四个纯模型、正常 MSI-X I/O、blkdebug EIO
  reset 和 doorbell timeout reset 均通过；正常路径报告 16 页/请求、4 outstanding、
  6 次 MSI-X，两个失败路径各 reset 一次并完整回收资源；
- 第五增量最终 caw 回归为 199/199、0 失败：60 unit、70 integration、42
  randomized、27 system，含 25 条 failure-path；CTest 204.33 秒，完整 `verify`
  205.17 秒，峰值 RSS 4265240 KiB；
- 第六增量 focused caw 证据：三档 NVMe rootfs/swap、ATA fallback 和三启动 NVMe
  持久化/损坏拒绝均通过；bootstrap 报告 root `0x10000000` 块、swap
  `0x038E0008` 块，并在完整工作负载后 shutdown/reclaim；
- 第六增量最终 caw 回归为 204/204、0 失败：60 unit、70 integration、42
  randomized、32 system，含 25 条 failure-path；CTest 291.43 秒，完整 `verify`
  292.37 秒，峰值 RSS 4269244 KiB；NVMe 持久化用例为 45.30 秒；
- 当前 Kernel 生产运行路径优先 NVMe，ATA 保留启动与自动回退。尚不声称真机
  兼容、多核多队列或公开发布完成。
