# v0.7：传统中断与设备启动闭环

## 阶段目标

本阶段让内核第一次接收异步硬件事件，并拥有最小的时钟、键盘和磁盘访问能力。
QEMU 仍只模拟 PC 硬件；中断路由、IDT 入口、EOI、设备命令、扫描码解析和时间
换算全部由项目实现。

## 处理器与中断控制器

- IDT 向量 32..47 从 not-present 改为 DPL0 interrupt gate。
- NASM 为 16 个硬件 IRQ 提供独立桩，补齐零错误码并形成既有 160 字节帧。
- 硬件 IRQ 使用独立 C++ 分发器，不把异步事件交给异常 panic 策略。
- 内核清除并回读 `IA32_APIC_BASE[11]`，显式恢复传统 PIC→INTR 路由。
- 两片 8259A 写 ICW1..4，重映射到 `0x20/0x28`，默认屏蔽全部 IRQ。
- 设备完成初始化后只开放 IRQ0、IRQ1，最终 mask 为 `0xFFFC`。
- EOI 对主片、从片和级联采用不同顺序；ISR 区分虚假 IRQ7/IRQ15。
- 软件 `INT 0x27` 在开放 IF 前验证虚假 IRQ7 分支。

## 时钟

- 8254 通道 0 使用模式 2、低高字节访问和除数 `0x04A9`，目标 1000 Hz。
- IRQ0 热路径只递增 64 位 tick，不执行串口格式化。
- 单调毫秒按实际硬件除数换算，并对 64 位乘法溢出饱和。
- 启动至少收到 16 个真实 IRQ0 后才输出 `TIMER_SELF_TEST_PASSED`。
- 宿主 QEMU 捕获器为每条串口行附加 `[QEMU][T+......ms]` 到达时间；它与
  来宾 PIT 单调时间明确分离。

## 键盘

- i8042 访问全部具有有界等待：写前等输入缓冲空，读前等输出缓冲满。
- 初始化关闭两端口、清输出、读取并修改配置 byte、开放第一端口。
- 配置启用 IRQ1 和扫描码翻译，禁用 IRQ12；键盘 `F4` 必须收到 `FA`。
- 集合 1 解码器支持 Escape、Backspace、Enter、Space、A 和四个方向键。
- 状态机区分 make、break、`E0` 前缀和未知码；前缀不会产生伪事件。
- QEMU 成功测试等待 `READY`，再通过 QMP 虚拟键盘注入 `A`，目标机必须输出
  扫描码 `0x1E` 和 `KEYBOARD_EVENT=A_PRESSED`。

## ATA PIO

- 内核新增独立 primary master LBA28 单扇区读取，不调用 Stage 1 代码。
- 命令前写 `nIEN`，设备选择后读取 alternate status 四次形成 400 ns 延时。
- 轮询严格区分 BSY、ERR/DF、DRQ 和预算耗尽。
- DATA 端口精确读取 256 个 16 位 word，拆成 512 个 little-endian 字节。
- 启动重读 LBA 0 并校验 `OSSTAGE1` magic，形成磁盘硬件闭环。

## 工程与测试

- 端口号、命令、位掩码、频率和日志全部使用项目/模块/功能命名常量。
- 硬件驱动头源分离；纯 `device_model` 可在宿主目标复用。
- 单元测试覆盖 PIC/PIT/键盘/ATA 边界，集成测试组合设备启动契约。
- 固定种子随机测试执行 4096 轮 IRQ、PIT 和键盘组合性质。
- ELF 审计新增公共 IRQ 入口、分发器、桩表和 16 个向量符号要求。
- Python QEMU 运行器用标准库 QMP Unix socket 注入输入；最终里程碑驱动正常
  收尾，五秒总截止覆盖慢速 CI，且不依赖 Shell。
- 完整验证为 46 项 CTest；单元、集成、随机、系统和 19 条失败路径全部通过。

## 关键故障与结论

首次实现仅重映射 PIC、开放 IRQ0 并执行 `STI`。QEMU 中 PIT IRQ 统计持续增长，
PIC IRR bit0 已置位，master IMR bit0 已清除，CPU 的 IF=1 且处于 HLT，但
向量 32 从未进入。原因是 `qemu64` 的本地 APIC 仍全局启用，而自研 ROM 没有
传统 BIOS 建立虚拟线模式。

修复不是延长等待或重新写 PIT，而是把控制器之间的路由纳入内核显式状态：
清除 `IA32_APIC_BASE[11]` 并回读后，8259A INTR 可以直接交付，真实 IRQ0 和
IRQ1 同时通过。这个案例说明“每个局部寄存器都正确”仍不能替代跨芯片连接契约。

首次远端 CI 还暴露出宿主调度差异：固定两秒捕获预算在慢速 runner 上可能先于
最终时钟/键盘里程碑结束。测试生命周期改为“最后一个必需标记到达即收尾，五秒
只是失败上界”，并把 QMP 等待 READY 的预算与整机预算对齐。它没有放宽任何
来宾验收标记，只消除了把宿主速度误判为来宾协议错误的时间假设。

## 已知限制与下一阶段

- 当前仅支持单 CPU 与传统 PIC；没有 I/O APIC、LAPIC timer 和 MSI。
- 键盘只保留一个待消费事件，还没有环形队列、布局与终端行规程。
- ATA 仍是同步单扇区 PIO，没有 IRQ14、DMA、写请求和通用块层。
- PIT 只提供单调时钟基础，没有睡眠队列、超时对象和调度预算。

下一阶段是 v0.8：建立 Ring 3 代码/数据段和用户页权限，装载最小用户 ELF，
实现受控系统调用入口、用户指针校验与用户异常隔离。
