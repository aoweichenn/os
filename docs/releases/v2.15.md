# v2.15 每 inode I/O 协调与 V2 rootfs v5 目标

状态：六个增量已完成，工程候选，尚未发布

日期：2026-08-24

## 目标与六个增量

1. 冻结 V2 自研 rootfs v5 小型 ext4 核心和 v2.16..v2.20 顺序；
2. 建立完整 inode identity、generation token、LRU、统计和 Validate 的 128 槽协调器；
3. 迁移 write/pwrite/append，删除 VFS 全局 append mutex；
4. 把 path/O_TRUNC/ftruncate prepare、共享 mmap dirty 和同步入口接入 guard；
5. 完成容量、并发、LRU、十万步随机、truncate 强制交错与 prepare EIO；
6. 完成 freestanding 构建、Ring 3、4 GiB ATA/NVMe/persistence 与 fresh CAW 回归。

## 完成范围

- V2 终态冻结为自研 rootfs v5：4 KiB block、约 128 MiB block group、extent、HTree、
  multi-block/delayed allocation、ordered journal、orphan file、xattr/ACL/quota 和独立
  mkfs/fsck/migration；不宣称 Linux ext4 盘面兼容；
- `InodeIoCoordinator` 常驻 128 个槽，以 superblock/node identifier+generation 为 identity；
  token generation、零引用 LRU、容量拒绝、复用/替换/峰值统计和完整 Validate 已实现；
- 槽管理只持短 SpinLock，实际等待使用每槽独立 RuntimeMutex；全部槽被不同活跃 identity
  引用时返回 CapacityExhausted，不回退到全局锁；
- Write、WriteAt 与 Append 在 `RegularFileIoGuard` 内使用共同内部 helper；Append 在 guard 内
  读取缓存逻辑 EOF、执行 RLIMIT_FSIZE 裁剪并写入，V2.14 的 `append_lock_` 已删除；
- truncate prepare 由 ProcessRuntime 一次配置到 VFS；TruncateNode 在 guard 内按
  cancel/protect/unmap/writeback → backend → metadata invalidation → cache truncate 提交；
- OpenCurrentProcessFileAt 不再先关闭 O_TRUNC 再二次提交；path truncate 和 ftruncate 不再
  在 VFS 外 stat/prepare，prepare DeviceFailure 不改变 backend/cache size；
- writable shared mmap 首次写在同 inode guard 内完成 MarkDirty 与 writable PTE；fsync/
  fdatasync retain 短期 OpenFile 后在 guard 内保护映射、范围写回和 sync，guard 外推进 error
  cursor；同步 msync 对每个 shared file range 使用相同 guard；
- 后台 writeback 明确不取得 inode guard，继续使用 Dirty/Writeback/Error、页 waiter、backing
  引用和 rootfs transaction，避免 truncate/fsync 主动回写时递归锁死；
- 首轮完整 verify 的 NVMe persistence 暴露 DF fallback 系统调用恰在返回前被调度时，dispatcher
  实际执行 IRETQ 却未记录 return method；dispatcher 现按最终 frame entry method 记录 IRET，
  保留原生 IRET 安全门禁而不依赖时序；
- ABI v2.6.0、调用 1..105、错误 -1..-60、rootfs v4、4 GiB RAM、128 GiB 盘、ATA/NVMe 与
  VGA 协议均未改变；正常来宾不新增逐 inode/lock 日志。

## 已知边界

- rootfs v4 后端修改仍由实例锁串行；VFS 的不同 inode 已独立，但盘面 block-group 并发属于
  v2.16 以后 rootfs v5；
- 活跃槽容量为 128，与 phone-primary Thread 功能容量一致；达到容量明确失败；
- 后台 writeback 使用页级而非 inode guard 协调，这是避免同步路径递归锁的设计，不表示缺少
  writeback 唯一终态；
- v2.15 不改变盘面或 ABI，不实现 extent、fallocate、打洞、HTree 或 xattr；这些按
  v2.16..v2.20 顺序完成；
- 本阶段形成工程候选，不创建 `v2.15` tag；教材目录存在独立在制编辑，本候选不覆盖这些用户
  改动，也不启动网站/Sites 公共发布闭环。
