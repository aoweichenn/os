# v0.10：同步、阻塞/唤醒与有界管道 IPC

## 阶段目标

本阶段把 v0.9 的“所有存活进程始终可运行”扩展为真实条件等待。验收要求
Ring 3 生产者在满管道上停止参与 Ready 调度，消费者释放空间后再被唤醒；
消费者也必须在空管道上阻塞，并在写入或关闭写端后继续。整个过程由自研
系统调用、调度器和管道完成，QEMU 只提供 x86-64 CPU、PIT 和内存。

架构决策见
[ADR 0013](../adr/0013-blocking-wakeup-and-bounded-pipe.md)。

## 实现结果

- `SpinLock` 使用 acquire/release 原子顺序和 x86 `PAUSE`，RAII guard
  封闭临界区。
- 调度器加入 `Blocked`、等待原因、block/wakeup 统计和定向唤醒；Blocked
  不参与 round-robin。
- `Pipe` 使用 64 字节固定环形缓冲，支持部分读写、回绕、would block、EOF、
  broken pipe、端点关闭和统计快照。
- ABI 新增编号 4..9，分离 Try、Wait 与 Close；用户 `ReadPipe/WritePipe`
  包装在唤醒后重新检查条件。
- 用户可写内存验证与 `CopyToUser` 补齐读方向边界；管道锁内不访问用户页。
- PID1 生产者生成 256 字节确定性序列，PID2 消费者以 31 字节块逐字节验证；
  PID3/PID4 继续执行抢占和同址 BSS 隔离。
- 进程退出或用户异常自动关闭归属端点，并唤醒可能等待 EOF/broken pipe 的
  对侧。
- 内核冷路径核对 256 字节写/读、零残留、两端关闭、一次 EOF、阻塞/唤醒
  守恒、每进程方向统计和物理页回收。

## 装载容量修正

新增用户 ELF 和内核机制使旧低端暂存容量接近上限。Stage 1 把 Kernel 文件
暂存迁移到 `0x03E00000..0x03F00000`，容量扩为 1 MiB；同时把所有
`PT_LOAD` 的结束上界收紧为 `0x03E00000`，从布局上杜绝复制目标覆盖源 ELF。

高地址并不自动意味着可用 RAM。Stage 1 在读盘前扫描已经取得并排序的 E820
图，要求暂存半开区间完整落在一个 type 1 条目中。宿主布局测试、Python ELF
审计和目标汇编使用相同上下界。

## 自由站立运行时审计修正

代码审查发现历史上的全局 `InterruptRuntime` 产生 `.init_array`，而自研
入口没有 C++ CRT 去执行该数组。既有显式初始化让错误尚未表现，但依赖关系
并不成立。本阶段把 PIC 和键盘解码器状态改为 `constexpr/constinit`，
彻底移除动态全局构造；ELF 审计新增对 `.init_array`、`.fini_array`、
`.ctors` 和 `.dtors` 的拒绝规则，并加入 Python 正反单测。

## 测试证据

完整回归为 64 项 CTest，全部通过：

- 管道单元测试覆盖初始化、非法参数、空/满、部分读写、回绕、EOF、
  broken pipe、双重关闭和统计；
- 同步集成测试使用四个宿主线程，各执行 50,000 次受锁递增，总计 200,000
  次且无丢失；
- 固定种子管道随机测试执行 32,768 步，并在每步与独立字节队列模型比较内容、
  容量、读写统计和端点状态；
- 调度器单元、集成和 4096 轮随机测试加入阻塞、定向唤醒、无 Ready 后继、
  等待原因与统计守恒；
- 六个用户 ELF 分别审计 AMD64、`ET_EXEC`、W^X、对齐、入口和窗口；
- 正常 QEMU 路径精确检查生产者/消费者标记、256 字节统计、一次 EOF、
  阻塞/唤醒下界、四份退出结果和资源回收；
- 20 项 QEMU 系统测试、22 项失败路径和 v0.0--v0.9 全部回归继续通过。

当前真实目标代码统计为 82 个 `.cpp/.hpp/.asm` 文件、10,130 个物理行、
8,803 个非空非纯注释代码行，其中 C++ 6,639 行、NASM 2,164 行。统计只含
`source/` 中目标系统代码与接口，不含测试、工具、构建、文档、书籍和网站。

## 已知限制与下一阶段

当前为单 CPU、固定四 PCB、单 bootstrap pipe、单生产者/单消费者。尚无通用
等待队列容器、mutex/condition variable、超时、公平性、多个管道、文件描述符、
`dup/fork/wait`、信号或 SMP。下一阶段 v0.11 将先建立块设备与缓存边界，
再实现磁盘格式、inode、目录、文件描述符和 VFS，并把管道纳入统一对象生命
周期；不会把当前 bootstrap 权限规则伪装成通用 fd。
