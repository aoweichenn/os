# v1.4：类型化内核对象、共享 FileDescription 与动态 FileTable

## 阶段结论

v1.4 已删除每进程固定八槽 `IoDescriptorTable` 和平行
`FileSystemHandle[8]`。fd 现在只是 Process 局部整数名字，长期资源身份由
带 generation 的 `KernelObject` 表达，打开实例由强引用管理的
`FileDescription` 表达：

```text
Process
  └─ FileTable
       ├─ fd 0 ──handle──> ConsoleInput FileDescription
       ├─ fd 1 ──handle──> ConsoleOutput FileDescription
       ├─ fd 3 ──handle──> RegularFile FileDescription
       └─ fd 64 ─handle──┘  duplicate，共享同一偏移
```

Console、Pipe、普通文件和目录已经迁移到同一查找、临时引用、I/O 与最后引用
释放路径。functional 配置实际使用 hard limit 256，capacity 配置使用 4096；
FileTable 只为访问过的 64 项区间申请分块。

## 已完成能力

### KernelObject 生命周期

- KernelHeap 动态申请对象头与 payload；
- `KernelObjectType`、variant 和全局单调 generation 共同识别对象；
- `KernelObjectReference` 是不可复制的 RAII 临时强引用；
- `KernelObjectHandle` 只允许对象管理器和 FileTable 持有；
- acquire/release 与活动对象链在同一管理器锁内提交；
- 最后引用先把对象从活动链摘除，再在锁外执行模块 finalizer；
- 统计当前对象、当前强引用、创建、销毁、引用取得/释放、失败、峰值和代次；
- `Validate` 重新遍历双向活动链并核对类型、状态、generation 与引用总量。

### 共享 FileDescription

- 支持 ConsoleInput、ConsoleOutput、ConsoleError、RegularFile、Directory、
  PipeReader 和 PipeWriter；
- readable/writable file status flags 保存在共享对象中；
- `FileSystemHandle` 与 offset 一同保存在共享对象中；
- duplicate 增加强引用，因此共享 offset；
- 独立 open 建立新对象，因此 offset 独立；
- 管道端点只在最后一个引用释放时关闭；
- 普通文件和目录只在最后引用释放时调用 legacy FileSystem close；
- 控制台输出通过注入设备回调接入，宿主测试不依赖串口；
- 读、写、目录读取、可推进判断、字节统计和 finalizer 统一实现。

### 动态 FileTable

- fd 0/1/2 继续是标准输入、输出和错误，首个动态 fd 仍为 3；
- 64 项分块按 base fd 有序增长；
- 分别保存 soft limit 与 hard limit；
- 从 minimum 开始分配最低可用 fd；
- `InstallExact` 支持标准描述符事务安装；
- lookup 取得操作期间的临时强引用；
- duplicate 指向同一 FileDescription；
- close 移除表项后在表锁外释放对象；
- fd flags 与 file status flags 分离；
- 支持 `close-on-exec` 的设置、读取与批量关闭；
- 分块申请采用锁外准备、锁内复验、竞争回滚的两阶段提交；
- Destroy 摘除并释放全部分块和对象引用；
- `Validate` 核对分块排序、边界、handle、flag、活动计数与峰值。

### 三档容量

| 配置 | RAM | FileTable hard limit | 最大分块数 |
| --- | ---: | ---: | ---: |
| bootstrap | 64 MiB | 64 | 1 |
| functional | 256 MiB | 256 | 4 |
| capacity | 64 GiB | 4096 | 64 |

hard limit 是运行时配置，不改变 FileTable 类型。soft limit 初始等于 hard
limit，可以下降后恢复；已有高编号 fd 不会因下降被静默关闭。

为了容纳当前动态对象和描述符分块，高半区 KernelHeap 后备由 64 KiB 扩为
512 KiB，仍保持 RW/NX、best-fit、边界标记、精确释放与完整一致性检查。

### 用户 ABI

系统调用编号 23..28 新增：

- `DuplicateDescriptor`；
- `GetDescriptorFlags`；
- `SetDescriptorFlags`；
- `SetDescriptorSoftLimit`；
- `GetDescriptorSoftLimit`；
- `GetDescriptorHardLimit`。

ABI 新增 close-on-exec flag、描述符容量错误 `-24` 与对象层错误 `-25`。
默认入口仍为 v1.3 的 `SYSCALL`，所有新调用继续经过同一个 dispatcher、
`UserContext` 验证和 SYSRET/IRET 返回选择。

## 真实 Ring 3 证明

PID4 的 scheduler worker 新增一条不依赖宿主代做的验证：

1. 创建并写入八字节 `/fdv14.bin`；
2. 读方式打开 fd 3；
3. 查询 hard limit；256 MiB/64 GiB 档从 minimum 64 duplicate，64 MiB
   兼容档从 minimum 8 duplicate，并只给副本设置 close-on-exec；
4. 源 fd 读取 `ABC`，副本随后读取 `DEF`；
5. 独立 open 为 fd 4，再次读取 `ABC`；
6. 分别读取和修改两个 fd 的 flags，证明它们相互独立；
7. soft limit 降至选定 minimum 后，同一下界的 duplicate 必须返回 `-24`；
8. 恢复 hard limit，关闭 fd 4 后重新 open，必须复用 fd 4；
9. 关闭全部动态 fd，输出 `FILE_DESCRIPTION_MODEL_OK`。

该分档不是降低语义要求：64 MiB 的 hard limit 本身等于 64，minimum 64
没有合法候选区间；minimum 8 仍会建立高于连续低编号的空洞，并完整验证最低
编号选择、共享对象、独立 fd flags、限额拒绝和失败原子性。

内核按 Process 记录 PID4 文件读取 9 字节、写入 8 字节，并在全部进程退出后
要求以下有界摘要成立：

```text
[OS][KERNEL] OBJECT_ACTIVE_COUNT=0x0000000000000000
[OS][KERNEL] OBJECT_ACTIVE_REFERENCES=0x0000000000000000
[OS][KERNEL] OBJECT_CREATIONS=0x0000000000000017
[OS][KERNEL] OBJECT_DESTRUCTIONS=0x0000000000000017
[OS][KERNEL] FILE_DESCRIPTION_ACTIVE_COUNT=0x0000000000000000
[OS][KERNEL] FILE_DESCRIPTION_FINALIZATIONS=0x0000000000000017
[OS][KERNEL] FILE_DESCRIPTION_FAILED_FINALIZATIONS=0x0000000000000000
[OS][KERNEL] FILE_TABLE_HARD_LIMIT=0x0000000000000100
[OS][KERNEL] FILE_TABLE_PEAK_DESCRIPTORS=0x0000000000000006
[OS][KERNEL] FILE_TABLE_CHUNK_ALLOCATIONS=0x0000000000000005
[OS][KERNEL] FILE_TABLE_CHUNK_RELEASES=0x0000000000000005
[OS][KERNEL] RUNTIME_STATE_VALIDATION=0x0000000000000001
[OS][KERNEL] SMOKE_STATE_VALIDATION=0x0000000000000001
[OS][KERNEL] PROCESS_RESOURCE_VALIDATION=0x0000000000000001
[OS][KERNEL] FILE_DESCRIPTION_MODEL_VALID
```

累计调度次数可能随宿主时序变化；对象创建/销毁、finalizer 与分块守恒是本次
functional 工作负载的确定性事实。QEMU 验收器同时要求 active 与失败统计为
零、三项 validation 精确为一、hard limit 精确匹配来宾内存配置。

| `os_kernel_file_table_unit_tests` | 单元 | 所有权转移、duplicate、flags、limit、复用、close-on-exec |
| `os_kernel_file_description_lifecycle_integration_tests` | 集成 | 真实文件共享/独立偏移、管道最后引用、finalizer 守恒 |
| `os_kernel_file_table_capacity_integration_tests` | 集成 | 实际填满 4096 fd 与 64 分块、耗尽原子、完整释放 |

- 全部宿主单元、集成和固定种子随机测试；

## 阶段边界

v1.4 没有宣称已经具备：

- Vnode、Dentry、Mount、路径缓存或 memfs；
- fork 时的 FileTable 共享/复制；
- 磁盘 exec 对 close-on-exec 的实际调用；
- append、nonblocking、poll 集合或 Unix pipe 创建系统调用；
- 百万 fd 优化结构、SMP 原子引用或按需增长 KernelHeap。

这些边界防止把下一阶段的接口名写成当前实现。v1.5 将建立
VFS、memfs 与 legacy 文件系统适配，但继续复用本版本已经冻结的对象和 fd
所有权。
