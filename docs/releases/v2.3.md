# v2.3 128 GiB rootfs v4

状态：本地候选完成，待 caw 与手机持久化发布闭环

日期：2026-08-18

## 目标

把 v2.1 已固定但 rootfs 尚未使用的 128 GiB 参考盘交给项目自研文件系统，
一次完成格式 4、大文件、链接、时间戳、打开后删除、崩溃恢复和宿主工具，
不引入网络、权限、swap 或外部 bootloader/文件系统。

## 当前实现

- rootfs v4 magic `OSRFV004`，268402688 个 rootfs 块，数据区精确到绝对
  LBA `0x0FFFFFFF`；生产数据容量 137369755136 字节。
- 65536 inode、65504 块 data bitmap、4096 块 journal、248 transaction
  credits；较小同构几何用于真实 ENOSPC 集成测试。
- 单至五级间接树、完整数据区大小的稀疏文件与高 LBA 读回。
- 硬链接、相对/链式符号链接、40 跳环路保护、四纳秒时间戳、open-unlink、
  last-close 回收和断电后的 mount orphan 清理。
- ABI v2.2.0：系统调用仍为 71 个，`FileInformation` 从 64 扩为 96 字节，
  `stat` 输出 atime/mtime/ctime/btime；`df` 使用完整 rootfs 容量。
- `rootfs_v4.py` 公开 mkfs/install/inspect/fsck/corrupt/read；旧
  `rootfs_v2.py` 名称仅保留导入兼容，实际格式已经是 4。
- 启动成功标记改为 `ROOTFS_V4_MOUNTED`；详细文件系统与 journal 统计继续
  写宿主内存日志，不向 VGA Shell 前台逐块刷屏。

## 已通过的本地证据

- 最终统一 CTest：181/181 通过，0 失败，总墙钟 718.89 秒；
- 53 项 unit、66 项 integration、38 项 randomized、24 项 system 全部通过；
- 23 条 failure-path 全部通过；
- rootfs 主集成：30 项断言通过；
- 高 LBA Kernel 集成：2 项断言通过；
- journal 1000 点 crash matrix：374620 项断言通过；
- Python rootfs v4 高 LBA 稀疏镜像：末 LBA、fsck、读回与物理占用通过；
- 128 GiB 工具镜像逻辑长度保持 137438953472 字节；
- 64 MiB bootstrap 37.36 秒、256 MiB functional 89.96 秒、32 GiB 主规格
  111.91 秒、双启动持久化/损坏拒绝 182.34 秒；
- 10 万步 VFS/rootfs 命名空间随机模型 136.34 秒通过；
- Kernel payload 约 1.7 MiB，RW `MemSiz=0x5d3bf8`，仍远低于 Stage 1
  冻结装载窗口。

首轮统一回归中，64 MiB 在旧 35 秒内部预算结束时已到
`FILE_SYSTEM_SYNCED`，但最终 v4 Validate/截图晚约 1–2 秒；没有协议或状态
失败。按资源实测把内部预算调整为 45 秒、CTest 外层调整为 55 秒后，第二次
完整 181 项统一回归零失败，不以分次结果替代全量门禁。

## 已知边界

- metadata-only ordered journal 不回滚已覆盖的普通文件旧数据；
- 普通 read 使用 noatime；没有时区数据库；
- v2.3 冻结链接后端与 VFS 语义，用户态 `ln/readlink` 命令和权限检查进入
  v2.4；
- Kernel mount 使用有界流式校验，完整重复所有权集合由独立宿主 fsck 重建；
- caw 当前经 Tailscale SSH 在 banner 阶段超时，本页不宣称远端、手机或正式
  发布闭环已完成。
