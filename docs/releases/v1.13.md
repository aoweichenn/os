# v1.13 发布记录：单调时间、deadline 与 timed wait

## 发布结论

v1.13 把 8254 PIT 的实际除数转换为 64 位单调纳秒，建立统一 deadline queue，
并把 sleep、private futex 与 ConditionVariable 超时纳入 ThreadScheduler
单赢家唤醒协议。墙钟、RTC 与日期不进入本阶段。

## 交付能力

- `MonotonicClock` 用整纳秒与分子余数精确累计 PIT 周期，支持批量 tick；
  周期乘积与分数中间值按有限分块约化，只有最终时间不可表示时才进入
  `UINT64_MAX` 饱和；
- `DeadlineQueue` 提供 512 个 Thread deadline 槽，按
  `(deadline, sequence)` 稳定排序，并以 Thread 索引直接取消；
- ThreadScheduler 同时维护 WaitQueue 与 deadline membership，通知、超时、
  终止和取消只允许一个 `WakeReason` 获胜；
- IRQ0 在 Ring 3、Ring 0 与 idle 来源下都推进时间并解析到期项，唤醒只提交
  need-resched，不在任意中断调用链直接换栈；
- ABI 固定新增系统调用 54--56 和 `TIMED_OUT=-51`；
- 用户运行时新增 `GetMonotonicTime`、`SleepUntil`、饱和 `SleepFor`、
  `WaitPrivateFutexUntil` 与强类型 `ConditionVariable::WaitUntil`；
- rootfs 新增 `/bin/time_probe`，PID1 负责执行和回收；
- QEMU runner 验证来宾单调时间、语义 marker、deadline 守恒与 futex 超时
  计数，并继续使用有界墙钟预算回收模拟器。

## 测试证据

v1.13 构建图为 151 项 CTest：

- 单调时钟单元测试覆盖实际除数、余数携带、批量推进、周期乘积越界但结果
  可表示、分数中间值越界但结果可表示、最终饱和和无倒退；
- deadline queue 单元测试覆盖稳定顺序、重复登记、取消、到期与验证；
- scheduler 集成测试覆盖不早醒、Timeout、condition 先赢、重复解析无副作用
  和最终统计守恒；
- 固定种子随机测试执行 100000 步 deadline 操作；
- ABI 集成测试冻结系统调用 54--56；
- 64 MiB bootstrap 证明单线程配置下 sleep/futex/condition timeout；
- 256 MiB functional 与 64 GiB capacity 证明 notifier Thread 在 deadline
  前获胜，且整机结束 active deadline 为零。

整机终态必须满足：

```text
ACTIVE_DEADLINES = 0
DEADLINE_SCHEDULES = DEADLINE_EXPIRATIONS + DEADLINE_CANCELLATIONS
RUNTIME_STATE_VALIDATION = 1
PROCESS_RESOURCE_VALIDATION = 1
```

QEMU 仍由两层有界预算管理。64 MiB、256 MiB 和 64 GiB 的 runner 上限分别
为 30、120 和 240 秒，外层 CTest 上限分别为 40、130 和 250 秒；到期后
工具 terminate、wait 并报告最后串口里程碑，不允许遗留后台模拟器。十万步
VFS 双后端随机模型也以 300 秒为硬上界，不把共享宿主的性能波动变成无限等待。

## 日志策略

IRQ0 和 deadline 热路径不逐项打印。用户探针只在事务完成后输出一次性 marker，
内核只在全部用户进程回收后输出六项时间汇总。宿主 `[QEMU][T+...ms]` 与来宾
单调纳秒同时保留，但明确属于不同时间域。

## 兼容性与下一阶段

历史启动链、磁盘格式、ELF、VFS、fork/COW、动态管道和线程 ABI 保持兼容。
v1.14 将在现有 WaitQueue/deadline 单赢家协议上加入 signal、进程组与系统
调用中断语义；不得绕过当前 Thread 状态机。
