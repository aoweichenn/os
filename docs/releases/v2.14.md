# v2.14 打开文件描述与定位 I/O

状态：六个增量已完成，工程候选，尚未发布

日期：2026-08-24

## 目标与六个增量

1. 建立 regular-file seek 与 duplicate/fork 共享 offset 语义；
2. 完成不改变共享 offset 的 pread/pwrite，并冻结边界与错误；
3. 把 append 原子性扩展到独立 open description，并接入 RLIMIT_FSIZE；
4. 完成 fstat/ftruncate/fchmod/fchown 与打开 vnode 身份；
5. 冻结 ABI v2.6.0 的 97..105、status flags、用户包装和 Ring 3 路径；
6. 完成生命周期、真实 rootfs、VGA、writeback、资源与 fresh CAW 回归矩阵。

## 完成范围

- regular file 支持 Beginning/Current/End seek；duplicate/fork 共享 offset，pipe、terminal 与目录
  返回 -60 `NotSeekable`；位移拒绝负结果和超过 `INT64_MAX` 的结果；
- pread/pwrite 使用显式 64 位 offset，不改变顺序 offset；Linux 兼容的 append+pwrite 写到文件
  尾但同样不改变 offset；
- VFS 用共同 append mutex 串行“读取缓存逻辑 EOF + RLIMIT_FSIZE 裁剪 + 写入”，覆盖独立
  FileDescription，避免两个 append open 互相覆盖；
- fstat/ftruncate/fchmod/fchown 针对打开 vnode 执行；truncate 先准备文件映射和页缓存，再提交
  后端 size 变化；准备会取消预读、写保护共享映射、释放 EOF 外映射并等待同文件 writeback，
  消除后台写回导致的“后端已改、cache Busy、syscall 失败”；地址空间 owner 用 stable 位阻止
  全局 VMA 扫描进入退出/OOM teardown；metadata cache 继续按规则失效；
- buffered write 把 writeback backing retain 移到可能阻塞的 cache Acquire 之后，并在无阻塞
  窗口内 MarkDirty；descriptor 预先覆盖完整 write end，持久盘慢 I/O 不再提前释放 backing；
- file status flags 区分 Readable/Writable/Append，set 不允许改变 access mode；FileTable 的
  close-on-exec descriptor flag 保持独立；
- ABI v2.6.0 保留 1..96，在末尾追加 97..105；错误区间从 -1..-59 扩为 -1..-60；rootfs v4、
  4 GiB RAM、128 GiB 磁盘、ATA/NVMe 与 VGA 协议不变；
- 新用户包装独立编译并按 function section 回收；不使用 97..105 的静态 ELF 不携带这些代码，
  避免 ABI 增长无条件扩大所有程序的映射页与 rootfs 冷页工作集；
- `fs_probe` 在真实 rootfs 上覆盖全部九项调用，最终 persistence barrier 把新定位写与
  truncate 的 Dirty 页在进程退出前收束；正常终端不新增逐操作日志。

## 验证证据

- fresh CAW 配置并构建 3457 个目标；ABI、FileDescription 双线程 append、VFS、rootfs、release
  identity、Python tooling、ELF layout、符号裁剪与命名门禁全部通过；
- 4 GiB `-mem-prealloc` ATA primary 64.68 秒；ATA/NVMe reclaim 67.31/68.17 秒，ATA/NVMe
  OOM 68.18/68.47 秒，NVMe normal/EIO/timeout 2.62/2.49/10.04 秒，NVMe root primary
  63.73 秒；所有系统测试均要求 QMP VGA 可见画面；
- ATA/NVMe `snapshot=off` 三阶段 persistence 为 130.29/129.40 秒，均完成首次写入、第二次
  恢复并重写 positioned payload、以及故障注入后的损坏拒绝；
- Ring 3 `fs_probe` 核对 shared offset、positioned I/O、append、size、mode、owner、flags 与
  最终持久内容；失败只按 positioned/truncate/metadata/status/sync 分组输出；
- final fresh CAW `python3 tools/os.py verify` 为 249/249、0 失败：75 unit、85 integration、
  56 randomized、33 system，含 25 条 failure-path；CTest 790.32 秒，verify 墙钟 791.41 秒。

## 已知边界

- seek/positioned I/O 当前只接受 regular file；没有目录 seek cookie、字符设备 seek 或块设备
  用户接口；
- append mutex 当前是单 VFS 粗粒度串行点，优先保证单 BSP 正确性，尚未按 inode 分片；
- 不实现 `fcntl` 通用命令、文件记录锁、异步文件 I/O、direct I/O、稀疏洞操作或 extent API；
- 本阶段只形成工程候选，不创建 `v2.14` tag，不执行网站、教材或公共 v2 发布闭环。
