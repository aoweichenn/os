# v1.1：可回收资源基础与生命周期收口

## 阶段目标

v1.1 把“能够申请内存”提升为“所有跨层资源都能验证、失败时完整回滚、成功
使用后回到原所有者”。阶段范围不是某一个分配器，而是一条完整依赖链：

```text
动态物理内存
  → buddy 连续页
    → 可回收 Kernel heap
      → 固定尺寸 type cache
        → 32 TiB KVA 所有权
          → 页表空分支回收
            → 双 guard 动态内核栈
              → 通用回滚、引用计数与 ResourceSnapshot
```

启动仍完全由自研 ROM 和 Stage 1 完成，QEMU 只模拟 x86-64 CPU 与 PC 硬件。
完成标准要求 64 MiB bootstrap、256 MiB functional 和 64 GiB capacity
使用同一份实现，并由宿主模型和真实目标机共同证明资源闭合。

## 完成内容

### 动态物理内存与 direct-map

- 页帧状态按 E820 最高可用 PFN 动态定容，不再被 Stage 1 的低 64 MiB
  身份映射限制；
- 在低端可访问 RAM 中为 2-bit frame state 和 buddy 双位图整体选择启动
  元数据区，避开低 1 MiB、Kernel、初始栈和既有保留区；
- 建立 64 TiB 高半物理直映，内部对齐区间使用 2 MiB 大页，边界使用
  4 KiB 页；64 GiB QEMU 必须在 4 GiB 以上申请、写回并回收真实页帧。

### 可回收分配层

- `PhysicalFrameAllocator` 与双位图 buddy 共用唯一页状态，支持精确 order
  所有权、拆分、合并、范围申请和错误阶/重复释放拒绝；
- `KernelHeap` 使用边界标记、地址有序空闲链和 best-fit，支持任意显式对齐、
  双向合并、失败原子性与完整结构校验；
- `KernelFixedObjectCache` 从 heap 取得单一后备块，使用活动位图和槽内空闲
  链，支持精确释放、耗尽、LIFO 复用和无活动对象时整体销毁；
- `KernelVirtualAddressAllocator` 管理
  `0xFFFFC90000000000..0xFFFFE90000000000` 的 32 TiB 软件所有权窗口，
  用 256 项有序描述符和隐式空洞实现 best-fit，不为整个窗口建立逐页位图。

### 页表与动态内核栈

- 页表根显式区分 `Exclusive`、`KernelShared` 和 `Process`；撤销最后一个
  叶项后只回收当前根拥有且完整为空的 PT/PD/PDPT；
- 映射失败记录新表帧和父项原值，逆序恢复 U/S 提升与所有新建分支；
- 每个 Ring 0 动态栈占六页 KVA：lower guard、四页 supervisor RW/NX 数据、
  upper guard；四个物理后备页不要求连续；
- 进程切换从活动栈对象设置 TSS.RSP0。终止路径先回到永久 Kernel 栈，再在
  安全点撤销映射、清零并释放页帧和 KVA；
- 栈创建改用九项 `ScopeRollback`，不再维护一份易与创建步骤失配的手写
  回滚分支。

### 通用资源生命周期

- 新增 freestanding `ReferenceCounter`：显式启动、获取、最后释放、零后
  禁止复活、上溢拒绝和失败输出保持；
- 新增无分配 `ScopeRollback`：调用方固定存储、严格逆序补偿、提交、
  显式回滚、析构安全网，以及单项失败后继续执行其余动作；
- 新增 26 字段 `ResourceSnapshot`，聚合 frame、buddy、heap、KVA、动态栈
  的当前稳定量，并为 Process、Thread、FileDescription、Vnode、CachePage
  和 BlockRequest 冻结后续接入位置；
- 快照比较先验证容量/所有权守恒式，再返回 64 位变化掩码和变化字段数；
  成功申请/释放等累计历史不进入泄漏判断；
- 内存初始化创建并销毁一个真实动态栈后比较零差异；四进程运行前后再做一次
  独立快照，任意差异都返回 `ResourceLeakDetected`。

## 构建工程收口

### Kernel 功能目录

Kernel 不再把四十余组头文件和实现直接堆放在 `include/os/kernel` 与 `src`
根目录。两棵树现在都按
`arch/boot/core/device/fs/io/ipc/memory/process/sync/user` 划分，公开头文件
与实现保持 `<module>/<name>` 对称路径。CMake 源清单按同一模块集合分组，
在线代码目录也直接呈现这层所有权。

结构规则不是一次性人工整理。Python 布局检查会拒绝根目录实现、两侧模块集合
漂移、缺少同模块 `.cpp` 的公开头文件、孤立 `.tpp` 以及未登记的额外实现；
真实仓库与故意构造的错误树都进入既有 tooling CTest。完整决策见
[ADR 0028](../adr/0028-kernel-functional-directory-layout.md)。

### 跨目录生成依赖

v1.1 收口时复现了此前“清理产物后打包偶发 No rule to make target”的问题。
原因是 Unix Makefiles 不会自动把其他 CMake 二进制目录中的文件级自定义命令
提升为当前目录的生成目标依赖。修复显式建立两条目标级边：

```text
七个 user ELF targets
  → os_kernel_user_images_object
    → 所有 kernel ELF targets
      → os_stage1_images
```

因此全新构建、局部删除 ELF 或切换生成器时，打包都会先重建生产者目标，不再
依赖旧文件碰巧存在。正式构建入口仍是 `python3 tools/os.py build`，由
`developer` preset 固定 Clang、Ninja 和 x86-64 freestanding 选项。

## 测试证据

- 引用计数/作用域回滚单元测试覆盖全部状态、容量、幂等拒绝、失败输出保持和
  回滚动作继续执行；
- 固定种子 `0x5245534F55524345` 用独立模型执行 100000 个资源事务；
- 资源快照单元测试逐项翻转 26 个字段，验证差异位位置、变化计数、五类守恒式
  损坏和失败原子性；
- 组合集成测试用真实 frame、buddy、页表、KVA 与栈管理器创建四个栈，活动
  快照必须同时反映 16 个物理页、24 个 KVA 页、16 个映射页和 8 个 guard，
  逆序销毁后差异为零；
- buddy、heap、type cache、KVA、页表回收和动态栈分别保留 100000 步固定
  种子随机模型；
- 256 MiB `os_qemu_functional_smoke` 执行完整四进程、Shell、IPC、文件系统、
  用户故障隔离和资源快照；64 GiB capacity 额外要求 4 GiB 以上页帧证据；
- 完整集合为 97 项 CTest，包含全部历史成功、失败注入、持久化、ELF/镜像
  审计、命名门禁与教材结构检查。

## 可观测性

资源热路径不逐次打印。启动期只在事务全部提交后输出：

```text
[OS][KERNEL] RESOURCE_LIFECYCLE_READY
[OS][KERNEL] RESOURCE_SNAPSHOT_TRACKED_FIELDS=0x000000000000001A
[OS][KERNEL] RESOURCE_SNAPSHOT_CHANGED_FIELDS=0x0000000000000000
[OS][KERNEL] REFERENCE_COUNTER_SELF_TEST_PASSED
[OS][KERNEL] SCOPE_ROLLBACK_SELF_TEST_PASSED
[OS][KERNEL] RESOURCE_SNAPSHOT_SELF_TEST_PASSED
```

四进程安全点回收后另输出
`RESOURCE_SNAPSHOT_PROCESS_LIFECYCLE_PASSED`。正常系统累计动态栈创建/
销毁各五次：一次来自启动资源事务，四次来自实际进程；峰值仍为四个并发栈。
QEMU 捕获器继续为每行附加宿主单调相对时间，来宾时间仍只来自 PIT。

## 规模

按 `python3 tools/os.py source-metrics` 的唯一口径，v1.1 有 109 个目标代码
文件、21586 个物理行、19549 个非空非纯注释代码行；其中 C++ 为 17383 行，
NASM Intel 语法汇编为 2166 行。统计只包含 `source/` 下进入目标系统的
`.cpp`、`.hpp` 与 `.asm`，排除 `.inc`、`.tpp`、测试、工具、构建描述、
链接脚本、书籍和网站。

## 已知边界与下一阶段

- `ReferenceCounter` 当前只用于单 BSP 语义与基础自检；原子内存序、弱引用、
  并发最后释放和动态 KernelObject 接入留给 v1.4；
- Process/Thread 仍合并在四槽 PCB 中，v1.2 将分离资源容器与调度实体，
  增加 WaitQueue 和完整 FXSAVE/FXRSTOR 上下文；
- heap 后备仍为 64 KiB，type cache 仍是单 slab，KVA 描述符仍固定 256 项；
- 当前只有单核四级页表，没有远端 TLB shootdown、PCID、NUMA 或内存压力
  回收；
- ATA 仍是同步单扇区 PIO，固定布局文件系统还没有 journal。

这些限制是已记录的阶段边界，不影响 v1.1 的验收结论。v1.2 必须继续复用
`ScopeRollback` 和 `ResourceSnapshot`，并把 Process/Thread 当前量接入已冻结
字段，不能另建旁路泄漏检查。
