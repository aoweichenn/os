## 1. 阶段目标

在编写第一条固件指令前，先建立一个能够持续回答以下问题的工程系统：

- 当前机器是否具备完整工具链？
- 同一份 C++ 实现能否在宿主机测试并交叉编译为 x86-64？
- 目标产物是否意外依赖 libc 或 C++ 运行时？
- 逻辑错误能否在进入 QEMU 前快速暴露？
- QEMU 是否确实加载了项目提供的 ROM 和磁盘？
- 新环境能否只通过文档复现构建与测试？

阶段刻意不实现可执行固件。这样可以把构建和测试系统本身的问题，与后续复位代码问题分开。

## 2. 交付范围

- CMake 3.28+ 工程和统一 `developer` preset。

## 4. 构建结构

同一份 `foundation/address_range.cpp` 被编译成两个目标：

```text
os_foundation_host
  └── 面向宿主机，供单元、集成和随机测试执行

os_foundation_x86_64
  └── 面向 x86-64-unknown-none-elf，验证 freestanding 约束
```

这种结构避免了两套实现：测试执行的是将来进入固件和内核的同一份逻辑，而不是重新写一份“测试版本”。

x86-64 目标明确关闭异常、RTTI、栈保护、红区、SSE、位置无关代码和宿主 C++
标准库头文件。静态库生成后，测试继续检查 ELF 架构和未解析符号。

## 5. Foundation 模块

本阶段实现了最小但真实可复用的地址模型：

- `PhysicalAddress` 保存物理地址。
- `ByteCount` 保存字节数量。
- `AddressRange` 表达半开区间。
- `AddressRangeCreationStatus` 显式报告地址溢出。

没有直接使用裸整数作为所有参数，是为了从第一阶段开始建立类型边界。区间创建失败不会修改输出对象，这一承诺同时由单元测试和随机测试验证。

## 6. 测试记录

CTest 共注册六项测试：

| 测试 | 层级 | 验证内容 |
| --- | --- | --- |
| `os_foundation_unit_tests` | 单元 | 类型值、顺序、空区间、半开边界、溢出与失败原子性 |
| `os_foundation_integration_tests` | 集成 | ROM、复位向量、Stage 1、内核计划区间 |
| `os_foundation_randomized_tests` | 随机 | 10,000 组输入与 100,000 次性质断言 |
| `os_freestanding_symbol_audit` | 集成 | ELF64、x86-64 Machine 字段、零未解析运行时符号 |
| `os_qemu_hardware_smoke` | 系统 | 空 ROM、空磁盘、TCG、PC 与 IDE 参数 |
| `os_qemu_rejects_invalid_image_size` | 失败路径 | 错误镜像尺寸必须被测试框架拒绝 |

QEMU 冒烟测试显式传入：

```text
-machine pc,accel=tcg
-cpu qemu64
-nodefaults
-S
-bios <项目空 ROM>
-drive file=<项目空磁盘>,format=raw,if=ide
```

`-S` 让 CPU 保持暂停，因此不会把空 ROM 当作已经实现的固件。`timeout`
到期返回预期状态，只证明 QEMU 进程和硬件配置稳定存在。

## 8. 实施中发现的问题

### 8.1 静态库成员标题被误判为未解析符号

`llvm-nm --undefined-only` 对静态库即使没有未解析符号，也会输出：

```text
address_range.cpp.o:
```

最初的审计脚本把这个成员标题当成错误。修复方式是过滤空行和以冒号结尾的成员标题，只保留真正的未解析符号行。

### 8.2 Bash 多行条件解析失败

QEMU 测试最初将 `[[ ... ]]` 比较运算符拆到不合法的换行位置，Bash 报告
`unexpected argument newline`。修复后将条件表达式保持在同一逻辑行，并增加
`bash -n` 语法检查。

### 8.3 Ubuntu CI 缺少 LLVM 检查工具

第一轮远程 CI 安装了 Clang 和 LLD，但没有安装提供 `llvm-nm` 与
`llvm-readelf` 的 `llvm` 工具包。工具链检查正确阻止了测试继续运行。工作流补齐
`llvm` 后，原生工程任务成功。

这些问题说明工程基线的价值：它们都发生在真正的固件开发之前，并且已经转化为自动检查或明确依赖。

## 9. 已知限制

- 空 ROM 不包含可执行固件，QEMU 以 `-S` 暂停 CPU。
- 尚未生成可启动镜像或串口输出。
- 尚未引入 NASM 源文件；NASM 在工具链基线中完成检查。
- 当前地址区间的结束地址必须能由 64 位值表示，因此不能表示结束点恰好为
  `2^64` 的非空区间。

## 10. 下一阶段

`v0.1 复位与串口` 将实现自定义 ROM 链接布局、复位向量跳转、串口初始化和可机器判断的启动退出状态。

开始 `v0.1` 前必须先写清楚：

- 128 KiB ROM 的链接地址与文件偏移关系。
- 复位向量最后 16 字节的跳转策略。
- 16 位入口的寄存器和段寄存器假设。
- 16550A 兼容串口的端口、初始化顺序和超时失败语义。
- 反汇编、GDB、串口捕获和 QEMU 退出码的验收方式。
