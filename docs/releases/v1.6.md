# v1.6：rootfs v2、完整命名空间与独立一致性工具

## 阶段结论

v1.6 已把生产根目录从 legacy 旧格式迁移到严格挂载的 rootfs v2，并在
v1.5 的 VFS 边界内完成删除、重命名、截断和 stat。正常启动链现在是：

```text
1 GiB sparse boot disk
  -> self-written ROM and Stage 1
  -> Kernel ATA PIO
  -> RootFileSystem strict mount
  -> VFS root mount
  -> Memfs mounted at /tmp
  -> per-Process FsContext and FileDescription
  -> Ring 3 Shell
```

Kernel 不再具有“看到空盘就格式化”的生产分支。构建系统先用独立 Python
mkfs 生成 rootfs；Kernel 只接受布局、版本、功能位、CRC、事务状态和全盘
可达性都一致的介质。Dirty 或损坏介质只会输出失败状态并停机。

## 容量与盘面格式

- 启动盘逻辑容量：1 GiB，宿主存储采用稀疏文件；
- rootfs 起始：LBA 2048；
- rootfs 区域：524288 × 512 字节，即 256 MiB；
- inode：8192 个，每个 256 字节；
- 目录项：320 字节，名称上限 255 字节；
- inode 指针：八个 direct，加 single/double/triple indirect；
- 每个间接块：63 个 64 位相对块号和 CRC32；
- 单文件公开上限：64 MiB；
- 多字节字段：显式 little-endian 编码；
- 身份：64 位 inode number 与 64 位 generation。

布局固定为：

| 相对块 | 内容 |
| --- | --- |
| 0 | version 2 superblock |
| 1..2 | inode bitmap |
| 3..4098 | inode table |
| 4099..4226 | data bitmap |
| 4227..524287 | 数据块和间接指针块 |

superblock、inode、目录项和间接块各自具有 CRC32 与必须为零的保留区域。
解码不依赖 C++ struct padding；Kernel 与 Python 工具逐字段读写冻结偏移。

## 文件和目录语义

### 稀疏文件

零块号表示未分配逻辑块。读空洞返回零，读操作不会产生磁盘分配；越过文件尾
写入只分配实际触及的数据块和所需的间接路径。`stat` 同时报告逻辑大小与
实际分配大小。

### truncate

- 扩展只改变逻辑大小，新增区间保持空洞；
- 缩小清零最后一个保留块的尾部；
- 完整后缀数据块会释放；
- 空的单/双/三级间接块从叶到根释放；
- 区间剪枝跳过不相交或未分配子树。

64 MiB 文件可以真正跨越三级间接边界，随后缩回零并完整归还块。

### 短写与容量耗尽

每个逻辑块写入前先计算叶数据块和间接路径需要的块数。空间不足时：

- 已完成的连续前缀提交为短写，返回实际字节数；
- 若尚未写入任何字节，返回 `CapacityExhausted`；
- inode size、offset、allocated counts 与 bitmap 只反映已提交部分；
- 再次 `Validate` 和独立 fsck 必须通过。

容量集成测试在真实 256 MiB 格式上构造近满直接/单/双/三级树，只留下少量
块，再执行真实短写和零字节 ENOSPC，而不是缩小常量伪造容量。

### unlink、rmdir 与 rename

- unlink 只删除普通文件；
- rmdir 只删除空目录；
- 根、挂载点和挂载根不能删除或替换；
- 打开引用非零的目标返回 `Busy`；
- rename 支持同目录、跨目录和显式替换；
- 跨 Superblock 返回 `CrossDevice`；
- 文件和目录不能互相替换；
- 替换目录必须为空；
- 目录不能移动到自己的后代；
- 移动目录同步更新 parent inode；
- 失败不发布半个目录项或泄漏 inode/data bitmap。

本阶段有意不实现 Unix orphan inode：名字删除后让已打开文件继续存活需要
单独的延迟回收和崩溃一致性协议。在该协议落地前，Busy 比伪造语义更可靠。

## 用户 ABI 与 Shell

新增系统调用：

| 编号 | 名称 | 关键参数/结果 |
| ---: | --- | --- |
| 31 | `UnlinkFile` | path + length |
| 32 | `RemoveDirectory` | path + length |
| 33 | `Rename` | source、destination，第四参数经 `r10` |
| 34 | `TruncateFile` | path + 64 位 size |
| 35 | `StatFile` | path + 64 字节可写结果 |

`FileInformation` 固定为八个 64 位字段：mount、superblock、inode、
generation、type、size、allocated size 和 link count。新增 ABI 错误码：

- `-30`：目录非空；
- `-31`：跨文件系统；
- `-32`：资源忙；
- `-33`：操作不支持。

Shell 新增 `rm`、`rmdir`、`mv`、`truncate` 和 `stat`。解析器继续使用固定
容量存储，不依赖 libc 或动态分配。

## 事务与失败边界

每个修改事务严格执行：

```text
persist Dirty superblock
  -> mutate and cache data/metadata
  -> flush cache and ATA device
  -> persist Clean superblock with advanced generation
```

设备失败会把当前 RootFileSystem 实例永久标记为 failed，禁止继续提交。
若掉电发生在最后一个 Clean 之前，下次挂载返回 `IncompleteTransaction`；
CRC、保留字节、指针范围、重复所有权、父链、可达性或 bitmap 不一致返回
`Corrupt`。v1.6 不承诺恢复旧/新事务之一，因此没有把 Dirty/Clean 错称为
journal；ordered metadata journal 与 replay 仍按路线单独实现。

## 宿主工具

`tools/os.py` 新增四个入口：

```bash
python3 tools/os.py mkfs-rootfs disk.img --create
python3 tools/os.py inspect-rootfs disk.img
python3 tools/os.py fsck-rootfs disk.img
python3 tools/os.py corrupt-rootfs disk.img superblock-checksum
```

- mkfs 创建规范 root、bitmap、inode 和 Clean superblock；
- inspect 以 JSON 输出布局、容量、事务和使用量；
- fsck 只读解析并独立重建可达 inode/data bitmap；
- corrupt 支持 superblock/inode CRC、两种 bitmap 和 Dirty 状态注入。

稀疏镜像复制器只复制非零 extent，并显式保留逻辑长度；测试覆盖远端尾部
extent，防止打包时把 1 GiB 镜像截断或物化全部空洞。

## 性能与可解释性

实现保留简单、确定的全局锁模型，但修复了两处会把随机测试放大的算法问题：

- inode/data 分配器保存可回绕 hint，顺序分配不会每次从 bitmap 第 0 位扫描；
- Validate 先在内存 bitmap 标记所有引用，结束时一次比较盘面 bitmap，不在
  每访问一个块时复制整张 bitmap。

superblock 直接写改为命中同一 BlockCache 并立即 sync，既保持
Dirty/Data/Clean 顺序，也不会在每个事务中无条件丢弃热 inode/bitmap 缓存。
这些 hint 与缓存只改变成本，不改变盘面事实或失败语义。

## 日志证据

启动期只输出一次规格与挂载结果：

```text
[OS][KERNEL] ROOTFS_V2_MOUNTED
[OS][KERNEL] ROOTFS_V2_REGION_BYTES=0x0000000010000000
[OS][KERNEL] ROOTFS_V2_MAX_FILE_BYTES=0x0000000004000000
[OS][KERNEL] FILE_SYSTEM_CONSISTENT
```

初始化和最终同步各输出一次聚合统计，包括事务代次、inode、数据块、元数据块
和空闲块。每个 lookup、block 和 bitmap bit 不打印日志，避免串口流量改变
TCG 时序。来宾继续输出 PIT 单调时间，宿主 runner 为每行添加
`[QEMU][T+...ms]`，所有 QEMU 用例同时具有阶段和外层超时。

## 工程变更

- 项目版本提升为 `1.6.0`；
- 新增 `root_file_system_format.*` 与 `root_file_system.*`；
- legacy 文件系统留在 `fs/`，但生产根不再初始化它；
- 启动镜像由固定 2 MiB 改为逻辑 1 GiB 稀疏镜像；
- Python 构建/打包统一使用稀疏范围复制；
- 新 C++ 继续遵循头源分离、`this->`、固定宽度类型、中文注释、函数大驼峰、
  变量 snake_case 和具名常量规则；
- 网站代码仍在独立 `web/`，不进入本仓库或核心代码统计。

## 阶段边界

v1.6 没有宣称已经具备：

- journal、replay、在线 fsck 或自动修复；
- orphan inode、硬链接、符号链接、权限和时间戳；
- dentry/inode/page cache 与并发写回；
- 异步块请求、ATA IRQ/DMA、AHCI 或 NVMe；
- PID1、从 rootfs 加载用户 ELF、exec/wait；
- fork 后 FsContext/FileTable 继承语义。

下一阶段是 v1.7：由 PID1 从当前 rootfs 读取并验证用户 ELF，建立真实父子
进程树和 exec/wait 生命周期。
