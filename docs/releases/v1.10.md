# v1.10：fork 与写时复制

## 阶段结论

v1.10 已完成：

```text
current Thread
  → fork Process/Thread/resource transaction
  → parent/child shared private frames
  → read-only PTE + software COW bit
  → user #PF or Kernel CopyToUser
  → exclusive restore or single-page copy
  → exec/exit/wait reference reclamation
```

父子初始共享匿名页和可写 private 文件页，任一方写入后正确隔离；只读文件页
保持真正只读，不会被误当作 COW。fork 同时继承 fd、共享
FileDescription offset、FsContext、FileBacking、VMA 与调用 Thread 现场。
QEMU 仍只提供 x86-64 CPU、RAM 和 PC 设备模型，fork、页表、异常、复制、
调度和回收全部由项目代码完成。

## ABI 与返回语义

系统调用 44 为 `ForkProcess`：

- 父 Thread 返回子 PID；
- 子 Thread 从同一用户指令之后继续，返回值为 0；
- 失败返回负状态，父进程所有可观察状态不变；
- 子 Process 只拥有调用 Thread，不复制其他 Thread。

子 Thread 克隆 176 字节 `UserContext` 与 512 字节、16 字节对齐的 FXSAVE
现场。独立动态 KernelStack 继续保留上下 guard，子 Process 在全部候选资源
完成并发布前不可进入 ready queue。

`VirtualMemoryStatistics` 从 160 字节扩展为 200 字节，新增五个 `uint64_t`
字段：

- `copy_on_write_page_count`；
- `copy_on_write_fault_count`；
- `copy_on_write_copy_count`；
- `copy_on_write_exclusive_restore_count`；
- `fork_clone_count`。

## PTE 与 COW 状态

`PagePermissions` 新增 `copy_on_write`。页表软件位 9 编码 COW，合法 leaf
满足 `Present=1, User=1, Writable=0, COW=1`；页表 API 拒绝 Writable+COW。
`PageTableManager::ReplacePage` 只替换已经存在的 4 KiB leaf，保持虚拟权限
契约并在当前地址空间执行 `INVLPG`。

fork 只把“VMA 本来允许写且属于 private 所有权”的驻留页改成 COW：

| 页类型 | fork 行为 |
| --- | --- |
| anonymous writable | 父子共享 private frame，双方 COW |
| writable file private / ELF data | 父子共享 private frame，双方 COW |
| read-only file/ELF clean cache | 保持 read-only，共享 cache 引用 |
| read-only private tail | 保持 read-only，复制生命周期引用 |
| 尚未驻留 VMA | 只克隆 VMA/后备，之后各自 fault |

真正只读页没有 COW bit，非法写仍结束对应用户 Process。

## 稀疏引用模型

新增 `UserPageReferenceManager`。独占 private 用户页隐含引用数为 1，不占用
表项；第一次参与 fork 时建立 `(physical_address, reference_count=2)`，
后续 fork、退出或私有化再 retain/release。表容量为 32768 项，并使用
SpinLock 保护固定宽度状态。

引用降到 1 时保留元数据，等待最后持有者写入或 fork 回滚调用
`RestoreExclusive`；引用降到 0 时最终释放 frame。完整进程树结束后强制检查：

```text
USER_PAGE_REFERENCE_ACTIVE_ENTRIES=0
USER_PAGE_REFERENCE_ACTIVE_REFERENCES=0
```

统计还输出 peak、first share、retain、release 和 exclusive restore，既防
“永远为零的假功能”，也防活动引用泄漏。

## 统一 COW break

以下路径全部复用 `BreakCopyOnWritePage`：

- CPL3 present+write 页故障；
- `CopyToUserAddressSpace`；
- `ValidateUserWritableMemory`；
- 系统调用结果结构写回；
- 返回用户态前需要写入的用户栈。

引用数为 1 时删除稀疏元数据并原地恢复 writable，不复制。引用数大于 1 时：

1. 申请并清理新 frame；
2. 经 direct-map 复制完整 4096 字节；
3. 替换当前 AddressSpace leaf；
4. 释放旧 frame 的一个引用；
5. 更新 COW page/fault/copy 统计。

准备失败发生在修改 PTE 之前，旧映射与内容保持有效。

## fork 两阶段事务

准备阶段建立候选子 Process：

- 独立页表根、VMA 图和 UserAddressSpace；
- FileBacking clone 与 clean cache mapping 引用；
- 精确 fd 编号/fd flags 的 FileTable clone；
- 共享 FileDescription 强引用和 offset；
- 独立 FsContext；
- ProcessTree 身份、Thread、KernelStack、FXSAVE 与用户现场。

提交阶段才逐页把 parent writable private leaf 改为 COW，并登记共享引用。
任一页提交失败，先销毁 child 地址空间，再扫描已提交页：只剩 parent 时删除
引用元数据并恢复 parent writable PTE。之后逆序释放其他候选资源。失败子
不会进入调度队列，也不会留下 ProcessTree 或 Zombie。

## 文件资源继承

`FileTable::CloneFrom` 保留所有 fd 的精确槽号和每项 flags，并通过
KernelObject 强引用共享 FileDescription。父子关闭 fd 相互独立，但文件
offset 共享。

`Vfs::CloneContext` 复制 cwd/root/mount 语义；父子初始 cwd 相同，之后
`chdir` 不互相修改。`FileBackingManager::Clone` 为 VFS 打开实例或内存后备
增加独立生命周期引用，mmap 不重新依赖原 fd。

## Ring 3 端到端证据

新增 rootfs 程序 `/bin/fork_probe`。它依次：

1. `chdir("/bin")` 并打开 `/bin/smoke`，先读取一个 ELF magic 字节；
2. 建立两页匿名映射、一个 writable private 文件映射和一个 readonly 映射；
3. 预先触页后 fork；
4. child 检查继承内容、cwd、readonly 页与共享 fd offset；
5. child 写匿名/private 页，并让 Kernel 把 200 字节 VM 统计复制进另一张
   COW 页；
6. parent wait 后确认自己的匿名/private/sentinel 未改变；
7. parent 继续读取 fd，证明 offset 已由 child 共同推进；
8. 顺序执行 32 次 fork；每个 child exec `/bin/exec_target`，parent wait；
9. unmap/close/exit，由 PID1 回收 fork probe。

成功协议：

```text
[OS][USER][FORK] COW_ISOLATION_VERIFIED
[OS][USER][FORK] FD_OFFSET_AND_CWD_VERIFIED
[OS][USER][FORK] FORK_EXEC_WAIT_32_VERIFIED
[OS][USER][FORK] COMPLETED
[OS][USER][INIT] FORK_PROBE_REAPED
```

失败使用 `CHILD_STATE_FAILURE`、`CHILD_STATISTICS_FAILURE`、
`CHILD_DESCRIPTOR_FAILURE`、`PARENT_STATE_FAILURE` 或 Kernel
`FORK_FAILURE_STAGE/STATUS`；正常 QEMU 全部列为禁止标记。

## 运行时资源验收

正常工作负载从 v1.9 的 11 个 Process 增为 45 个：

- PID1 与既有十个工作/探针 Process；
- `/bin/fork_probe`；
- 首次 COW 验收 child；
- 32 个 fork 后 exec child。

Process registered/exited/collected 均为 45，wait success 为 44，Zombie 为
零；动态 KernelStack/KVA 生命周期同样为 45。用户页引用、VMA、FileBacking、
FilePageCache、FileTable、FsContext、KernelObject、页表、frame 与 buddy
最终都通过守恒或零活动检查。

## 日志策略

fork 与 COW 热路径不逐页打印。用户层每个语义只打印一次；Kernel 在所有
Process 回收后打印冷路径摘要：

```text
[OS][KERNEL] USER_PAGE_REFERENCE_ACTIVE_ENTRIES=0x...
[OS][KERNEL] USER_PAGE_REFERENCE_ACTIVE_REFERENCES=0x...
[OS][KERNEL] USER_PAGE_REFERENCE_PEAK_ENTRIES=0x...
[OS][KERNEL] USER_PAGE_REFERENCE_FIRST_SHARES=0x...
[OS][KERNEL] USER_PAGE_REFERENCE_RETAINS=0x...
[OS][KERNEL] USER_PAGE_REFERENCE_RELEASES=0x...
[OS][KERNEL] USER_PAGE_REFERENCE_EXCLUSIVE_RESTORES=0x...
```

来宾 PIT 继续输出单调时间，宿主给每条串口行增加 `[QEMU][T+...ms]`。每个
QEMU 阶段有内部 deadline 和外层 CTest timeout，新增 fork 循环不能留下
后台 QEMU。

## 实现中捕获的问题

真实 QEMU 闭环发现并修复三类仅靠纯模型难以暴露的问题：

1. 父提交曾把原本 readonly leaf 也标 COW，导致只读 PTE 与 VMA 语义不一致；
2. `GetVirtualMemoryStatistics` 写 COW 用户页时，旧 writable 验证在主动
   private break 前拒绝地址；
3. 进程数量扩展后，Kernel 结果汇总数组仍按旧容量遍历，产生越界风险。

两阶段回滚还补齐了“提交中途失败后 child 已释放，但 parent COW 元数据只剩
一个引用”的恢复路径。最终实现会删除该元数据并恢复父页 writable。

## 阶段边界

v1.10 没有宣称：

- 用户多 Thread fork 停世、`vfork` 或 Linux `clone`；
- pipe/dup/重定向、外部 Shell 或 job control；
- shared anonymous、huge-page COW、swap、overcommit 或 OOM killer；
- writable `MAP_SHARED`、dirty/writeback 或 `msync`；
- SMP TLB shootdown。

下一阶段 v1.11 在本阶段已经稳定的 FileTable 继承和 fork/exec/wait 上实现
Unix I/O、外部 Shell 与核心工具。
