# v2.11 VFS 元数据缓存与可扩展路径解析

状态：第一增量已完成，工程候选，尚未发布

日期：2026-08-23

## 目标

在不改变 VFS 可观察语义的前提下，逐步加入 dentry/inode metadata cache，减少重复
open/stat/exec/chdir 的后端 lookup 与 metadata I/O。rootfs v4、ABI 2.4.0、ATA/NVMe 和
4 GiB 手机参考规格保持不变。

## 增量顺序

1. identity、Positive/Negative/Stale、引用、generation 与 LRU 纯模型（已完成）；
2. inode metadata cache；
3. Positive dentry 生产 lookup 与 miss 合并；
4. Negative dentry 与创建失效；
5. 全部命名空间修改、mount、cwd/root 与符号链接一致性；
6. hash/shrinker、内存压力、错误恢复和持久化矩阵。

## 第一增量范围

- 新增固定容量 `VfsNamespaceCache`，存储由调用方长期提供，操作不分配、不访问后端；
- dentry key 冻结为 mount、parent inode identity、精确名称长度和全部名称字节；
- inode identity 冻结为 superblock/node identifier+generation，不包含 mount；
- Positive dentry 持 inode generation token，Negative 不持 inode；
- Cached/Stale 分离 lookup 可见性与旧引用寿命，同 key 新旧项可并存，token 防 ABA；
- inode 单独统计 dentry/external 引用，失效级联目标项和全部 child 正负项；
- dentry/inode 各自按 access generation 选择零引用 LRU，inode 淘汰还要求零 dentry 引用；
- 本增量不接 `Vfs::Resolve`、不缓存 stat 字段、不新增 QEMU marker 或用户 ABI。

## 第一增量验证证据

- unit 覆盖正负项、alias、Stale、父级失效、容量、完整名称、类型冲突、LRU 和 ABA；
- integration 覆盖跨 mount key 隔离、共享 inode 和 rename 风格新旧项并存；
- randomized 使用种子 `0x44454E5452594C52` 执行十万轮生命周期 oracle；
- fresh CAW Debug build 共 3406 步且零警告；新增三组、现有 VFS unit/randomized 与命名
  focused 门禁为 6/6、0 失败，CTest 58.77 秒；
- final fresh CAW `python3 tools/os.py verify` 为 243/243、0 失败：73 unit、82 integration、
  55 randomized、33 system，含 25 条 failure-path；CTest 992.72 秒，端到端 1065 秒；
- 4 GiB ATA primary 78.38 秒，ATA/NVMe reclaim 84.70/81.81 秒，ATA/NVMe OOM
  82.23/81.59 秒，NVMe 正常/EIO/timeout 2.62/2.56/10.12 秒，NVMe root primary
  78.36 秒，ATA/NVMe persistence 170.54/159.20 秒；
