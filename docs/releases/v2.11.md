# v2.11 VFS 元数据缓存与可扩展路径解析

状态：六个增量已完成，工程候选，尚未发布

日期：2026-08-23

## 目标

在不改变 VFS 可观察语义的前提下，逐步加入 dentry/inode metadata cache，减少重复
open/stat/exec/chdir 的后端 lookup 与 metadata I/O。rootfs v4、ABI 2.4.0、ATA/NVMe 和
4 GiB 手机参考规格保持不变。

## 增量顺序

1. identity、Positive/Negative/Stale、引用、generation 与 LRU 纯模型（已完成）；
2. inode metadata cache（已完成）；
3. Positive dentry 生产 lookup 与 miss 合并（已完成）；
4. Negative dentry 与创建失效（已完成）；
5. 全部命名空间修改、mount、cwd/root 与符号链接一致性（已完成）；
6. hash/shrinker、内存压力、错误恢复和持久化矩阵（已完成）。

## 第一增量范围

- 新增固定容量 `VfsNamespaceCache`，存储由调用方长期提供，操作不分配、不访问后端；
- dentry key 冻结为 mount、parent inode identity、精确名称长度和全部名称字节；
- inode identity 冻结为 superblock/node identifier+generation，不包含 mount；
- Positive dentry 持 inode generation token，Negative 不持 inode；
- Cached/Stale 分离 lookup 可见性与旧引用寿命，同 key 新旧项可并存，token 防 ABA；
- inode 单独统计 dentry/external 引用，失效级联目标项和全部 child 正负项；
- dentry/inode 各自按 access generation 选择零引用 LRU，inode 淘汰还要求零 dentry 引用；
- 本增量不接 `Vfs::Resolve`、不缓存 stat 字段、不新增 QEMU marker 或用户 ABI。

## 第二增量范围

- inode slot 保存 backend 原始 size/allocated size/link count/time/uid/gid/mode；
- Empty/Loading/Ready 与独立 metadata generation 组成 load ticket，失效后迟到结果不能提交；
- 第一个 miss 在 cache lock 外读取 backend；Ready 顺序命中复用，Loading、容量和 generation
  耗尽正确旁路且不发布结果；
- `Stat`、权限检查、普通/目录/exec 打开、sticky/创建权限与 `StatOpenFile` 共享缓存，
  `StatOpenFileUncached` 保持页缓存递归边界；
- chmod/chown/write/truncate/create/link/rename/unlink/rmdir/symlink 成功后按 target/parent
  identity 失效，backend 失败不失效；
- 内核 BSS 固定配置 4096 dentry + 2048 inode slot，不分配、不在 spin lock 内执行 I/O；
- FilePageCache 逻辑 size 在返回时覆盖原始 metadata，不写回 inode slot；
- Positive/Negative dentry 生产 lookup、并发 metadata waiter 和 hash/shrinker 仍在后续增量；
- 本增量不新增来宾日志、QEMU marker、ABI、rootfs v4 格式或硬件能力。

## 第三至第五增量范围

- `LookupChild` 先查完整 dentry key：Positive 重建 vnode，Negative 返回 NotFound；
- 只有 cache miss 调 backend，Succeeded/NotFound 分别发布正/负项，EIO/Corrupt/权限错误
  永不缓存；
- 全局 resolution transaction 合并同 key 并发 miss，hosted 八线程只产生一次 backend
  lookup；容量或 generation/counter 耗尽只旁路发布；
- create/mkdir/symlink、link、rename、unlink/rmdir 在 backend commit 后精确失效目标 key、
  target/source/destination 与 parent metadata；
- resolution/metadata 两把 RuntimeMutex 使用固定顺序，关闭 commit 后、失效前的陈旧命中
  窗口；backend 失败不发布新结果；
- mount crossing 继续在命中后处理，mount id 隔离 key；cwd/root 的打开 Path、符号链接
  target、DAC、orphan 和 vnode generation 语义保持不变。

## 第六增量范围

- 调用方固定提供 dentry/inode hash entry 与 bucket，生产配置为 4096/8192 和 2048/4096；
- 只有 Cached 项入 index，Stale token 留槽但立即从 hash lookup 消失；完整 key 二次判等；
- 容量满时先回收一个零引用 LRU，仍不足才旁路；Loading 和引用项不可回收；
- `ReclaimNamespaceCache` 接入 background pressure worker，每批有界收缩 64/64 个逻辑条目；
- 固定 BSS backing 不计入 reclaimed physical pages，不虚报真实 RAM 下降；
- 两个十万轮模型启用 hash，十万步 memfs/rootfs namespace oracle 也启用生产缓存；
- 不新增系统调用、ABI、rootfs v4 格式、网络、SMP、图形或逐 lookup VGA 日志。
