# v0.9：独立地址空间与 PIT 抢占式进程调度

## 阶段目标

本阶段把 v0.8 的单个同步用户执行单元扩展成真实多进程系统。验收不以“轮流
调用四个函数”为目标，而要求 QEMU 中的 x86-64 CPU 使用不同 CR3、不同
TSS.RSP0 和不同保存帧，在真实 PIT IRQ0 上抢占同址用户 ELF，并在退出后
回收全部进程页。

架构决策见
[ADR 0012](../adr/0012-preemptive-process-scheduling.md)。

## 进程模型

- 固定四槽 PCB，不依赖尚不能释放的早期内核堆。
- PID 从 1 开始使用 64 位单调编号；创建失败释放 Ready 槽位，但不复用
  已经对外分配过的 PID。
- 状态只实现当前有完整语义的 `Unused`、`Ready`、`Running`、
  `Terminated`，不提前伪造 blocked、zombie 或线程。
- round-robin 默认量子为四个 PIT tick。只有预算到期且存在另一个 Ready
  进程时才计为抢占；单进程到期不会制造无意义的自切换。
- 每个槽位累计 run tick 和 dispatch 次数；全局累计创建、终止、PIT tick、
  抢占和派发。

## 每进程地址空间

`PageTableManager::InitializeProcessRoot` 以永久内核根为模板：

1. 分配新的 PML4 和低端 PDPT。
2. 复制模板 PML4，清空用户栈使用的 PML4[255]。
3. 复制 PML4[0] 指向的 PDPT，清空程序窗口使用的 PDPT[1]。
4. 保留 PDPT[0] 等 supervisor 内核子树的共享引用。

用户 ELF 被进一步限制在 `0x40000000..0x7fffffff`，宿主 Python 审计与
目标 C++ 验证使用相同窗口。用户栈仍位于
`0x00007ffffffeb000..0x00007ffffffeffff`，从独立 PML4[255] 建表。
相同 ELF 可以在多个 CR3 中使用完全相同虚拟地址而落到不同物理帧。

销毁根时只递归释放 PDPT[1] 程序子树、PML4[255] 栈子树、克隆 PDPT 和
PML4 本身。接口拒绝销毁永久内核根或当前活动 CR3，防止释放正在取指/用栈的
页表。

## 上下文与内核栈

每个进程拥有“4 KiB not-present guard + 16 KiB Ring 0 栈”。内存管理器
建立低端身份映射时显式跳过四个 guard。首次现场直接在对应栈顶下方构造：

- 15 个通用寄存器；
- 规范化 vector 和 error code；
- 用户 RIP、CS=`0x23`、RFLAGS=`0x202`；
- 用户 RSP 与 SS=`0x1b`。

该结构共 176 字节，与 IRQ、异常和系统调用入口生成的用户特权帧完全同形。
三个汇编公共分发器现在采用 C++ 返回的帧地址替换 RSP，再恢复寄存器并执行
`IRETQ`。切换次序为“保存旧帧—调度状态转换—写 CR3—写 TSS.RSP0—恢复
新帧”。

`osKernelEnterScheduledProcess` 只在首个进程启动时保存内核调用链。
最后一个进程结束后，`osKernelReturnFromUserMode` 才恢复该调用链；中间
退出和用户异常直接交接到下一 PCB。

## 系统调用与故障

ABI 新增编号 3 `GetProcessId`。系统调用入口除验证 CPL、vector、CS、SS、
RSP 和栈权限外，还查询 RIP 叶页，要求它是 user、executable 且不可写。
每次调用计入当前 PCB。

`ExitProcess` 和用户 `#UD/#PF` 共享终止主路径：记录退出码或异常现场，
把 PCB 标记 Terminated，选择后继，切回内核 CR3，释放当前地址空间，再
恢复后继。Ring 0 异常仍走原有 panic，未因引入进程而放宽。

## QEMU 端到端证据

正常镜像创建一个 v0.8 smoke 和三个相同 scheduler worker。worker 都在
相同程序/BSS 虚拟地址运行，并各自执行三轮 1,500,000 次递增。每轮都验证
累计值；若叶页错误共享，至少一个实例会发现计数不是本进程期望值并失败。

一次代表性 QEMU TCG 执行观察到：

- 创建与终止进程均为 4；
- 调度期处理 107 个 PIT tick；
- 发生 24 次真实抢占和 28 次派发；
- smoke 执行 6 次系统调用；
- 三个 worker 各执行 6 次系统调用并输出一次
  `ADDRESS_SPACE_ISOLATED`；
- 四份结果全部为退出码 0；
- 退出后物理页帧统计与创建前一致，输出
  `PROCESS_RESOURCES_RECLAIMED`。

tick、抢占和派发的精确数值受 TCG/IRQ 边界影响，不作为跨环境常量；测试要求
它们达到语义下界。创建数、终止数、固定用户文本和每进程结果则执行精确次数
检查。

## 测试与审计

完整回归为 59 项 CTest：

- 调度单元测试：初始化、非法量子、容量、PID、创建回滚、量子边界、终止、
  越界读取和四块内核栈布局；
- 调度集成测试：三个进程运行 24 tick，各获得 8 tick，并核对派发/终止；
- 固定种子随机测试：4096 组量子、进程数和 tick 序列，每步保持单一
  Running 与 run tick 守恒；
- 第四个用户 ELF 审计：worker 的 AMD64、`ET_EXEC`、W^X、对齐、入口和
  1 GiB 程序窗口；
- QEMU 正常路径：精确统计四次装载、三组 worker 进度、四次终止和一次回收，
  并检查调度统计下界；
- 既有用户非法指令、用户页故障和非法 ELF 用例改经进程运行时，全部继续通过；
- v0.0--v0.8 的固件、Stage 1、内核异常、内存、设备、键盘和失败路径全部
  保持回归。

当前真实目标代码统计为 76 个 `.cpp/.hpp/.asm` 文件、8,949 个物理行、
7,743 个非空非纯注释代码行，其中 C++ 5,616 行、NASM 2,127 行。该口径只
统计 `source/` 中会进入目标系统或定义目标接口的代码，不含测试、Python
工具、CMake、链接脚本、文档、书籍和网站。

## 已知限制与下一阶段

当前只有一个 CPU、每进程一个执行线程、固定四槽和固定优先级。尚未保存
x87/SSE/AVX 扩展状态，也没有 blocked、睡眠、等待队列、父子关系、zombie、
wait、内核抢占、PCID、SMP 或负载均衡。

下一阶段 v0.10 将先定义等待条件与唤醒丢失不变量，再实现禁中断/自旋边界、
睡眠等待队列、进程等待和最小 IPC。同步原语必须建立在当前可验证的 Ready/
Running 生命周期上，不能把忙等包装成“阻塞”。
