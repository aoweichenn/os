# v2.9 内核后台执行与工作集回收

状态：六个增量已实现，工程候选，尚未发布

日期：2026-08-22

## 目标

建立可独立承载 writeback、延迟工作和后台回收的 Kernel Thread/WorkQueue 基础，随后
引入页面 aging 与后台水位回收。网络、SMP、图形和新增硬件驱动不在本阶段。

## 增量顺序

1. Kernel Thread 生命周期、协作上下文切换与资源回收（已实现）；
2. WorkQueue、任务合并、取消和 drain（已实现）；
3. writeback 从 user-return safe point 迁移到 worker（已实现）；
4. x86 PTE Accessed 采样与 file/anonymous active/inactive 队列（已实现）；
5. 低水位唤醒、高水位停止的后台回收线程（已实现）；
6. direct reclaim、后台回收、swap 和 OOM 压力矩阵（已实现）。

## 第一增量

- `ThreadEntry` 显式区分 User/Kernel；Kernel Thread 不属于 Process；
- User TID 保持低位序列，Kernel TID 从 `0x8000000000000000` 开始；
- 动态内核栈预构造协作上下文，汇编保存 callee-saved 寄存器、RFLAGS 和 RSP；
- ProcessRuntime 保存独立入口、参数、FXSAVE 状态与统计；
- 支持 create、dispatch、yield、WaitQueue block/wake、exit 和调度栈上的 reap；
- PID1 前运行两个真实 Kernel Thread，最终 scheduler、stack、KVA 和 frame 回到基线；
- QEMU 只输出九项最终聚合，不在切换或队列热路径打印。

## 第二增量

- 新增 caller-storage `WorkQueue`，容量上限 256，句柄包含 slot 和 generation；
- 即时任务使用 FIFO，延迟任务使用 `(deadline, sequence)` 二叉最小堆；
- 状态机覆盖注册、即时/延迟提交、合并、取消、锁外执行、完成、reset 和 release；
- drain 封闭新注册/提交，等待 Delayed/Queued/Running 全部归零后再开放；
- 单个任务失败只累计结果，不暂停 worker 或丢弃后继任务；
- PID1 前由第三个真实 Kernel Thread worker 执行 4 项任务并清空 6 个注册句柄；
- 第二增量冻结时 writeback 仍保持 safe-point，第三增量再迁移。

## 第三增量

- `ExecuteProcesses` 成为 User/Kernel 共同 dispatcher，跨类型切换先恢复对应 dispatcher
  stack，再按目标现场形状进入；同类型切换保持原路径；
- User→Kernel 分支收束用户 CR3、FS、FX、TSS、CpuLocal、SYSCALL/IRQ 入口状态，
  Kernel→User 分支保存 Kernel RSP/FX；
- 常驻第四个 Kernel Thread 使用稳定 WorkHandle 执行普通文件 writeback；user-return
  只提交工作，不再执行 VFS I/O；
- 低水位 Dirty 页使用 Linux 默认同量级的 5 秒老化 deadline；软水位/显式请求会把
  Delayed 项即时提升到 ready；
- Worker 通过 `KernelWork` WaitQueue 和 scheduler deadline park/unpark，每个 64 页 batch
  后 yield；timer IRQ 只到期/wake/reschedule；
- 最后一个 User Thread 退出后取消残余工作、停止/reap Worker 并释放句柄；硬 Dirty limit
  direct fallback、显式同步和退出 flush 仍保持同步完成语义。

## 当前边界

- `ExecuteReadyKernelThreads` 独立测试 API 仍拒绝 User Thread；生产 dispatcher 已支持混合；
- Ring 0 timer IRQ 不抢占 Kernel Thread，调度仍为单 BSP 协作式；
- 常规 writeback 已由 Worker 驱动，user-return 仅提交；
- PTE Accessed aging、active/inactive 队列和后台水位 reclaim 已实现；
- direct/background 已共享 0..200 swappiness 配额与候选不足转赠策略；
- 本版本不启动教材、网站、Sites 或公开发布闭环。

## 第四增量

- 新增 PageAgingManager：物理帧+kind 身份、开放寻址 hash、file/anonymous 四队列、
  alias Accessed OR/eligibility AND、提升/降级/候选与跨轮重分类；
- 页表接口读取并清除 4 KiB leaf A 位，保留地址和全部权限位，仅对活动 CR3 `invlpg`；
- 同一常驻 Worker 增加每秒周期 WorkItem；file cache、用户 VMA/PTE 和 Zombie/帧复用
  生命周期在一个 observation transaction 中收束；
- PageAging backing 使用真实 frames/KVA：4 GiB 为 4096/8192，32 GiB 为
  32768/65536；常驻分配在资源基线前建立，不扩大 BSS、不隐藏 resident；
- 新增单元与十万步随机两项；ATA focused 已观察 active/inactive、冷热提升/降级与候选
  非零并最终归零；ATA/NVMe pressure 为 38.15/39.64 秒，两条用户故障隔离通过；
- 本增量不消费 candidate，不改变既有 direct reclaim、swap 与 OOM 顺序。
- 最终完整 `verify` 为 213/213、0 失败：64 unit、72 integration、46 randomized、
  31 system，含 25 条 failure-path，CTest 386.00 秒；最终轮 ATA/NVMe primary 为
  36.84/37.98 秒，ATA/NVMe pressure 为 40.23/40.37 秒，两条三启动持久化为
  75.42/77.49 秒。

## 第五增量

- 新增 `BackgroundReclaimController`，用 Sleeping/Running/BackingOff 冻结 low 唤醒、
  high 停止、每批 64 页和一秒退避；用户 direct reclaim 收紧到 minimum watermark；
- 常驻 Worker 注册第三个生产 WorkHandle。后台批次按 cold clean file、dirty/error
  writeback、cold anonymous swap 执行并在批次后 yield；IRQ/队列锁内没有 VFS 或 I/O；
- PageAging candidate 改为显式条目状态，解决“刚降级 Inactive 被误判为候选”；file cache
  access generation 改变会撤销旧候选，selection/completion 防止复用帧重复消费；
- FilePageCache 增加有界 clean candidate selection/completion；匿名 swap 增加同构回调，
  成功释放前由 `PageAgingManager::Forget` 删除精确物理身份；
- 新增 BackgroundReclaim 单元与十万步随机状态机，并扩展 PageAging、FilePageCache、
  MemoryPressure 单元/随机模型；聚焦 9/9、0 失败，实耗 4.95 秒；
- 4 GiB ATA/NVMe pressure 分别 39.00/40.06 秒通过。ATA 有效轨迹为 wake/sleep 9/9、
  batch 24、clean 588、writeback 329、anonymous 36、reclaimed 624、failure 0；
- 后台写回与随后一轮 aging/clean eviction 是异步阶段，旧 V2.8
  `reclaimed_written_file_page_count` 不再作为后台成功条件；稳定门禁改为后台 clean、
  writeback、total 非零并继续要求系统总 anonymous swap 非零。固定后台 anonymous 份额
  留给第六增量，避免把协作调度时序写成脆弱断言。
- 最终 CAW Debug `verify` 为 215/215、0 失败：65 unit、72 integration、47 randomized、
  31 system，含 25 条 failure-path，CTest 374.98 秒；全量 ATA/NVMe pressure 为
  38.40/41.19 秒，primary 为 36.49/36.84 秒，三启动持久化为 72.49/74.89 秒。

## 第六增量

- `PlanMemoryReclaim` 新增 file/anonymous 预算，以 `floor(target*swappiness/200)` 分配，
  两类候选都存在时保留最小公平份额，候选不足自动转赠；0 禁止匿名、200 优先匿名；
- direct reclaim 与后台 Worker 使用同一 planner，file 预算内部保持 clean-first，再进入
  dirty/error writeback；最终输出计划 file/anonymous 累计页数与当前 swappiness；
- 私有匿名 frame 的最后引用在归还分配器前执行 aging forget，覆盖 swap completion、
  unmap、exec、exit 和 OOM 生命周期，避免 frame 复用继承旧身份；
- 新增可配置 `swappiness=0` 的 `oom-pressure` 内核 profile 和 `/bin/oom_probe`。程序从
  `/proc/meminfo` 读取实时预算，让较大子进程持有匿名页，较小父进程制造压力并验证
  SIGKILL wait 结果；
- 最终 ATA/NVMe OOM 门禁分别 40.19/40.93 秒通过；ATA/NVMe reclaim-pressure 分别
  39.05/39.52 秒通过。OOM 路径均为 invocation 1、kill 1、anonymous swap 0，最终
  runtime/smoke/resource validation 全部通过；
- MemoryPressure 与 BackgroundReclaim 单元/十万步随机、OOM ELF layout focused 5/5
  通过；最终 CAW Debug `verify` 为 218/218、0 失败：65 unit、73 integration、
  47 randomized、33 system，含 25 条 failure-path，CTest 476.96 秒；ATA/NVMe
  persistence 为 77.80/79.08 秒。
