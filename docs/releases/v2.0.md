# v2.0 发布记录：集成冻结与可复现交付

## 发布结论

v2.0 是第二周期的集成发布，不是第十九个机制开发版本。生产系统保持 v1.18
冻结的 ABI v2.0.0、69 个系统调用、rootfs 格式 3、最小 devfs、六文件只读
procfs 和 32 个用户工具；本阶段只提升项目版本，执行完整回归，并把主仓、
教材、手机副本、独立网站和 Sites 生产部署绑定为一份可追溯交付。

QEMU 仍只模拟 x86-64 PC 硬件。ROM 固件、Stage 1、模式切换、ELF loader、
Kernel、驱动、运行时、用户程序、rootfs 和测试协议全部由项目实现；v2.0
没有引入 BIOS、UEFI、GRUB、第三方 bootloader、宿主 syscall 或宿主文件
系统作为来宾启动捷径。

## 冻结范围

v2.0 冻结以下产品事实：

- 项目版本为 2.0.0；
- 用户 ABI 保持 2.0.0，调用号 1--69，公共错误区间 -1---57；
- rootfs 继续使用格式 3 和 256 块 ordered metadata journal；
- 正常启动链为自研 ROM → Stage 1 → Kernel → `/sbin/init` → `/bin/sh`
  → `/bin/*`；
- 生产 Kernel 不内嵌普通 Shell、工具、producer 或 worker 用户载荷；
- 三档运行规格为 64 MiB bootstrap、256 MiB functional、64 GiB capacity；
- capacity 下限为 256 Process、512 Thread、单 Process 64 Thread、
  4096 fd 和 1024 pipe；
- rootfs 固定包含 32 个独立工具 ELF，Shell 支持 16 级流水线；
- 后续新增机制进入 v2.x，不修改 v2.0 的范围陈述。

项目版本、ABI 版本和 rootfs 版本由不同消费者使用。项目版本升级不要求
破坏 ABI 或持久盘面；为追求数字同步而修改线协议会违反纯集成发布边界。

## 集成审计

冻结期重新检查了以下跨模块关系：

- Process 是共享资源容器，Thread 是唯一调度实体；
- `CpuLocal`、原生 `SYSCALL` 和兼容 `INT 0x80` 汇合到同一
  `UserContext`；
- VMA 表示地址意图，PTE 表示驻留事实，COW 与 Kernel user-copy 共用
  私有化路径；
- fd、FileDescription、Vnode 和持久 inode 保持分层身份；
- IRQ、deadline、signal、close 和 cancel 只允许一个 WakeReason 获胜；
- writable shared 页经 write-notify、dirty/writeback/error 和 VFS
  `WriteAt` 落盘；
- ordered journal 在相关数据稳定后才提交元数据，mount replay 幂等；
- devfs 只拥有设备名称，Terminal/FileDescription 拥有字符行为；
- procfs provider 在不持 procfs 锁时采集快照，热路径只更新有界统计；
- 正常 `/sbin/init → /bin/sh → /bin/*` 路径只依赖磁盘用户 ELF。

本阶段没有新增 Kernel C++ 或汇编机制。文档审计修正了仍指向已删除专用
console 文件系统的历史“当前入口”链接，并把当前架构从“演进中”改为
“已冻结”；历史发布记录仍保留机制首次出现时的原貌。

## 验证结果

最终验证使用 caw 上的唯一临时目录。完整候选归档首次校验通过后，冻结期
变更以小增量覆盖，并使用本地生成的全量文件清单逐文件验证远端源码；全部
698 个期望文件通过 SHA-256 校验后才删除该专属目录中的旧构建产物。构建、
CTest 与 QEMU 不复用旧产物。

发布审计发现，工程构建 22 个合法用户 ELF，但 v1.18 的 CTest 只逐文件审计
其中 18 个；fork、Thread、time 和 signal 探针虽有真实 QEMU 运行证据，
仍缺少最终 ELF 的 W^X、入口、段范围、对齐和目标身份门禁。v2.0 新增四项
产物测试，总测试图从 169 增至 173；这只补齐冻结证据，不改变目标代码。

最终源码身份与执行结果：

- 全量文件清单：698 个文件、81458 字节；
- 清单 SHA-256：
  `ef9bf628994537f33f371759cb55c5b522fcffc0db2a05a4489b5ef1182393f4`；
- 冻结增量：205712 字节，SHA-256
  `494cbc1e0e9d71e28862d161acb867a61c1740f7000888787b99fdac2cc4f659`；
- 干净 CMake 配置：0.45 秒；
- 2057 个构建步骤：5.06 秒；
- CTest：173/173、0 失败、墙钟 63.61 秒；
- QEMU：24/24，其中 bootstrap 5.56 秒、functional 8.66 秒、
  failure-path 23 项合计 6.80 秒，system 标签累计 63.22 秒。

清单记录每个文件的相对路径和内容哈希；远端 `sha256sum -c` 退出码为零。
它避免把“增量包传输成功”误当成“完整源码一致”。这些数据来自四项新增
门禁已经进入候选源码后的最终运行，不沿用 169 项候选结果。

QEMU 资源锁只串行 24 项系统测试；149 项宿主单元、集成、随机、产物和源码
门禁仍按可用 CPU 并行。每条远端命令都有有限 timeout，只管理本次验证创建
的进程，不扫描、修改或终止 caw 上其他工作负载。

验证环境：

- 主机名 `caw`；
- Intel Core Ultra 7 265KF，20 个在线 CPU；
- 内存 16223396 KiB；
- Clang 21.1.8；
- QEMU 10.1.5；
- Linux 6.6.87.2 WSL2 x86-64；
- 唯一验证目录使用 `/tmp/aoweichen-os-v20-final-*` 模板。

## 目标产物与正常启动

构建测试直接检查最终 ROM、Stage 1、Kernel ELF、用户 ELF 和 rootfs：

- 复位向量位于 `0xFFFFFFF0`，ROM/Stage 1/Kernel 容器校验一致；
- Kernel 与用户程序为 AMD64 `ET_EXEC`，段地址、对齐和 W^X 合法；
- freestanding 目标不链接 libc、libstdc++、异常、RTTI 或宿主运行时；
- 共享 ABI 的结构大小、对齐、字段 offset 和 ELF 身份编译期锁定；
- 32 个工具路径对应 32 个唯一 regular-file inode 和真实 ELF magic；
- functional Shell 实际执行新增工具，而不是只检查磁盘目录项。

三档 QEMU 运行同一生产实现，只调整 RAM 与运行时 capacity profile。64 GiB
用例必须在 4 GiB 以上分配、写回、读回并释放页帧，不能以配置常量替代硬件
行为证据。

## 日志与时间

v2.0 保持 v1.18 的日志契约：

- Kernel 日志打印来宾 PIT 单调时间、模块、事件和必要标识；
- QEMU runner 的 `T+...ms` 只表示宿主收到串口行的相对墙钟；
- 不逐 tick、逐页、逐字节、逐锁、逐 procfs read 或逐 journal block 输出；
- 正常状态在提交后输出一次，失败只保留最接近根因的一条；
- panic 路径不依赖动态分配、VFS、页缓存或可睡眠锁。

项目版本变化不修改来宾时间源，也不把宿主 wall clock 混入 ABI。

- 208 个文件；
- 61158 个物理行；

## 网站与生产发布

网站是主仓忽略的独立 Git 仓库。它从已推送且干净的 v2.0 主仓 SHA 重新
生成：

- 首页版本、测试数、终端证据和里程碑；
- 路线与架构的 v2.0 完成状态；
- v2.0 发布记录和学习章；
- 完整代码目录、代码走读和核心代码统计；
- 教材版本、页数、大小和 PDF；
- sitemap、robots、发布清单和生产 Worker 包。

网站 commit 推送后才能构建 Sites archive；Sites 只保存该精确 commit 的
产物。生产部署完成后必须从公网逐项访问首页、架构、路线、文档、代码、教材
和 sitemap，不能只依据控制面状态宣布成功。

## 已知限制

v2.0 是范围明确的教学系统，不声称等价于现代 Linux：

- 单 BSP、内核不可抢占，不支持 SMP 和跨核 TLB shootdown；
- 不支持 AVX/XSAVE、动态链接、共享库和完整 POSIX；
- 没有用户/组权限、capability、网络、图形、音频或 USB；
- ATA 为 primary master、LBA28、PIO/IRQ14 单飞，没有 DMA/AHCI/NVMe；
- 没有 `msync`、swap、overcommit、OOM killer 或通用 dentry cache；
- journal 只保护元数据，不是 data journal、快照或在线扩容；
- devfs/procfs 是项目接口，不承诺 Linux 文本或设备模型兼容。

这些限制是 v2.0 的显式非目标。它们不会以“隐藏待办”形式修改冻结结论。

## 下一周期

v2.x 必须重新选择一条主线并单独写 ADR、依赖图和退出条件。SMP、现代存储、
权限、网络、动态链接和更完整的 VM/文件系统策略都可以成为候选，但不得一次
并行展开全部方向。v2.0 保持为能够复现、解释和回归的稳定学习基线。
