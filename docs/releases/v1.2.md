# v1.2：Process/Thread、统一等待与完整 x87/SSE2 现场

## 阶段结论

v1.2 已把旧四槽 PCB 执行模型完整迁移为两级对象：

```text
Process（地址空间、描述符、文件系统上下文）
  └─ owns Thread(s)
       ├─ 通用寄存器 / 动态内核栈 / 用户栈 / TLS / signal mask
       ├─ 512-byte FXSAVE x87/SSE2 state
       └─ Ready | Running | Blocked | Exited
```

Thread 是唯一调度实体，最后一个 live Thread 退出后 Process 才成为 Zombie。
所有正常四程序、用户异常隔离、Shell、IPC、文件系统持久化和资源回收行为保持
通过；旧 `ProcessScheduler` 源码和旧测试均已删除。

## 已完成能力

### 两级身份、状态与生命周期

- `ProcessId` 与 `ThreadId` 都是显式 `uint64_t` 强类型包装，零值无效；
- PID/TID 单调分配，不等于指针或槽位，槽位复用不复用身份；
- Process 保存地址空间根和 Thread 所有权链；
- Thread 保存动态内核栈槽、用户栈、TLS、signal mask、运行统计和三类队列
  成员关系；
- run queue 使用无分配侵入式 FIFO，只有一个 Running Thread；
- `TerminateCurrentThread`、`ReapExitedThread` 与 `ReapZombieProcess`
  分开，禁止跳过 Thread 直接回收仍含成员的 Process；
- 26 字段 ResourceSnapshot 的 Process/Thread 预留字段已通过补充计数接口
  接入运行结束检查。

### WaitQueue 与锁模型

- WaitQueue 保存具名 ID、FIFO waiter、当前/累计计数与关闭状态；
- condition、timeout、signal、object close、cancel 共用单赢家 WakeReason；
- 第二次竞争唤醒返回 `WakeAlreadyResolved`，不会重复 Ready；
- close 先冻结队列，再以 `ObjectClosed` 唤醒全部 waiter；
- `SpinLock` 使用 acquire/release 原子操作与 `pause`；
- `IrqSaveSpinLock` 保存进入前 IF，在解锁后恢复原状态；
- `Mutex` 只在 Thread 上下文使用，竞争失败进入 WaitQueue，解锁直接把 owner
  交给 FIFO 队首；
- 持有任意 spinlock 时 Mutex 阻塞明确返回 `SpinLockHeld`。

### FXSAVE/FXRSTOR

- 启动读取 `CPUID.01H:EDX` 的 FXSR/SSE/SSE2；
- 配置 CR0.MP/NE、清 EM/TS，配置 CR4.OSFXSR/OSXMMEXCPT，并清
  CR4.OSXSAVE；
- 以 `FNINIT + MXCSR 0x1F80 + FXSAVE64` 建立确定性初始模板；
- 每 Thread 拥有 16 字节对齐、512 字节的 FXSAVE 区；
- 抢占、阻塞、退出保存当前 Thread，激活时恢复目标 Thread；
- 正常路径输出配置与累计保存/恢复计数，热切换不逐次打印；
- 同一镜像在 `qemu64,-sse2` 下输出 `EXTENDED_STATE_UNSUPPORTED` 并停止。

### 真实容量事务

| QEMU RAM | Process | Thread | 单 Process Thread |
| ---: | ---: | ---: | ---: |
| 64 MiB | 4 | 4 | 1 |
| 256 MiB | 64 | 128 | 32 |
| 64 GiB | 256 | 512 | 64 |

每档都建立真实用户页表根、动态双 guard 内核栈和 FXSAVE 区，不是只初始化
数组。事务让全部 Thread 进入 Exited、Process 进入 Zombie，再按两级所有权
回收；前后 frame、buddy、heap、KVA、stack、Process 和 Thread 快照零差异。
为容纳 512 个并发动态栈，KVA 描述符容量提升为 1024，栈槽容量提升为 512。

## 用户态隔离证据

正常四个用户程序按 PID 安装四组不同模式：

- XMM0 两个 64 位分量；
- XMM15 两个 64 位分量；
- 四种有效 MXCSR 舍入/控制模式；
- 四种 x87 control word；
- ST0 中的 1.0、2.0、3.0、4.0。

Shell 经真实 PS/2 输入反复阻塞；producer/consumer 经 64 字节管道发生满/空
等待与唤醒；worker 经 PIT 多次抢占。每个程序退出前再次验证自己的模式并
输出一次：

```text
[OS][USER] EXTENDED_STATE_ISOLATED
```

QEMU 协议要求精确四次，并同时要求 `EXTENDED_STATE_SAVES` 与
`EXTENDED_STATE_RESTORES` 均非零。

## 失败回滚修正

容量事务在页表根创建成功后立即登记回滚所有权，再创建 Process；因此调度器
拒绝不会遗失“尚未写入 Process 槽”的根。栈和页表正常销毁后立即清除回滚
标志，再执行 scheduler reap，避免后续失败清理对已释放资源二次销毁。

用户程序的扩展状态 NASM 对象作为显式构建产物进入七个用户 ELF；C++ 仍使用
`-mno-sse -mno-sse2`。生产 Kernel ELF 审计确认没有 `.init_array`、隐藏
构造器或宿主运行时符号。

## 已知边界与下一阶段

- 正常用户进程当前各有一个初始 Thread；用户 CreateThread/Join/Futex 留到
  v1.13，但内核模型和目标容量生命周期已经支持一 Process 多 Thread；
- `INT 0x80` 仍是唯一用户入口，下一阶段 v1.3 引入 CpuLocal、
  `SYSCALL/SYSRET`、`SWAPGS` 和统一 UserContext；
- 内核仍是单 BSP、内核不可抢占模型，不实现 SMP、远端 TLB shootdown 或
  per-CPU run queue；
- AVX/XSAVE 明确禁用；
- Process/Thread 后端仍有 256/512 编译期上界，后续对象缓存接入不得改变
  已冻结的 ID、状态或等待语义。

完整设计理由见
[ADR 0029](../adr/0029-process-thread-waitqueue-fxsave.md)。
