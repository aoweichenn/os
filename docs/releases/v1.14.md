# v1.14 发布记录：进程信号、进程组与安全 sigreturn

## 发布结论

v1.14 把异步用户通知接入现有 Process/Thread 所有权与 WaitQueue/deadline
单赢家协议。系统现在支持 Process disposition、Thread mask、普通 pending
合并、进程组发送、用户 handler、严格验证的 sigreturn，以及阻塞系统调用的
中断和显式重启策略。

## 交付能力

- 新增 1--63 号普通信号位图；Kill 不可屏蔽、不可忽略且不可安装 handler；
- `SignalManager` 分离 Process 与 Thread 状态，按轮转游标只选择一个未屏蔽
  Thread，无法选择时保留 Process pending，重复普通信号合并；
- Default、Ignore 和 Handler 三种 disposition 具备明确交付与统计语义；
- 新增进程组身份、查询、设置和按组发送；fork 继承组，用户探针建立独立组；
- ABI 固定系统调用 57--63、40 字节 `SignalAction`、176 字节
  `SignalUserContext` 与 240 字节 `SignalFrame`；
- Kernel 在用户栈合成符合 System V AMD64 对齐的 restorer 返回槽和信号帧；
  Intel NASM restorer 以系统调用 61 提交精确帧地址；
- sigreturn 验证帧身份、cookie、版本、mask、canonical 地址、段、RFLAGS、
  Thread 栈边界以及 RIP/RSP 页权限；
- 畸形帧只按 Exception/vector 13 终止目标 Process，不 panic Kernel；
- Signal 通过 `WakeThread(..., WakeReason::Signal)` 与 condition、timeout、
  close、cancel 竞争，胜者唯一且同步取消 deadline；
- descriptor/pipe wait、wait process 与 join 可按 action flag 重启；sleep 与
  futex 明确只返回中断语义；
- fork 复制 disposition 和调用 Thread mask，exec 保留 Ignore 并把 Handler
  重置为 Default，exit 回收全部信号状态；
- 主用户栈支持信号帧向紧邻未提交页的受控增长，复用 VMA、页故障权限和增长
  间距检查，fork 后栈页按需解除 COW。

## 测试证据

v1.14 构建图为 154 项 CTest：

- SignalManager 单元测试覆盖 mask 选择、普通信号合并、Ignore/Default/Handler、
  活动 frame 身份、fork 继承与 exec 重置；
- scheduler 集成测试证明 Signal 赢得 condition/timeout 竞争后只产生一个
  `WakeReason`，业务 WaitQueue 和 deadline 同时解除；
- 固定种子随机测试执行 100000 步 send/mask/deliver/complete，逐步验证普通
  信号没有重复 Thread 所有者；
- ABI 集成测试冻结系统调用 57--63 和信号结构尺寸；
- 64 MiB bootstrap、256 MiB functional 与 64 GiB capacity 运行同一个
  `/bin/signal_probe`，验证阻塞 descriptor 重启、mask 合并、进程组 Ignore、
  fork handler 继承、畸形 frame 隔离和默认信号终止；
- 历史启动、异常、内存、VFS、rootfs、fork/COW、Shell、线程、futex 和时间
  测试继续通过。

整机终态必须满足：

```text
ACTIVE_SIGNAL_PROCESSES = 0（由 ProcessRuntime 资源门禁验证）
ACTIVE_SIGNAL_THREADS = 0（由 ProcessRuntime 资源门禁验证）
ACTIVE_DEADLINES = 0
SCHEDULER_CREATED_PROCESSES = SCHEDULER_TERMINATED_PROCESSES
PROCESS_TREE_ZOMBIES = 0
RUNTIME_STATE_VALIDATION = 1
PROCESS_RESOURCE_VALIDATION = 1
```

用户端验收 marker 每项恰好一次：

```text
RESTART_WAIT_VERIFIED
MASK_COALESCE_VERIFIED
PROCESS_GROUP_VERIFIED
FORK_INHERITANCE_VERIFIED
BAD_FRAME_ISOLATED
DEFAULT_TERMINATION_VERIFIED
COMPLETED
```

QEMU runner 继续使用有界墙钟预算、QMP 状态探测和 finally 回收，不允许测试
超时留下后台模拟器。信号引入的睡眠与阻塞均使用来宾单调时间，不把宿主 TCG
速度当作语义判断。

## 安全与失败路径

- handler/restorer 必须位于用户程序地址窗口，否则安装失败；
- 用户 action、old-action、old-mask 与 signal frame 均通过逐页用户内存检查；
- 帧 magic/version/size/reserved 或 Kernel 登记五元组不一致即拒绝；
- 用户不能通过 sigreturn 设置 Kill mask、Kernel 地址、错误 selector、危险
  RFLAGS、不可执行 RIP 或不可写/可执行 RSP 页；
- 信号 frame 无法获得合法用户栈空间时只终止目标 Process；
- 按组发送找不到成员、PID 不存在、非法信号和非法 action 都返回明确错误；
- Process/Thread 回收后 SignalManager 的活动计数必须归零，不能保留 pending
  或指向旧槽位的 frame 身份。

## 日志策略

动作安装和真实投递记录具名 disposition；queued 与 handler count 只在计数
实际变化且达到二次幂时采样。重复合并不会重复打印同一个 queued count。
失败帧和帧构造失败记录有界诊断，正常结束统一输出九项信号汇总。IRQ、Thread
扫描和每个 mask 位不逐项打印。

## 兼容性与下一阶段

系统调用 0--56、旧用户 ELF、rootfs v2、ProcessWaitResult、VMA、COW、Thread、
futex 和 deadline ABI 保持兼容。新增信号终止原因使用已有 wait 结果的
termination reason 与 exception-vector detail 字段表达。

v1.15 将在现有进程组与信号交付上加入 TTY、session、controlling terminal
和前台作业控制。键盘 IRQ 只采集输入；Ctrl-C/Ctrl-Z 必须由 TTY 层翻译并发送
到前台进程组。
