## 第二周期：从 v1.0 到 v2.0

v1.0 已经证明“从复位向量到交互式 Ring 3 Shell”的纵向链路成立，但当前
用户环境仍是静态模型：进程容量固定为四，正常镜像启动时一次创建四个进程，
用户 ELF 内嵌于 Kernel，Shell 命令直接在同一个进程中执行，文件系统只支持
5120 字节文件，物理分配器只管理低 64 MiB，描述符、目录和终端能力也没有
形成可扩展的类 Unix 资源模型。

第二周期不再增加彼此孤立的演示机制，而是把这些静态边界逐步替换为可以组合的
长期架构。v2.0 的定位是：

> 一个完全沿用自研启动链、单处理器运行、可从自研文件系统装载程序、支持
> 父子进程、写时复制、VFS、管道、重定向、信号、终端、按需分页和崩溃恢复的
> 多进程类 Unix 教学操作系统。

```text

  → ABI 冻结和系统加固
  → v2.0
```

### v2.0 最终能力下限

下表给出验收下限，不把当前样例值误写成协议位宽。内部标识、计数、容量、
偏移、时间和地址仍优先使用 64 位；硬件、磁盘和 ABI 字段服从各自精确布局。

| 维度 | v2.0 验收下限 |
| --- | --- |
| 处理器 | QEMU TCG、x86-64、单 BSP；所有特权代码和启动链均由项目实现 |
| 物理内存 | 64 GiB 主规格、64 MiB 最小回归；容量由 E820/CPUID/direct-map 驱动 |
| 进程 | 至少 64 个同时存在的 PCB 槽位；PID 为单调 64 位值且不与槽位绑定 |
| 描述符 | 每进程至少 64 个描述符；共享 open-file description 具有引用计数 |
| 路径与参数 | 路径至少 1024 字节、单组件至少 255 字节、最多 64 个参数，参数和环境总计至少 32 KiB |
| 用户内存 | ELF、用户栈、匿名页和文件映射按需建立，代码保持 W^X，栈保留 guard |
| 文件系统 | 根文件系统至少 64 MiB，单文件至少 16 MiB，支持目录、rename、unlink、truncate 和崩溃重放 |
| IPC | 可动态创建至少 128 条 4 KiB 管道，支持 EOF、broken pipe、继承和阻塞唤醒 |
| 用户环境 | `/sbin/init`、外部 Shell 和至少 16 个独立 ELF 工具从磁盘装载 |
| Shell | 支持引号、环境、前后台执行、至少 8 级流水线以及 `<`、`>`、`>>` 重定向 |
| 可观测性 | 进程、内存、VFS、块层、信号和系统调用均有有界汇总，不在热路径刷日志 |

这些容量通过具名常量或运行时资源事实表达，不把 `64`、`128` 等值散落到实现
中。达到容量上限必须返回明确错误，不能覆盖现有对象、静默截断或部分提交。

### v2.0 明确不包含

为了保证第二周期可以真正完成，以下能力不进入 v2.0 验收范围：

- 多处理器启动、SMP 调度、跨核 TLB shootdown 和真正并行内核；
- ACPI 全解析、IOAPIC/MSI、AHCI、NVMe、USB 和通用 PCI 驱动框架；
- 网络协议栈、套接字、图形桌面、音频和鼠标；
- 多用户权限、安全隔离策略、容器和虚拟化；
- 动态链接器、共享库、完整 POSIX 兼容或自举编译器。

现有自旋锁和固定宽度 ABI 继续保留未来扩展空间，但不得用“以后支持 SMP”
掩盖当前单核正确性。上述能力将在 v2.x 或 v3.0 路线重新评估。

### 跨版本演进规则

- 1.x 期间系统调用编号只追加，不复用；v2.0 才允许删除已经有替代路径的
  历史专用管道和文件调用。
- 所有跨特权结构都带显式版本、长度和固定宽度字段；内核先复制到有界缓冲，
  再验证和使用。
- 文件系统 v2 使用新 magic/version。旧格式必须明确识别并拒绝或由离线工具
  迁移，不允许把非零旧盘当作空盘重新格式化。
- 每个版本只引入一个主要状态模型；实现按纯模型、宿主集成、随机性质、产物
  审计、QEMU 成功和 QEMU 失败路径逐层提交。
- 正常启动始终只创建必要的系统进程。压力测试进程必须由用户态或专用测试场景
  动态创建，不能继续作为生产镜像的固定四进程脚手架。
- 任意创建、复制、打开、映射或提交失败都必须保持原对象可用，并完整回滚本轮
  已获得的页、描述符、引用和磁盘资源。

## v1.1 可回收资源基础

### 当前进度

第一增量已经完成动态物理内存基础：

- 主 QEMU 系统测试固定为 64 GiB，64 MiB 保留为最小兼容回归；
- 受管上界由最高可用 E820 页、处理器物理地址宽度和 64 TiB direct-map
  共同决定，不存在 64 GiB 硬编码截断；
- 2-bit 页帧元数据在低端可访问 RAM 动态选址，并显式避开平台、Kernel、
  早期栈和自身占用；
- 建立 `0xFFFF888000000000` 高半区物理直映，内部使用 2 MiB 页、边界使用
  4 KiB 页；
- 页表遍历、用户页清零和 ELF 复制不再把物理地址直接当成 C++ 指针；
- 64 GiB 整机测试已经在 4 GiB 以上执行页帧分配、直映读写与释放。

仍待完成的 v1.1 内容是可分裂/合并页分配器、可释放内核堆、动态 Ring 0 栈、
64 PCB/描述符容量和通用对象生命周期；因此本节尚未标记为整个版本完成。

### 目标

消除“低 64 MiB + 64 KiB 单调堆 + 四份静态内核栈”对后续设计的限制，
让进程、VFS 和缓存能够按真实生命周期获得与归还内核资源。

### 实现范围

- 为全部可用 E820 页建立动态元数据和高半区物理直映窗口；
- 实现可分裂、合并并检测重复释放的页分配器；
- 在页分配器上建立支持对齐、释放和统计的内核堆或固定对象缓存；
- 把 Ring 0 进程栈改为按进程分配，继续保留未映射 guard page；
- 将 PCB 容量提升到至少 64，PID 与槽位彻底分离；
- 将每进程描述符容量提升到至少 64，并把底层对象所有权从槽位布局中解耦；
- 为物理页和内核对象准备引用计数与统一失败回滚工具，但本阶段不实现 COW。

### 验收标准

- QEMU 以 64 GiB 主规格启动，管理全部 64 GiB 可用 RAM，并在 4 GiB 以上
  完成读写回收；64 MiB 最小配置继续启动；
- 固定种子模型至少执行 100000 次分配、释放、分裂、合并和耗尽操作；
- 重复释放、释放保留页、错误对齐、范围溢出和元数据不足均被明确拒绝；
- 连续创建并销毁动态内核栈后，页帧、堆字节和对象计数恢复基线；
- 最终 Kernel ELF 不出现隐藏分配、`.init_array` 或新增未解析运行时符号；
- v1.0 的 73 项回归保持通过。

## v1.2 VFS 与文件系统 v2

### 目标

先建立稳定的命名空间和大文件能力，再让进程从磁盘执行，避免 exec 直接依赖
现有固定布局文件系统的内部句柄。

### 实现范围

- 定义 vnode、mount、open-file description、dentry/path view 和文件类型；
- 每进程保存 cwd，路径解析支持绝对路径、相对路径、`.` 与 `..`；
- 根文件系统升级为版本 2，采用 4 KiB 逻辑块和直接/间接块索引；
- 扩大原始磁盘并明确启动区域、根文件系统区域和工具写入边界；
- 增加 stat、truncate、unlink、rename、create、mkdir 和目录非空检查；
- 所有描述符改为引用 open-file description，共享偏移与 vnode 引用；
- 当前 Shell 命令迁移到 VFS 接口，不再直接调用具体磁盘文件系统。

### 验收标准

- 创建、重挂载并逐字节验证至少 16 MiB 的普通文件；
- 至少 1024 字节路径和 255 字节组件边界具有成功与超限测试；
- 相对路径、父目录、根目录夹取、rename 覆盖和非空目录删除语义明确；
- 两次独立 open 的偏移保持独立；内核级多引用 open-file description 的共享
  偏移由纯模型测试验证，用户 Dup ABI 留到 v1.5；
- 旧格式、截断间接块、循环/重复块所有权、孤儿 inode 和 bitmap 不一致均拒绝；
- QEMU 双启动继续证明真实 ATA 持久化，且不会静默格式化未知非零磁盘。

## v1.3 进程树与磁盘执行

### 目标

把“Kernel 内嵌四个用户 ELF”替换为“PID1 从根文件系统启动普通程序”的
长期模型。

### 实现范围

- PCB 增加 parent PID、子进程关系、退出状态和 `Zombie` 状态；
- 正常启动只创建 `/sbin/init`，由 PID1 启动 `/bin/sh` 并回收孤儿；
- 实现 Spawn、Exec 和 WaitProcess/WaitProcessId 系统调用；
- 从 VFS 读取 ELF，继续执行两遍结构、权限、范围、重叠和入口验证；
- 构造 `argc/argv/envp` 用户初始栈，参数切片不引用内核临时缓冲；
- exec 成功时原子替换地址空间并保留既有描述符引用，失败时原程序继续运行；
  close-on-exec 标志与 Dup ABI 在 v1.5 一并加入；
- 生产者、消费者和 worker 变为可由测试启动的磁盘 ELF，不再固定占用 PID。

### 验收标准

- Shell 能执行 `/bin/echo hello world`，参数跨四层边界后逐字节一致；
- 父进程等待时其他 Ready 进程继续运行，退出状态只能被成功收取一次；
- 父进程提前退出时子进程重归 PID1，PID1 能最终回收其 Zombie；
- 非法路径、非普通文件、非法 ELF、参数过多、内存不足和进程表耗尽保持失败原子性；
- 目标机连续创建并等待至少 256 个短进程，资源统计回到启动基线；
- 生产正常路径不再依赖内嵌用户 ELF；专用故障镜像可以保留最小测试载荷。

## v1.4 fork 与写时复制

### 目标

学习 Unix 进程复制语义与页故障协作，不用每次 fork 立即复制全部用户页。

### 实现范围

- 实现 ForkProcess，父子从同一系统调用返回点获得不同结果；
- 为可共享用户页维护物理帧引用计数；
- 将可写用户页暂时映射为只读 COW，代码和只读数据继续只读共享；
- 写页故障验证 COW 原因后分配、复制、更新 PTE 并失效对应 TLB 项；
- fork 复制描述符引用、cwd、信号状态和进程关系，不复制内核锁状态；
- 物理页不足或页表分配失败时撤销全部新引用，不改变父进程。

### 验收标准

- 父子在相同虚拟地址读到初始值，任一方写入后数据和物理页所有权分离；
- 只读代码写入仍是保护故障，不能被 COW 路径错误放行；
- 多代 fork、父先退出、子先退出和 exec-after-fork 均正确回收；
- 随机页模型覆盖共享、写入、退出、失败回滚和引用计数下溢；
- QEMU 证明 fork 初始物理页增量显著小于立即复制全部地址空间；
- fork/exec/wait 压力结束后页表、叶页、描述符和 PCB 统计回到基线。

## v1.5 Unix I/O 与外部 Shell

### 目标

让文件、终端和管道真正通过描述符继承组合，使 Shell 从命令实现者变成进程
编排者。

### 实现范围

- 实现动态 Pipe、Dup、Dup2/Dup3、描述符继承和 close-on-exec；
- open-file description 维护共享偏移、状态标志和引用计数；
- Shell 解析简单命令、至少八级流水线、`<`、`>`、`>>` 和后台标记；
- 除 cd、export、jobs、exit 等必须影响 Shell 自身状态的命令外，其余命令
  迁移为 `/bin` 下独立 ELF；
- 建立自研用户启动入口和基础字符串、数字格式化、系统调用包装；
- 增加 echo、cat、ls、pwd、mkdir、rm、mv、cp、wc、true、false 等独立工具。

### 验收标准

- `cat input | wc > output` 经两个管道端点、dup 和 exec 得到正确持久文件；
- 父进程关闭无关端点后，读者准确观察 EOF，写者在无读者时得到 broken pipe；
- 同一 open-file description 的共享偏移与两次独立 open 的独立偏移可区分；
- 流水线中任一 spawn/pipe/dup 失败时，已创建子进程和描述符均被回收；
- QEMU 自动执行混合引号、重定向、流水线和后台命令脚本；
- Shell 自身不再包含 cat、ls、write 等业务实现。

## v1.6 时间、信号与终端

### 目标

为异步控制流建立明确的进程级语义，使用户可以停止、等待和中断前后台任务。

### 实现范围

- 建立单调 deadline 队列和 Sleep 系统调用，不用忙等实现延时；
- 实现最小信号集：SIGCHLD、SIGINT、SIGTERM、SIGKILL、SIGPIPE、
  SIGSTOP 和 SIGCONT；
- 定义信号 pending、mask、默认动作、用户处理器和受验证的 signal frame；
- 增加进程组、会话、前台进程组和父子等待事件；
- 把控制台拆为字符设备与 canonical line discipline，处理 Ctrl-C、Ctrl-D；
- Shell 支持前台等待、后台任务、jobs、fg、bg 和 kill。

### 验收标准

- sleep 进程阻塞期间 CPU 进入 idle，deadline 到达后只唤醒到期对象；
- Ctrl-C 只作用于前台进程组，不能终止 Shell 或后台任务；
- SIGCHLD 不丢失，多个子进程近同时退出时仍能全部回收；
- 用户伪造、越界或重复使用的 signal frame 被拒绝且不会提权；
- 停止、继续、终止和 broken-pipe 默认动作均有单元与 QEMU 证据；
- 终端热路径保持有界，逐字符输入不刷串口日志。

## v1.7 按需虚拟内存与用户运行时

### 目标

把“装载时一次映射全部页面”演进为按需地址空间，并让普通用户程序可以安全
使用自研动态内存。

### 实现范围

- 以 VMA 描述 ELF、栈、匿名和文件映射，保持区间不重叠与权限不变量；
- 实现 Brk、Mmap、Munmap 和受限的文件映射；
- ELF 只先登记 VMA，首次访问由页故障按需读取、补零或分配；
- 用户栈按受控规则增长，越过最大范围或 guard 时终止进程；
- 自研用户运行时提供启动入口、malloc/free、字符串、格式化和环境访问；
- OOM 只终止或拒绝责任进程，不破坏内核全局资源。

### 验收标准

- 大 ELF 启动时的常驻页少于其全部可装载页，访问后统计按预期增长；
- BSS 首次读取为零，文件尾页补零，私有映射写入不修改原文件；
- W^X、用户/内核边界、栈 guard、区间溢出和 unmap 后访问均由真实 #PF 验证；
- 随机 VMA 模型覆盖 map/unmap/split/merge/fork/exec 和失败原子性；
- 用户 malloc/free 压力后可用字节恢复，重复释放和无效指针被稳定处理；
- 物理内存耗尽场景仍能输出一次有界诊断并回收失败进程。

## v1.8 异步块层与崩溃恢复

### 目标

把同步 ATA PIO 调用和 Dirty/Clean 全盘提交演进为可排队、可等待、可重放的
持久化系统。

### 实现范围

- 建立与具体文件系统解耦的块设备和请求队列；
- 启用 ATA IRQ14，用中断推进有界 PIO 请求并唤醒等待进程；
- 统一块缓存、文件页和写回所有权，定义锁顺序与回写策略；
- 为元数据更新实现有校验和、序号和 commit record 的日志；
- 启动时扫描日志并重放已提交事务，丢弃未提交事务；
- 实现 Sync 和 Fsync 的稳定完成语义与设备 flush 边界。

### 验收标准

- 前台文件 I/O 等待设备时其他进程仍能运行，IRQ14 路径不轮询刷日志；
- 请求超时、ERR、DF、短传输和设备队列耗尽均有明确错误与恢复策略；
- 在每个日志写入边界终止 QEMU 后重启，文件系统只呈现事务前或事务后状态；
- 日志损坏、重复 commit、序号回绕边界和重放幂等性通过随机测试；
- fsync 返回后启动新 QEMU 必须观察到相同数据；
- 缓存、请求、日志和 inode 的锁顺序通过审计并无丢失唤醒。

## v1.9 ABI v2 与系统加固

### 目标

在最终发布前冻结长期用户接口，清除 0.x/1.x 过渡入口，并扩大可观测性和
故障隔离证据。

### 实现范围

- 以 x86-64 SYSCALL/SYSRET 作为主系统调用入口，设置 STAR/LSTAR/FMASK；
- 入口使用专用内核栈和受控用户现场，非 canonical 返回目标改走安全 IRETQ；
- 冻结 ABI v2 的调用号、错误值、结构版本、参数寄存器和兼容策略；
- 移除已经被统一描述符、VFS 和进程接口替代的历史专用调用；
- 提供 `/dev/console`、`/dev/null` 与只读 `/proc` 进程/内存统计；
- 增加按模块限流的诊断、断言、锁顺序检查、系统调用统计和资源泄漏快照；
- 对 ELF、路径、VFS、signal frame、系统调用结构和磁盘日志执行固定种子变异。

### 验收标准

- SYSCALL 正常返回、信号打断、抢占、fork 返回和非 canonical 目标均有机器码级审计；
- 任意用户寄存器、指针、长度和标志组合不能访问 supervisor 页或提升 IOPL；
- `/proc` 快照自洽且读取过程不会要求在热路径逐事件打印；
- 所有资源对象都有创建、引用、关闭、回收和泄漏统计；
- 完整历史失败镜像继续在原提交边界停止；
- ABI 文档、用户运行时、内核分发和独立审计器对同一编号与布局达成一致。

## v0.10 验收记录

- 调度状态机新增 `Blocked` 和具名 `ProcessWaitReason`；阻塞进程不再参与
  Ready 轮转，条件满足后由定向唤醒恢复，block/wakeup 分别计数。
- 自旋锁使用原子 exchange-acquire、store-release 和 x86 `PAUSE`；RAII
  guard 保证所有管道早退路径释放锁。内核 ELF 审计同时拒绝 `.init_array`、
  `.fini_array`、`.ctors` 和 `.dtors`，不依赖未执行的动态全局构造。
- 固定 64 字节环形管道实现部分读写、回绕、would block、EOF、broken pipe、
  端点关闭与统计；用户复制发生在管道锁外，单次 ABI 传输最多 64 字节。
- 系统调用编号 4..9 分离 Try 与 Wait。唤醒只表示条件可能推进，用户包装必须
  循环重试，避免把等待误当成已完成 I/O。
- 正常镜像创建 PID1 生产者、PID2 消费者和两个 worker。256 字节确定性载荷
  经 31 字节消费缓冲完整校验，真实产生读/写阻塞并最终观察一次 EOF。
- 端点权限、非法用户指针、未知调用、重复关闭和异常终止自动关闭均具有稳定
  失败语义；关闭会唤醒对侧，避免等待不可能再发生的条件。
- Kernel ELF 暂存区迁移到 `0x03E00000..0x03F00000` 的 1 MiB usable RAM
  窗口。Stage 1 先用 E820 图验证完整覆盖，并把 `PT_LOAD` 上界收紧为
  `0x03E00000`，防止源/目标重叠。
- 单元测试覆盖管道所有边界和调度状态转换；四线程同步集成测试执行 200,000
  次受锁递增；固定种子管道模型执行 32,768 步，调度器随机测试继续逐步检查
  单一 Running、等待原因和统计守恒。
- 完整回归共 64 项 CTest，其中 20 项 QEMU 系统测试、22 项失败路径、10 项
  固定种子随机测试；全部通过。

## v0.11 验收记录

- 启动磁盘扩为精确 2 MiB。LBA `0..2047` 固定归启动链，打包器拒绝
  Kernel 文件越过 1 MiB 边界；LBA `2048..3071` 是 1024 个文件系统块，
  最后 1024 个扇区保留。该边界修复了真实 Kernel ELF 与早期 LBA 1024
  设计重叠的问题。
- 固定磁盘格式包含带 CRC32 的 superblock、32 inode 位图、八块 inode 表、
  数据位图、1013 个数据块和 64 字节目录项。所有多字节字段显式小端编码，
  不把 C++ 结构体布局当作磁盘 ABI。
- inode 0 永久保留、inode 1 固定为根目录；每个 inode 有十个 64 位直接块，
  当前普通文件与目录最大均为 5120 字节。绝对路径最长 128 字节，组件最长
  40 字节并拒绝斜杠、控制字符、`.` 和 `..`。
- 八项固定容量 LRU 写回缓存统计命中、未命中、淘汰与设备 I/O；热路径不打印
  逐块日志。ATA PIO 新增 `WRITE SECTORS` 和 `FLUSH CACHE`，轮询继续保持
  有界并区分 busy timeout、DRQ timeout 与设备错误。
- 修改操作先把 superblock 持久化为 Dirty，再写回数据和元数据，最后写为
  Clean；挂载拒绝 Dirty、magic/CRC 损坏和所有非零未知格式，仅在超级块
  整扇区全零时首次格式化。
- 一致性检查联合验证 inode/data bitmap、CRC、块唯一所有权、目录类型与名称、
  根目录可达性、孤儿、环和重复引用。当前无硬链接格式下，每个根外 inode
  必须恰有一条可达目录引用。
- 系统调用编号 10..15 提供 Open、Read、Write、Close、Mkdir 和 Sync；
  每个 PCB 保存四个独立文件句柄并在退出或异常时自动关闭。第三参数经 RDX
  传递，用户指针先复制到有界内核缓冲。
- PID1 把 256 字节确定性载荷写入 `/shared/payload.bin` 并同步，PID2 在
  管道 EOF 后重新打开文件验证。每进程文件读写统计、最终全盘一致性和内核
  独立读回共同构成目标内证据。
- 单元测试覆盖格式编码与 CRC，集成测试覆盖跨块文件、重挂载、截断、孤儿和
  非法名称，固定种子随机测试执行 128 次“写入—新实例挂载—模型对照”。
  QEMU 持久化测试在同一 snapshot-off 临时磁盘上连续启动两次，随后翻转
  超级块字节；第三次必须报告损坏且不能进入 Ring 3 或 `READY`。
- 完整回归共 68 项 CTest，包含四项文件系统宿主/目标新增测试，既有启动、
  异常、设备、用户态、调度和 IPC 路径继续通过。

## v1.0 验收记录

- 每个进程拥有八槽统一描述符表；fd 0/1/2 固定为控制台输入、输出和错误，
  动态槽保存普通文件、目录或管道端点，退出路径按表关闭全部资源。
- ABI 编号 16..22 提供通用 TryRead/TryWrite、可读/可写等待、通用 Close、
  OpenDirectory 和 ReadDirectory；第四参数位置固定为 R10。
- PS/2 Set 1 解码器覆盖基础 US 键区、左右 Shift、Caps Lock、Enter、
  Backspace 与 Tab。字符进入 256 字节 FIFO，满时拒绝覆盖并统计丢弃。
- 最后一个 Running 进程可以进入 Blocked。只剩阻塞进程时，内核恢复永久
  CR3 与默认 RSP0，执行相邻的 `sti; hlt; cli`，由 IRQ 改变条件后重新派发。
- 独立 freestanding Shell ELF 使用固定 128 字节行、八参数解析器和 256
  字节写缓冲，不链接 libc 或 C++ 标准库；编译器需要的 memset/memcpy 由
  用户最小运行时自研。
- Shell 提供 help、echo、pwd、ls、mkdir、write、cat、sync、exit；引号、
  转义、超长、未知命令、目录 EOF 与文件错误均有明确语义。
- 正常镜像创建 Shell、生产者、消费者和一个 worker。管道与文件回归迁移到
  统一描述符，原 256 字节载荷、持久化和地址空间隔离证据继续成立。
- QEMU 在 Shell READY 后逐字产生十条命令的键盘事件；109 个字符完整经过
  i8042、IRQ1、解码、FIFO、阻塞唤醒和 Ring 3 读取，最终零丢弃、零残留。
- Kernel ELF 审计在实现过程中实际拒绝了隐式 `.init_array`，描述符表改为
  平凡构造并由显式 Initialize 完整建立状态。
- 控制台、描述符和解析器单元测试、目录集成测试、4096 轮解析随机测试、
  真实 QEMU Shell、同盘双启动和损坏拒绝共同组成 73 项 CTest。
