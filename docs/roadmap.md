# 开发路线

| 版本 | 阶段 | 核心验收目标 |
| --- | --- | --- |
| v0.0 | 工程基线（完成） | 构建、测试、持续集成和文档结构可复现 |
| v0.1 | 复位与串口（完成） | 自定义 ROM 从复位向量输出串口日志 |
| v0.2 | 固件加载（完成） | IDE PIO 正确加载自研 Stage 1 |
| v0.3 | Long Mode（完成） | 独立完成 16 位到 32 位再到 64 位切换 |
| v0.4 | 内核加载（完成） | 校验并加载 ELF64 内核，交接 BootInfo |
| v0.5 | 内核基础（完成） | 建立 GDT、IDT、TSS、异常和 panic |
| v0.6 | 内存管理（完成） | 实现物理页、虚拟地址空间和内核堆 |
| v0.7 | 中断与设备（完成） | 驱动 PIC、PIT、键盘和 IDE |
| v0.8 | 用户边界（完成） | 进入 Ring 3，实现用户 ELF 和系统调用 |
| v0.9 | 进程调度（完成） | 实现抢占调度和进程生命周期 |
| v0.10 | 同步与 IPC（完成） | 实现锁、阻塞/唤醒和管道 |
| v0.11 | 文件系统（完成） | 实现 inode、目录、文件和持久化 |
| v1.0 | 用户环境 | 提供 Shell、基础命令和完整系统回归 |

每个阶段的详细验收项维护在本文档中；阶段开始前应进一步拆分为可独立验证的任务。

## v0.1 验收记录

- 128 KiB ROM 精确映射 `0xFFFE0000..0xFFFFFFFF`。
- `0xFFFFFFF0` 复位向量通过 16 位 near jump 进入 `0xFFFFF000`。
- 入口自行建立段寄存器、栈和方向标志状态。
- COM1 自行完成 115200、8N1、FIFO 和 modem control 初始化。
- 发送前轮询 THRE 状态位，最多 `0xFFFF` 次后返回失败。
- 正常镜像输出 `RESET` 与 `SERIAL_READY`。
- 故障注入镜像输出 `RESET`，但必须在超时后停止且不能输出
  `SERIAL_READY`。
- ROM 布局由最终二进制审计，错误位移由 256 组固定种子随机输入验证。
- LaTeX 教材可以独立检查并编译为 PDF。

## v0.2 验收记录

- LBA 0 保存固定宽度、自描述、带版本的 Stage 1 描述符。
- 负载从描述符声明的 LBA 开始，当前生成镜像使用 LBA 1。
- 固件逐字段验证 magic、版本、头长度、标志、扇区数、LBA、加载范围和入口。
- 描述符整扇区 16 位字和为零；负载使用独立 16 位字和校验。
- IDE 主通道使用 LBA28 `READ SECTORS`，每次传输一个 512 字节扇区。
- 每次状态轮询同时处理 BSY、DRQ、ERR、DF，并具有 `0xFFFF` 次预算。
- Stage 1 装入 `0x0800:0x0000`，通过 `retf` 重载 CS 后独立输出进入标记。
- 成功、串口失败、IDE 永久忙、设备错误、描述符损坏和负载损坏均有整机测试。
- 宿主工具拒绝截断镜像、非整扇区、越界 LBA、非法加载范围与校验错误。
- 512 组固定种子性质测试覆盖有效镜像往返和越界 LBA 拒绝。

## v0.3 验收记录

- Stage 1 建立空描述符、基址为零的平坦代码段和平坦数据段。
- 通过 `LGDT` 将 GDTR 指向自研 GDT，并输出 `GDT_READY` 启动证据。
- 代码段选择子为 `0x0008`，数据段选择子为 `0x0010`；描述符字段见芯片文档。
- 当前验收已设置 `CR0.PE`，通过物理入口偏移远跳进入 32 位保护模式。
- 自行打开并验证 A20，别名测试后恢复两个探测地址的原值。
- 已在独立物理页中构造并自检 PML4、PDPT 和 PD，建立首个 2 MiB 身份映射。
- 设置并回读 `CR4.PAE` 与 `CR3`，设置并回读 `IA32_EFER.LME`。
- 设置 `CR0.PG` 后验证 `IA32_EFER.LMA`，证明 IA-32e 已激活。
- 通过 L 位代码段远跳进入 64 位子模式，由独立 64 位串口例程输出 `LONG_MODE`。
- 时间戳暂不伪造；PIT 初始化后再启用从复位开始的单调毫秒时间戳。

## v0.4 验收记录

- 建立头源分离的 freestanding C++20 内核入口，使用 LLD 链接为 x86-64
  `ET_EXEC`，入口固定为 `0x00100000`。
- 固定 LBA 65 保存 Kernel v1 描述符，LBA 66 起保存精确 ELF 文件。
- 描述符和负载分别使用 IEEE CRC32；文件末尾的扇区填充必须全零。
- Stage 1 在 64 位模式中使用自研 ATA PIO 读取描述符和最多 512 KiB 负载。
- 低 64 MiB 由 32 个 2 MiB 大页恒等映射，加载目标、暂存区和 64 KiB
  内核栈互不重叠。
- ELF 第一遍验证头、最多 64 个程序头、地址范围、4 KiB 对齐、权限、W^X、
  段间不重叠和入口；第二遍才复制 `PT_LOAD` 并清零 BSS。
- Stage 1 构造 80 字节固定宽度 BootInfo，通过 RDI 和 System V AMD64 ABI
  调用内核。
- 内核重新初始化 COM1，验证 BootInfo、BSS 和 CR3，输出文件长度、加载段数
  和 `READY`。
- Kernel ATA 超时、ATA 错误、描述符损坏、负载损坏和语义非法 ELF 均有
  真实 QEMU 失败注入。
- 单元、集成、固定种子随机和 QEMU 系统测试共 32 项，完整验证命令通过。

## v0.5 验收记录

- 内核建立五槽 GDT：空描述符、Ring 0 长模式代码段、数据段和占两个槽的
  64 位 TSS 描述符；不继续依赖 Stage 1 的 GDT。
- TSS 精确为 104 字节，配置 RSP0，并为双重故障、NMI、机器检查保留三个
  独立 16 KiB IST 栈；`LTR` 后回读 TR 验证选择子。
- IDT 预留 256 个 16 字节槽，向量 0..31 全部安装 present 异常门；
  breakpoint 和 overflow 允许 DPL3 软件触发，其余保持 DPL0。
- 32 个 NASM Intel 语法异常桩按硬件是否压入错误码形成统一 160 字节
  `ExceptionFrame`，保存 15 个通用寄存器并在调用 C++ 前恢复 ABI 对齐。
- C++20 分发器只允许受控 breakpoint 返回；其他异常进入不可重入、无分配、
  不中断的 panic，记录向量、错误码、RIP、CS、RFLAGS，页故障另记录 CR2。
- 启动后通过 SGDT、SIDT、CS、SS、STR 和 TSS 字段回读验证实际处理器状态，
  再执行真实 `INT3` 自检。
- 独立内核镜像执行 `UD2` 和访问 `0x04000000`，分别验证向量 6 与向量 14；
  页故障同时验证错误码 0 和 CR2，panic 后不得出现 `READY`。
- 单元测试验证 TSS/IDT 位字段和全部错误码向量；固定种子随机测试执行
  4096 组 64 位地址往返；ELF 审计要求 32 个异常入口和分发符号完整。
- 完整验证共 36 项 CTest，正常、边界、随机、目标失败路径和既有启动回归
  全部通过。

## v0.6 验收记录

- Stage 1 直接访问 `fw_cfg` 的 `0x510/0x511` 端口，验证 `QEMU` 签名，
  流式遍历大端文件目录并读取 `etc/e820`；QEMU 只提供硬件数据，目录解析、
  条目转换、排序与失败策略均由自研汇编实现。
- BootInfo 升级为版本 2、104 字节，新增物理内存图地址、条目数和 24 字节
  条目宽度；布局集成测试覆盖 `0x16000` 元数据、`0x17000` 暂存和
  `0x18000` 内存图区间。
- 内核拒绝空、过大、零长度、溢出、乱序、重叠或管理范围内无可用 RAM 的
  内存图，并分别统计描述地址、可用 RAM 与当前管理范围内 RAM。
- 物理页帧分配器用每帧 2 bit 区分不可用、空闲、已分配和已保留，管理低
  64 MiB；保留请求先完整预检，跨越已分配页时不会留下部分修改。
- 内核自行分配并清零四级 4 KiB 页表，保留零页、64 KiB 初始栈 guard 和
  三个 IST guard；代码映射为 RX，只读数据映射为 R/NX，数据、栈和堆映射
  为 RW/NX。
- 内核检测 NX 能力，设置 `IA32_EFER.NXE` 与 `CR0.WP`，切换到新 CR3
  后回读控制状态和关键映射；专用故障镜像让 Ring 0 写只读页，必须得到
  #PF、错误码 `0x3` 和精确 CR2。
- 64 KiB 高半区早期堆采用显式初始化、对齐、溢出与容量检查；目标机用两种
  对齐实际写入并读回，正常路径才输出 `HEAP_SELF_TEST_PASSED`。
- 纯逻辑单元测试覆盖内存图、页帧状态、页表索引/表项和堆；集成测试覆盖
  启动保留布局；固定种子随机测试完成 8192 组页表项和 4096 步分配器模型
  对照；真实 QEMU 覆盖成功、内存图失败、not-present #PF 与写保护 #PF。
- 完整验证共 43 项 CTest，既有复位、ATA、长模式、ELF、描述符和异常回归
  同时通过。

## v0.7 验收记录

- IDT 向量 32..47 安装 present、DPL0 的 interrupt gate；16 个 NASM IRQ
  桩补齐零错误码，复用 160 字节寄存器帧布局，但进入独立硬件中断分发器。
- 内核把 LAPIC MMIO 页映射为 RW/NX/PCD，保持 `IA32_APIC_BASE[11]`，
  设置 SVR 软件启用，并将 LVT LINT0 配为未屏蔽的 ExtINT；该 virtual-wire
  路径解决“PIC 已积累 IRR、IF 已置位而 CPU 仍收不到 IRQ”的兼容边界。
- 主从 8259A 依次写 ICW1..4，重映射为 `0x20/0x28`，初始全屏蔽后只开放
  IRQ0、IRQ1；从片 EOI 先从后主，IRQ7/IRQ15 通过 ISR 正确分类虚假中断。
- 8254 通道 0 使用模式 2、低高字节写入除数 `0x04A9`，目标 1000 Hz；
  时间换算保留硬件实际除数，16 个真实 IRQ0 后输出 tick 与单调毫秒。
- i8042 初始化等待全部有界，启用第一端口、IRQ1 与集合 1 翻译，向键盘发送
  `F4` 并验证 `FA`；解码器覆盖按下、释放、`E0` 扩展和未知扫描码。
- 内核 ATA PIO 驱动以 LBA28 重读 LBA 0，区分忙超时、ERR/DF 和 DRQ，
  校验 Stage 1 描述符 magic；读取使用 256 个精确 16 位端口字。
- 启动日志只记录设备初始化、首批时钟汇总、首个键盘事件和故障，不在
  1000 Hz IRQ 中刷串口；QEMU 宿主日志为每行附加独立单调到达时间。
- 纯模型单元测试覆盖 PIC 映射/屏蔽、PIT 舍入/时间、键盘状态机和 ATA 请求；
  集成测试串联设备启动契约；固定种子随机测试执行 4096 轮组合性质。
- ELF 审计要求硬件 IRQ 公共入口、C++ 分发器、桩表和向量 32..47 全部存在；
  正常 QEMU 通过 QMP 注入 `A` 键，目标机必须经过 IRQ1 输出扫描码与事件。
- 完整验证共 46 项 CTest，既有 19 条失败路径和所有启动、异常、内存回归
  同时通过。

## v0.8 验收记录

- 独立 `abi` 模块固定 `INT 0x80` 的编号、参数寄存器、最大写入长度和
  `int64_t` 错误结果；独立 `user` 模块生成不依赖标准库的 AMD64
  `ET_EXEC` ELF64。
- 内核严格检查 ELF 标识、机器、版本、头尺寸、程序头数量与范围、4 KiB
  对齐、W^X、段重叠、用户虚拟范围、总页数和可执行入口；真实用户 ELF 另由
  独立 Python 解析器审计。
- 页表管理器在全部四级传播 U/S；用户代码为 RX，数据与四页栈为 RW/NX，
  栈底和独立 16 KiB TSS.RSP0 转换栈底分别有未映射 guard page。
- GDT 加入 `0x1B` 用户数据段和 `0x23` 用户代码段，TSS 移到 `0x28`；
  自写 NASM 入口构造五项 `IRETQ` 帧进入 CPL3。
- IDT `0x80` 使用 DPL3 interrupt gate。系统调用入口离开用户栈后校验
  生命周期、向量、CS/SS、RIP、RSP 和栈页权限，再分发 `WriteLog` 与
  `ExitProcess`。
- 用户指针按完整 64 位半开区间检查，逐叶页验证 present/U/S，最多复制
  160 字节到内核缓冲；验收程序确认未映射指针和未知调用均被稳定拒绝。
- 用户 `#UD` 和用户 not-present `#PF` 只终止用户执行，记录现场并恢复原
  内核调用链；Ring 0 的同类异常仍 panic。
- 正常 QEMU 路径从 `0x40000000` 进入用户态，输出 Ring 3 日志、以 0
  退出并继续处理 IRQ；三个专用镜像验证 `#UD`、`#PF` 和截断 ELF 拒绝。
- 单元、集成、固定种子随机、ELF 审计、QEMU 系统与既有回归共 55 项
  CTest，全部通过。

## v0.9 验收记录

- 固定容量为四的 PCB 模型实现 `Unused → Ready → Running → Terminated`，
  PID 单调分配，创建失败可回滚 Ready 槽位。
- 单核 round-robin 时间片固定为四个真实 PIT tick；只有 CPL3 中断、预算
  到期且存在另一个 Ready 进程时才发生抢占。
- 每个进程拥有独立 PML4。PML4[0] 的 PDPT 克隆后清空 PDPT[1]，所以
  `0x40000000..0x7fffffff` 的同址 ELF 不共享叶页；PML4[255] 保存独立
  用户栈，内核 supervisor 子树继续共享。
- 每个进程拥有 16 KiB Ring 0 栈和一页 not-present guard；调度切换同步
  更新 CR3 与 TSS.RSP0，汇编按 C++ 返回的 176 字节帧执行 `IRETQ`。
- 系统调用 ABI 新增编号 3 `GetProcessId`。正常镜像运行一个 smoke 与三个
  相同 worker，三个独立 BSS 计数均通过并发生至少一次真实抢占。
- 退出和用户异常先切回内核 CR3，再递归释放用户叶页、中间页表和 PML4。
  正常路径比较创建前后物理页统计并输出 `PROCESS_RESOURCES_RECLAIMED`。
- IRQ0 热路径不写日志；全部进程结束后只汇总 tick、抢占、派发和每进程
  run tick/dispatch/syscall/终止原因。QEMU 验收还检查稳定标记的精确次数
  和统计下界。
- 单元、集成、4096 轮固定种子随机、四个用户 ELF 审计、QEMU 系统与既有
  回归共 59 项 CTest，全部通过。

## v0.10 验收记录

- 调度状态机新增 `Blocked` 和具名 `ProcessWaitReason`；阻塞进程不再参与
  Ready 轮转，条件满足后由定向唤醒恢复，block/wakeup 分别计数。
- 自旋锁使用原子 exchange-acquire、store-release 和 x86 `PAUSE`；RAII
  guard 保证所有管道早退路径释放锁。内核 ELF 审计同时拒绝 `.init_array`、
  `.fini_array`、`.ctors` 和 `.dtors`，不依赖未执行的动态全局构造。
- 固定 64 字节环形管道实现部分读写、回绕、would block、EOF、broken pipe、
  端点关闭与统计；用户复制发生在管道锁外，单次 ABI 传输最多 64 字节。
- 系统调用编号 4..9 分离 Try 与 Wait。唤醒只表示条件可能推进，用户包装必须
  循环重试，避免把等待误当成已完成 I/O。
- 正常镜像创建 PID1 生产者、PID2 消费者和两个 worker。256 字节确定性载荷
  经 31 字节消费缓冲完整校验，真实产生读/写阻塞并最终观察一次 EOF。
- 端点权限、非法用户指针、未知调用、重复关闭和异常终止自动关闭均具有稳定
  失败语义；关闭会唤醒对侧，避免等待不可能再发生的条件。
- Kernel ELF 暂存区迁移到 `0x03E00000..0x03F00000` 的 1 MiB usable RAM
  窗口。Stage 1 先用 E820 图验证完整覆盖，并把 `PT_LOAD` 上界收紧为
  `0x03E00000`，防止源/目标重叠。
- 单元测试覆盖管道所有边界和调度状态转换；四线程同步集成测试执行 200,000
  次受锁递增；固定种子管道模型执行 32,768 步，调度器随机测试继续逐步检查
  单一 Running、等待原因和统计守恒。
- 完整回归共 64 项 CTest，其中 20 项 QEMU 系统测试、22 项失败路径、10 项
  固定种子随机测试；全部通过。

## v0.11 验收记录

- 启动磁盘扩为精确 2 MiB。LBA `0..2047` 固定归启动链，打包器拒绝
  Kernel 文件越过 1 MiB 边界；LBA `2048..3071` 是 1024 个文件系统块，
  最后 1024 个扇区保留。该边界修复了真实 Kernel ELF 与早期 LBA 1024
  设计重叠的问题。
- 固定磁盘格式包含带 CRC32 的 superblock、32 inode 位图、八块 inode 表、
  数据位图、1013 个数据块和 64 字节目录项。所有多字节字段显式小端编码，
  不把 C++ 结构体布局当作磁盘 ABI。
- inode 0 永久保留、inode 1 固定为根目录；每个 inode 有十个 64 位直接块，
  当前普通文件与目录最大均为 5120 字节。绝对路径最长 128 字节，组件最长
  40 字节并拒绝斜杠、控制字符、`.` 和 `..`。
- 八项固定容量 LRU 写回缓存统计命中、未命中、淘汰与设备 I/O；热路径不打印
  逐块日志。ATA PIO 新增 `WRITE SECTORS` 和 `FLUSH CACHE`，轮询继续保持
  有界并区分 busy timeout、DRQ timeout 与设备错误。
- 修改操作先把 superblock 持久化为 Dirty，再写回数据和元数据，最后写为
  Clean；挂载拒绝 Dirty、magic/CRC 损坏和所有非零未知格式，仅在超级块
  整扇区全零时首次格式化。
