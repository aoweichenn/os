# Stage 1 模块

## 职责

`stage1` 是由自研 ROM 从磁盘装入 RAM 的第一段代码。当前职责包括：

- 以 NASM Intel 语法生成位置约定明确的 16 位平坦二进制。
- 被固件加载到描述符声明的实模式段，当前为 `0x0800:0x0000`。
- 入口重新以 CS 建立 DS，不继承 ROM 的常量寻址假设。
- 使用已经初始化的 COM1 独立输出 `[OS][STAGE1] ENTERED`。
- 加载基址为零的平坦 GDT，设置 `CR0.PE` 并远跳进入 32 位保护模式。
- 保护模式栈顶使用物理地址 `0x7000`，与 `0x8000` 起始的 Stage 1 负载区分离。
- 通过端口 `0x92` 打开 A20，并用 1 MiB 边界别名测试验证后恢复原值。
- 在 `0x10000..0x12FFF` 建立并自检 PML4、PDPT 和 PD，用 32 个 2 MiB
  大页恒等映射低 64 MiB。
- 依次启用 PAE、LME 和分页，回读控制状态后远跳到 64 位代码段。
- 使用独立的 64 位 COM1 发送路径输出 `[OS][STAGE1] LONG_MODE`。
- 通过 `fw_cfg` 端口验证 QEMU 签名，流式查找并读取 `etc/e820`。
- 把 QEMU 20 字节内存项转换为 24 字节项目 ABI，并按物理基址排序。
- 用自研 ATA PIO 驱动读取 LBA 65 描述符和 LBA 66 起的 Kernel ELF。
- 验证描述符 CRC32、负载 CRC32、扇区补零和 ELF64 全部结构。
- 先完整验证所有 `PT_LOAD`，再复制文件内容并清零 BSS。
- 在 `0x14000` 构造 104 字节 BootInfo v2，切换独立内核栈并调用
  `0x00100000`。

## 磁盘格式

LBA 0 是 512 字节描述符，LBA 1 开始保存按扇区补零的负载。头部前 28 字节：

| 偏移 | 宽度 | 字段 |
| --- | --- | --- |
| `0x00` | 8 | magic `OSSTAGE1` |
| `0x08` | 2 | 版本 |
| `0x0A` | 2 | 头长度 |
| `0x0C` | 2 | 加载段 |
| `0x0E` | 2 | 入口偏移 |
| `0x10` | 2 | 负载扇区数 |
| `0x12` | 2 | 标志 |
| `0x14` | 4 | 负载 LBA |
| `0x18` | 2 | 负载 16 位字和 |
| `0x1A` | 2 | 描述符校验字 |

描述符全部 256 个小端 16 位字相加后必须为零。负载校验字段等于所有补零后
负载字的模 `2^16` 和。校验用于发现变化，范围检查用于阻止越界，两者不能
互相替代。

## 交接契约

固件跳转前保证中断关闭、方向标志清零、SS 为零、SP 为 `0x7000`，Stage 1
负载已校验。CS:IP 来自描述符，DS 仍为零，因此入口必须先执行 `push cs` /
`pop ds` 才能用自身相对偏移访问常量。

长模式加载器使用以下互不重叠的物理区间：

| 区间 | 用途 |
| --- | --- |
| `0x00008000..0x0000FFFF` | Stage 1 自身，构建时限制不超过 32 KiB |
| `0x00010000..0x00012FFF` | PML4、PDPT 和 PD |
| `0x00013000..0x000131FF` | Kernel 描述符 |
| `0x00014000..0x00014067` | BootInfo v2 |
| `0x00015000..0x00015FFF` | ELF 遍历临时状态 |
| `0x00016000..0x00016FFF` | 内存图条目数等元数据 |
| `0x00017000..0x00017FFF` | `fw_cfg` 文件名暂存 |
| `0x00018000..0x00018BFF` | 最多 128 个 24 字节内存图项 |
| `0x00100000..0x035FFFFF` | `PT_LOAD` 目标窗口 |
| `0x03600000..0x03DFFFFF` | Kernel ELF 暂存区，最大 8 MiB |
| `0x03FEF000..0x03FFEFFF` | 内核初始栈保留区 |

ELF 校验采用两遍算法。第一遍验证 ELF64 标识、`ET_EXEC`、x86-64 机器号、
程序头表、最多 64 个程序头、所有加载段的文件/内存范围、4 KiB 对齐、恒等
装载、R/W/X 权限、W^X、段间不重叠，以及入口确实被可执行段覆盖。任何验证
失败都不会改写内核目标区。第二遍才执行复制和 BSS 清零。

暂存区位于 54--62 MiB，而不是传统 VGA 孔洞前的低端 RAM。Stage 1 在读取
Kernel 前遍历已经规范化的 E820 图，要求完整的 8 MiB 半开区间落在同一个
usable 条目中；不能仅因 QEMU 使用 `-m 64` 就假定该地址可写。`PT_LOAD`
目标上界同步收紧到 `0x03600000`（不含），从格式上禁止复制目标覆盖仍作为
源文件使用的暂存区。

内存发现先从 selector `0x0000` 读取 `QEMU` 签名，再从 selector `0x0019`
读取大端文件目录。目录最多遍历 256 项；找到名称精确为 `etc/e820` 的文件后，
要求长度非零、是 20 的整数倍且不超过 128 项。每项的 base、length、type
保持硬件宽度，尾部属性字段补零。由于 `fw_cfg` 文件顺序不是内核 ABI，
Stage 1 最后执行有界冒泡排序。签名、目录、选择子、长度或数量任一失败都只
输出一次 `MEMORY_MAP_INVALID`，并禁止继续读取 Kernel。

交接时 RDI 指向 `0x14000` 的 BootInfo，RSP 设为 `0x03FFF000`，通过
`CALL` 进入 C ABI 的 `OsKernelEntry`。内核入口不应返回；若意外返回，
Stage 1 输出 `KERNEL_RETURNED` 并停机。

## 失败边界

| 标记 | 含义 |
| --- | --- |
| `MEMORY_MAP_INVALID` | `fw_cfg` 签名、目录或 `etc/e820` 结构不满足边界 |
| `KERNEL_ATA_TIMEOUT` | BSY/DRQ 轮询超过 `0x000FFFFF` 次固定预算 |
| `KERNEL_ATA_ERROR` | 设备返回 ERR 或 DF |
| `KERNEL_HEADER_INVALID` | 描述符字段、范围、保留区或描述符 CRC 错误 |
| `KERNEL_CHECKSUM_INVALID` | 精确 ELF CRC 或扇区补零错误 |
| `KERNEL_ELF_INVALID` | ELF 结构、段关系、权限或入口错误 |

每条失败路径只输出一次标记并停止，不输出后续成功里程碑。
