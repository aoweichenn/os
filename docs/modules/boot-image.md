# Boot Image 模块

## 职责

`boot_image` 在宿主机上把两个独立且已验证的目标产物组合到同一块原始磁盘：

- Stage 1 二进制仍由 LBA 0 的既有描述符定位和校验。
- Kernel ELF64 使用 LBA 65 的独立描述符。
- 两种格式分别解析、分别校验，任何一个失败都不会被另一层掩盖。

QEMU 只把该文件作为 IDE 磁盘提供给目标机，不解析或装载其中内容。当前第二
增量完成宿主打包与审计；下一增量由 Stage 1 自己读取 Kernel 描述符和 ELF。

## 磁盘布局

| LBA | 内容 | 当前约束 |
| --- | --- | --- |
| 0 | Stage 1 描述符 | 512 字节，自带整扇区字和 |
| 1..64 | Stage 1 最大负载区 | 当前实际使用 3 个扇区 |
| 65 | Kernel 描述符 | 512 字节，CRC32 覆盖整个扇区 |
| 66..N | `kernel.elf` | 当前 6,136 字节、12 个扇区 |
| 其余 | 零 | 留给后续文件系统或格式升级 |

固定 LBA 65 使 Kernel 格式不随 Stage 1 当前大小漂移。Stage 1 最多占 64 个
扇区，因此宿主工具显式证明其结束 LBA 不大于 65。

## Kernel 描述符

所有整数采用小端固定宽度编码：

| 偏移 | 宽度 | 字段 | 约束 |
| --- | --- | --- | --- |
| `0x00` | 8 | magic | `OSKERN64` |
| `0x08` | 2 | version | 当前为 1 |
| `0x0A` | 2 | header size | 当前为 48 |
| `0x0C` | 4 | flags | 当前必须为 0 |
| `0x10` | 8 | payload LBA | 当前必须为 66，且受 ATA LBA28 上限约束 |
| `0x18` | 8 | ELF file size | 精确文件字节数，不包含扇区补零 |
| `0x20` | 8 | payload sector count | 必须等于文件长度向上取整 |
| `0x28` | 4 | payload CRC32 | 只覆盖精确 ELF 文件字节 |
| `0x2C` | 4 | descriptor CRC32 | 计算时本字段置零，覆盖完整 512 字节 |
| `0x30..0x1FF` | 464 | reserved | 当前版本必须全零 |

LBA、长度和扇区数使用 64 位字段，为后续更大的磁盘格式保留空间；当前 ATA
驱动仍只接受 LBA28。格式能力与当前设备能力分别验证，不能因为字段更宽就假定
硬件已经支持。

## 审计顺序

1. 先完整验证 Stage 1 描述符和负载。
2. 证明 Stage 1 结束位置没有越过 LBA 65。
3. 验证 Kernel 描述符 magic、版本、长度、标志、保留区和 CRC32。
4. 验证文件长度、扇区数量、LBA28 与磁盘末尾边界。
5. 验证 Kernel 文件 CRC32。
6. 再按 ELF64 规则验证头、`PT_LOAD`、权限、对齐和入口。

CRC32 用于检测传输、打包和存储中的偶然损坏，不提供对恶意输入的密码学认证。
边界检查和格式不变量仍然必须独立成立。
