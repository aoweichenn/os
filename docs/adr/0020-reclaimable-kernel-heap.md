# ADR 0020：用边界标记建立可回收内核堆

## 状态

已接受，作为 v1.1 可回收资源基础的第一个完整实现增量。

## 背景

v0.6 的 `KernelHeap` 是 64 KiB 高半区单调分配器。它以极少状态证明了
页表之上的对象分配、二次幂对齐、容量失败和真实访存，但没有释放语义。
这对与内核同寿命的启动对象足够，却不能支撑 v1.2 之后的 Thread、动态内核
栈、FileTable 和其他具有明确销毁点的对象。

直接开始实现 slab/type cache 会同时引入页后备、对象类型策略、并发、回收
水位和构造/析构约束，难以判断错误来自通用字节分配还是类型缓存。先建立一个
可独立验证的通用内核堆，可以冻结以下更基础的契约：

- 分配与释放的所有权边界；
- 对齐、溢出、耗尽和非法释放的显式失败状态；
- 分裂、前后合并与失败不修改旧状态；
- 活动、累计、峰值和最大连续空闲负载统计；
- 不依赖 libc、宿主标准库、异常、RTTI 或隐藏动态初始化。

本增量仍运行在单 BSP 启动路径。它不提前删除四个 PCB、静态 Ring 0 栈，
也不把内核堆伪装成物理页分配器、KVA 分配器或对象缓存。

## 决策

### 区间与块格式

`KernelHeap` 直接在调用者提供的连续虚拟区间中保存元数据和负载。区间基址、
长度和每个块均为 16 字节对齐，最小块为 64 字节。块头固定为 48 字节：

```text
低地址
┌─────────────────────────────────────────────┐
│ size_bytes                    8 B             │
│ previous_block_size_bytes       8 B             │
│ requested_size_bytes           8 B             │
│ state_signature               8 B             │
│ previous_free_block            8 B             │
│ next_free_block                8 B             │
├─────────────────────────────────────────────┤
│ payload，起始地址至少 16 字节对齐            │
└─────────────────────────────────────────────┘
高地址
```

`size_bytes` 与 `previous_block_size_bytes` 构成边界标记。当前块地址加自身长度
得到后块，当前块地址减前块长度得到前块，因此释放时不需要从堆首扫描相邻块。
状态签名区分空闲、活动和已释放的旧块头；签名只用于尽早发现所有权错误，
不能替代完整边界验证。

### 空闲集合与分配策略

所有空闲块进入按地址递增的双向链表。分配遍历空闲链表并选择能够容纳请求的
最小块，即 best-fit。选择完成前不修改任何块和输出指针。

每个候选块先计算对齐后的负载位置，再反推出紧邻负载的块头位置。对齐产生的
前缀只有达到 64 字节时才拆成独立空闲块；不足 64 字节时继续尝试下一个对齐
位置。后缀不足 64 字节时并入活动块，否则形成新的空闲块。所有地址加法、
对齐上取整和区间差都在提交前检查溢出与边界。

best-fit 不是对所有工作负载都最优。本项目选择它是因为当前堆只有 64 KiB，
实现和模型容易审计，并能避免 first-fit 持续切割首个大块。未来 type cache
负责固定尺寸热对象，buddy 负责页粒度连续块；通用堆不承担所有分配策略。

### 释放与合并

`TryRelease` 只接受活动分配返回的精确负载首地址。空指针、区间外指针、
内部指针、重复释放和损坏元数据分别返回明确状态。

释放按以下顺序执行：

1. 验证负载地址、块头、物理块成员关系、请求长度和统计下界；
2. 在不修改状态的前提下预检前后相邻块；
3. 把当前块标为已释放；
4. 若前块空闲，从空闲链移除并向前合并；
5. 若后块空闲，从空闲链移除并向后合并；
6. 更新合并后继块的 `previous_block_size_bytes`；
7. 把唯一合并结果按地址插回空闲链并提交统计。

这保证普通参数失败不会留下半分裂或半合并状态。元数据已经被越界写破坏时，
接口返回 `CorruptedMetadata`；此时内核不得继续假定分配器可用。

### 一致性与统计

`Validate` 同时遍历物理块链和空闲链，检查：

- 每个块的范围、尺寸、对齐、状态和前块长度；
- 物理块无缝覆盖整个堆；
- 空闲链地址严格递增、双向链接一致且没有超出块数上界的环；
- 每个物理空闲块在空闲链中恰好出现一次；
- 活动块数、活动请求字节、占用跨度与保存统计一致；
- `successful_allocation_count = release_count + allocation_count`；
- 峰值不低于当前占用。

统计语义固定如下：

| 字段 | 语义 |
| --- | --- |
| `capacity_bytes` | 包含全部块头与负载的堆区间长度 |
| `consumed_bytes` | 当前活动块占用的完整跨度，包含块头和吸收的短后缀 |
| `remaining_bytes` | `capacity_bytes - consumed_bytes`，不是单次可分配上限 |
| `allocation_count` | 当前活动分配数 |
| `active_requested_bytes` | 当前调用者请求的有效负载总数 |
| `successful_allocation_count` | 初始化以来成功分配累计数 |
| `release_count` | 初始化以来成功释放累计数 |
| `peak_consumed_bytes` | 活动块完整跨度的历史峰值 |
| `largest_free_allocation_bytes` | 当前单个空闲块扣除块头后的最大负载 |

`remaining_bytes` 可能分散在多个块中，因此容量请求必须以实际分配结果为准，
不能仅比较该字段。

### 启动自检与日志

目标内核仍分配 64 字节/16 字节对齐对象和 4096 字节/4096 字节对齐对象，
写入并读回两个 64 位模式。与 v0.6 不同，自检随后逆序释放两个对象，执行
完整一致性检查，并要求活动数和当前占用回到零、累计成功数等于累计释放数。

成功路径只增加三个汇总字段：

```text
[OS][KERNEL] HEAP_ACTIVE_ALLOCATIONS=0x0000000000000000
[OS][KERNEL] HEAP_PEAK_CONSUMED_BYTES=0x...
[OS][KERNEL] HEAP_LARGEST_FREE_ALLOCATION_BYTES=0x...
```

不逐次打印分配、分裂或释放。宿主系统测试要求活动数精确为零，峰值和最大
连续空闲负载非零，然后才接受 `HEAP_SELF_TEST_PASSED`。

### 并发边界

当前分配器不在内部取得锁，只允许已经串行化的启动路径调用。v1.2 建立正式
Thread、IRQ/调度边界和锁模型后，调用者必须通过外层堆锁串行化普通 Thread
上下文；IRQ、NMI 和 panic 路径不得调用通用堆。锁策略不会隐藏进本次增量，
避免在执行模型冻结前错误承诺中断安全或可睡眠语义。

## 测试证据

- 单元测试覆盖无效区间、重复初始化、1/16/64/256/4096 字节对齐、失败
  原子性、非法/内部/重复释放、乱序三向合并、地址复用和全部统计；
- 集成测试使用目标同规格 64 KiB 区间，组合小对象、缓存行和页对齐对象，
  写入数据后乱序释放，再分配整个最大连续负载；
- 固定种子 `0x4845415056313031` 执行 100000 次随机分配/释放，逐步核对
  对齐、负载首尾模式、活动请求字节、累计计数和失败输出，并周期性执行
  完整拓扑验证；
- Kernel ELF 继续通过 freestanding 符号与加载段审计；
- QEMU 从复位开始真实执行分配、访存、释放、合并与恢复为空的自检。

## 明确不包含

- 物理页 buddy 的连续页阶次与分裂合并；
- KVA 虚拟区间分配和动态 guard stack；
- 空中间页表回收；
- 固定尺寸 type cache/slab、per-CPU cache 或内存压力回收；
- 多线程并发、IRQ 分配、NMI 分配和 panic 分配；
- 扩展 64 KiB 后备映射或按需增长堆。

这些仍是 v1.1 的后续独立增量。本 ADR 的接受不表示 v1.1 已完成。

## 后果

正面影响：

- 内核第一次拥有可验证的通用字节级释放和碎片合并语义；
- 失败路径与统计可作为后续 `ResourceSnapshot` 的堆侧事实；
- type cache 可以建立在已验证的后备分配接口之上；
- 目标自检不再永久消耗启动测试对象。

代价：

- 每个活动对象至少承担 48 字节块头，当前实现偏向可解释性而非空间效率；
- best-fit 需要线性遍历空闲链；
- 64 KiB 固定后备区仍限制容量，不能替代 KVA 与页后备增长；
- 分配器尚无并发保护，调用上下文必须受控。

## 被拒绝的方案

- **继续单调分配直到 v1.2**：无法验证动态对象销毁和资源回到基线。
- **直接引入 slab**：把字节分配、类型策略与并发问题混在同一故障域。
- **只保存单链空闲表**：释放时难以在常数时间定位前块，合并验证更复杂。
- **立即实现通用 `new/delete`**：会隐藏失败状态并扩大 freestanding 运行时
  与构造语义范围；本阶段保持显式 `TryAllocate/TryRelease`。
- **用宿主分配器测试替代目标实现**：不能证明高半区块头、真实访存和无运行时
  依赖。
