# ADR 0011：用户 ELF、Ring 3 边界与 `INT 0x80`

- 状态：接受
- 关联阶段：v0.8 用户边界
- 日期：2026-07-25

## 背景

v0.7 已经具备内核自有的 GDT、TSS、IDT、4 KiB 页表、页帧分配器、异常路径和
可工作的硬件中断。用户程序若仍在 Ring 0 运行，错误指针、非法指令或越权访问
都会破坏整个内核；这既无法解释操作系统的保护边界，也无法为进程调度建立可信
前提。

本阶段需要在不引入第三方运行时、加载器或内核替代品的前提下，完成第一条真实
的用户执行链：

```text
内嵌 ET_EXEC ELF64
  → 内核严格验证
  → 分配 U/S 页面并按 W^X 装载
  → IRETQ 进入 CPL3
  → INT 0x80 切换到 TSS.RSP0
  → 内核校验帧和用户指针
  → exit 或用户异常回到原内核调用链
```

## 决策

1. 用户程序使用 x86-64 `ET_EXEC` ELF64，初始链接基址固定为
   `0x0000000040000000`。内核只接受小端、AMD64、当前 ELF 版本和最多八个
   `PT_LOAD`，拒绝未知程序头。
2. 每个加载段必须 4 KiB 对齐、文件范围和内存范围无溢出、段间不重叠、
   `p_filesz <= p_memsz`，且必须可读并满足 W^X。入口必须位于可执行段。
3. 用户地址采用低半 canonical 范围
   `0x0000000000010000..0x00007FFFFFFFFFFF`。本阶段至多装入 32 个 ELF
   页面；用户栈为四个 RW/NX 页面，栈底再留一个未映射 guard page。
4. 所有页表层级都传播 U/S 位。用户代码为 RX，用户只读数据为 R/NX，
   用户数据和栈为 RW/NX；不允许用户可写且可执行的叶页。
5. GDT 增加 Ring 3 数据段 `0x1B` 和代码段 `0x23`。TSS 选择子移动到
   `0x28`，`RSP0` 指向独立的 16 KiB 特权转换栈，而不是当前启动栈。
   转换栈底部有独立未映射 guard page。
6. 首次降权使用自写 NASM Intel 语法的 `IRETQ` 五元组：
   `SS:RSP:RFLAGS:CS:RIP`。初始 RFLAGS 只显式设置保留位和 IF。
7. 系统调用选用 DPL3 的 IDT interrupt gate `0x80`。ABI 使用
   `RAX=编号`、`RDI/RSI=参数 0/1`、`RAX=返回值`，当前提供
   `WriteLog=1` 与 `ExitProcess=2`。错误使用稳定的负 `int64_t`。
8. `WriteLog` 最大复制 160 字节。内核先验证完整半开地址区间，再逐叶页确认
   present 和 U/S，复制到固定内核缓冲后才访问串口。零长度、超长、跨页和
   未映射输入都有明确结果。
9. 系统调用入口除 CPL3 外还校验向量、CS、SS、RIP、RSP 和当前栈页的
   U/S、RW、NX 权限。违反入口不变量说明内核控制流已损坏，直接停止处理器。
10. Ring 3 的异常只终止当前用户执行，记录向量、错误码、RIP 和可选 CR2，
    然后丢弃 TSS 转换栈并恢复进入用户态前保存的内核调用链。Ring 0 异常仍
    进入不可恢复 panic。
11. v0.8 只有一个同步执行的用户程序和一个内核页表根，不伪造进程、线程或
    地址空间切换。页回收、调度和并发系统调用留给 v0.9。

## 为什么先采用 `INT 0x80`

长模式也支持 `SYSCALL/SYSRET`，但它要求同时配置 `EFER.SCE`、`STAR`、
`LSTAR` 和 `FMASK`，入口还必须自行建立安全内核栈；`SYSRET` 对返回地址和
标志也有特殊限制。`INT 0x80` 能复用本项目已经验证过的 IDT、统一异常帧和
TSS.RSP0，让本阶段把注意力集中在特权切换、用户页权限和指针验证。

它不是性能终局。ABI 编号与参数寄存器独立于入口指令，后续可以增加
`SYSCALL` 快路径，并让两种入口共用同一 C++ 分发层。

## 被拒绝的方案

- 使用 QEMU `-kernel`、宿主进程或第三方用户运行时执行用户程序：会绕过本
  项目必须学习和实现的页表、ELF 与特权切换。
- 继续把用户代码当普通 Ring 0 函数调用：无法形成硬件隔离，用户错误仍是
  内核错误。
- 复用启动栈作为 TSS.RSP0：系统调用进入时会覆盖仍需恢复的内核调用链，
  产生与日志和编译布局相关的隐蔽损坏。
- 在用户栈上调用 C++ 分发器：内核将依赖不可信且可能未映射的内存。
- 在验证完 ELF 前逐段映射：后续程序头失败会留下部分地址空间，破坏失败
  原子性。
- 立即实现 `fork`、调度和每进程 CR3：会把用户边界、资源生命周期和并发
  错误混在同一个增量中，降低学习与定位质量。

## 结果

本阶段得到一条可执行、可失败注入、可回归的最小保护边界。代价是当前用户页在
执行结束后仍保留、系统调用同步串行、日志调用只服务教学观测。因为 v0.8 不
允许并发解除映射，先验证再复制不存在本阶段内的 TOCTOU；引入多线程或异步
地址空间修改时，复制例程必须与页表生命周期建立锁或固定页关系。
