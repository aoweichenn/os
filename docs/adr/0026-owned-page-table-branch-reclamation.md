# ADR 0026：按页表根所有权回收空分支并事务化映射

## 状态

已接受，作为 v1.1 可回收资源基础的第七个完整实现增量。它消除
[ADR 0024](0024-reclaimable-kernel-virtual-address-allocator.md) 和
[ADR 0025](0025-kva-backed-dynamic-kernel-stacks.md) 中记录的“撤销叶映射后
长期保留空 PT、PD、PDPT”限制，并保持当前四进程与动态 Ring 0 栈路径不变。

## 背景

x86-64 处理器只负责按 CR3 和页表项翻译地址，不负责给操作系统申请或归还
页表帧。映射一个此前完全空闲的 4 KiB 虚拟页，四级分页通常需要新建：

```text
PML4（根，已存在）
  └── PDPT / level 3，新建 4 KiB
        └── PD / level 2，新建 4 KiB
              └── PT / level 1，新建 4 KiB
                    └── PTE → data frame
```

旧 `UnmapPage` 只把 PTE 清零并执行 `INVLPG`。数据页可以归还，但上面三张
已经变空的表继续占用三个 order-0 页帧。KVA 自检曾先映射一页“暖机”，把这
12 KiB 泄漏纳入后续基线；动态栈反复创建和销毁时也只能证明数据帧与 KVA
守恒，不能证明页表自身守恒。

直接递归释放所有空表同样不正确。进程根不是完整复制内核页表树：

- 内核 PML4 项按值复制进每个进程 PML4；
- 这些不同的 PML4 项仍指向同一张内核 PDPT；
- 进程低地址 PML4[0] 使用克隆的 PDPT，以便独立拥有用户程序分支；
- 用户栈使用 PML4[255] 下的进程独占分支；
- 其余高半区分支是借用，不属于进程销毁路径。

若内核根释放一张空 PDPT，只清除自己的 PML4 项，已经复制到进程根中的 PML4
项仍保存被归还帧的物理地址。该帧一旦复用，进程页表遍历就会把无关数据解释
成页表。相反，清除共享 PDPT 内的一项对所有引用它的根同时可见，因此该项
指向的空 PD 或 PT 可以安全回收。

本增量必须同时解决两类问题：

1. 撤销最后一个叶映射时，只回收当前根真正有权回收的空分支；
2. 建立映射途中分配失败时，不能留下新表、父项或被错误升级的 U/S 位。

## 决策

### 显式声明三种页表根

`PageTableManager` 构造时必须提供 `PageTableRootKind`，不再从地址猜测所有权：

| 根类型 | 可修改范围 | PT/PD 回收 | PDPT 回收 |
| --- | --- | --- | --- |
| `Exclusive` | 整个根 | 允许 | 允许 |
| `KernelShared` | 整个内核根 | 允许 | 禁止 |
| `Process` | 用户程序分支与 PML4[255] 用户栈分支 | 允许 | 仅用户栈分支允许 |

`KernelShared` 保留空 PDPT，是因为其 PML4 项可能已经复制到进程根。空 PT 和
PD 的父项位于共享树中，先清父项再释放子表对全部进程同时生效。

`Process` 只允许修改两类明确自有分支：

```text
user program: PML4[0]   → cloned PDPT[1] → owned PD/PT
user stack:   PML4[255] → owned PDPT     → owned PD/PT
```

对借用的低端内核分支或高半区内核分支执行 `MapPage`/`UnmapPage`，返回
`SharedBranchMutationDenied`，且不分配帧、不改页表项。进程低地址克隆 PDPT
在进程存活期间保持稳定，即使其用户程序项暂时为空；`ReleaseProcessRoot`
最终统一释放它。用户栈 PDPT 完全独占，所以最后一页撤销后可一直回收到 PML4。

### “空表”要求其余项逐字等于零

回收候选不是“其余项 present 位都为零”，而是“排除即将删除的父项后，其余
511 项逐字等于零”。not-present 项未来可能保存 swap、诊断或软件状态位；
只检查 present 会把带软件元数据的表误判为空。

对一个普通 4 KiB 叶项，回收判定从下向上进行：

```text
PT 除目标 PTE 外全零
  → PD 除目标 PDE 外全零
    → 根类型允许回收 PDPT
      且 PDPT 除目标 PDPTE 外全零
```

任一层不空，所有更高层都不能回收。2 MiB 叶页的撤销尚未进入本接口，本阶段
继续返回 `UnexpectedLargePage`，避免把 order-9 数据块生命周期偷偷并入
4 KiB API。

### 破坏前完成范围、环和精确所有权预检

每次解引用页表帧前都验证：

- 物理地址按 4 KiB 对齐；
- 完整一页位于允许访问的物理范围；
- 地址字段没有超出当前页表格式；
- 子表物理地址不等于根或任一祖先，拒绝明显页表环；
- 页帧分配器仍精确拥有该 order-0 帧。

待释放的 PT、PD、PDPT 在任何页表项清除前再次完成精确所有权预检。预检失败
返回 `InvalidTableFrame` 或 `TableFrameNotOwned`，叶映射与调用方输出保持
不变。当前页帧元数据还不区分“数据帧”和“页表帧”，精确 order-0 所有权是
现阶段可证明的边界；类型化页帧归属留给后续 AddressSpace 对象。

### 撤销采用“断开、失效、由子到父释放”

成功路径按以下顺序提交：

1. 清除目标 PTE；
2. 若 PT 将空，清除指向 PT 的 PDE；
3. 若 PD 将空，清除指向 PD 的 PDPTE；
4. 若根类型允许且 PDPT 将空，清除指向 PDPT 的 PML4E；
5. 若当前管理器负责活动映射，对目标虚拟地址执行一次 `INVLPG`；
6. 依次清零并归还 PT、PD、PDPT 帧。

父项先断开，保证任何新的硬件遍历都不能到达即将归还的表。释放仍由子到父，
与创建依赖相反。一个叶地址只执行一次 `INVLPG`，不为每张中间表重复刷同一
TLB 项；当前单 BSP 没有远端 TLB shootdown。

`PageTableUnmapResult` 只在完整成功后写回，分别报告本次释放的 level 1、
level 2、level 3 表数量和总表帧数。数据页不由 `UnmapPage` 释放，也不计入
结果。失败时调用方原结果保持不变。

### 建立映射成为可回滚事务

旧 `MapPage`/`MapLargePage` 每缺一级就立即分配并链接新表。若后一级分配
失败，前面已经链接的空表无法回收；若为用户映射给已有父项增加 U/S 位，后来
发现叶项已存在，父项权限也不会恢复。

新实现为每次非叶穿越记录：

```text
TableMutation
  entry                  父项地址
  original_entry         修改前完整 64 位值
  table_physical_address 当前子表帧
  table_created          本事务是否新建
```

叶项提交前发生 `FrameAllocationFailed`、`UnexpectedLargePage`、
`AlreadyMapped`、损坏帧或所有权错误时：

1. 恢复全部父项原值，包括临时增加的 U/S 位；
2. 对目标地址执行一次必要的 TLB 失效；
3. 按创建相反顺序清零并释放本事务新建的表帧。

回滚自身若检测到所有权或释放失败，返回 `RollbackFailed`，不能用最初错误
掩盖已经无法证明的状态。正常失败必须保持根项和页帧统计与调用前相同。

### 查询与整体进程销毁共用防损坏边界

`QueryPage` 在每一级执行同样的范围、环和所有权验证，并修复了旧实现遗漏的
4 KiB 页内偏移：查询 `virtual_page + offset` 返回
`physical_page + offset`。2 MiB 查询继续保留对应大页偏移。

`ReleaseProcessRoot` 只递归释放用户程序和用户栈自有树，不遍历借用的内核
分支。逐页撤销已经清空的分支会被跳过；尚未逐页撤销的叶数据和表则由整体
销毁路径递归归还。递归下降时携带从根到当前表的完整祖先地址链；任一下级
项回指根或祖先都在释放发生前返回 `InvalidTableFrame`，允许修复损坏项后
重试。释放过的父项随即清零，使部分失败仍不会保留指向已归还子表的项。

## 目标启动自检与日志

KVA 暖机仍保留，但目的从“隐藏三帧泄漏”改为“验证共享边界”：

1. 记录暖机前页帧统计；
2. 映射一页，真实写入并查询；
3. 撤销后必须回收 PT 和 PD；
4. 内核共享根必须不回收 PDPT；
5. 释放数据帧和 KVA 后，物理活动帧只能比进入前多一张共享 PDPT。

随后四页 KVA 主事务复用该 PDPT，重新申请 PT/PD，并在最后一页撤销时再次
回收两张表。两段事务合计稳定输出：

```text
PAGE_TABLE_RECLAIM_READY
PAGE_TABLE_RECLAIMED_LEVEL1_TABLES = 2
PAGE_TABLE_RECLAIMED_LEVEL2_TABLES = 2
PAGE_TABLE_RECLAIMED_LEVEL3_TABLES = 0
PAGE_TABLE_RETAINED_SHARED_LEVEL3_TABLES = 1
PAGE_TABLE_RECLAIM_SELF_TEST_PASSED
```

因此 KVA 主事务相对暖机后 buddy 基线会新增并释放三次操作：一个 order-2
数据块、一个 PT 和一个 PD。日志只在完整内存初始化提交后输出一次，不在映射
或撤销热路径逐页打印。

## 测试证据

- 单元测试覆盖根类型、重复初始化、单页三级回收、同 PT 相邻页、内核共享
  PDPT 保留、进程借用分支拒绝、程序/栈分支差异、分配耗尽回滚、帧所有权
  破坏与原址修复、越界子表、查询环、递归销毁祖先回指和失败输出保持；
- 集成测试执行 128 轮内核共享映射/撤销和 64 轮进程根创建/映射/逐页撤销/
  销毁，同时覆盖整体进程销毁递归释放尚存叶项；
- 固定种子 `0x5047545245434C4D` 执行 100000 步，在 4 个 PML4 槽、2 个
  PDPT 项、4 个 PD 项和 32 个 PTE 的 1024 页空间中随机映射/撤销；独立模型
  计算活动数据页与三级表数量，每 257 步逐页查询并校验 buddy；
- 动态栈随机模型改为状态相关基础设施：空闲时只保留根与共享 PDPT 两帧，
  有活动栈时临时持有 PD/PT，总映射排空后恢复两帧；
- 64 MiB 正常启动、64 GiB 主容量、内核故障和两个用户故障 QEMU 镜像使用
  同一实现；串口协议精确验收上述五项页表回收标记；
- 本增量加入三项测试后完整 CTest 集合为 92 项，Kernel ELF、命名、书籍和
  Python 工具门禁继续通过。

## 结果

### 正面结果

- KVA 和动态栈不再用暖机泄漏掩盖中间页表生命周期；
- 映射失败对页帧、父项和 U/S 权限具有明确回滚语义；
- 页表根的拥有、共享和借用关系成为构造参数与测试契约；
- 进程可继续共享内核高半树，不会留下指向已归还 PDPT 的 PML4 项；
- 损坏页表在解引用前被诊断，宿主随机测试不会因越界指针崩溃；
- 回收计数同时进入宿主模型、真实 QEMU 自检、文档和日志协议。

### 受控限制

- 当前仍是单 BSP；没有页表锁、并发 page walk、远端 TLB shootdown 或 RCU；
- `KernelShared` 保守地保留所有空 PDPT，没有跟踪哪些 PML4 项实际复制给了
  多少进程；
- 只处理 4 KiB 叶项撤销；2 MiB 大页数据块回收需要独立 API 与 order-9
  所有权；
- 页帧分配器只证明精确 order-0 allocation，尚未给帧附加 PageTable 类型；
- 没有 PCID、全局页优化、批量 unmap 或延迟 TLB 回收；
- 跨多个资源管理器的通用作用域回滚与 `ResourceSnapshot` 仍是 v1.1 后续
  产出，本 ADR 只把页表自身事务闭环。

## 被否决方案

### 对所有空层一路释放

它适用于独占根，却会释放仍被进程 PML4 项引用的内核 PDPT，形成悬空硬件
指针。空不等于独占。

### 永久保留所有中间页表

实现最短，但动态 KVA、栈和未来 VMA 的地址跨度会把短期映射转化为永久物理
内存占用，也无法形成资源守恒证据。

### 给每张页表立即加入通用引用计数

真正的引用计数需要在复制 PML4 项、进程销毁、映射并发和 TLB 延迟释放之间
建立统一原子协议。当前只有单 BSP 串行根创建；显式根类型能以更小状态完整
表达现有共享关系。通用 AddressSpace 引用模型在 v1.2 之后单独设计。

### 扫描全部进程根判断 PDPT 是否仍被引用

扫描把页表回收反向依赖调度器全局进程集合，仍存在“扫描后新建引用”的并发
窗口，也让基础内存层无法独立测试。所有权在根创建时确定，应由类型协议表达。

### 只在下一次映射时顺便清理旧空表

延迟清理不能保证对象销毁后资源恢复，也让内存压力失败发生在无关调用者。
撤销最后一页已经拥有完整路径和空表事实，应在该事务中同步完成。
