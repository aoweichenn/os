# ADR 0021：统一 C++ 标识符与自研 ABI 命名

- 状态：已接受
- 日期：2026-07-25

## 背景

项目早期同时存在两套命名习惯：

- 类型和普通函数使用大驼峰；
- 变量、参数、字段以及部分 C/汇编符号使用小驼峰。

随着内核、用户态、测试和教材共同增长，小驼峰变量已经扩散到公开 ABI
结构、模块接口、局部状态和测试参考模型。仅靠人工审查难以保证新旧文件一致，
也无法可靠区分变量、函数、类型、常量和外部符号。

此外，`osKernelEntry`、`osKernelImageStart` 一类名称虽然位于 C++ 与 NASM
或链接脚本的边界，但这些 ABI 完全由项目自行定义，并非硬件或第三方运行时
强制。继续保留旧拼写只会把历史习惯固化为永久例外。

## 决策

### C++ 标识符

- 类型、类、结构体、枚举和 concepts 使用大驼峰。
- 自由函数、成员函数、静态函数和函数模板使用大驼峰。
- 局部变量、参数、数据成员、结构化绑定和 Lambda 捕获使用
  `lower_snake_case`。
- 私有和受保护的非静态数据成员允许使用单个尾部下划线，例如
  `free_frame_count_`；语义单词之间仍必须使用下划线。
- 常量继续使用 `OS_<模块>_<功能>` 全大写格式。
- 命名空间每一层只使用一个简短、完整的小写单词；复杂归属使用多层
  命名空间表达。

成员函数访问数据成员或其他成员函数时仍显式使用 `this->`。尾部下划线只用于
避免参数遮蔽，不替代成员访问规则。

### 自研 C/汇编边界

项目自己拥有的 C++/NASM 函数入口使用大驼峰，例如：

```text
OsKernelEntry
OsKernelDispatchException
OsUserEntry
OsUserInvokeSystemCall
```

项目自己拥有的数据、表和链接位置符号使用小写蛇形，例如：

```text
os_kernel_exception_stub_table
os_kernel_image_start
os_kernel_user_shell_elf_start
```

NASM、链接脚本、C++ 声明、ELF 审计器和测试必须在同一变更中同步。由 C
语言和编译器运行时固定的 `main`、`memset`、`memcpy` 保留标准名称，并限制在
最小 ABI 边界。

### 自动门禁

仓库根目录保存 `.clang-tidy`，使用 Clang AST 的
`readability-identifier-naming` 检查变量、成员、参数、函数和命名空间。
Python 词法检查器另外要求命名空间的每个显式层级匹配 `[a-z]+`，因而
`memory_manager`、`Kernel` 和 `v2` 都会失败；匿名命名空间不受影响。
`os_cpp_identifier_naming_check` 把两种检查组合成一个 CTest 集成测试，并将
任一诊断视为失败。

AST 检查是主门禁，因为简单正则无法可靠区分：

- 类型名与变量名；
- 函数调用与函数指针变量；
- 常量与普通全局变量；
- 头文件声明与跨编译单元引用；
- 注释、字符串和真实标识符。

自动检查保证“每层一个小写英文单词”，代码审查继续判断单词是否简短、完整且
符合领域含义。当前扫描只出现 `os::abi`、`os::foundation`、`os::kernel`、
`os::test` 和 `os::user`。

## 迁移

本次迁移扫描 136 个 C++ 头文件和源文件。初始 AST 结果包含 7018 条编译单元
诊断；公共头文件会被多个编译单元重复报告，因此该数字不是不同变量的数量。
工具生成 91 组编译单元修复，随后完成：

1. 所有普通变量、参数和字段由小驼峰迁移为小写蛇形；
2. 私有和受保护成员保留统一尾部下划线；
3. 自研 C/汇编函数符号迁移为大驼峰；
4. NASM 数据标签和链接脚本符号迁移为小写蛇形；
5. Python ELF 审计、系统测试、当前文档和教材引用同步更新；
6. 重新构建全部宿主与 freestanding 目标；
7. 再次执行 AST 与命名空间扫描，命名诊断和 Clang 解析错误均为零。

## 后果

### 正面

- 变量与函数在视觉上立即可区分。
- 名称中的单位、地址空间和所有权边界更容易阅读。
- C++、NASM、链接脚本和产物审计使用同一套可解释规则。
- 后续提交若重新引入小驼峰变量，会在完整回归中直接失败。
- 规则由 AST 执行，不依赖容易误报的文本启发式。

### 代价

- 本次变更涉及大量机械重命名，代码评审必须把行为变更与命名迁移分开检查。
- 自研 ABI 符号名发生变化，旧 ELF 和旧调试脚本不能与新对象混用。
- 新环境除 Clang 编译器外还需要安装 Clang-Tidy 工具。
- 私有成员尾部下划线与强制 `this->` 同时存在；前者避免遮蔽，后者明确成员
  访问，二者职责不同。

## 未采用方案

### 继续允许小驼峰变量

会让用户要求与现有代码长期不一致，也无法形成明确的自动门禁。

### 只修改新代码

新旧风格会永久混杂，公共结构和测试模型仍会传播旧字段名。

### 只用正则扫描

无法可靠理解 C++ 语法和跨文件引用，既会漏报，也可能错误修改函数、类型、
注释和字符串。

### 把所有 C/汇编符号都视为例外

这些符号由项目自己控制，没有外部兼容负担。保留例外只会扩大历史命名债务。
