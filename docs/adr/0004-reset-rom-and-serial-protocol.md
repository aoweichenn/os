# ADR 0004：高端 ROM、near jump 与串口验收协议

状态：已接受
日期：2026-07-24

## 背景

v0.1 必须在不使用第三方 BIOS、UEFI 或引导器的前提下，从 x86 复位向量执行
项目代码，并能在无图形 CI 环境判断正常与失败路径。

## 决策

1. 使用 128 KiB ROM，物理范围为 `0xFFFE0000..0xFFFFFFFF`。
2. 在 `0xFFFFFFF0` 放置 `E9` 16 位 near jump，目标 IP 为 `0xF000`。
3. 入口位于 `0xFFFFF000`，依赖复位时 CS 隐藏基址，不使用低端 ROM 别名。
4. 入口初始化 COM1 为 115200、8N1，并在发送前有界轮询 THRE。
5. 使用 `RESET` 和 `SERIAL_READY` 作为阶段协议。
6. 固件完成后 `HLT`；宿主在有界时间后验证串口，而不把 QEMU 专用退出设备
   变成目标软件依赖。
7. 用同源故障镜像屏蔽就绪状态，覆盖串口超时路径。

## 原因

near jump 保留复位时的 CS 隐藏基址，能够直接执行 ROM 高端入口；固定 ROM
大小使文件偏移和物理地址可静态换算；串口协议既适合早期固件，也能在后续阶段
继续扩展。让固件停机而由宿主控制测试预算，更接近真实固件在无后续任务时的
行为。

## 后果

- 链接脚本和 ROM 审计成为硬件契约的一部分。
- 在重载 CS 前，ROM 常量必须通过 CS override 访问。
- 失败通道若正是串口，不能要求串口继续报告错误；测试需要通过缺失标记判断。
- v0.2 可以在 `SERIAL_READY` 后增加磁盘探测与 Stage 1 协议，不必推翻入口。
