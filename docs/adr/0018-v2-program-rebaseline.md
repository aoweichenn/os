# ADR 0018：按依赖波次重塑 v2 演进计划

## 状态

已由 ADR 0019 取代。本文保留第一次依赖重排的推导过程，不再作为当前版本
边界、执行模型和容量下限的依据。

## 背景

第一次 v2 路线已经正确选择“单核类 Unix 用户系统”作为收敛目标，但把
v1.1 至 v1.9 划成九个近似等宽阶段后暴露出四个结构问题：

1. VFS、全新磁盘格式和大文件被放在同一个版本，状态模型过多；
2. fork/COW 排在 VMA 和按需分页之前，导致 COW 必须依赖尚未存在的地址空间
   描述、页引用和统一页故障解析；
3. 进程仍被当作唯一调度实体，没有区分共享地址空间的 Process 与拥有独立
   CPU 现场、内核栈和信号掩码的 Thread；
4. 大量新系统调用先建立在 `INT 0x80` 上，最后才整体迁移到
   `SYSCALL/SYSRET`，会迫使入口、返回和信号现场在收口期重新改造。

此外，“至少 64 个进程、每进程 64 个描述符”仍然像固定数组规格，而不是
现代内核常用的运行时限制。64 MiB、256 MiB 与 64 GiB 也承担不同测试目的，
不能继续写成同一条完整系统验收。

## 决策

### 目标系统

v2.0 定义为：

> 由自研 ROM 与 Stage 1 启动、运行在单 BSP 上、支持多进程与多线程、能够
> 从自研根文件系统执行 PID1、外部 Shell 和普通 ELF64 工具，并具备按需虚拟
> 内存、fork/COW、动态描述符、信号、终端和可恢复持久化的类 Unix 教学系统。

“对齐现代 Linux”表示学习并采用可扩展的身份、所有权和分层方法，不复制
Linux 的全部实现：

- Process 与 Thread 分离，调度器调度 Thread；
- 地址空间、文件表、工作目录和信号状态通过显式引用共享；
- fd 引用 open-file description，后者再引用 VFS 对象；
- VMA 描述地址意图，PTE 只表达当前驻留事实；
- 块请求、缓存页、日志事务和磁盘块分别拥有身份；
- 容量由运行时配置、分配器和资源限制决定，不由固定对象数组决定。

### 三种测试配置

不同内存配置承担不同证据：

- 64 MiB 是启动兼容配置，只要求自研启动链、异常和内存基础通过；
- 256 MiB 是完整功能配置，运行 PID1、Shell、工具、VM、线程和持久化场景；
- 64 GiB 是主容量配置，验证全部 RAM 管理、高内存、较大对象规模和压力回归。

不得再要求 64 MiB 客户机运行与 64 GiB 相同的并发和缓存压力。

### 版本波次

版本不再被限制为 v1.1 至 v1.9 九个等宽盒子。当前路线扩展到 v1.13：

1. v1.1：内存分配与资源生命周期；
2. v1.2：Process/Thread 与可扩展调度、双系统调用入口；
3. v1.3：类型化内核对象与动态描述符；
4. v1.4：VFS 命名空间和旧文件系统适配；
5. v1.5：rootfs v2 与大文件磁盘格式；
6. v1.6：PID1、进程树、磁盘 exec 与 wait；
7. v1.7：VMA、按需分页、页缓存和用户运行时；
8. v1.8：fork 与 COW；
9. v1.9：Unix I/O、外部 Shell 与工具集；
10. v1.10：线程、TLS 与 futex；
11. v1.11：时间、信号、TTY 与作业控制；
12. v1.12：异步块 I/O、journal 与崩溃恢复；
13. v1.13：ABI v2 冻结、加固和可观测性；
14. v2.0：只做集成发布，不再引入主要机制。

其中 `SYSCALL/SYSRET` 的入口骨架在 v1.2 与新 Thread 现场一起建立，
`INT 0x80` 作为兼容入口保留到 v1.13；ABI 编号和结构只追加，最终在
v1.13 冻结。

### 统一质量门禁

每个小版本必须依次通过：

1. ADR、状态机、不变量、所有权和失败原子性审查；
2. 与硬件无关的单元与参考模型测试；
3. 模块集成和固定种子随机测试；
4. ELF、磁盘格式、ABI 或汇编入口的产物审计；
5. 适用配置上的 QEMU 成功、边界和故障注入；
6. 资源基线回归、文档、教材、网站和发布记录同步。

任何版本若需要下一个版本尚未验收的状态模型，必须先调整路线或缩小增量，
不得用临时跨层接口绕过依赖。

## 关键顺序理由

### VMA 必须早于 COW

COW 不是单独的页表技巧。它依赖地址空间区域、页来源、共享引用、页故障分类
和 unmap/exec/exit 回收。先建立 VMA 与统一页故障解析，再加入 COW，才能把
普通只读页、文件私有映射和真正的 COW 页区分开。

### VFS 与 rootfs v2 必须分开

v1.4 先让 vnode、dentry、mount、file description 和路径解析在旧文件系统
适配器上成立；v1.5 才替换磁盘格式。若两者同时改变，路径语义错误和磁盘布局
错误无法从测试证据中分离。

### Thread 与 futex 不能缺席

只增加进程槽并不能表达现代用户程序的并发模型。Thread 共享 Process 的地址
空间和多数资源，但拥有自己的 TID、CPU 现场、内核栈、用户栈、TLS 和信号
掩码。futex 则把用户态原子快路径与内核阻塞/唤醒连接起来；其等待操作必须在
比较 32 位 futex word 与进入等待队列之间保持原子性。

### journal 保持在用户系统之后

rootfs v2 先交付明确同步语义、设备 flush 和离线一致性检查。等 VFS、页缓存
和正常用户负载稳定后，再异步化 ATA 并加入 journal。这样崩溃恢复面对的是
稳定对象和稳定写集合，而不是仍在变化的文件接口。

## 容量策略

v2.0 的验收下限是压力目标，不是 ABI 上限：

- 64 GiB 配置至少同时存在 512 个 Thread、其中至少 256 个 Process；
- 单 Process 至少创建 64 个 Thread；
- fd 采用分块动态表，默认 soft limit 为 256，验收 hard limit 至少 4096；
- 至少 1024 条按需分配缓冲页的 64 KiB 管道；
- 路径 4096 字节、组件 255 字节，参数和环境合计至少 128 KiB；
- 稀疏磁盘镜像至少 1 GiB，rootfs 区域至少 256 MiB，单文件至少 64 MiB；
- 至少 32 个独立用户 ELF 工具和 16 级流水线。

实现可以在不同测试配置下设置更低 soft limit，但达到限制必须明确失败且不
改变已有对象。计数、身份和容量仍使用固定宽度大类型，磁盘与硬件字段服从
实际协议。

## 非目标

v2.0 仍不包含：

- AP 启动、SMP 调度、per-CPU 分配器和跨核 TLB shootdown；
- 网络、图形、音频、USB、AHCI、NVMe 和通用 PCI 框架；
- 多用户权限、容器、虚拟化和完整 POSIX；
- 动态链接器、共享库和自举编译器。

这些能力进入 v2.x/v3.0 候选，不得提前侵入当前关键路径。

## 后果

正面结果：

- COW、VFS、线程和 ABI 的依赖顺序可证明；
- 版本增量更小，磁盘格式、命名空间和用户语义可以分别定位；
- 并发容量来自动态结构和资源限制，不再来自固定 64 槽数组；
- 64 MiB、256 MiB 和 64 GiB 的测试职责明确。

代价：

- v2.0 前的小版本从 9 个增加到 13 个；
- 双系统调用入口会在过渡期同时维护；
- VFS 适配层和文件系统 v2 会短期共存；
- 多线程会扩大调度、退出、exec、fork 和信号的状态组合。

这些代价通过质量门禁、固定波次和系统级资源守恒测试控制。
