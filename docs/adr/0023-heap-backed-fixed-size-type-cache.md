# ADR 0023：在可回收内核堆上建立固定尺寸类型缓存

## 状态

已接受，作为 v1.1 可回收资源基础的第四个完整实现增量。前三个增量分别建立
动态物理内存与 direct-map、可回收内核堆和双位图 buddy 页帧分配器。

## 背景

`KernelHeap` 已经能从一段连续虚拟区间中分配任意字节数，也能释放和合并
相邻块。直接让 Process、Thread、VMA、文件描述和等待节点等高频固定尺寸对象
长期调用通用堆，仍有三个问题：

1. 每次申请都要搜索可容纳块、计算对齐并修改边界标记，固定尺寸对象没有利用
   “所有槽完全同构”这一事实；
2. 每个小对象都携带通用堆块头和分裂边界，空间开销与碎片来源难以和对象容量
   分开解释；
3. 对象耗尽、重复释放、峰值并发和某一类型的泄漏会混入全局堆统计，难以作为
   v1.2 动态 Process/Thread 的独立资源证据。

历史上的 slab/slub 分配器会按对象类型管理一个或多个页后备 slab，并进一步
处理构造器、着色、per-CPU 快速路径、空/部分/满 slab 列表和内存压力回收。
一次把这些策略全部引入，会同时跨越 KVA、页映射、并发和对象模型边界。当前
v1.1 尚未冻结 Thread 与锁语义，也尚无 KVA 分配器，因此本增量只交付一个
固定容量、单后备块、可以完整销毁的最小类型缓存。

## 决策

### 两层接口

核心类 `KernelFixedObjectCache` 接受显式的对象尺寸、对象对齐和容量，管理
无类型存储。`KernelTypeCache<ObjectType>` 只用 `sizeof(ObjectType)` 与
`alignof(ObjectType)` 提供类型化包装。两层使用同一个实现，不为宿主测试
复制参考版本。

类型化接口只交付对齐存储，不隐式执行构造或析构。当前启动自检使用只含
固定宽度整数的平凡对象；未来非平凡内核对象必须由其所属模块明确提交构造、
失败回滚和析构顺序。缓存不能猜测对象生命周期，更不能在 freestanding
环境中偷偷引入宿主运行时。

### 单后备块布局

初始化时只向 `KernelHeap` 申请一次。设对象尺寸为 \(Z\)，请求对齐为 \(A_T\)，
容量为 \(N\)，则：

\[
\begin{aligned}
B &= \left\lceil \frac{N}{8} \right\rceil,\\
A &= \max(A_T, 8),\\
S &= \operatorname{align\_up}(\max(Z, 8), A),\\
O &= \operatorname{align\_up}(B, A),\\
H &= O + N \times S.
\end{aligned}
\]

其中 \(B\) 是活动位图字节数，\(S\) 是槽步长，\(O\) 是对象区相对后备块
起点的偏移，\(H\) 是唯一后备申请大小。所有加法、乘法和向上对齐在修改堆前
检查 64 位溢出。

```text
backing allocation
┌────────────────────────────── H bytes ──────────────────────────────┐
│ active bitmap: B │ alignment padding │ slot 0 │ slot 1 │ ... │ N-1 │
└──────────────────┴───────────────────┴────────┴────────┴─────┴─────┘
                                         每槽 S 字节、按 A 对齐
```

即使对象小于 8 字节，槽仍至少容纳一个 `uint64_t` 空闲索引。位图和槽放在
同一后备块中，因此初始化成功只增加一项堆活动申请，销毁成功也只归还一项。

### 位图与槽内空闲链

每槽只有两种所有权状态：

- 位图位为 1：槽由调用者持有，槽内容完全属于调用者；
- 位图位为 0：槽属于缓存，槽首 8 字节保存下一个空闲槽索引。

缓存保存一个空闲链头索引；`UINT64_MAX` 表示链尾。初始化把 `0..N-1`
串成空闲链。申请从链头弹出一个槽并置位，释放先清位，再把槽压回链头。
因此成功申请与释放均为 \(O(1)\)，刚释放的槽按 LIFO 顺序优先复用。

活动位图不是多余副本。只有空闲槽才能保存链指针，活动槽内容不可覆盖；
位图让释放路径能在写入槽前拒绝重复释放，也让完整校验可以独立计算活动集合。

### 精确释放与失败原子性

`TryRelease` 只接受对象区内、恰好位于槽首且当前位图为活动的指针。空指针、
区间外指针、槽内指针和重复释放分别返回明确状态。任何验证失败都不能修改
位图、空闲链、计数或调用者对象。

`TryAcquire` 在成功前验证计数守恒、空闲链头和下一索引。耗尽时返回
`OutOfObjects`，并保持调用者输出指针原值。累计计数即将溢出时返回
`CounterOverflow`，不把计数回绕伪装成一次成功操作。

`Destroy` 只允许活动对象数为零时执行，并先运行完整一致性校验。堆拒绝后备
释放时，缓存保持初始化状态，调用者仍可以检查和重试；只有堆释放成功后才
清空内部状态。

### 完整一致性校验

`Validate` 不申请临时内存，并核对：

- 由配置重新计算的位图尺寸、对齐、步长、对象偏移与后备总长；
- 位图确实位于后备块起点，未使用的尾位始终为零；
- 活动数、空闲数、峰值、累计申请和累计释放满足守恒关系；
- 位图观察到的活动槽数等于统计值；
- 从空闲链头遍历得到的槽均在范围内、均未活动，且步数不超过容量；
- 空闲链观察数等于空闲统计，因此断链、环和遗漏槽都会失败。

活动集合与空闲集合的计数之和必须精确等于容量。单链中重复访问某槽必然形成
环，容量上界会在越界读取前拒绝它。

### 并发边界

当前缓存与其后备 `KernelHeap` 一样，只由 BSP 串行启动路径或已经由调用者
串行化的路径使用。它不在内部临时关闭中断，也不假装已经具备 v1.2 的
Thread/IRQ 锁语义。IRQ、NMI 和 panic 路径不得调用缓存。

v1.2 冻结 `SpinLock`、`IrqSaveSpinLock` 和 Thread 执行模型后，具体缓存的
所有者负责选择外层锁。未来 per-CPU 快速路径属于独立优化，不能改变本次
已经冻结的所有权和失败语义。

## 启动自检与日志

真实内核启动使用一个 64 字节、64 字节对齐的代表对象建立 32 槽缓存：

1. 申请全部 32 槽，逐槽验证对齐并写入首尾 64 位模式；
2. 第 33 次申请必须明确耗尽且不修改输出；
3. 读回全部模式，证明槽不重叠且高半区后备存储可写；
4. 先释放偶数槽，确认重复释放被拒绝，再释放奇数槽；
5. 再申请一次，确认取得最后释放的槽，然后归还；
6. 核对 33 次成功申请、33 次释放、峰值 32、活动 0、空闲 32；
7. 销毁缓存，并确认通用堆当前占用、活动申请和最大空闲块恢复进入前基线。

申请和释放热路径不打印日志。只有整个事务提交后，内核输出一次配置、最终
统计和 `TYPE_CACHE_SELF_TEST_PASSED`。宿主 QEMU 验收同时检查顺序、出现次数、
活动数精确为零及其余数值下限。

## 测试证据

- 单元测试覆盖未初始化操作、无效尺寸/对齐/容量、布局溢出、堆容量不足、
  重复初始化、耗尽输出保持、空/内部/外部指针、活动对象销毁拒绝、重复释放、
  LIFO 复用、最终归还，以及 1 字节对象、9 槽非整字节位图和 8 字节最小步长；
- 集成测试让 8、64、256 字节对齐的三种缓存共享一个 64 KiB 通用堆，交错
  申请、释放和乱序销毁，并验证活动对象数据不被其他缓存破坏；
- 固定种子随机测试执行 100000 步申请/释放，与独立活动记录比较指针唯一性、
  数据模式、累计统计和重复释放语义，并周期性运行完整校验；
- 64 MiB QEMU 兼容路径执行上述真实写回与回收；64 GiB 主规格由完整验证
  继续覆盖同一缓存协议；
- Kernel ELF 审计确认没有新增构造器、异常、RTTI、隐藏分配或未解析运行时
  符号。

加入三项宿主测试后，当前完整 CTest 集合为 83 项。

## 结果

### 正面结果

- 固定尺寸对象的稳态申请和释放不再搜索通用堆；
- 每种缓存拥有独立容量、峰值、耗尽和泄漏证据；
- 位图与槽内空闲链同时提供 \(O(1)\) 操作和重复释放拒绝；
- 后备块可以在活动对象归零后完整交还通用堆；
- v1.2 可以在不先改变旧四 PCB 正常路径的前提下获得动态对象基础。

### 受控限制

- 单个缓存容量在初始化后固定，不会增长、收缩或跨多个 slab；
- 空缓存不会自动回收部分页，只能整体销毁；
- 没有构造器、析构器、poison、red-zone、per-CPU magazine 或锁；
- 后备仍来自当前固定 64 KiB 通用堆，不适合大规模长期对象池；
- 本增量只提供基础设施，不提前把旧 PCB 迁移为新 Process/Thread。

这些限制是明确的阶段边界。KVA 与按页增长后备完成后，可以在不改变
`TryAcquire`/`TryRelease` 所有权语义的前提下扩展为多 slab 缓存。

## 被否决方案

### 每个对象直接调用通用堆

实现最少，但固定尺寸热对象仍承担搜索、块头和碎片成本，类型容量与泄漏无法
独立观测，不能形成对象缓存学习闭环。

### 现在直接实现 Linux SLUB

它需要同步引入多页 slab、KVA、节点状态、per-CPU 并发、回收水位、构造析构
和调试对象布局。当前依赖尚未冻结，失败将无法归因。

### 只使用槽内空闲链，不保存位图

活动槽不能存放缓存元数据。没有独立活动位时，重复释放会把同一槽插入两次，
以后可能把同一地址同时交给两个调用者；完整校验也无法证明未在链中的槽确实
活动。

### 只使用位图并线性寻找零位

能够检测重复释放，但每次申请最坏扫描全部容量。它没有利用释放时已经知道
槽索引这一事实，也不提供明确的 LIFO 局部性。

### 缓存内部自行加锁或关闭中断

v1.2 前尚未冻结 Thread 与 IRQ 共享规则。提前隐藏锁会掩盖调用上下文错误，
也可能在 panic 或中断路径制造死锁。当前由调用者负责串行化更诚实。
