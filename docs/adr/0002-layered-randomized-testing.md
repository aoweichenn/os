# ADR 0002：建立分层与随机测试基线

- 状态：已接受
- 日期：2026-07-23

## 背景

操作系统错误经常只在地址边界、损坏输入、特定硬件状态或长序列操作下出现。只编写少量单元样例无法充分验证这些情况，而只运行 QEMU 又会导致反馈缓慢、故障定位困难。

## 决策

所有适合生成输入的纯逻辑模块必须采用四层测试：

1. 单元测试验证明确样例和边界。
2. 模块集成测试验证真实模块契约和数据布局。
3. 固定种子随机测试验证大量输入下的通用性质。
4. QEMU 系统测试验证依赖硬件状态的完整路径。

随机测试必须报告种子、迭代位置和失败性质。发现随机故障后，应将最小复现输入加入独立回归测试。

## 影响

- 逻辑错误可以在进入 QEMU 前获得快速反馈。
- 大量边界组合得到持续验证。
- 固定种子保证 CI 和本地结果可复现。
- 测试代码和测试数据需要与接口同步维护。
