# ADR 0016：以单核类 Unix 用户环境作为 v2.0 收敛目标

## 状态

已被 [ADR 0018](0018-v2-program-rebaseline.md) 取代。本文保留第一次 v2
路线推导及其历史理由，不再作为当前版本顺序和容量验收依据。

## 背景

v1.0 已经从自研复位向量进入 C++20 内核，建立中断、内存、Ring 3、抢占
调度、阻塞管道、持久文件系统、统一描述符和交互式 Shell。但这些机制仍由
固定四进程、内嵌用户 ELF、低 64 MiB 页管理、八槽描述符和 5120 字节文件
连接。继续逐项增加设备或 Shell 内建命令，会扩大代码量，却不会解决进程、
地址空间、命名空间和资源生命周期的静态假设。

同时把 SMP、网络、图形、现代存储、完整 POSIX 和自举编译器全部放入 v2.0，
会形成多个互相放大的未知边界，使每个阶段无法保持单一验收目标。

## 决策

v2.0 收敛为单处理器、多进程、类 Unix 的教学操作系统。它必须保留完整自研
启动链，并围绕以下用户场景组织架构：

```text
ROM → Stage 1 → Kernel
  → mount rootfs
  → exec /sbin/init
  → exec /bin/sh
  → fork/exec/wait
  → pipe/dup/redirection
  → signal/terminal/job control
  → demand paging and persistent files
```

路线顺序固定为：

1. 先建立可回收内核资源与更大容量；
2. 再建立 VFS 和能够容纳 ELF 的文件系统 v2；
3. 再实现磁盘 exec、父子进程和 wait；
4. 在稳定进程生命周期上实现 fork/COW；
5. 在稳定描述符所有权上实现管道、重定向和外部 Shell；
6. 再加入信号、终端、按需分页和用户运行时；
7. 最后演进异步块层、崩溃恢复和 ABI v2。

v2.0 正常路径只由内核创建 PID1，其他进程由用户态动态创建。PID 不再等于
PCB 槽位；fd 不再等于文件系统句柄；VMA 不再等于已分配物理页；vnode、
open-file description、页缓存和块请求分别表达各自身份与生命周期。

## 为什么不先实现 fork

当前用户程序来自 Kernel 内嵌数组，正常镜像没有父子关系、Zombie 或磁盘
exec。此时先实现 fork 会把固定四进程和内嵌镜像假设复制到新接口中。先完成
VFS、exec 和 wait，可以让 fork 只负责复制已经稳定的进程状态；COW 也能以
明确的页所有权和失败回滚为基础。

## 为什么 VFS 位于 exec 之前

现有文件系统句柄直接绑定固定磁盘布局，最大文件只有 5120 字节，而当前用户
ELF 已经明显大于该上限。若 exec 直接依赖该接口，后续引入挂载、cwd、设备
文件和大文件时需要重写进程 ABI。先用 VFS 隔离命名对象和磁盘格式，exec
只依赖 vnode/read 接口。

## 为什么 SMP 不进入 v2.0

SMP 会同时要求 AP 启动、ACPI 或 MP 表、IOAPIC、per-CPU 状态、并行调度、
跨核中断、TLB shootdown 和更严格的锁设计。它与当前用户环境主线正交，
但会把几乎每个失败路径变成并发问题。v2.0 保持单 BSP，可以完整学习进程、
虚拟内存、VFS、信号和持久化；已有 acquire/release 锁和所有权文档为后续
SMP 提供输入，但不宣称当前代码已可并行运行。

## 兼容策略

- 1.x 系统调用只追加，不复用编号；
- v1.9 同时提供 INT 0x80 兼容入口和 SYSCALL/SYSRET 主入口；
- v2.0 可以删除已有统一替代的历史专用文件/管道调用，并冻结 ABI v2；
- 文件系统 v2 使用新的 magic 和 version；未知非零磁盘不得自动格式化；
- 专用故障镜像可以保留最小内嵌用户 ELF，生产正常路径必须从磁盘执行。

## 后果

正面结果：

- 每个阶段有清晰的输入、输出和资源模型；
- Shell、进程、VFS、内存与块层沿长期边界演进，不依赖临时数组索引；
- v2.0 有可完成的范围和可量化验收场景；
- SMP、网络和图形将获得独立路线，而不是以半成品混入当前主线。

代价：

- v1.1 和 v1.2 主要建设资源与命名基础，用户可见功能增长较慢；
- 文件系统 v2 不保证原地兼容 v1 格式，需要离线迁移或重建测试镜像；
- 单处理器目标无法验证真正的锁并行性；
- 在 v1.9 前需要维护过渡系统调用入口和历史回归。

## 重新评估条件

当 v2.0 全部端到端验收完成后，重新评估下一周期。若优先学习并发硬件，则以
AP 启动、IOAPIC 和 SMP 调度为主线；若优先扩展用户能力，则以网络、套接字
和更完整的 POSIX 子集为主线。不得在 v2.0 收口前提前混入两条路线。
