# ADR 0014：固定布局、显式事务状态与有界文件系统

## 状态

已接受，适用于 v0.11。

## 背景

v0.10 已经具备 ATA PIO 读取、进程、同步、用户内存复制和系统调用边界，但磁盘
仍只承载 Stage 1 与 Kernel ELF。v0.11 需要第一次把“块设备上的持久化字节”
提升为“可通过路径访问的目录和普通文件”，同时保留学习项目必须具备的可解释
布局、损坏检测、失败原子性和真实重启证据。

本阶段不采用 FAT、ext2 或宿主目录映射。使用现成格式会把关键学习内容转移到
兼容实现；使用 QEMU virtio-9p、共享文件夹或宿主文件 API 则会越过自研文件
系统边界。

## 决策

### 1. 固定磁盘区域

原始 IDE 磁盘固定为 2 MiB。前 1 MiB，即 LBA `0..2047`，专供启动描述符、
Stage 1、Kernel 描述符和 Kernel ELF；文件系统占用 LBA `2048..3071`，
共 1024 个 512 字节块；LBA `3072..4095` 作为后续扩展保留。磁盘布局如下：

| 相对块 | 数量 | 内容 |
| --- | ---: | --- |
| 0 | 1 | superblock |
| 1 | 1 | inode bitmap |
| 2..9 | 8 | 32 个、每个 128 字节的 inode |
| 10 | 1 | data block bitmap |
| 11..1023 | 1013 | 目录与普通文件数据 |

固定的 1 MiB 边界让启动加载器与文件系统不存在动态互相追赶的问题，也让宿主
工具可以在不运行来宾的情况下检查重叠。早期草案曾从 LBA 1024 开始；真实
QEMU 构建发现增长后的 Kernel ELF 已占到 LBA 1054，因此在实现落地前把边界
提升到 LBA 2048，而不是接受启动文件覆盖文件系统的隐患。

### 2. 不直接映射 C++ 结构体

superblock、inode 和目录项均使用显式小端编码/解码函数。持久化格式不依赖
编译器填充、结构体对齐、枚举底层布局或宿主 ABI。

- superblock 精确占一个块，并在末尾保存 CRC32；
- inode 精确为 128 字节，包含类型、长度、代次、链接数、10 个直接块和
  自身 CRC32；
- 目录项精确为 64 字节，包含 inode 号、类型、名称长度和 40 字节名称；
- inode 0 保留，根目录固定使用 inode 1。

普通文件最多使用 10 个直接块，即 5120 字节。这个上限是 v0.11 的显式范围，
后续通过间接块扩展，而不是现在隐藏一个不完整的大文件实现。

### 3. 绝对路径与有界解析

当前只接受以 `/` 开头的绝对路径。路径最大 128 字节，单个名称最大 40
字节；拒绝空组件、尾随 `/`、`.`、`..`、控制字符和超长组件。目录可嵌套，
每个目录最多使用 10 个直接块。

路径解析逐组件读取父目录并验证目录项引用的 inode 类型。创建只允许最后一个
组件不存在，父路径必须已经存在且为目录。

### 4. 写回块缓存

内核维护 8 项、每项 512 字节的固定容量 LRU 写回缓存。缓存项保存 LBA、
有效位、脏位和单调访问代次；淘汰脏项前必须先写回。缓存不分配堆内存，
统计命中、未命中、磁盘读取、磁盘写入和淘汰。

### 5. 显式事务状态

每次修改操作按以下顺序提交：

1. 把 superblock 状态写为 `Dirty`，递增事务代次并执行 ATA FLUSH CACHE；
2. 修改缓存中的数据块、inode、目录项和 bitmap；
3. 写回全部脏缓存并再次执行 FLUSH CACHE；
4. 把 superblock 状态写为 `Clean`，更新 CRC32，再次执行 FLUSH CACHE。

该协议不是完整日志或写时复制。断电发生在步骤 1..3 时，下次挂载会明确检测
未完成事务并拒绝继续，而不会把部分写入误认为一致文件系统。v0.11 的目标是
“检测并停止”，恢复和重放留给后续日志层。

### 6. 首次格式化与损坏区分

只有整个 superblock 块全零时才允许首次格式化。非零但 magic、版本、布局、
状态或 CRC32 非法时返回损坏，不自动覆盖。这样故障注入不会被“自动格式化”
掩盖。

### 7. 用户接口

`INT 0x80` ABI 扩展第三参数寄存器 RDX，并新增：

- `OpenFile(path, pathLength, flags)`；
- `ReadFile(fd, destination, capacity)`；
- `WriteFile(fd, source, length)`；
- `CloseFile(fd)`；
- `CreateDirectory(path, pathLength)`；
- `SyncFileSystem()`。

每个进程拥有四个文件描述符槽，退出或异常终止会自动关闭。打开标志支持读、
写、创建和截断；权限、用户指针、长度、描述符和路径错误使用稳定的
`int64_t` ABI 结果。

## 后果

### 正面

- 从 ATA 扇区、缓存、bitmap、inode、目录项、路径到用户 ABI 形成完整学习链；
- 所有格式字段都能在十六进制镜像中独立解释；
- 首次格式化、正常挂载、未完成事务和结构损坏可以明确区分；
- 固定容量使目标代码不依赖动态容器或外部运行时；
- v1.0 Shell 可以直接复用当前文件描述符边界。

### 负面

- 单文件上限为 5120 字节，inode 和目录数量固定；
- 修改操作期间持有全局文件系统锁，当前单核环境中正确但并发度有限；
- 检测到 Dirty 事务时只拒绝挂载，不执行恢复；
- 只支持绝对 UTF-8/字节名称，不提供权限、时间戳、硬链接或删除。

## 验证

- 单元测试逐字段验证 superblock、inode、目录项、路径和 CRC32；
- 内存块设备集成测试覆盖格式化、嵌套目录、创建、读写、截断、缓存淘汰与重新
  挂载；
- 固定种子随机测试把实现与内存参考模型对照；
- 损坏磁盘 QEMU 路径必须输出 `FILESYSTEM_CORRUPT` 且不得进入用户态；
- 持久化测试对同一可写磁盘连续启动两次，第二次必须在用户修改前验证第一次
  写入的完整载荷。
