# ADR 0006：固定 Kernel 描述符与 CRC32 磁盘容器

- 状态：接受
- 日期：2026-07-24

## 背景

v0.4 已能生成可信 ELF64 内核，但 ROM 仍只认识 Stage 1 描述符。若让 Stage 1
通过构建时隐含偏移寻找内核，Stage 1 大小变化会移动 Kernel，磁盘内容也无法
独立审计。此时引入文件系统又会把目录、分配和持久化问题提前带入最早启动链。

## 决策

在原始启动磁盘上增加独立 Kernel 容器：

- LBA 0 和 LBA 1..64 保持 Stage 1 v1 格式。
- LBA 65 固定保存 512 字节 Kernel v1 描述符。
- LBA 66 开始保存精确的 `kernel.elf`，尾部只做扇区补零。
- 描述符使用 64 位 LBA、文件长度和扇区数字段。
- 描述符与文件分别使用 CRC32；当前保留字节必须为零。
- 打包前先审计 ELF，解析时再验证 CRC、范围和 ELF 结构。

## 原因

固定 LBA 让 Stage 1 与 Kernel 的增长相互独立：只要 Stage 1 不超过已承诺的
64 扇区，Kernel 位置就不变化。自描述字段使目标机不需要把宿主构建参数编进
代码。CRC32 比当前 Stage 1 的 16 位加法更适合较大的 ELF 文件，同时仍可由
后续自研汇编实现解释和验证。

64 位字段表达格式的长期容量，但当前读取路径仍必须拒绝超过 LBA28 的值。
宽字段不会自动扩大硬件能力。

## 未采用方案

- 紧跟 Stage 1 动态放置：节省少量空扇区，但位置随 Stage 1 大小变化。
- 在 ROM 描述符中加入 Kernel：让最小固件同时承担两个不同阶段的格式演进。
- 立即引入 FAT 或其他文件系统：把不属于 v0.4 的目录和分配机制提前加入。
- 只依赖 ELF 内部结构：ELF 不能说明自己在磁盘上的 LBA 和精确容器长度。

## 后果

- 磁盘镜像可以在 QEMU 启动前独立审计 Stage 1 与 Kernel。
- 损坏描述符和损坏 ELF 分别拥有确定的失败镜像。
- Stage 1 下一步必须实现 ATA 读取、CRC32 和 ELF64 边界验证。
- 未来改变固定位置或字段语义必须提升 Kernel 描述符版本。
