# ADR 0010：传统中断路由与最小设备启动闭环

- 状态：接受
- 日期：2026-07-25
- 关联阶段：v0.7 中断与设备

## 背景

v0.6 已有内核 GDT、TSS、IDT、页表和 guard page，但 IF 始终关闭。v0.7
需要第一次接收异步硬件事件。QEMU `pc` 同时模拟 8259A、I/O APIC 与本地
APIC；处理器复位后本地 APIC 可以保持全局启用，而自研 ROM 并没有传统 BIOS
替内核建立虚拟线模式。仅重映射 PIC、开放 IRQ0 并执行 `STI` 不足以保证
8259A 的 INTR 被 CPU 接收。

设备启动还必须形成可验证闭环。只在纯模型中计算向量不能证明 EOI 正确；只让
PIT 计数不能证明外部输入；只复用 Stage 1 ATA 结果又不能证明内核拥有端口
访问能力。

## 决策

1. v0.7 采用 LAPIC virtual-wire 与传统 8259A 的兼容路由。内核把
   `IA32_APIC_BASE` 指定的 LAPIC MMIO 页映射为 supervisor RW/NX/PCD，
   保持 APIC 全局启用并拒绝 x2APIC 模式；随后设置 SVR 软件启用且向量为
   `0xFF`，把 LVT LINT0 配成未屏蔽的 ExtINT，回读确认后再初始化 PIC。
2. PIC 主从片重映射到向量 32 和 40。全部 IRQ 默认屏蔽，设备就绪后只开放
   IRQ0 与 IRQ1；不开放尚无驱动的 IRQ。
3. 向量 32..47 使用独立汇编桩和 C++ 硬件分发器。寄存器保存布局与异常帧
   相同，异常策略与 EOI 策略保持分离。
4. PIT 通道 0 运行模式 2，目标 1000 Hz。ISR 只更新 64 位计数，时间由
   `tick × divisor × 1000 / 1193182` 换算。
5. PS/2 IRQ1 只读取一个及时字节并推进有界扫描码状态机；复杂文本布局留给
   后续终端层。宿主用 QMP `sendkey` 产生 QEMU 键盘硬件事件，不直接写来宾
   内存或调用内核函数。
6. ATA 当前保持 PIO 轮询和 `nIEN`，内核独立重读 LBA 0 作为设备自检。
   IRQ14 与异步块请求属于后续驱动演进，不在本阶段伪造。
7. IRQ 路径禁止逐 tick 日志。启动期记录配置与一次统计，事件循环只记录有
   语义的键盘事件；宿主为串口行附加单调到达时间。

## 结果

- 首次建立了从物理设备模型到 IDT、汇编 ABI、C++ 状态和 EOI 的完整异步链。
- LAPIC 当前只作为 PIC 输出的 virtual-wire 兼容桥；暂不使用 LAPIC timer、
  IPI、I/O APIC 或多核目标路由。升级时必须新增控制器抽象和相应 ADR。
- PIT 提供启动后的单调时间基础，但不是墙钟，也不保证每 tick 恰好 1 ms。
- PS/2 只保留一个待消费事件；持续输入的环形缓冲、溢出统计和终端处理属于
  下一次最小增量。
- ATA 自检证明内核拥有 IDE 端口协议，但仍是同步轮询，不声明完成通用块层。

## 否决方案

### 继续依赖处理器复位后的隐含中断路由

真实 QEMU 诊断显示 PIC 的 IRR 已出现 IRQ0/IRQ1、IF=1 且 CPU 处于 HLT，
事件仍未交付。隐含平台状态不可作为内核 ABI，因此否决。

### 直接关闭 LAPIC 全局启用位

这一策略在 QEMU 10.2 可以让 PIC 直接交付 INTR，但 QEMU 8.2 中 PIC 已置
IRR、IF 已开启并等待五秒后仍没有向量 32，说明跨版本行为不足以作为稳定平台
契约。显式配置 SVR 与 LVT LINT0 的 ExtINT 路径同时保留 APIC 架构状态并
匹配 PC virtual-wire 模型，因此否决直接关闭方案。

### 立即实现 I/O APIC 和本地 APIC timer

这会同时引入 ACPI/MP 拓扑、MMIO、重定向表、LAPIC EOI 和多核目标选择，
超过 v0.7 的最小学习增量。传统 PIC 更适合先验证统一 IRQ ABI。

### 让 Python 直接向端口或来宾内存写扫描码

这样绕过 QEMU 的 i8042 与键盘状态机，无法证明 IRQ1 硬件路径。QMP 只操作
虚拟键盘前端，设备协议仍由来宾自行处理。
