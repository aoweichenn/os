# ADR 0015：统一描述符、交互式 Shell 与无 Ready 空闲路径

## 状态

已接受，适用于 v1.0。

## 背景

v0.11 已经分别提供控制台日志、专用管道系统调用和普通文件系统调用，但三类
对象没有共同的进程局部名字。用户程序无法把标准输入、标准输出、管道和文件
看成同一种“可读或可写端点”，目录也没有迭代接口。与此同时，v0.10 的调度器
要求进程阻塞后仍有另一个 Ready 进程；交互式 Shell 在等待真实键盘输入时，
如果其他进程已经结束，就会遇到“存在 Blocked、但没有 Ready”的正常状态。

把命令文本预置在内核、让 QEMU 使用串口后门、引入宿主共享目录或由 QEMU
代替终端驱动，都会越过本项目要学习的设备、中断、调度和用户边界。v1.0
必须让外部按键经过 PS/2、IRQ1、内核队列、系统调用和阻塞唤醒后才到达
Ring 3。

## 决策

### 1. 每进程固定八槽描述符表

描述符是进程局部的 64 位无符号索引。槽位 0、1、2 固定为标准输入、标准
输出和标准错误；动态槽从 3 开始，当前容量为 8。槽位类型显式区分：

- 控制台输入、控制台输出、控制台错误；
- 普通文件、目录；
- 管道读端、管道写端；
- 已关闭。

文件和目录槽在同索引的文件系统句柄数组中保存偏移与权限。生产者和消费者
创建时分别把管道写端或读端安装到 fd 3。退出和用户异常沿描述符表逐槽关闭，
不再另外维护一套“是否拥有管道端点”的资源生命周期。

v0.11 的 OpenFile 继续返回动态 fd；新增通用 TryReadDescriptor、
TryWriteDescriptor、WaitDescriptorReadable、WaitDescriptorWritable 和
CloseDescriptor。旧的编号 4..13 暂时保留为兼容 ABI，使历史故障镜像与
教材仍可复现；正常 v1.0 用户程序只用通用读写与关闭路径。

### 2. 目录使用专用迭代操作

目录不是字节流。OpenDirectory 返回普通描述符，但 ReadDirectory 返回固定
64 字节 ABI 项：inode 号、明确节点类型、名称长度和 40 字节名称。返回 1
表示一个目录项，返回 0 表示迭代结束，负数表示错误。目录不能通过通用
ReadDescriptor 读取，普通文件也不能调用 ReadDirectory。

这种设计统一“句柄命名与关闭”，同时保留对象操作的语义差异；它不是把所有
内核对象强行伪装成相同字节流。

### 3. 键盘 IRQ 向固定 FIFO 提交字符

Set 1 解码器维护左右 Shift 和 Caps Lock 状态，按 US 键盘行把 make code
转换为 ASCII；break code 只更新状态，不产生字符。Caps Lock 只影响字母，
标点仍只由 Shift 改变。Enter、Backspace、Tab 和 Space 使用明确字符值。

可打印按键由 IRQ1 处理路径提交到 256 字节固定 FIFO。队列统计提交、读取、
丢弃和当前缓冲字节；满队列拒绝覆盖旧输入。中断热路径不逐键打印，只在字符
成功提交后唤醒等待 DescriptorReadable 的进程。

### 4. 没有 Ready 时回到内核执行 STI; HLT; CLI

调度器允许当前进程从 Running 变为 Blocked，即使没有 Ready 后继。此时清除
当前索引并返回永久内核地址空间与默认 TSS.RSP0，汇编恢复
ExecuteProcesses 的内核调用链。执行器观察到 NoReadyProcess 后执行：

```text
STI
HLT
CLI
重新检查 Ready 队列
```

x86 的 STI 中断屏蔽影子保证紧随其后的 HLT 先进入空闲，再响应已经到达或
随后到达的可屏蔽中断。三条指令必须位于同一个内联汇编块，避免 C++ 调用边界
插入 RET/CALL；IRQ 返回后紧邻的 CLI 恢复调度临界区。IRQ0 可以只更新时间；
IRQ1 提交字符并把 Shell 从 Blocked 变回 Ready。执行器随后激活该进程 CR3
与 TSS.RSP0，从保存的系统调用帧继续。

本阶段不创建伪造的 idle 用户进程，也不让 NoReady 等同于“全部结束”。只有
不存在 Ready、Running 和 Blocked，且所有已创建进程均终止时，调度才完成。

### 5. Shell 是普通 Ring 3 程序

Shell 由 freestanding C++20 与最小 NASM 系统调用桩链接为独立 ELF64。
它没有堆、标准库或隐藏运行时，使用 128 字节命令行、最多 8 个参数和固定
256 字节写入缓冲。解析器支持空白分隔、单双引号与反斜杠转义，拒绝未闭合
引号、悬空转义、超长行和参数溢出。

v1.0 命令为 help、echo、pwd、ls、mkdir、write、cat、sync 和 exit。
当前 cwd 固定为根目录，pwd 因而稳定输出 `/`；write 采用
create+truncate；ls 通过真实目录句柄迭代。命令实现只调用公开用户 ABI，
不依赖内核符号。

### 6. QEMU 只产生外部按键

系统测试在观察到 `[OS][USER][SHELL] READY` 后，通过 QMP
`human-monitor-command/sendkey` 逐字符输入一组命令。每个字符仍由 QEMU
PC 键盘前端产生扫描码，来宾必须自行经过 i8042、PIC、IDT、IRQ 汇编入口、
Set 1 解码、控制台 FIFO、等待唤醒和用户复制。

测试不把命令字节写入来宾内存，不调用内核测试入口，也不使用 QEMU
`-kernel`、共享目录或宿主 stdin 代替自研链路。

## 后果

### 正面

- 标准 I/O、文件、目录和管道共享同一进程局部命名与关闭规则；
- Shell 等待键盘时 CPU 进入可被中断唤醒的真实空闲状态，不忙等；
- 目录 ABI 的大小、类型和结束语义可独立审计；
- 交互式整机测试同时覆盖硬件输入、阻塞调度、系统调用和持久文件系统；
- 控制台统计能证明输入没有静默丢失，日志仍保持冷路径汇总。

### 负面

- 描述符容量固定为 8，没有 dup、继承、引用计数或跨进程传递；
- 仍保留历史专用系统调用，ABI 表暂时存在兼容入口；
- Shell 没有 fork/exec、管道语法、重定向、相对路径或可变 cwd；
- 控制台只实现 US Set 1 到单字节 ASCII，不处理 Unicode、终端模式或行规程；
- 所有 DescriptorReadable 等待者共享同一原因，尚无按对象组织的等待队列。

## 验证

- 控制台 FIFO 单元测试覆盖空、FIFO、部分读取、回绕、满队列与丢弃统计；
- 描述符表单元测试覆盖标准槽、管道方向、分配、关闭、复用和容量耗尽；
- Shell 解析器单元测试覆盖命令、引号、转义与全部显式失败；
- 4096 轮固定种子随机测试把随机参数拼接后与解析结果逐字节对照；
- 文件系统生命周期集成测试通过目录句柄迭代重挂载后的目录；
- 调度单元测试覆盖最后一个 Running 阻塞、NoReady、唤醒和恢复；
- Kernel ELF 反汇编审计要求空闲函数中的 `STI/HLT/CLI` 精确相邻；
- QEMU 正常路径逐字输入十条命令，要求命令标记各一次、四进程退出为零、
  控制台 submitted=read、dropped=buffered=0；
- 同盘双启动继续执行同一 Shell 回归，随后损坏超级块的第三次启动不得进入
  Ring 3。
