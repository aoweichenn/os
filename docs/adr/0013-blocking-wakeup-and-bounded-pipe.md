# ADR 0013：条件驱动的阻塞/唤醒与有界字节流管道

- 状态：接受
- 关联阶段：v0.10 同步与 IPC
- 日期：2026-07-25

## 背景

v0.9 只有 `Unused/Ready/Running/Terminated`。进程要么可运行，要么已经
结束；用户代码等待资源只能反复系统调用，既浪费 CPU，也无法表达“当前不应
参与调度，但条件改变后仍可继续”的生命周期。

v0.10 需要用一个足够小、又能暴露真实并发边界的 IPC 对象验证：

- 条件检查与阻塞之间不能丢失唤醒；
- 阻塞进程不能继续占用 Ready 调度机会；
- 数据提交与唤醒顺序必须明确；
- 端点关闭必须形成 EOF 或 broken pipe，而不是永久等待；
- 用户地址不能在持有共享对象锁时访问；
- 当前单核实现不能把关闭 IF 错称为适用于 SMP 的锁。

## 决策

1. `ProcessScheduler` 新增 `Blocked` 状态，并在 PCB 中保存
   `ProcessWaitReason::{None, PipeReadable, PipeWritable}`。阻塞从 Running
   直接转移到 Blocked；唤醒只把原因匹配的进程移回 Ready。
2. 阻塞操作必须存在另一个 Ready 后继。若所有未终止进程均被阻塞，运行时
   返回 `NoReadyProcess` 并停机诊断，不把死锁当作正常调度完成。
3. 当前系统调用入口是 DPL3 interrupt gate，进入内核时硬件清 IF。单核上，
   条件检查、标记 Blocked 和选择后继不会被本地普通 IRQ 插入。该事实只保证
   当前调度转换原子性，不替代未来跨 CPU 同步。
4. 提供 `SpinLock` 和 `SpinLockGuard`。获取使用 exchange-acquire，释放使用
   store-release，观察使用 relaxed；竞争循环执行 x86 `PAUSE`。锁只保护
   不睡眠的短临界区。
5. 本阶段只实现一个 bootstrap pipe：64 字节固定环形数组、一个读端、一个
   写端、一个生产者和一个消费者。固定对象避免在 IPC 语义稳定前混入通用堆、
   文件描述符和引用计数的不变量。
6. 管道允许部分读写。空且写端开放时读为 `WouldBlock`，空且写端关闭时为
   EOF；满且读端开放时写为 `WouldBlock`，读端关闭时为 `BrokenPipe`。
7. ABI 把 `TryRead/TryWrite` 与 `WaitReadable/WaitWritable` 分成独立编号。
   Try 不调度；Wait 只阻塞并在唤醒后返回。用户包装始终循环重新 Try，因为
   “被唤醒”只表示条件可能变化，不等于 I/O 已提交。
8. 用户复制与管道锁分离。写先验证并复制到最多 64 字节的内核缓冲，再持锁
   提交；读先持锁取到内核缓冲，释放锁后才 `CopyToUser`。当前读复制失败不会
   回滚已经消费的数据，因此系统调用必须在消费前完整验证用户可写范围。
9. 写入数据后唤醒读者，读取数据后唤醒写者。关闭写端唤醒读者以观察 EOF，
   关闭读端唤醒写者以观察 broken pipe。正常退出和用户异常都自动关闭当前
   进程拥有的端点。
10. IRQ0、锁竞争和每次读写均不打印串口。进程全部结束后统一输出阻塞、唤醒、
    传输、EOF 和每进程字节统计；日志不参与调度热路径。

## 不采用的方案

- 在用户态循环 Try：它是忙等，无法证明 Blocked 状态和调度资格正确变化。
- 在一次系统调用中自动睡眠并重放读写：挂起现场的 RIP 已越过 `INT 0x80`，
  直接返回会让用户误以为 I/O 已完成；倒退 RIP 又会隐式重做寄存器与副作用。
- 用 `volatile bool` 实现锁：`volatile` 约束编译器访问，不提供互斥、原子
  read-modify-write 或跨核 happens-before。
- 只靠 `CLI/STI` 保护全部共享对象：它只能阻止当前 CPU 的可屏蔽中断，不能
  阻止另一 CPU；而且无条件 STI 会破坏调用者原 IF 状态。
- 立即实现任意数量管道、fd、dup、fork 和引用计数：这些属于 v0.11 的对象
  命名与 VFS 生命周期，会遮蔽本阶段的等待条件和端点语义。
- 把日志写在阻塞/唤醒和锁循环中：115200 波特串口会扩大临界区并改变原本要
  验证的调度行为。

## 结果

系统首次拥有不消耗 CPU 时间片的条件等待，以及由真实 Ring 3 生产者/消费者
驱动的 IPC 闭环。64 字节内核容量与 31 字节用户读取块迫使环形回绕和部分
传输；256 字节载荷迫使满/空条件多次出现。调度 block/wakeup 守恒、管道写入/
读取守恒、EOF、端点关闭和页帧回收共同构成端到端证据。

该决策没有解决通用等待队列对象、多个生产者/消费者、公平唤醒、信号、超时、
可睡眠 mutex、优先级继承、SMP、fd 或 VFS。后续扩展必须保留“条件在同一同步
规则下检查与改变、唤醒后重新检查、关闭也会唤醒”的核心不变量。
