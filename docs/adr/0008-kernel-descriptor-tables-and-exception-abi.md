# ADR 0008：内核接管描述符表并规范化异常 ABI

- 状态：接受
- 日期：2026-07-24

## 背景

Stage 1 的 GDT 只包含模式切换需要的平坦段，生命周期、选择子和内存归属都属于
加载器。内核若继续依赖它，就无法安全引入 Ring 3 特权切换、IST、设备中断和
独立异常策略。x86-64 异常还有两种不同的硬件栈形状：部分向量压入错误码，
部分不压；未来跨特权级进入时还会增加旧 RSP 和 SS。普通 C++ 函数不能直接
消费这些不一致的现场。

## 决策

- 内核进入后自行构造并加载 GDT、TSS 和 IDT，不把 Stage 1 描述符状态作为
  长期接口。
- 当前 GDT 只保存空项、Ring 0 代码段、Ring 0 数据段和 64 位 TSS，避免在
  用户边界实现前预设 Ring 3 ABI。
- TSS 的 RSP0 指向 BootInfo 声明的内核初始栈；IST1、IST2、IST3 分别保留给
  双重故障、NMI 和机器检查，每个栈为 16 KiB。
- IDT 分配完整 256 槽，只把架构异常 0..31 标记为 present；设备向量在 v0.7
  建立控制器和中断确认协议后再开放。
- 每个异常拥有独立 NASM Intel 语法入口。无硬件错误码的入口先压入零，所有
  入口再压向量号并进入公共保存路径。
- 公共路径保存 15 个通用寄存器、执行 `CLD`、动态对齐调用栈，再把固定
  160 字节 `ExceptionFrame` 指针传给 C++20 分发器。
- 只有受控 breakpoint 被视为可恢复并通过 `IRETQ` 返回；其他异常统一进入
  无分配、不可重入、禁止中断的 panic。
- panic 记录原始向量、错误码、RIP、CS 和 RFLAGS；页故障额外记录 CR2，
  不在最早异常路径加入格式化库、栈回溯或动态容器。
- 正常镜像通过 `INT3` 验证往返；两个独立镜像分别通过 `UD2` 和访问首个
  未映射地址验证 panic。故障镜像只替换入口，不能复制或替代生产异常代码。

## 原因

内核重新拥有描述符表后，Stage 1 和 Kernel 的依赖方向变成单向交接，而不是
共享隐藏可变状态。统一异常帧把硬件差异限制在汇编边界，C++ 分发器可以使用
明确位宽结构体和 `static_assert`，也便于单元与随机测试。

为关键不可屏蔽异常预留 IST，是因为这些异常最需要在普通栈损坏时仍留下证据。
当前不强行制造真实双重故障：双重故障触发条件容易退化为三重故障复位，无法
稳定区分“IST 正确”和“偶然未坏”。本阶段通过 TSS 布局、`LTR` 回读和真实
异常门验证机制；更强的栈保护要等 v0.6 能建立 guard page。

## 未采用方案

- 继续使用 Stage 1 GDT：代码最少，但把加载器实现细节变成永久内核 ABI。
- 全部 256 个 IDT 槽指向同一无向量入口：无法可靠识别来源，也掩盖未配置 IRQ。
- 为每个向量编写独立 C++ `interrupt` 属性函数：编译器扩展和栈布局难以跨版本
  审计，也不能自然统一硬件错误码。
- 在 C++ 中手工调整 RIP 跳过所有 fault：不同异常的重启语义不同，会把真实
  内核缺陷伪装成继续运行。
- panic 使用标准格式化、堆和锁：异常可能正由这些基础设施损坏引起，容易递归。
- 立即启用 `STI` 和 PIC：没有 IRQ 分发与 EOI 协议时开放中断会扩大状态空间，
  属于 v0.7。

## 后果

- 内核 BSS 增加完整 IDT、TSS 和三个 16 KiB IST 栈；ELF 文件不保存这些零字节，
  但 `p_memsz` 和装载时间会增加。
- 汇编压栈顺序和 C++ `ExceptionFrame` 成为严格 ABI，字段变化必须同时修改
  入口、退出、静态断言、单元测试和教材。
- v0.6 可以依靠可靠页故障诊断建立页分配与页表；v0.7 可以在同一 IDT 上增加
  PIC/PIT/键盘向量和 EOI 处理。
- IST 当前没有 guard page；在 v0.6 建立内核页表后必须补上并增加溢出测试。
