## 背景

v0.8 只有一个同步用户执行单元。内核把用户 ELF 映射进当前 CR3，通过一块
TSS.RSP0 转换栈进入 Ring 3，并在退出或异常后恢复启动该程序的内核调用链。
这个模型能证明特权隔离，却不能同时保存两个用户现场，也不能解释 PID、就绪队列、
时间片、公平性和资源回收。

v0.9 必须建立真实的多进程边界，同时保持以下既有约束：

- 单核 x86-64 与 8254 PIT 仍是当前硬件基础；
- 中断热路径不能打印串口或动态分配；
- 内核低端身份映射、高半区堆、GDT、IDT 和设备 MMIO 必须在所有进程 CR3
  下继续可用；
- 同一个 `ET_EXEC` 用户 ELF 必须能以相同虚拟地址同时存在于多个进程；
- 退出和用户异常必须回收用户页、用户页表和根页表，不能只改变状态字段。

## 决策

1. 进程上限固定为 4，PID、计数、时间和索引均使用显式 64 位类型。固定上限是
   当前启动期教学增量，不使用堆分配 PCB。
2. 采用单核、固定时间片的 round-robin。默认时间片为 4 个 PIT tick。进程状态
   为 `Unused → Ready → Running → Terminated`；本阶段不伪造尚未实现的
   sleeping、blocked 或多线程状态。
3. 每个进程拥有独立 PML4 根、用户 ELF 页、四页用户栈和 16 KiB Ring 0
   内核栈。每块内核栈下方保留一页 not-present guard。
4. 内核映射作为只读模板共享。PML4[0] 的 PDPT 为每个进程复制一份，只共享
   supervisor 内核子树并清空用户程序所在的 PDPT[1]；用户栈使用独立的
   PML4[255]。这样既保留用户 ELF 的 `0x40000000` 链接地址，也不会让一个
   进程修改另一个进程的页表。
5. IRQ、异常与系统调用入口继续形成 176 字节用户特权帧。PCB 保存该帧地址；
   汇编分发器采用 C++ 返回的帧地址恢复寄存器并执行 `IRETQ`。
6. PIT IRQ 先完成设备计数与 PIC EOI，再通知调度器。只有中断来源是 CPL3、
   时间片到期且存在另一个 Ready 进程时才抢占；Ring 0 中断和单一可运行进程
   不切换。
7. 切换时先保存当前帧，再更新进程状态、CR3 和 TSS.RSP0，最后由汇编恢复新
   帧。所有进程共享的内核映射保证 C++ 分发器可以在切换 CR3 后安全返回。
8. `ExitProcess` 和用户异常把当前进程标记为 Terminated，切回内核 CR3 后
   递归释放该进程独占的用户叶页、用户页表和 PML4。若仍有 Ready 进程则恢复
   下一个现场；否则恢复调度启动前的内核调用链。
9. 调度 IRQ 热路径只更新固定大小状态，不输出日志。进程全部结束后，内核一次性
   输出创建数、终止数、抢占数、调度次数、每进程 tick/dispatch/退出原因以及
   页帧回收前后统计。
10. 同一个 worker ELF 至少创建两个实例。worker 的可写全局变量必须各自从零
    演进到相同终值，用相同虚拟地址上的独立物理页证明地址空间隔离。

## 不采用的方案

- 为每个进程选择不同用户虚拟基址：避免了 CR3 切换，不能证明相同地址的隔离，
  也让固定地址 ELF 退化成伪进程。
- 在一个公共 TSS.RSP0 栈上保存所有现场：后续中断会覆盖已挂起进程的帧，无法
  建立可追踪的内核栈所有权。
- 在 IRQ0 中直接打印每次切换：串口轮询会放大中断延迟并冲刷日志，改变被测调度
  行为。
- 立即加入优先级、睡眠队列、SMP 和 FPU/SSE 保存：这些机制拥有独立不变量，
  应在基本 round-robin、资源生命周期和通用寄存器 ABI 稳定后再演进。

## 结果

本阶段得到可由真实 PIT 抢占、能切换 CR3 和 TSS.RSP0、能隔离同址 ELF 并在
退出后回收资源的最小多进程系统。当前仍只有单核、单线程进程和通用寄存器现场；
阻塞、唤醒、同步、IPC、FPU/SSE 状态与多核调度留给后续阶段。
