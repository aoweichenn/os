## 1. 上一阶段缺少什么

v0.1 的全部逻辑都固化在 ROM。真实启动链需要让稳定的小固件从可写介质加载更大、
更容易更新的程序。v0.2 建立：

```text
ROM
  → ATA PIO 读取 LBA 0
  → 验证 Stage 1 描述符
  → 读取 LBA 1..N
  → 验证填充后负载校验和
  → far return 到描述符声明的 segment:offset
  → Stage 1 自己建立 DS 并输出 ENTERED
```

这里不使用 `INT 13h`，因为项目没有 BIOS；不使用 GRUB；QEMU 也不会替固件读
磁盘。

历史验收见 [v0.2 发布记录](../releases/v0.2.md)，磁盘格式细节见
[boot-image.md](../modules/boot-image.md)。

## 2. Stage 1 磁盘契约

### 2.1 为什么先放描述符

固件不能从 CMake 知道运行时 Stage 1 的实际大小。若约定“固定读 64 个扇区”，
会混淆有效数据与填充，也无法知道入口和加载地址。LBA 0 因此保存自描述元数据。

当前布局：

```text
LBA 0       512-byte Stage 1 descriptor
LBA 1..64   Stage 1 payload capacity
LBA 65      Kernel descriptor（v0.4）
LBA 66..    Kernel ELF（v0.4）
```

### 2.2 描述符字段

前 28 字节为：

| 偏移 | 大小 | 字段 | 当前约束 |
| ---: | ---: | --- | --- |
| 0 | 8 | magic | ASCII `OSSTAGE1` |
| 8 | 2 | version | 1 |
| 10 | 2 | header size | 28 |
| 12 | 2 | load segment | 默认 `0x0800` |
| 14 | 2 | entry offset | 默认 0，必须位于真实负载内 |
| 16 | 2 | payload sector count | 1..64 |
| 18 | 2 | flags | 必须为 0 |
| 20 | 4 | payload LBA | 默认 1，必须满足 LBA28 和镜像边界 |
| 24 | 2 | payload checksum | 填充后负载的 16 位字和 |
| 26 | 2 | descriptor checksum | 使整扇区 16 位字和为 0 |

所有多字节字段是 little-endian。剩余描述符扇区必须参与 checksum，所以未知
尾部内容不能被静默忽略。

### 2.3 两个 checksum 的语义

描述符 checksum：

```text
sum(all 256 little-endian words in LBA 0) mod 65536 == 0
```

生成器先把 checksum 字段置零，计算整扇区字和，再写入其二进制补数。

负载 checksum：

```text
sum(all words in sector-padded payload) mod 65536
```

它覆盖实际 Stage 1 和末尾零填充。16 位加法和只能发现常见传输或镜像损坏，
不是密码学认证，不能证明代码来源可信。

## 3. RAM 加载窗口

默认 `loadSegment=0x0800`：

```text
physical address = 0x0800 << 4 = 0x8000
```

固件验证：

- 起点至少为 `0x8000`，避免覆盖低端固件数据和栈附近约定。
- 按扇区计算的结束地址不超过 `0x9FC00`。
- 加法不得溢出。
- entry offset 小于负载扇区覆盖大小。
- 当前最大 64 扇区，即 32 KiB，适合一次实模式 segment 内连续传输。

宿主镜像生成器还要求入口不能落在实际文件之后的零填充中。

## 4. ATA PIO 读取状态机

主通道、主盘、LBA28 的单扇区读顺序是：

1. 向 `0x1F6` 写 `0xE0 | LBA[27:24]`，选择 master 和 LBA 模式。
2. 从 alternate status `0x3F6` 读取四次，满足约 400 ns 设备选择延迟。
3. 轮询状态，等待 BSY 清零，同时检查 ERR/DF。
4. 向 `0x1F2` 写扇区数 1。
5. 向 `0x1F3/0x1F4/0x1F5` 写 LBA 的低 24 位。
6. 向 `0x1F7` 写 READ SECTORS `0x20`。
7. 轮询到 `!BSY && DRQ`，期间检查 ERR/DF 和预算。
8. 用 `rep insw` 从 `0x1F0` 读取 256 个 word 到 `ES:DI`。

这里不能只等待 DRQ：设备可能以 ERR/DF 结束；也不能只等待 BSY 清零，因为数据
可能尚未就绪。

### 4.1 为什么每次只读一扇区

多扇区 ATA 命令还需要处理每扇区 DRQ、错误位置和边界。v0.2 选择最小状态机：
每条命令一个扇区，上层循环 LBA。性能较低，但每次传输的前置条件和失败位置更
清楚。

### 4.2 `rep insw` 的隐含状态

`insw` 从 DX 指定的端口读取 word，写到 `ES:DI`。入口已执行 `CLD`，所以 DI
递增。固件必须正确设置 ES，并确保 512 字节传输不会越过约定内存窗口。

## 5. 固件源码执行路径

仍在
[reset_and_serial.asm](../../source/firmware/src/reset_and_serial.asm)。

### 5.1 `os_firmware_load_stage1`

1. `ES=0, DI=0x0500`，把描述符读到低内存缓冲。
2. 调用 `os_firmware_validate_stage1_descriptor`。
3. 输出 `STAGE1_HEADER_VALID`。
4. 从描述符取 load segment 写入 ES，DI 清零。
5. 从 payload LBA 开始逐扇区调用 `os_firmware_read_ata_sector`。
6. 把 DS 临时切到负载段，对填充后全部 word 求和。
7. 与描述符 payload checksum 比较。
8. 恢复 DS=0，返回成功。

函数用 AL 返回分类错误码、CF 返回成功与否。调用者把错误码映射成稳定串口标记。

### 5.2 描述符验证顺序

代码先验证整扇区 checksum，再验证：

- 四个 16 位 magic word。
- version、header size 和 flags。
- sector count 非零且不超过 64。
- LBA 起点、LBA28 上限、加法溢出和磁盘扇区上限。
- load segment 形成的物理起点。
- 载荷结束地址。
- entry offset。

先验证再使用，防止损坏字段影响后续读盘或内存写入。

### 5.3 远控制转移

成功后代码从描述符读取：

```asm
mov bx, [load_segment]
mov dx, [entry_offset]
push bx
push dx
retf
```

栈顶先被 `retf` 弹到 IP，然后下一项弹到 CS，所以 push 顺序是先 CS、后 IP。
远返回会刷新可见 CS 和隐藏段状态，进入 Stage 1 的 `segment:offset`。

### 5.4 Stage 1 的第一个动作

[entry.asm](../../source/boot/stage1/src/entry.asm) 是 `org 0` 的平坦二进制。
固件可能按描述符改变加载 segment，所以 Stage 1 不假定 DS 仍由固件正确保留：

```asm
push cs
pop ds
```

随后它才能用自身相对标签读取字符串并输出 `ENTERED`。这是组件所有权边界：调用
者负责交付控制权，被调用组件负责建立自己的数据环境。

## 6. 宿主镜像实现

[stage1_image.py](../../tools/os_tools/stage1_image.py) 与固件共享同一格式语义，
但不共享可执行代码：

- `calculatePayloadSectorCount` 向上取整扇区数。
- `validateStage1Layout` 验证磁盘、LBA、RAM 和入口范围。
- `createStage1DiskImageBytes` 编码描述符、补零、计算两个 checksum。
- `parseAndValidateStage1DiskImage` 独立解析并审计生成结果。

生成器和解析器放在同一模块并不意味着应互相信任。测试还会手工损坏字节、截断
镜像和随机化布局，确保 parser 会拒绝。

## 7. 成功与失败协议

成功路径关键标记：

```text
[OS][FIRMWARE] RESET
[OS][FIRMWARE] SERIAL_READY
[OS][FIRMWARE] STAGE1_HEADER_VALID
[OS][FIRMWARE] STAGE1_LOADED
[OS][STAGE1] ENTERED
```

失败分类：

- `ATA_TIMEOUT`：BSY 或 DRQ 状态未在预算内完成。
- `ATA_ERROR`：ERR 或 DF。
- `STAGE1_HEADER_INVALID`：格式、范围或描述符 checksum。
- `STAGE1_CHECKSUM_INVALID`：负载字和不匹配。
- `SERIAL_FAILURE`：无法可靠报告后续状态。

失败后不尝试执行可能损坏的负载。

## 8. 测试

### 8.1 格式单元测试

检查：

- 正常生成/解析往返。
- magic、version、header size、flags。
- 描述符和负载 checksum。
- 截断与非整扇区。
- 负载大小、LBA28、磁盘末尾。
- 实模式加载窗口和入口。

### 8.2 随机测试

随机生成有效负载做 round-trip，并生成越界 LBA、错误长度等非法组合。随机种子
固定，失败输入可复现。

### 8.3 QEMU 故障注入

- IDE 永久 busy。
- IDE ERR。
- Stage 1 描述符损坏。
- Stage 1 payload 损坏。

这些用真实固件控制流验证，不把 Python parser 通过当作 CPU 已正确执行。

## 9. 调试方法

最后标记停在：

- `SERIAL_READY`：检查 LBA 0 读取和 ATA 状态。
- `STAGE1_HEADER_VALID` 之前：转储描述符 512 字节并按偏移检查。
- `STAGE1_HEADER_VALID` 之后：检查 ES:DI、payload LBA、sector count。
- `STAGE1_LOADED` 之后但无 `ENTERED`：检查 push/retf 顺序、入口 offset、
  Stage 1 首字节和 CS:IP。

GDB 中同时查看线性物理地址和 `CS:IP`，不要把 `0x0800:0` 写成物理
`0x0800`。
