# 背景知识专题：先理解机器，再阅读操作系统

## 1. 为什么还需要一组背景分册

[前置篇](../00-prerequisites-and-hardware.md) 是进入阶段文档前的快速机器模型，
[背景知识总览](../../background_knowledge.md) 则把项目从复位到进程串成一篇
连续说明。它们适合先建立全貌，但许多初学者还会遇到更深的问题：

- CPU 为什么从一个固定地址开始，而不是自动寻找 `main`？
- 8086 已经退出历史舞台，为什么现代 x86-64 仍有段寄存器、GDT 和 A20？
- “地址是 64 位整数”为什么不足以解释物理地址、虚拟地址、端口和 LBA？
- 编译器、汇编器、链接器、加载器各自决定了哪些字节？
- C++ 对象已经写了 `{}`，为什么 freestanding ELF 仍可能需要 `.init_array`？
- 中断、异常、系统调用和普通函数调用到底在哪一层不同？
- 单核为什么仍会出现竞态、丢失唤醒和资源生命周期问题？
- 文件写入成功、设备收到写命令、数据跨重启存在为什么是三种证据？

本目录把这些问题拆成七个专题。它不是百科全书，也不要求先学完大学整套计算机
课程；每册只展开当前项目真正需要的概念，并明确指出暂未实现的现代机制。

## 4. 每册的阅读方法

### 第一遍：找问题

只回答“没有这个机制会怎样”。例如学习分页时，先区分：

- 没有分页，两个程序为何容易互相覆盖？
- 有页表但没有物理所有权，为什么仍会把同一帧分给两人？
- 有映射但没有权限，为什么用户仍能写 Kernel？

### 第二遍：画状态

把名词画成状态而不是背定义：

```text
CPU mode
  Reset → Real → Protected → IA-32e/64-bit

process
  Ready → Running → Blocked → Ready
                    └──────→ Terminated

filesystem transaction
  Clean → Dirty → data/metadata writeback → Clean
```

### 第三遍：对照项目

每个专题都提供“项目落点”。打开对应源码，找：

- 常量是否带单位和地址空间。
- 状态是否由 enum 表达。
- 输入是否先做溢出与范围验证。
- 正常与失败是否都有稳定返回值。
- 测试是否验证了最终产物或真实 QEMU 路径。

### 第四遍：反事实推理

主动删掉一个前提，解释会发生什么：

- 不开 A20。
- 只设置叶页的 U/S。
- 在 PIC 尚未路由到 LAPIC 时执行 STI。
- 把用户指针直接交给 ATA。
- 管道关闭时不唤醒对端。
- 事务 Dirty 状态不先落盘。

能够预测故障，比能够复述成功路径更接近真正掌握。

## 5. 统一符号

专题中使用以下约定：

| 记号 | 含义 |
| --- | --- |
| `0x...` | 十六进制 |
| `b7..b0` | 从高到低的 bit |
| `[begin,end)` | 包含 begin、不包含 end 的半开区间 |
| `VA` | virtual/linear address，当前分页输入 |
| `PA` | physical address，内存控制器或总线看到的地址 |
| `LBA` | 磁盘逻辑扇区号 |
| `CPL` | 当前特权级 |
| `DPL` | 描述符声明的特权级 |
| `RPL` | 选择子携带的请求特权级 |
| `IF` | RFLAGS interrupt-enable flag |
| `PTE` | 页表叶项的泛称 |

项目正式术语仍以 [glossary.md](../../glossary.md) 为准。

## 6. 背景与实现文档的职责边界

背景分册回答：

- 为什么形成这种硬件或软件结构。
- 它解决了什么一般问题。
- 哪些概念容易混淆。
- 当前项目选择了哪种最小语义。

版本阶段文档回答：

- 仓库中是哪一个文件和函数。
- 当前常量、地址、布局和日志是什么。
- 这一版本怎样构建、失败和验收。

架构与模块文档回答：

- 当前主线的正式模块边界和不变量。
- 后续改动必须保持的接口与依赖方向。

三类文档互相链接，但不能用背景文章替代当前源码事实，也不能用一个当前常量
冒充 x86 架构的普遍上限。

## 7. 完成背景学习的最低标准

读完七册后，应能不用类比词独立解释：

- CPU、内存、总线和设备之间传递的到底是指令、地址还是数据。
- ISA、微架构、平台和操作系统各自负责什么。
- 一段 C++ 如何经过编译、重定位、链接、装载后成为目标内存中的机器指令。
- 物理所有权、虚拟映射、权限和缓存为何是四个不同问题。
- 异常、中断、系统调用与普通 `call` 的入口现场为何不同。
- 进程为什么不等于函数，描述符为什么不等于文件。
- 空管道的 WouldBlock 和 EOF 为什么不能共用一个结果。
- 写回 cache、ATA FLUSH 和跨 QEMU 重启分别证明什么。
- 单元、随机、产物和 QEMU 测试各自不能证明什么。

达不到时不必继续堆版本；回到对应专题，画一张布局图或完成一次手工推导，通常
比重复看代码更有效。
