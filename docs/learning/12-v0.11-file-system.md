## 1. 从字节流到持久命名空间

管道只在进程存活期间保存匿名字节。v0.11 建立完整持久化链：

```text
Ring 3 path/file syscall
  → user pointer copy
  → per-process file handle
  → path traversal
  → directory entry + inode
  → data/inode bitmap ownership
  → 8-entry write-back block cache
  → ATA PIO WRITE/FLUSH
  → raw disk
  → 新 QEMU 实例重新 mount/read
```

完成标准不是“写后马上从同一对象读回”，而是跨全新 QEMU 进程、同一可写磁盘
仍能恢复，并能拒绝损坏和未完成事务。

历史验收见 [v0.11 发布记录](../releases/v0.11.md)，设计决策见
[ADR 0014](../adr/0014-transactional-educational-file-system.md)。

## 2. 整盘所有权

当前 raw IDE disk 精确 2 MiB、4096 sectors：

```text
LBA 0..2047      1 MiB boot area
  0              Stage 1 descriptor
  1..64          Stage 1 payload capacity
  65             Kernel descriptor
  66..N          Kernel ELF
  N+1..2047      boot reserved

LBA 2048..3071   1024-block filesystem = 512 KiB
LBA 3072..4095   512 KiB reserved
```

最初草案从 LBA 1024 开始，但增长后的 Kernel 已延伸到约 LBA 1054。宿主内存
设备测试无法发现“最终镜像的两个所有者重叠”。修复因此冻结 1 MiB boot ABI，
并让镜像生成器拒绝 Kernel 越过 LBA 2048。

## 3. 文件系统块布局

文件系统相对块等于 `disk LBA - 2048`：

| 相对块 | 数量 | 内容 |
| --- | ---: | --- |
| 0 | 1 | superblock |
| 1 | 1 | inode bitmap |
| 2..9 | 8 | inode table |
| 10 | 1 | data bitmap |
| 11..1023 | 1013 | directory/file data |

固定参数：

- block size 512。
- 32 inodes，每个 128 bytes，每块 4 个。
- inode 0 reserved。
- inode 1 root directory。
- 每 inode 10 个 direct blocks。
- 最大文件/目录 data 5120 bytes。
- directory entry 64 bytes，每块 8 项。
- name 最多 40 bytes。
- absolute path 最多 128 bytes。

[file_system_format.hpp](../../source/kernel/include/os/kernel/fs/file_system_format.hpp)
用 `static_assert` 证明各区域精确相接。

## 4. 为什么不把 C++ struct 直接写盘

C++ struct 可能受：

- padding/alignment。
- enum underlying type。
- compiler/ABI。
- host/target endianness。

影响。磁盘格式必须独立稳定，所以
[file_system_format.cpp](../../source/kernel/src/fs/file_system_format.cpp) 用显式
offset 和 little-endian encode/decode。

解码不是 memcpy 后“相信字段”，而是同时验证 magic、version、layout、reserved、
type、size、block count 和 CRC。

## 5. Superblock

逻辑字段包括：

- format version。
- block size/total blocks。
- inode bitmap/table 位置和数量。
- data bitmap/start/count。
- inode count。
- root inode。
- transaction state。
- transaction generation。

编码块还有 magic、CRC 和必须为零的保留区域。解码后的所有布局字段必须与项目
冻结常量精确相等，不能接受一个指向 boot area 的“自描述布局”。

状态：

- `Clean=1`
- `Dirty=2`

generation 每次 BeginTransaction 增加，用于观察事务推进，不是完整日志序号。

## 6. Inode

一个 inode 的逻辑内容：

```text
type: Unused / RegularFile / Directory
sizeBytes
generation
linkCount
allocatedBlockCount
directBlocks[10]
CRC32
reserved zero
```

验证：

- allocated inode 不能是 Unused。
- size ≤ 5120。
- block count 与 size/类型一致且 ≤10。
- 每个 direct block 位于 data area。
- 未使用 direct slots 为零。
- 当前 link count 语义只允许树结构所需值。
- CRC 正确。

inode number 是表索引，不是磁盘 LBA；需要计算所在 inode-table block 和
块内 128-byte offset。

## 7. Bitmap 所有权

- inode bitmap bit 表示 inode slot 是否 allocated。
- data bitmap bit 表示 data block 是否 owned。
- 超出实际 32/1013 容量的 bitmap 尾部 bit 必须保持规定状态，不能当作未来
  空间默默分配。

分配先找 free bit，再初始化对象；失败路径必须避免一个 bitmap bit 指向未初始化
inode，或 inode 引用未标记 data block。

全盘 checker 不只看“bit 已设”，还建立 seen-data bitmap，证明每个 data block
至多被一个 inode 引用，最终 seen 与 allocated data bitmap 精确一致。

## 8. Directory entry 与路径

64-byte entry：

```text
u64 inodeNumber
u64 type
u64 nameLengthBytes
u8  name[40]
```

未使用 name 尾部必须遵守编码约束。entry type 必须与目标 inode type 一致。

### 8.1 Path parser

当前只接受 absolute path：

- 必须以 `/` 开始。
- `/` 表示 root。
- 总长 ≤128。
- component 长度 1..40。
- 拒绝重复 separator 形成的空 component。
- 拒绝 trailing slash。
- 拒绝 `.`、`..`。
- 拒绝 NUL/control characters。
- component 数有固定上界。

### 8.2 Resolve

从 inode 1 开始：

1. 当前 inode 必须是 Directory。
2. 遍历它的 directory entries。
3. 精确比较 length 和 bytes。
4. 读取目标 inode并交叉检查 type。
5. 继续下一 component。

Create 解析 parent 和 final name；parent 必须已存在且为目录，final 必须不
存在。

没有 cwd、symlink 或 mount point，所以路径语义保持有界。

## 9. 8 项 LRU write-back cache

[BlockCache](../../source/kernel/include/os/kernel/fs/block_cache.hpp) 每项：

- 512-byte data。
- logical block address。
- monotonically increasing access generation。
- valid。
- dirty。

Read：

- 命中：复制并更新 generation。
- 未命中：选 invalid；若无则选最小 generation 的 LRU。
- victim dirty：先写回。
- 从 device 读新 block。

Write：

- 获取/创建 cache entry。
- 复制整块。
- 标记 dirty。
- 不一定立刻写磁盘。

Sync：

- 写回全部 dirty entries。
- device Flush。

统计 hit/miss/eviction/device read/write/flush。热路径不逐块打印。

cache 自己有 lock；FileSystem 还有全局 lock。必须保持固定获取顺序，避免未来
形成 lock inversion。

## 10. 块设备边界

`FileSystemBlockDevice` 是窄接口：

- `ReadBlock(lba,512 bytes)`
- `WriteBlock(lba,512 bytes)`
- `Flush()`

宿主测试用 memory block device；目标使用 `AtaPioDevice`。文件系统算法不直接
执行端口 I/O。

v0.11 ATA 新增：

- WRITE SECTORS `0x30`。
- 256 word `out`。
- 命令完成状态。
- FLUSH CACHE `0xE7`。
- bounded BSY/DRQ/ERR/DF。

Flush 是持久性顺序的一部分，不只是性能提示。

## 11. Mount 或 Format

`MountOrFormat` 首先绕过未初始化 cache，直接读取 superblock block：

### 全零

只在 512 字节全部为零时允许首次 format：

1. 初始化 clean superblock。
2. 清 bitmap/table。
3. reserve inode 0。
4. allocate inode 1 root directory。
5. 写各 metadata。
6. flush。
7. 初始化 cache。
8. consistency check。

### 非零有效

1. decode magic/version/layout/CRC。
2. 若 state=Dirty → `IncompleteTransaction`。
3. state=Clean 才初始化 cache。
4. 执行全盘 consistency check。
5. mount 成功。

### 非零无效

返回 `Corrupt`，绝不自动格式化。否则一次 bit flip 会被“新文件系统”掩盖并
永久丢数据。

## 12. 修改事务

每个修改操作：

```text
BeginTransaction
  transactionGeneration++
  state = Dirty
  encode superblock CRC
  direct device write
  device flush

mutate cache
  data blocks
  inode
  directory
  bitmap

CommitTransaction
  cache.Sync()       # write all dirty + flush
  state = Clean
  encode superblock CRC
  direct device write
  device flush
```

superblock 直接 I/O，避免它自己的 Dirty/Clean 顺序被 write-back cache 延后。

这不是 journal：

- 崩溃在 Dirty 后，下次只会检测并拒绝。
- 没有 redo/undo log。
- 不保证自动回滚到旧版本。

阶段目标是“不把部分提交当成一致数据”，恢复属于后续版本。

## 13. 文件操作

### Open

flags：

- read。
- write。
- create。
- truncate。

验证组合和 path。找不到且 create=false → NotFound；存在 directory 用 file
方式打开 → IsDirectory；truncate 要求 write permission并在事务中释放旧 data
blocks、重置 inode。

### Read

- handle open/readable/regular。
- EOF 时 `readBytes=0`。
- 从 offset 定位 direct block 和 block内偏移。
- 处理跨块和 partial last block。
- 更新 handle offset 和 bytes-read stats。

### Write

- handle open/writable/regular。
- `offset+length <=5120`。
- 按需 allocate data blocks。
- 对 partial block 执行 read-modify-write。
- 更新 inode size/block count/generation/CRC。
- 在事务中提交。

### Directory

v0.11 支持创建多级目录；v1.0 增加 OpenDirectory/ReadDirectory 用户 ABI。
directory handle 的 offset 表示下一 entry index，末尾返回显式 EOF。

### Close/Sync

Close 使 handle 无效；重复 close 拒绝。Sync 写回 cache并 flush。进程退出或
异常会自动 close 所有 open handles。

## 14. 全盘一致性检查

Checker 执行：

1. 验证 bitmap unused bits。
2. 遍历每个 allocated inode，解码和 CRC。
3. 验证 inode type、size、block count 和 direct blocks。
4. 用 seen bitmap 禁止 data block 重复引用。
5. 遍历每个 directory entry，验证名称、inode范围、allocation和类型。
6. 每个目录内禁止 duplicate name。
7. 从 root 做有界 BFS。
8. 所有 allocated inode 必须恰好 reachable。
9. 拒绝 orphan、cycle、额外 hard link。
10. seen data bitmap 必须等于 allocated data bitmap。

这比“superblock CRC 正确”强得多：CRC 只能发现局部字节改变，不能证明跨对象
所有权和图结构。

## 15. 用户 ABI 与验证工作负载

v0.11 新增 syscall 10..15：

- OpenFile。
- ReadFile。
- WriteFile。
- CloseFile。
- CreateDirectory。
- SyncFileSystem。

每进程初版有四个普通 file-handle slots；v1.0 把它们接入 8-slot unified
descriptor table。

Producer：

1. `mkdir /shared`，允许 AlreadyExists。
2. create+truncate `/shared/payload.bin`。
3. 写 256-byte deterministic payload。
4. close + sync。
5. 再通过 pipe 发送同一 payload。

Consumer：

1. 从 pipe 逐字节验证到 EOF。
2. 打开同一路径。
3. 读 256 bytes并再次验证。
4. 再读一次要求 EOF。

Kernel 在全部进程结束后独立 Sync、CheckConsistency、Open/Read/Verify，避免
只相信用户程序声称成功。

## 16. 跨启动持久化测试

系统测试：

1. 复制正常 boot disk 到临时可写文件。
2. QEMU `snapshot=off` 第一次启动，可能 format，写 payload，sync，退出。
3. 使用同一个磁盘启动全新第二个 QEMU。
4. 第二次必须 mount existing FS，并在用户修改前恢复旧 payload。
5. 宿主翻转 superblock 字节。
6. 第三个 QEMU 必须报告 Corrupt，且不得 format、进入 Ring 3 或 READY。

两个“全新 QEMU”排除 RAM、cache、进程或 QEMU snapshot 偶然保留数据。

## 17. 测试

- 格式 unit：superblock/inode/directory round-trip、CRC、reserved、layout。
- lifecycle integration：format、nested dirs、1300-byte cross-block file、
  remount、truncate、capacity、orphan/cycle/corruption。
- randomized：128 轮 rewrite，每轮 new FS/cache object remount，与 byte-array
  reference 对比。
- tooling：boot area 与 FS region 不重叠。
- QEMU：Ring3 ABI、ATA write/flush、consistency、Kernel independent read。
- persistence：两次正常重启 + 一次 corruption rejection。

## 19. 实验

### 实验 A：手工磁盘定位

disk LBA。

### 实验 B：跨块写

### 实验 C：崩溃点

## 20. 阶段验收

应能解释：

- 2 MiB disk 的 boot/FS/reserved 所有权。

- 8-entry LRU write-back cache。
- Dirty→data→Clean 的顺序和非 journal 边界。
- 只有全零 superblock 才 format。
- path resolve、direct-block read/write 和 handle offset。
- consistency checker 如何证明可达性和唯一所有权。
- 两个全新 QEMU 如何证明真实持久性。
