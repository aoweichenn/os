# v0.7：中断路由与设备驱动

> 背景先修：
> [中断、时间与 PC 设备](background/05-interrupts-time-and-pc-devices.md) 和
> [测试与分层诊断](background/07-testing-debugging-and-evidence.md)。

## 1. 从同步启动到异步世界

此前 CPU 只在软件主动调用时与设备交互，中断始终关闭。v0.7 首次让外部事件在
任意指令边界改变控制流：

```text
PIT / PS/2
  → 8259A PIC
  → LAPIC LINT0 ExtINT
  → CPU IDT[0x20/0x21]
  → NASM IRQ stub
  → C++ dispatcher
  → device handler
  → PIC EOI
  → IRETQ
```

同时内核建立自己的 ATA 读取路径，证明 Kernel 不再依赖 Stage 1 的磁盘函数。

历史验收见 [v0.7 发布记录](../releases/v0.7.md)，决策见
[ADR 0010](../adr/0010-legacy-interrupt-routing-and-device-bootstrap.md)。

## 2. 为什么同时需要 PIC 和 LAPIC

QEMU `pc` 平台包含传统 8259A PIC，也向 CPU 暴露 Local APIC。项目选择
virtual-wire 兼容路径：

```text
legacy device IRQ
  → master/slave 8259A
  → master INTR
  → Local APIC LINT0 in ExtINT mode
  → CPU
```

这条路径适合单核教学，能显式展示传统 IRQ 和 APIC CPU 入口。它不是 IOAPIC
redirection，也没有 SMP。

### 2.1 Local APIC

内核先用 CPUID 确认 APIC，读取 APIC base，要求 4 KiB 对齐，并把
`0xFEE00000` 页映射成 supervisor RW、NX、cache-disabled。

初始化：

- Spurious Interrupt Vector Register：软件 enable，并选择 vector `0xFF`。
- LVT LINT0：delivery mode=ExtINT，unmask。
- 不启用 x2APIC。

MMIO 寄存器访问使用 `volatile` 语义；它不是 I/O 端口。

## 3. 8259A PIC

### 3.1 为什么重映射

PC 默认 master PIC 向量可能从 `0x08` 开始，与 CPU #DF 等异常重叠。内核通过
ICW1..4 重新初始化：

- master base `0x20`。
- slave base `0x28`。
- slave 接在 master IRQ2。
- 8086 mode。

初始化期间 mask 全部 IRQ，设备准备好后只开放 IRQ0 和 IRQ1：

```text
16-bit mask = 0xFFFC
```

### 3.2 EOI

处理完成必须发 End Of Interrupt：

- master IRQ：只给 master。
- slave IRQ：先给 slave，再给 master 的 cascade。

过早 EOI 可能允许同源中断在状态未处理完时再次进入；不发 EOI 会让控制器不再
投递后续同优先级事件。

### 3.3 虚假 IRQ7/IRQ15

PIC 的中断请求可能在 CPU acknowledge 前消失。通过读取 ISR 判断：

- spurious IRQ7：不给 master EOI。
- spurious IRQ15：不给 slave EOI，但 master 已确认 cascade，需要给 master
  EOI。

内核用软件 `INT 0x27` 验证 spurious 分支不会错误改变计数或 EOI。

## 4. IDT 和 IRQ 汇编入口

v0.5 的 IDT 32..47 是 not-present。v0.7 为每个 legacy IRQ 安装 DPL0
interrupt gate。

硬件 IRQ 不压 error code。每个 stub：

```asm
push 0
push vector
jmp osKernelHardwareInterruptDispatch
```

公共入口保存与异常相同的 15 个寄存器，形成同样 160-byte frame，但进入独立
`osKernelDispatchHardwareInterrupt`。异常策略和硬件 EOI 不能混在一起。

dispatcher 返回 `ExceptionFrame*`。v0.7 通常返回原 frame；v0.9 PIT handler
可以返回另一个进程的 frame，实现中断返回即上下文切换。

## 5. PIT 时钟

### 5.1 编程

8254 PIT channel 0：

- command port `0x43`。
- data port `0x40`。
- mode 2 rate generator。
- low byte then high byte。
- divisor `0x04A9`，即 1193。

实际频率约：

```text
1,193,182 / 1,193 ≈ 1000.15 Hz
```

### 5.2 时间换算

不能简单返回 `ticks` 并声称它就是毫秒。项目根据实际除数：

```text
milliseconds = ticks × divisor × 1000 / 1,193,182
```

实现需要考虑 64 位乘法溢出边界。PIT tick 是来宾内核时间；QEMU runner 附加的
宿主 monotonic timestamp 只是测试观察信息。

### 5.3 IRQ0 handler

每次：

1. 增加 64 位 tick。
2. v0.9 之后交给 scheduler 更新运行时间和时间片。
3. 向 PIC EOI。
4. 返回应恢复的 frame。

热路径不逐 tick 写串口，否则串口延迟会改变调度行为。

## 6. PS/2 键盘

### 6.1 i8042 初始化

控制器端口：

- `0x64`：status/command。
- `0x60`：data。

典型流程：

1. 等 input buffer 可写。
2. 禁用端口，清残留 output。
3. 读取/修改 controller configuration。
4. 启用第一 PS/2 port 和 IRQ1。
5. 向键盘发送 enable scanning `0xF4`。
6. 等待 ACK `0xFA`。
7. 最后才在 PIC 开放 IRQ1。

每次等待都有预算，并区分 command 写入、data 响应和超时。

### 6.2 Set 1 decoder

v0.7 初版验证基础 make code；v1.0 最终 decoder 已扩展且 v1.4 继续保留：

- make/break。
- `0xE0` extended prefix。
- 左右 Shift。
- Caps Lock。
- 字母、数字、空格、Enter、Backspace、Tab 和基础标点。

IRQ1 handler 从 data port 读扫描码，交给纯 C++ 状态机。v1.0 起若形成字符，
就提交控制台 FIFO 并唤醒等待读 descriptor 0 的 Thread；这部分在 v1.0
重点解释，Process/Thread 差异见 v1.2 发布记录。

IRQ handler 不直接实现 Shell，也不在每个按键上刷串口。

## 7. Kernel ATA PIO

[ata_pio.cpp](../../source/kernel/src/device/ata_pio.cpp) 重新实现主通道、master、
LBA28、单扇区同步 PIO。

v0.7 首次能力是读取：

- bounded BSY/DRQ。
- ERR/DF 分类。
- 400 ns delay。
- 256 次 16-bit port read。
- LBA0 读取后验证 Stage 1 magic，证明读到的是启动盘。

v0.11 在同一驱动增加：

- WRITE SECTORS `0x30`。
- 256 次 16-bit port write。
- FLUSH CACHE `0xE7`。
- 写后状态检查。

IRQ14 保持屏蔽，当前 ATA 是同步轮询驱动。不要把“系统已有中断”误写成“所有
设备都使用中断 I/O”。

## 8. 设备初始化顺序

当前 Kernel 主线中的关键顺序：

1. 内存子系统映射 LAPIC MMIO。
2. 配置 LAPIC virtual-wire。
3. 重映射 PIC，保持 mask。
4. 配置 PIT。
5. 初始化 PS/2 controller/keyboard。
6. 初始化 ATA 并读取 LBA0 自检。
7. 只 unmask IRQ0/IRQ1。
8. 执行软件 spurious IRQ 测试。
9. `STI`。
10. 等待至少 16 个真实 PIT ticks。
11. 验证 tick、时间和键盘/ATA统计。

先 STI 再准备 IDT/PIC/设备会把尚未定义的异步输入引入初始化临界区。

## 9. `PortIo` 与设备模型

[port_io.cpp](../../source/kernel/src/device/port_io.cpp) 集中封装 `inb/inw/outb/outw`，
使：

- 汇编约束和 compiler barrier 不散落。
- 8/16 位宽明确。
- 高层驱动代码用端口类型表达动作。

[device_model.cpp](../../source/kernel/src/device/device_model.cpp) 保存可在宿主测试的
纯逻辑：

- PIC vector 和 EOI 决策。
- PIT divisor/time conversion。
- PS/2 scan-code 状态。
- ATA 状态分类与边界。

模型不替代真实 I/O；它让复杂状态组合在启动 QEMU 前可穷举或随机验证。

## 10. 中断安全原则

### 10.1 共享状态

普通 Kernel 代码和 IRQ handler 可能交错访问 tick、keyboard queue 或 scheduler。
单核并不自动意味着无并发：中断可以在普通指令之间抢占。

v0.7 尽量使用简单原子宽度和短 handler；v0.10 才引入正式 spin lock 和等待
规则。

### 10.2 Handler 的上界

IRQ handler 应：

- 读取/确认设备必要状态。
- 更新有限状态或队列。
- 唤醒需要的主体。
- 发送 EOI。
- 快速返回。

不能进行无限轮询、复杂文件系统操作或无界日志。

### 10.3 IF

interrupt gate 进入时硬件清 IF。`IRETQ` 从原 RFLAGS 恢复。不要在普通 handler
中随意 STI 引入未设计的嵌套。

## 11. 失败路径

- LAPIC 不支持或 base 无效：设备初始化失败。
- PIC vector/mask/EOI 模型不一致：拒绝 READY。
- PIT divisor 非法或 tick 不增长：超时失败。
- i8042 input/output buffer 超时：键盘初始化失败。
- 键盘 ACK 错误：不开放 IRQ1。
- ATA busy timeout、ERR/DF、LBA 越界：分类错误。
- IRQ vector 不在 PIC 窗口：不发送错误 EOI。

设备状态错误必须保留来源，不能统一成“device failed”后失去定位证据。

## 12. 测试

### 单元/随机

- PIC remap、mask、master/slave/spurious EOI。
- PIT divisor 和 64 位时间换算。
- 键盘 make/break/extended/modifier 状态。
- ATA LBA28、状态位和轮询预算。
- 端口序列模型。

### 集成

- IDT 32..47 gate。
- LAPIC page cache-disabled。
- device init order。
- IRQ frame 与 descriptor layout。
- LBA0 magic 自检。

### QEMU

证明：

- LAPIC/PIC ready。
- PIT tick 真正增长。
- IRQ mask 精确。
- spurious IRQ 规则。
- PS/2/ATA 初始化。
- 旧异常和内存故障回归仍正确。

## 13. 调试

### 无 PIT tick

按顺序看：

1. IDT[0x20] present/selector/handler。
2. PIC master base/mask。
3. LAPIC SVR enable。
4. LINT0 ExtINT/unmasked。
5. RFLAGS.IF。
6. PIT command/divisor。
7. handler 是否发 EOI。

### 键盘一个键后不再中断

检查是否读取了 `0x60` 清设备输出、是否发 master EOI、decoder 是否把 break
错误当 command 状态。

### ATA 偶发卡死

检查每个命令前后的 BSY/DRQ 顺序、400 ns delay 和 budget；不要用无限 timeout
掩盖状态机错误。
